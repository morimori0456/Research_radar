## 2. 今週の精読1本

**→ [2608.06008 Adaptive-WAM: Quality-Guided Early-Exit Planning from Intermediate Video-Diffusion Features](../briefs/2026-08-08/2608.06008v1.md)**

選定理由: 話題性ゼロ(hf=0)で選定基準どおり**機構**で選ぶ。W30 の精読 HyWorldVLA が出した「pre-train は pixel 接地・運用は latent 専用」という**深さ方向の続編**であり、2週分の理解が1つの設計判断に閉じる —「world model を planner に繋ぐとき、どこまで実行すればいいのか」。しかも NAVSIM 90.8 PDMS と **end-to-end 170ms を同じ表で報告**しており、R3(VLA × world model 統合)と R1(latency 予算を固定した評価軸)を同時に射抜く。コード公開予定で追試可能。

読むときの問い(3つ):
1. **「denoising timestep に鈍感」はどこまで一般か。** planning が粗い意味情報しか使っていないから鈍感なのか、それとも **NAVSIM が粗い判断しか要求していない**から鈍感に見えるだけか。合流・遮蔽・カットインだけを抜いたサブセットで感度が復活しないか。飽和する層の深さはシーン難易度で動くか(動くなら adaptive exit の根拠が強まる、動かないなら固定 exit で十分)。
2. **quality scorer は何を見て「良い」と言っているのか。** scorer と exit head が同じ hidden state を共有している以上、**浅い exit の軌道を高く評価する自己都合バイアス**が入りうる。早期 exit が誤った時の失敗分布はどうなっているか。conformal 化するなら calibration と本番の交換可能性(exchangeability)は、exit が入力依存で変わる時点で壊れていないか。
3. **生成 pretraining の寄与は本当に本質か。** 推論で生成を一切回さないなら、**同じ backbone を最初から軌道予測だけで学習したもの**と差が出るのか。ここの ablation が薄ければ「world model は要らず大きい video encoder があればよい」ことになり、R3 の前提そのものが変わる。

## 4. 記憶チェック (5問)

1. **Q**: Adaptive-WAM は video diffusion planner から何を捨て、性能は何に鈍感で何に敏感だったか?
   **A**: deploy 時に **反復 denoising ループと VAE decode を丸ごと捨てた**(どちらも未来動画の合成にしか要らない)。
   **denoising timestep には鈍感**、効くのは **DiT の深さ**だが最終層は不要で中間層から良い軌道が読める。
   複数ブロックに trajectory head を付け、軽量 scorer が閾値を超えたら早期 exit。NAVSIM **90.8 PDMS / 平均 170ms**、
   fine-tuning なしで nuScenes に転移(L2 0.88m)。
2. **Q**: XEWorld で、未見ロボット機体への world model の汎化を決めていたのは何だったか? 含意は?
   **A**: **kinematic(関節構造)の類似度ではなく visual similarity(見た目の近さ)**。つまり現行モデルは本質的に
   **2D の視覚パターンマッチャ**で、数値の joint action を一貫した視覚的運動に翻訳できていない。zero-shot には
   **pixel-space action + 明示的な時空間 alignment** が要り、few-shot 適合は既知機体の **catastrophic forgetting** を招く。
   → 車種・カメラ搭載位置が変われば我々にとっても「未見 embodiment」。
3. **Q**: LAWM-3D が「multi-view を LAM に食わせても 3D 理解は出ない」とした原因と、処方3点は?
   **A**: 原因は (a) **未来フレームの見た目が漏れるショートカット学習(appearance leakage)**、(b) カメラ間の見た目差。
   処方は **multi-view invariant な行動 tokenization** / 中間特徴を **3D foundation model の特徴にアンカー**する
   (フル蒸留より軽い「部分蒸留」)/ **non-injective な RGB-D 同時再構成**で覗き見を封じる、の3点セット。
4. **Q**: ABSeeker と AgentOPSD は同じ問題を何の材料で解いたか。我々はどちらから試すべきで、なぜ?
   **A**: 同じ「**疎な結果報酬から密なステップ信号を作る**」問題。ABSeeker は **ground-truth の答えから逆算**して中間 clue を
   復元(answer-backtracked)、AgentOPSD は **teacher/student の log-prob 差**を turn 単位に集約し **log-odds 空間の
   Bayesian 更新**で pivotal turn を同定(critic も追加 rollout も不要)。**我々は事後的に最適軌道を計算できる場合が多い**ので、
   根拠の固い ABSeeker 側(正解からの逆算)から。AgentOPSD は正解が作れない場面用の代替。
5. **Q**: FailBench は安全をどう定式化し、なぜ衝突率より良いのか?
   **A**: **リスク = 接触確率 × エンティティ別の深刻度**。単一スカラーの衝突率は**歩行者と路側構造物を同じ重みで潰す**が、
   分解すれば planner の順位そのものが変わりうる。加えて **故障(センサ dropout・アクチュエータ劣化)を
   「たまに起きる事故」でなく制御可能な実験変数**にする MuJoCo ベースの評価基盤を公開した点が実務的貢献。
