## 4. 記憶チェック (5問)

**Q1. OPD を長く回すと、student が teacher を超えた後に成績が落ちるのはなぜか。SPOD の対策は? (`2610.25034`)**
A. OPD には 2 つの効果が同時に働く。repair (student の弱い判断を teacher が直す) と erosion (teacher が好まないが成功していた student の選択を削る)。序盤は repair が勝って teacher を超え、続けると erosion が勝って利得が消える。SPOD は成功 episode の中で teacher と衝突する部分を mask し、student の確率に下限 (soft floor) を入れる。必要なのは成功/失敗の 2 値だけ。LLM agent 3 benchmark で通常の OPD より最大 +15.2 pt。運転への移植には「成功」の定義が要る。

**Q2. 推論を挟む運転 VLA が、危険物を説明できるのに減速しないのはなぜか。どう直したか? (`2610.28184`)**
A. 危険の情報は表現に符号化されていて、軌道 generator も減速できる。弱いのは両者の結合で、縦方向の plan が ego-speed 履歴に支配され、危険物との距離にほとんど反応しない (perception-action binding gap)。危険物の距離だけ変えた対のシナリオで示した。修正は再学習なしで、frozen な flow-matching sampler に「危険物に近い軌道ほど高いコスト」を足す guidance。障害物への侵入率 58.1% → 14.5%。ただし障害物の正確な幾何が与えられた条件の数値。

**Q3. world model で plan の順位を付けるとき、画像の誤差が小さい model を選んではいけないのはなぜか。(`2610.29435`)**
A. return 誤差の中央値 70% は、報酬が出る・episode が終わる少数の event step から来る。event step は他の step と同程度にきれいに描けていて (pixel 誤差比の中央値 0.85)、画像誤差が最大の step を直してもランダムに直すより効かない。Atari-100k の 44 組中 39 組で event の差し替えがランダムを上回る。運転なら衝突・割り込みの瞬間だけ実データに差し替える診断が作れるが、検証は Atari と制御 task のみ。

**Q4. 新しい地域に planner を出すとき、expert の選択と少数シーンの fine-tuning のどちらが効くか。評価で何に注意するか? (`2610.31095`)**
A. 選択は頭打ち: シーンごとに最良を選ぶ oracle でも横ずれは平均 0.9 m しか減らない。新地域 20 シーンの fine-tuning (元データの replay 付き) は 12.4 m → 6.9 m。注意点は 2 つ。nuPlan では open-loop の offset が良くなっても closed-loop が悪化する。比較対象の 2 手法は退化した軌道で低い offset を出していた。offset の数字だけでは良し悪しが判断できない。

**Q5. 今週の OPD 改良 5 本は、teacher の何を疑って何を足したか?**
A. SPOD = 成功していた student の選択を削る → mask + 確率の下限。AOPD (`2610.31563`) = student の成功率を上げない箇所まで真似る → advantage で重み付け (追加 rollout は不要・最終 reward と確率比だけ)。MCPD (`2610.30880`) = 特権情報の見せ方で teacher の出力が揺れる → 複数の部分 view の平均を target に。OPTD (`2610.28048`) = 最終層だけ合わせる → 層間の log-probability の増分も合わせる (gap の回復率 約 75% → 約 90%)。OnQ (`2610.29378`) = 固定応答との文脈のずれと確率の過小・過大 → student 自身の生成 + 候補ごとに forward/reverse KL を切り替える Dynamic KL。5 本とも LLM のみの検証。
