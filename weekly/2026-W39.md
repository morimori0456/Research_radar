## 4. 記憶チェック (5問)

**Q1. OPD で student の応答が伸び続ける原因として、EOS mismatch 論文が示した機序は何か。デコード時の停止集合を揃えても直らないのはなぜか?**
A. teacher と student は、宣言上は同じ停止トークン集合を持つ。しかし集合の**中で**確率を置く token が違う (`<|im_end|>` 系と `<|endoftext|>` 系)。OPD の勾配は student が好む EOS を押し下げるが、teacher が好む EOS を持ち上げるとは限らない。その結果、どの EOS にも質量が乗らず生成が止まらなくなる。ずれているのは推論時の停止条件ではなく loss の側なので、デコード側を揃えても効かない。直し方は、等価な EOS 群の確率を**合算してから**蒸留目標を計算すること。

**Q2. 複数 teacher の logit を平均してから softmax すると、確率の上では何になるか。蒸留では何が起きるか?**
A. 確率の**幾何平均** (`√(P_A·P_B)` に比例) になる。そのため、1 つの teacher だけが強く推す答えは大きく抑え込まれる。軌跡予測のように正解が複数に分かれる課題では、少数派の mode を student が学ばなくなるおそれがある。少数派の mode を残したいなら、確率の算術平均 `mean(softmax(logits))` を使う。

**Q3. 遮蔽シーンで衝突率が見落とすものは何か。3 条件の比は何を分けるか?**
A. 衝突率は、(a) 遮蔽された歩行者を想定して減速した planner と、(b) 何も考えず偶然当たらなかった planner を区別しない。遮蔽あり (O) の軌跡が、遮蔽なし (F) と agent 削除 (A) のどちらに近いかを `d(O,A)/(d(O,F)+d(O,A))` で測る。F に近ければ「いる前提で動いた」、A に近ければ「いないものとして動いた」。**F と A で出力が変わらない planner は、遮蔽を一切モデル化していない。**これも報告できる結果である。

**Q4. Taste-Bench の「59.7%」はなぜ低いのか。privileged information distillation で teacher と student は何が違うか?**
A. 二択の問題なので、偶然でも 50% になる。最良のモデルでも偶然を 10 点しか上回らない。蒸留では teacher と student が**同じモデル (Qwen3.6-27B)** で、違うのは入力だけである。teacher にだけ正解を見せて推論させ、student は問題だけを見て teacher の token 分布に寄せる。出力は二択の答えで終わり、正解の文面を写す部分が無いので、答えがそのまま漏れる leakage を構造で防いでいる。

**Q5. Object Permanence 論文の「学習で身に付く」という題名の主張を、この論文の結果だけでは確かめられないのはなぜか?**
A. fine-tuning 前の土台 (Cosmos3-Nano) が、比較した 14 モデルに入っていない。そのため順位の高さが学習データのおかげなのか、土台が元から強いのかを切り分けられない。さらに学習データと試験は同じ 150 generator から作られていて、分布内の汎化しか測っていない。**使えるのは評価の形式 (事象の直前で切る・構造と見た目を分ける・OP と OS を分ける) だけである。**
