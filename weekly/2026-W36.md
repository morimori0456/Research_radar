## 2. 今週の精読1本

選定理由は話題性ではない (hf 0)。**R1 と主張が最も近い論文であり、かつ R1 が 10 月に出す数字が通るか落ちるかを決める検定手続きが、この論文に完成形で入っているからである。**
PDT は **proxy objective の改善が実際の運転の意思決定に伝わっているかを統計的に検定する枠組み**で、**432 通りの設定を「データ2分割 × seed 2つ」で再現するゲートに通し、通ったものはゼロだった。**

**ブリーフでなく原論文が要るのは、R1 の主張の形そのものをこの論文が決めるからである** —— 09-04 の時点で「solvability を入れると順位が変わる (小さく勝つ)」から「集約スコアが同じ2場面を solvability が分ける」へ主張を変えるべきだ、という判断がすでに出ている。その根拠が本論文の検定にある。

読むときの問い(3つ):

1. **Reliability-Constrained Validation の6条件のうち、事前に宣言が必要なのはどれで、事後に計算できるのはどれか。**
   **特に minimum meaningful effect の決め方を最優先で読む。**R1 の toy 実証は「順位が入れ替わる」ことを示す図だが、**入れ替え幅の閾値を後から決めれば、この論文が 432 設定で潰したのと同じ穴に落ちる。**

2. **`support-versus-selection regret` の定義は、事後 (正解軌跡との比較) を本当に必要としているか。**
   R1 の差分は「事後監査 vs 事前量」の1点に集約されているが、**もし support 側の量が正解なしで計算できるなら、差分は消える。**

3. **512 → 2048 → 全データで信頼区間が 0 をまたぎ直した現象を、著者はサンプルサイズの問題として扱っているか、それとも効果の異質性として扱っているか。**

   **どちらであるかは abstract からは判別できず、しかも 10月の実験設計を決める。**

## 4. 記憶チェック (5問)

1. **Q**: Driving on Memory の対照条件は何をどう外したか。そこから落ちてくる「名前の付いていない量」は何で、それがベンチマークごとにどう違ったか。
   **A**: **end-to-end 運転モデルから カメラ入力を丸ごと取り上げ、代わりに「同じ場所を過去に走ったときの記憶」を与えた。**記憶は道路の形とその場所での走り方の癖は持つが、**いま前に何がいるかは一切持たない。それで NAVSIM のスコアがほとんど落ちなかった。**
   落ちてくる量は **`score(フル観測) − score(記憶のみ)` = そのベンチマークが実際に測っている「動的シーンへの反応」の幅。**著者は名前を付けていないが、実質的な出力はこの差分である。**NAVSIM では小さく、Bench2Drive と RealEngine では大きい。**
   **一般形が重要**: **測りたいと主張している能力「だけ」を取り上げた対照条件を作り、同じ指標で走らせる。同点が取れるなら、その指標はその能力を測っていない。**
   **読み方の注意: 結論は「ベンチマークが壊れている」ではなく「ベンチマークごとに反応の余地が違い、それを測れる」である。**
2. **Q**: Intervention Gap の **capture-gated** の2段構成とは何か。なぜ R1 の図1の骨格になるのか。そして「反直観な副産物」は?
   **A**: **① capture: モデルがそもそもその問い合わせを内部に表現しているかを判定し、表現している事例だけを次に進める。② 測定: 想像した数ステップ先の介入の効果と、環境側で同じ介入を行ったときの効果の差を取る。**
   段を分ける理由は、**「表現していない」と「表現しているが間違っている」を混ぜて平均すると何も分からなくなるから。**
   R1 では「分母の健全性 (抜け穴監査)」を**守りの作業**として書いていたが、**この論文はそれを測定手続きの前段として組み込んでいる。「まず数える資格のある事例を選び、その上で新しい量を測る」という2段構成が、そのまま図1の骨格になる。**
   本体の発見は **intervention fidelity の誤差が大きくなるほど episode return は下がるのに、reward 予測誤差は平坦なまま**であること。**副産物は、タスク信号を一切使わない自己教師あり world model のほうが、タスクに合わせて学習したモデルより介入の作用素をよく保存していた** —— **「下流タスクに寄せたほうが良い」という標準的な直観と逆である。**
3. **Q**: PDT の3つの数字を挙げよ。そして R1 との差分は1行で何か。R1 にとって最も危険な隣接概念は?
   **A**: ① **component BCE が 0.705 → 0.530 と大きく下がったのに、実際に選ばれた軌跡の PDM スコアは 0.963 → 0.961 とわずかに悪化した。**
   ② **ある候補は 512 件では +0.00909 で 95% 区間が 0 を含まないが、2048 件と全データでは区間が 0 を含む。**
   ③ **432 通りの設定のうち、データ2分割 × seed 2つで再現するゲートを通ったものはゼロ。**
   差分は **「PDT は事後 (走らせた結果を対にして検定する)、R1 は事前 (現在の状態から計算する)」。**ASCEND の3要件で言えば **PDT は objective と repeatable を強く満たし、proactive を満たさない。R1 は3つ目を埋めに行く。**
   **最も危険な隣接概念は `support-versus-selection regret`** (良い軌跡が候補集合に在ったか / それを選べたかを分離する量)。**既存概念の中で solvability に最も近く、違いを図1のキャプションに書けなければ査読者は「言い換え」と読む。**
4. **Q**: OPD (on-policy distillation) の分解で、教師について何が分かったか。それと Switch Distillation を合わせると capacity gap の読み方はどう変わるか。
   **A**: **教師が採点しているのは生徒が書いた文章 = 教師にとって自分では書かない文章であり、その信号には相当なノイズがあった。しかも教師を大きくするほどノイズの割合が増えた。**
   **そして生徒はそのノイズにほとんど反応しなかった。**著者はこれを「頑健で良かった」ではなく逆に読み、**改善は教師の信号内容に依存していないと結論した。**分解すると **学習は低 log-probability の token に集中しており、教師由来の advantage を単一の固定された負の定数に置き換えても性能が変わらない。**つまり **OPD は主に「確率の低い token を抑制する」ことで効いていて、その動作に教師は要らない** (教師なしの OPSA で Qwen3-1.7B / AIME24 Avg@32 が +35.41 pt)。
   **Switch Distillation はこれに時間軸を足す** —— **forward KL 蒸留は、pre-training 中は推論も事実記憶も伸ばすのに、mid-training では推論だけ伸びて事実記憶の獲得が遅くなる。効果の符号が段階で変わる。**原因は2つの非対称性の積: **教師は手続き的データで自信が高く知識データで低い / 生徒は事実知識を学習の早い段階で獲得する。**対策は **teacher predictive entropy が低い token でだけ蒸留し、残りは通常の cross-entropy に戻す** (追加モデルもアノテーションも不要)。
   **合わせると capacity gap の読み方が変わる: 蒸留の利得の大部分が知識転移ではなく確率分布の整形であるなら、「capacity gap」として測られてきた量は、そもそも知識転移の量を測っていなかった可能性がある。**
   **引用前の注意: OPD の検証は Qwen3-1.7B・数学推論のみ。相対 263% は元の水準が低いことの裏返しでもある。**
5. **Q**: Video World Models が「時間をどこに持つか」を3段に切った内容は? なぜ画素予測では隠れ状態が載らないのか。IMPACT はその結論をどう補強するか。
   **A**: **① token の中に持つ (履歴を読み直す) —— pixel を予測目標にしている限り、隠れ状態はそこに載らない。② 追記のみのアーキテクチャ状態に持つ (Transformer の KV cache) —— 書き換えられないので毎回導出し直しになり、外挿しない。③ その場で書き換えられる状態に持つ (遷移固有値に負を許した linear attention / TTT の fast weight) —— 外挿する。**
   **理由が W35 の主張より1段強い: 画素は「粗い」のではなく、勾配が一度も届いていない。**見えていないもの (遮蔽の裏) は pixel loss に現れないので、学習信号としてゼロである。**解像度や denoise 回数で埋まらないのは当然で、実際に埋まっていない。**
   **IMPACT は同じ構造を、遮蔽ではなく面積で示した** —— 全体で平均を取る MSE の denoising objective の下では、**画面の大半を占める静止内容が最適化を支配し、面積は小さいが相互作用に決定的な動的物体が不釣り合いに学習されない。**
   **そして [Intervention Gap](../briefs/2026-09-02/2608.29998.md) が射程を確定させる: 潜在空間の world model でも同じ穴が空く。問題は表現の媒体 (画素か潜在か) ではなく、監督が届いていない範囲そのものである。**
   **R3 の設計原則が1行になる: world model に何かを保持させたいなら、それに勾配が届く経路を明示的に作らなければならない。**
