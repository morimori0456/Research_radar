## 2. 今週の精読1本

**→ [2608.24525 RoG-DAgger: Rollout-Guided Post-Training for End-to-End Driving](../briefs/2026-08-27/2608.24525.md)**

選定理由: **hf upvotes は 0。話題性はゼロである。それでも選ぶのは、この論文が学習のために発明した1つの量が、そのまま R1 の主指標の候補だからである。**
**solvability = 「いまこの状態から、まだ助かる候補が何本残っているか」** を kinematic rollout (車両の運動モデルで数秒先まで空走させる計算。学習不要) で数える。
**この1つの量の両端に、危険と過保守がそろって載る** —— 逃げ道がゼロに近づく頻度が危険、常に多すぎるのが過保守。
**R1 が9週間探していたのは、この形の物差しである** (「過保守を測る量が無い」は planner-evaluation サーベイの Open Questions に4週前から★付きで居座っている)。
**そして今週、独立に3本が同じ物差しの上に乗った** —— [Anytime GTMP](../briefs/2026-08-28/2608.25830.md) の mode coverage は **solvability を homotopy class で数え直したもの**、
[PDPO](../briefs/2026-08-29/2608.27158.md) の抜け穴監査は **その分母の健全性検査**、[PAWBench](../briefs/2026-08-29/2608.27345.md) は **同じ量を分布として測る手続き**。
**ブリーフでなく原論文を読む必要があるのは、§3・§6 の作業がこの論文の定義の細部にそのまま依存するからである** —— 定義が決まらないと実装が始まらない。

読むときの問い(3つ):
1. **solvability の定義は、環境の性質か、それとも候補集合の設計か。** 候補を「軌跡 × 速度」の二次元に張ると論文は書いているが、
   **張り方 (本数・格子の粗さ・horizon の長さ・「助かった」の判定条件) を変えれば残存本数は当然変わる。**
   **もし絶対値が候補設計に依存するなら、solvability は planner 間の比較には使えても、シーンの危険度を表す量としては使えない。**
   **最初に探すのは、候補集合の設計を変えたときの感度分析があるか。**無ければ R1 側で先に正規化 (例: 初期状態での残存本数で割る) を定義する必要があり、**それは移植ではなく我々の貢献になる。**
2. **kinematic 近似が崩れる領域を、論文はどう扱っているか。** 低摩擦路面や高速域では運動モデルが楽観側にずれ、
   **「まだ助かる」と誤判定して介入が遅れる**のが最悪ケースである。**学習側なら教師信号が少し汚れるだけで済むが、評価側に移すと話が変わる** ——
   **R1 は「保証付きの指標」を主張するので、指標そのものが近似の上に載っているなら、保証は近似の妥当性以上には強くならない。**
   **conformal を被せるなら、この近似誤差を非適合度スコアに含めるのか、それとも仮定として外に出すのか。ここは論文に答えが無くても、我々が先に決めておく必要がある。**
3. **3つの貢献 (解空間の拡張 / 介入タイミング / 専門家視野の整合) のうち、ablation はどれに寄与を割り当てているか。**
   **もし視野整合が単独で大部分を説明しているなら、solvability は「効いた概念」ではなく副次的な装置であり、評価指標として移植する根拠は弱まる。**
   逆に**介入タイミングが効いているなら、solvability は実際に意思決定を変えた量である**という強い証拠になる。
   **Longest6 v2 の 22 → 44 は元が破綻水準 (22) であることの裏返しでもあるので、倍という表現ではなく ablation の内訳を見ること。**

## 4. 記憶チェック (5問)

1. **Q**: solvability とは何を数える量か。なぜ**危険と過保守が同じ1本の物差しに載る**のか。そして mode coverage との関係は?
   **A**: **いまの状態から kinematic rollout を N 本張り、衝突しない候補が何本残っているかを数える。** ゼロになる直前が
   **point of no return (これ以降は何をしても助からない点)。** **ゼロに近づく頻度が高いのが危険、常に多すぎるのが過保守** ——
   **同じ量の両端**なので、衝突率と走行時間を別々に見る現行の評価と違い、1本の軸に両方が載る。
   **mode coverage は、この残存本数を homotopy class (障害物の右を通るか左を通るかで分けた同値類) で数え直したものである** ——
   **逃げ道が10本あっても、全部が「少し右にずれる」なら種類としては1つ。**
   **ここから過保守の捉え方が変わる: 過保守は「重みが保守的すぎる」という連続的な問題ではなく、
   「候補集合が構造的に痩せている」という離散的な問題として書き直せる。**待つ以外の類を生成していないから待つ、のである。
2. **Q**: 今週「指標そのものが汚れている」型が2つ確定した。それぞれ何が起きていて、AD ではどう現れるか。
   **A**: ① **抜け穴 (PDPO)** —— crowd navigation のベンチマークに明示的な境界条件が無く、**エージェントは有効領域の外へ出て混雑を迂回していた。
   成功率は上がるが、課題を解いていない。**著者が境界逸脱を衝突として数える設定を足すと、**評価を厳しくした側でこそ設計判断の優劣が入れ替わった。**
   AD での同型: **経路から逸脱して交通の薄い側へ出る / 極端に減速して評価区間内に危険地点へ到達しない / シナリオ終了まで停止し続ける。
   どれも衝突率は改善し、どれも運転として失敗している。**
   ② **採点器の癖 (VBVR-Pro)** —— モデルに採点させると judge のバイアスが結果に混入する。**対処は指標を「決定的な規則だけで計算できるか」で2分すること。**
   **そして conformal で保証を付ける対象がこの2つで汚れていれば、保証している内容は空になる** —— R1 はこれを弱点ではなく主張の前半として書く。
   なお ③ として **SIREN-Bench** の実測も同じ棚に置ける: **学習済み予測器9種が、等速直進を仮定するだけの基準線に平均で勝てなかった。**
   **素朴な基準線を併走させていない数字は、解釈できない。**
3. **Q**: Gen2Sim が出した最も鋭い数字は? そして今週、world model について5本が独立に収束した命題は一行で何か?
   **A**: **実装を伴う world model 論文 163 本のうち、実行中に物体の状態や物理パラメータを外から問い合わせられる窓口を持つのは 6 本だけ。**
   つまり大半は中で何が起きているかを読めず、**衝突率のような数値を計算する手段が無い = planner の評価環境として使えない。**
   命題は **「world model の予測対象は、下流が読める表現・行動が実行される空間に合わせろ」。**
   GeoWAM は具体的な反例 (画素でなく未来の幾何を予測する事前学習に変えたら open-loop でも closed-loop でも強くなった)、
   Gen2Sim はその一般的な根拠、WorldSync は評価の物差しも画素でなく SE(3) 幾何へ移せ、と言っている。
   **そして WorldSync の診断が R3 の前提に条件を付ける: world model は専門家の行動なら概ね実行するが、
   専門家がやらない妥当な行動では指令を無視するか映像が破綻する。** —— **world model を使う価値はまさに
   「専門家がやらない行動を試せること」にあったのだから、この構想はいちばん要る場所でいちばん弱い。**
4. **Q**: QLoRA の acquisition–retention frontier で最も意外だった結果は? そして R2 の破綻境界について、今週2つの説明候補が出た。それぞれ何か?
   **A**: **全パラメータを更新する FFT のほうが、高 rank の QLoRA より一般能力をよく保っていた。**
   「更新するパラメータが多いほど忘れる」は成り立たず、効いているのは更新の総量ではなく**低ランク部分空間に押し込められた更新の集中度**である。
   実務上の含意: **メモリが許すなら FFT を基準線に置き、QLoRA はその省メモリ近似として評価する。「PEFT だから安全」は根拠を失った。**
   R2 の破綻境界の説明候補は2つ。① **集中度仮説 (UC-MOPD)** —— **CLL (教師の出力分布の entropy で較正した「教師がこの token をどれだけ本気で推しているか」)**
   の上位1%占有率が容量比とともに上がり、閾値を超えたところが境界ではないか。**勾配より軽く、教師の出力分布がログにあれば再学習不要。**
   ② **clipping 仮説 (Echo-GRPO)** —— 容量差が開くほど教師トレースは student にとって分布外になり、
   **確率比が外れて gradient clipping に切り捨てられる token が増える。しかもそれが起きるのは意味的に最も重要な推論 token である。**
   結果は「答えは合うが、その答えを支える推論は学習されていない」。**境界とは、学習される token の割合が足りなくなる点ではないか。**
   **2本は治療の方向が正反対 (捨てる vs 救う) なので、R2 の予備実験では対照群として並べられる。**
