## 4. 記憶チェック (5問)

**Q1. VLA を bf16 のまま full-weight で fine-tuning すると、なぜ学習が進まないのか。直し方と数字は? (`2610.31859`)**
A. bf16 は仮数部が短く、weight の 1/512 未満の更新は丸めで 0 になる。LIBERO の実行では 100 step ごとの probe で更新の 79% 以上が消えていた。12 の open VLA codebase のうち 9 が該当し、4 は全 weight を bf16 で学習する (SmolVLA の default や π0.5 の guide)。fp32 master copy (更新を貯める 32 bit の複製) を持つと、LIBERO-Object で SmolVLA 4.3 → 49.3%、π0.5 5.1 → 80.9% (learning rate 1/10 の学習不足の条件)。learning rate が小さい少データ適合ほど影響が大きい。

**Q2. 「学習時だけ将来予測の補助 loss を足す」は効くのか。JAM と SaiVLA-JEPA は何が食い違うか? (`2610.37219` / `2610.38508`)**
A. JAM は foresight loss (head は推論で捨てる) で LIBERO-Plus 55.3 → 64.5、学習 FLOPs は推定 73% 減。SaiVLA-JEPA は paired 10,030 組で、JEPA 特徴を入れる効果 (71.6 → 約 82.5%) は大きいが、将来 supervision の gain は検出できない。両立しうる理由は 2 つ: 評価した学習予算の限定と、JEPA 特徴が既に時間情報を持つこと。どちらも manipulation のみ。

**Q3. 蒸留の capacity gap を loss でなくデータで埋める 2 方向は? (`2610.36477` / `2610.36445`)**
A. MPOPD は student の rollout を直す: student と teacher の確率の geometric mixture に近い proposal から sampling し、teacher の supervision が不安定になる場所を避ける (16 benchmark で OPD 超え、Qwen3-4B-Base の数学で +6.91、生成長 41% 減)。CARD は teacher の軌跡を直す: 既存の軌跡を RL で、student の分布に合う (Distribution Alignment) かつ筋の通った (Logical Coherence) 「教える軌跡」に変換する。どちらも LLM の text 推論のみ。

**Q4. planner の衝突を減らすのに、なぜ「その planner 専用」の危険場面を作るのか。(`2610.35448`)**
A. DiffusionDrive の NeuroNCAP 衝突の 95.9% は「見えているのに避けられない」planning の失敗で、perception でなく planning head に弱点がある。planning head から蒸留した軽い代理 model で、画像 renderer を使わず危険場面を探し、50 場面 (攻撃 + 回避軌道) で fine-tuning すると衝突率は SparseDrive 28.0 → 12.2%、DiffusionDrive 37.5 → 19.2%。他の planner 用の場面では 18.3 点の低下が 6.7 点に縮むので、評価 set は planner ごとに作る必要がある。

**Q5. 運転 policy の失敗を事前に警告する SRP は何を読み、評価にどう使えるか。(`2610.37299`)**
A. 凍結した policy の actor / ego / map の内部表現から、失敗直前の窓に付けたラベルで linear probe (線形の分類器) を学習し、policy を変えずに警告を出す。Bench2Drive の DriveTransformer で 2 秒先の ROC-AUC 0.833 (軌道のぶれ 0.715)、overhead 2.67%。評価では失敗率に加えて「何秒前に予告できたか」を指標にできる。内部表現にアクセスできない黒箱の planner には使えず、simulation のみの結果。
