# The Reality Gap in Automated Driving Systems Testing: Landscape, Challenges, and Research Directions (2610.38628)

- トピック: planner_ai (P1) / スコア 4.0 / arXiv RSS から回収 (planner_ai の keyword に一致せず)
- URL: https://arxiv.org/abs/2610.38628

## 何を解決する論文か

ADS (Automated Driving System; 自動運転 system) の test は simulation に大きく依存するが、simulation と現実の差 (reality gap) が test の結論を損ねることがある。どの差が研究され、「simulation と現実が対応している」という主張がどんな証拠で支えられているかは整理されていない。この論文は 4,195 本から選んだ 235 本の primary study を分類する systematic mapping (文献全体を系統的に分類する調査) である。

## 手法の核心

- 分類軸は、目的、対象、手法、実験設定、評価の証拠。simulation と実機の実行を、ADS の test component 6 種類について、**手法の側と評価の参照先の側で別々に**区別する。
- これで「手法を作るために使った現実の情報」と「主張を評価するために使った証拠」を切り分ける。ここが論文の中心的な貢献。
- 76% の研究は gap の緩和が目的で、主に scenario・actor の realism と perception を対象にする。94% は何らかの検証や測定を報告する。
- ただし、sensor/perception の対応、ADS の挙動、車両 dynamics、安全の結果のうち複数の metric family を報告するのは 61 本のみ。その範囲でも、差と test の判定 (verdict) の因果関係は確立されていない。
- 提言: claim-specific evaluation (主張ごとに必要な証拠を決める評価) と component 単位の報告。

## P1 への適用可能性

- P1 の評価指標づくりに、**「この simulator の結果から何を主張してよいか」を明示する枠組み**を与える。closed-loop の成績を出すときに、主張と証拠の対応表を付ける形式にそのまま使える。
- perception の realism が高くても、planner の挙動や安全の結論が現実と一致するとは限らない。metric を family ごとに分けて報告する設計にする根拠になる。
- 新しい metric の提案ではなく調査論文なので、すぐ動く recipe はない。本文の分類表を、自分の評価の checklist に変換して使う。
- 注意点: 対象は ADS test 全般で、planner に絞った結果ではない。

## 試すべき実験アイデア

1. 手元の planner 評価について「主張」「使った simulator」「使った現実データ」「主張を支える metric」を 1 行ずつ書いた表を作る。空欄が、証拠のない主張である。
2. 同じ scene を log replay (記録の再生) と reactive simulator (周囲が反応する simulator) で評価し、planner の順位が入れ替わる metric を探す。順位が変わる metric は、simulator の差に敏感な metric である。
3. sensor realism だけを落とした条件 (camera の画質劣化など) で走らせ、perception の誤差と planner の verdict の変化を比較する。論文が未確立とする「差 → verdict」の因果を、小さく測る。

## 注意

abstract のみに基づく。6 種類の component の内訳、simulator 別の傾向、planner に関する研究の本数は未確認。"Only 61 studies" は 235 本中の数で、その質までは abstract から判断できない。
