# You Don't Need Aligned Representations: Knowledge Distillation via Random Prototype Spaces (2610.37937)

- トピック: fm_distill_finetune (P2) / スコア 4.5 / arXiv RSS から回収 (fetch の窓または天井の外)
- URL: https://arxiv.org/abs/2610.37937
- コード: https://github.com/HamzaEtcibasi/RPKD

## 何を解決する論文か

knowledge distillation (大きい teacher の知識を小さい student に移す手法) では、teacher と student の特徴空間を揃える必要があると考えられてきた。そのため、異なる architecture の間 (ViT から CNN など) では学習可能な射影を設計する手間がかかる。この論文はこの前提を捨て、**ランダムに固定した prototype のベクトルを共通の物差しにする**ことで、特徴空間を直接合わせずに蒸留する。

## 手法の核心

- **RPKD (Random Prototype Knowledge Distillation)**: ランダム初期化して凍結した prototype (比較の基準となるベクトル) の bank を用意し、teacher と student をそれぞれ prototype と比較する。
- teacher 側の射影は学習しない固定のランダム写像で、学習するのは student 側だけ。bank と目的関数は teacher と student の組が変わっても同じで、入力の射影だけ architecture ごとに作る。
- **logit branch**: prototype との類似度の大域的な分布を合わせる。
- **feature branch**: prototype への活性を空間的に並べた map を合わせる。
- ランダムな射影がサンプル間の類似構造をおおよそ保つ、という random feature の解釈を与える。
- prototype の語彙が label 空間と独立なので、class 数が少ない問題でも supervision が痩せない。logit ベースの手法では class 数が減ると signal が減る。
- 結果: OFA (abstract に展開なし。異種 architecture 間の既存の蒸留手法と思われる) に対する gain の最大値は、CIFAR-100 で +7.98%、ImageNet-100 で +12.44%、ImageNet-1K で +1.28%。

## P2 への適用可能性

- P2 の capacity gap (teacher と student の能力差が大きいと student が学べない問題) の一因である**architecture の違いを、設計の手間なしに扱える** recipe である。組み合わせごとに adapter を設計する作業が減る。
- 運転の認識では class 数が少ない task が多いので、「少 class で supervision が増える」性質は実務に合う。label が少ない適合先でも使える可能性がある。
- teacher の特徴次元が student より大きい foundation model の蒸留に、固定射影だけで対応できるなら、前処理の cost が小さい。
- 注意点: 報告は画像分類のみ。検出、segmentation、BEV (Bird's-Eye View; 上から見た座標系) の特徴で spatial な activation map が機能するかは未検証。+12.44% は「最大」なので、平均は小さいはず。

## 試すべき実験アイデア

1. 公開 code で DINOv2 系の ViT teacher から軽量 CNN student への蒸留を、FitNet 型 (特徴を直接回帰する蒸留) と比較する。student の backbone を変えたときの調整工数も記録する。
2. prototype の数を {64, 256, 1024} と変え、class 数の少ない task で精度の変化を見る。論文の主張の核心を最小 cost で確かめられる。
3. feature branch を BEV 特徴に適用し、teacher と student の座標が揃っていない場合に効くかを見る。
4. prototype の seed を変えて結果の分散を測る。分散が大きいと、再現可能な recipe としては弱い。
