# Trajectory Evaluation via Rollout-Free World Model for End-to-end Autonomous Driving (2611.05072)

- トピック: next_arch / プロジェクト: P3 (P1 の planner 評価にも関連) / スコア 4.5
- URL: https://arxiv.org/abs/2611.05072

## 何を解決する論文か

E2E (end-to-end; 画像から直接軌道を出す) 運転の planner には、複数の候補軌道を出し、評価器 (trajectory evaluator) で 1 本を選ぶ構成がある。評価器が賢くなると planning は良くなるが、model-based な評価器は候補ごとに将来の状態を何ステップも予測する (論文の用語で rollout)。これは推論が重く、予測誤差も積み上がる。この論文は、**候補の比較に必要なのは将来の場面全体の再構成ではなく、比較に効く将来の情報だけ**と考え、rollout を使わない評価器 RFWorld (Rollout-Free World model) を提案する。

## 手法の核心

- shared scene memory: 場面を 1 つの共有 memory にまとめ、候補軌道の数に関係なく 1 回だけ作る。
- 学習時だけ、軽い temporal readout (memory から将来の情報を読み出す小さな head) を semantic supervision (意味的な教師) 付きで足し、memory を「将来が読み取れる表現」に整える。学習の追加費用は小さい。
- 推論時は、各候補軌道が sparse spatial readout (軌道が通る場所だけを memory から引く) で直接 memory に問い合わせて score を出す。再帰的な rollout が無いため、計算量は planning horizon (先読みのステップ数) × 候補数の分だけ減る(論文の見積もり)。
- NAVSIM (実走行ログを元にした planner の評価 benchmark) と Bench2Drive (CARLA 上の closed-loop 運転 benchmark) で state-of-the-art。

## 適用可能性 (P3 / P1)

- P3: world model を「将来を生成する」用途でなく「候補を比べる」用途に絞る設計の実例。生成の重さを避けて world model の予測の利点を取る方向は、車載の計算予算を考えると現実的である。
- P1: 候補軌道の scoring が planner の中核なら、評価器の差し替えは評価指標の設計とも直結する。NAVSIM と Bench2Drive の 2 つ (open-loop 寄りと closed-loop) で報告している点も評価の参考になる。
- 注意: 改善幅、比較した baseline、推論時間の実測値は abstract に無い。「候補数 × horizon 分」の削減は理論上の見積もりで、実測は別。

## 試すべき実験アイデア

1. 手元の planner に候補軌道の評価器があるなら、現行の score と RFWorld 型の「共有 memory + 軌道ごとの sparse readout」を同じ候補集合で比べる。先に推論時間を測り、候補数と horizon を振って scaling を確認する。
2. 学習時の temporal readout を外した ablation (部品を取り除く比較) を作り、「将来が読める表現」への整形が効く部分を切り分ける。
3. NAVSIM の score と closed-loop (Bench2Drive 相当) の結果が一致するかを確認し、評価器の改善が open-loop だけの見かけでないかを見る。
