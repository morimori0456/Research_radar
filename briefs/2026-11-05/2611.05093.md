# LoopQ: Fair, Closed-Loop Evaluation of Quantized Vision-Language-Action Models (2611.05093)

- トピック: next_arch → 評価設計の観点で P1 に配置 (P2 の compression、Jetson Thor での実機計測にも関連) / スコア 4.0
- URL: https://arxiv.org/abs/2611.05093

## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語から行動を出す model) の量子化 (重みを少ない bit 数で持ち、メモリと計算を減らす手法) は、PTQ (Post-Training Quantization; 学習し直さず後から量子化する) の論文が増えている。しかし各論文が「単純な既存手法」と同じ条件で比べておらず、提案手法が本当に効くのか判断できない。LoopQ は、**同じ checkpoint・同じ層・同じ推論 engine で、量子化の方法だけを変えて closed-loop で比べる benchmark** である。

## 手法の核心

- 比較対象: RTN (Round-To-Nearest; 最も近い量子化値に丸めるだけの最も単純な方法)、AWQ (Activation-aware Weight Quantization; 活性化の大きい重みを保護する)、GPTQ (二次情報で誤差を補正しながら量子化する)、ActQuant、QuantVLA。
- 4 つの VLA に対し、LIBERO と LIBERO-plus (robot 操作の simulation benchmark と、その摂動版) で 180,000 episode 以上を closed-loop で回す。公開されている 4 つの VLA 量子化の実装を再現できるかも検証する。
- 計測 hardware は NVIDIA H100、L4、Jetson AGX Thor。
- 結果: メモリは 2〜3 倍節約できるが、VLA 専用の PTQ は単純な汎用手法に勝てない。4 bit では RTN・AWQ・GPTQ が ActQuant・QuantVLA と同等以上で、RTN だけでも calibration 付きの手法に並ぶ。
- 標準の LIBERO では差が出ない設定でも、LIBERO-plus の摂動を入れると 1.5〜4.3 点落ちる。
- 速度は弱い結果: H100 の batch 1 では量子化した pi0.5 も OpenVLA-OFT も 16 bit 版より速くならない (1.06〜1.58 倍遅い)。**Thor は 4 bit のどの設定でも遅くなる**。原因の分析として、pi0.5 では量子化した backbone が compute-bound (計算律速) で、メモリ律速の action expert が GPU 時間の 63% を占めるのに 16 bit のまま残る。

## 適用可能性 (P1 / P2)

- P1: 評価の設計がそのまま流用できる。「同じ checkpoint・層・engine で 1 要因だけ動かす」「標準 benchmark で差が無い設定を摂動版で再検査する」の 2 点は、planner の評価にも要る。
- P2: 圧縮の手法を比べるときの基準線として RTN / AWQ / GPTQ を必ず入れる、という実務的な教訓。新しい圧縮手法は、まず RTN に勝てるかを確認する。
- Thor: 手元の Jetson Thor で 4 bit にしても速くならない可能性が高い、という計測がある。量子化に着手する前に、engine と kernel を固定した 16 bit 版の latency 分解 (backbone と action expert の時間配分) を取るべきである。
- 注意: 対象は manipulation の VLA で、運転の planner ではない。Thor での結果は pi0.5 / OpenVLA-OFT に対するもので、他の model では変わりうる。

## 試すべき実験アイデア

1. 手元の model を Thor で 16 bit のまま profile し、backbone と action expert (または decoder) の GPU 時間の比率を出す。律速が action 側なら、量子化より先にそこを削る。
2. 量子化を試すなら、RTN → AWQ → GPTQ の順に、同じ engine で closed-loop (または近い評価) を回し、最も単純な RTN との差を記録する。
3. 標準の評価に加えて、センサの摂動や条件変更を入れた版で 1.5〜4.3 点程度の落ちが出るかを確認し、「標準で劣化なし」を鵜呑みにしない評価を組む。
