# DriveMLP: When Training Strategy Outperforms Model Complexity in Autonomous Driving (2610.29676)

- トピック: planner_ai (P1) / スコア 4.5
- URL: https://arxiv.org/abs/2610.29676
- コード: https://github.com/alessandro-canevaro/DriveMLP

## 何を解決する論文か

IL (Imitation Learning; 人間の運転ログを教師として真似る学習) の planner は大量データで学べるが、closed-loop (planner 自身の出力で自車が動き、その結果が次の入力になる評価) では distribution shift (学習時に見なかった状態に入る) と compounding error (小さな誤差が積み重なって逸脱する) で崩れる。RL (Reinforcement Learning; 試行と報酬で方策を学ぶ) はこれに強いが、手作りの報酬と大規模な simulation が要る。この論文は「RL を最適化の道具としてだけ使い、報酬はログの expert 軌道との距離にする」学習方法を提案し、性能向上の大部分は model の大きさではなく学習方法から来る、と主張する。

## 手法の核心

- **EGRL (Expert-Guided RL)**: closed-loop で planner を走らせ、得られた軌道と記録された expert 軌道との距離を報酬にする。ルールベースの報酬設計 (衝突・車線逸脱などの重み付け) が要らない。
- 位置づけは「closed-loop の IL」。教師は expert のままで、RL は closed-loop 状態での勾配を得る手段に過ぎない。
- 統制実験 (controlled empirical study) で、model の大きさ・構造と学習手順を分けて比べ、学習手順の寄与が大きいことを示す。
- その結論の実例として、軽量な MLP の policy (DriveMLP) を EGRL で学習。nuPlan (自動運転 planner の標準 benchmark) の Val14 Reactive (他車が自車に反応する closed-loop 設定) で 86.51、既存の最良 IL planner (Flow Planner) を +3.2 上回り、推論は 15 倍以上速い。

## P1 への適用可能性

- 直接使える。手元の planner の「改善」が model 側か学習側かを切り分ける統制の作法として読む価値がある。手元で大きな model を入れて効いた改善が、実は学習の設定 (closed-loop で回したか) の差だった可能性を確認できる。
- 報酬が「expert 軌道との距離」なので、ルールベースの評価指標 (例: nuPlan の closed-loop score) と学習目標がずれている。score は上がったが、どの失敗が減ったか (衝突 / 進捗 / 快適性) の内訳は abstract には無い。

## 試すべき実験アイデア

1. 手元の IL planner と同じ構造のまま、学習だけ EGRL 型 (closed-loop rollout + expert 距離の報酬) に替え、closed-loop score の差分を取る。model を変えずに何点動くかが、この論文の主張の手元での再現になる。
2. 逆に、学習を固定して model を MLP まで縮め、score の落ち幅を見る。落ちなければ、onboard の latency 予算を他に回せる。
3. score の内訳 (collision / drivable area / progress / comfort) を EGRL 前後で並べ、expert 距離の報酬がどの項目を改善し、どれを犠牲にするかを確かめる。expert 距離は「安全だが expert と違う軌道」を罰するので、progress は上がっても慎重な回避が減る可能性がある。
