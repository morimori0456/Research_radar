# Events, Not Pixels: Where World Models Get the Return Wrong (2610.29435)

- トピック: planner_ai (P1) / スコア 4.0 (arXiv RSS から回収・candidates.json には無い)
- URL: https://arxiv.org/abs/2610.29435

## 何を解決する論文か

world model (環境が行動に対してどう変わるかを予測する学習済み model) を planning に使うとき、planner は model が想像した return (将来の報酬の合計) で候補の行動を順位付けする。ところが world model は主に「フレームがどれだけきれいに描けるか」で評価されている。この論文は、見た目が正しい rollout でも return を間違える原因がどこにあるかを、遷移 1 つ単位で診断する方法を提案する。

## 手法の核心

- **transition-level diagnostic**: 想像した遷移の一部を実際の遷移に差し替え、return の誤差がどれだけ減るかを測る。比較対象は、同じ数をランダムに差し替える対照 (budget-matched random control)。
- 発見 1: **event transition** (報酬が出る / episode が終わる数少ない step) は他の step と同程度にきれいに描けている (pixel 誤差の比は中央値 0.85) のに、そこだけ差し替えると return 誤差の中央値 70% が消える。
- 逆に MSE / SSIM / LPIPS (いずれも画像の再構成の良さを測る指標) の誤差が最大の遷移を差し替えても、ランダムより効かない = 画像指標は return の誤差の場所を指さない。
- 統計: Atari-100k (少ない環境 step で学ぶ RL の benchmark) の 44 組の model × データ収集のうち 39 組で event 差し替えがランダムを上回る (符号検定 p=1.4×10^-7)。報酬が稀な制御 task でも同じ集中が出る。
- 修復の手がかり: 事前に記録した規則で、diffusion model がこの失敗を直せる場合を予測できた。event を直すと plan の順位付けが改善する。

## P1 への適用可能性

- 運転の closed-loop simulation に学習済み world model (生成型の simulator) を使う場合、そのまま当てはまる。運転の「event」は衝突・車線逸脱・赤信号違反・合流成立など、score を決める少数の瞬間。world model の評価を FID や PSNR (画像の質の指標) でしていると、planner の順位付けに効く誤差を見落とす。
- planner 評価の観点では「評価器 (simulator) の誤差がどこに集中しているか」を測る方法として使える。ログ再生の simulator を使っていても、反応型エージェントの挙動が event (割り込み・接近) でだけ外れているかを同じ差し替えで検査できる。

## 試すべき実験アイデア

1. 手元の closed-loop 評価から、score を決めた event (衝突・TTC (Time-to-Collision; 衝突までの残り時間) の閾値割れ・逸脱) の時刻を抽出し、simulator / world model の予測をその時刻だけ実データに差し替えたときの score 誤差の減り方を、ランダムな時刻の差し替えと比べる。
2. world model を評価するときの指標を、画像指標と「event の検出率 (衝突や接近が起きたかを正しく予測したか)」の 2 本立てにし、どちらが planner の順位の一致 (実環境での順位との相関) を予測するかを見る。
3. planner の候補軌道の順位付けで、world model 上の順位と log-replay 上の順位の一致率を測り、不一致が event を含む候補に偏るかを確かめる。

## 注意

abstract のみに基づく。実験は Atari と制御 task で、運転のような連続的で event の定義が曖昧な設定での再現は未確認。
