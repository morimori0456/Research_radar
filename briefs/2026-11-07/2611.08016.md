# Learning Dynamics of On-Policy Distillation (2611.08016)

- トピック: fm_distill_finetune / プロジェクト: P2 / スコア 4.5
- URL: https://arxiv.org/abs/2611.08016

## 何を解決する論文か

OPD (On-Policy Distillation; student 自身が生成した応答に teacher が token ごとの密な feedback を返す蒸留) では、更新のたびに student が変わり、次の更新に使う rollout の分布も変わる feedback loop ができる。この loop が学習と汎化をどう決めるかはよく分かっていなかった。この論文は、OPD がなぜ「teacher と大きく食い違うのに student があまり動かない」ことや、「局所的には teacher に近づくのに劣化する」ことが起きるのかを機構として説明する。

## 手法の核心

- loop を 2 つの段階に分ける: (1) conversion: 蒸留の信号が parameter の更新に変わる段階、(2) broadcast: その更新が、別の prefix (途中までの生成) に対する予測を変え、rollout 分布を作り替える段階。
- (1) から、teacher と大きく食い違っていても student が動きにくい (responsiveness が低い) 現象を説明する。
- (2) から、局所的に teacher との一致を上げる更新が、失敗する続きの生成確率も上げ、**次の rollout で信頼できない supervision を受ける**劣化を説明する。
- 最後に、offline distillation (teacher が作った固定 data での蒸留) が OPD の準備になることを示す。offline だけでは held-out accuracy はあまり上がらないが、その後の OPD で大きく伸びる。OPD 単独だと生成が劣化することがある。

## 適用可能性 (P2)

- P2 の蒸留 pipeline の**順序設計**に使える: 「offline distillation で下準備 → OPD」を標準の recipe にする根拠になる。
- OPD が崩れたときの診断枠組みとして、conversion と broadcast のどちらで壊れたかを分けて見られる。2611.07722 (SD-OPD) の改善が conversion 側の対策か broadcast 側かを切り分ける視点にもなる。
- 注意: 解析は LLM post-training の設定。画像・行動系 model の蒸留で同じ分解が成り立つかは未確認。

## 試すべき実験アイデア

1. 手元の蒸留で、offline 蒸留の step 数を 0 / 少 / 多に振ってから OPD を回し、offline 段階の held-out accuracy と OPD 後の accuracy の関係を描く (最小の実験)。
2. rollout ごとに「teacher との一致度が上がったが成功率が下がった」例を数え、劣化の兆候を監視する指標にする。
3. 2611.07722 と組み合わせ、SD-OPD が offline 準備の有無でどう変わるかを見る。
