# Let's Scale Step by Step: Compute-Efficient Hyperparameter Transfer for Large-Scale Mixture-of-Experts

- 公開日: 2026-08-20 (fetch 実行時点で 4 日前。lookback_days:2 を超過 — 欠陥#3 による。DIGEST 参照)
- relevance: P2 **3.5** / P3 **3.0** / P1 **0**

## 何を解決する論文か

大規模モデルの事前学習では、**learning rate (LR) を間違えると学習が発散するか、収束しても性能が出ない。**しかし正解の LR を知る唯一確実な方法は sweep (複数の LR で実際に学習して比べる) であり、**モデルが大きくなるほど、トークン予算が伸びるほど、sweep 自体が実行不可能な計算コストになる。**10 兆トークン規模の学習を LR 5 点で試すという選択肢は存在しない。

本論文は **MoE (Mixture-of-Experts; 層の中に複数の expert = 小さい FFN を並べ、トークンごとに一部の expert だけを通す構造。総パラメータを増やしても 1 トークンあたりの計算量は増えない)** に対して、**小さい proxy model (代理モデル) の学習だけで、本番規模の最適 LR を当てにいく**枠組みを提案する。手順は 2 段階で、(1) モデルの **width (幅; 隠れ次元のサイズ)** 方向に LR を転移させ、(2) **token 方向**に scaling law (規模と最適値の関係を回帰式で表した経験則) で外挿する。**主張は「proxy 学習だけで大規模学習の LR が決まる」であり、これが正しければ本番規模の sweep という工程が丸ごと消える。**

## 手法の核心

- **μP (Maximal Update Parameterization; モデルの width を変えても各層の重み更新の大きさが同じスケールに保たれるよう、初期化と LR を幅に応じて割り付けるパラメータ化) を MoE 向けに定式化し直す。** μP の効能は **LR transfer** — width の小さいモデルで見つけた最適 LR が、width を拡大しても最適のまま残る。**論文の 1 段目はこれを MoE で成立させることに費やされている。**素の μP は dense な transformer 前提なので、expert 数・routing・active/total パラメータ比といった MoE 固有の軸がそのままでは扱えない。

- **対象は MoE 単体ではなく、MLA + Muon との組み合わせである。** **MLA (Multi-head Latent Attention; KV cache を低ランクの潜在ベクトルに圧縮して推論時のメモリを削る attention の変種)** と、**Muon (重み行列の更新方向を直交化してから適用する比較的新しい optimizer)** を使う構成に対して μP を導出している。**これは実装上の細部ではなく、本論文の主要な貢献である** — 標準的な μP の割り付けは Adam を前提に導かれており、更新の作られ方が違う Muon にはそのまま移らない。「現代的な大規模構成 (MoE + MLA + Muon) 一式で μP を成立させた」というのが売りである。

- **2 段目は token 軸の外挿。** width transfer で幅の問題は消えるが、**トークン予算が増えると最適 LR は下がる**という別の依存が残る。そこで限られた予算の proxy model 群から得た最適 LR に **linear regression (線形回帰) を当て、10 兆トークン地平まで外挿する。**報告されている当てはまりは **R² = 0.95** (R² は回帰の説明力、1 が完全一致)。

- **実証は自前の foundation model の事前学習。** 総パラメータ **155B / active パラメータ 17B** (1 トークンの推論で実際に通るのは 17B 分) の MoE を scratch から事前学習し、学習が安定したと報告している。

- **含意を一行でいうと「LR は測るものではなく予測するものになる」。**小規模で 2 つの方向 (幅・トークン) の振る舞いを測っておけば、本番の値は回帰で出る。

## 読むときの但し書き (abstract は 1500 字で切れており、以下は未確認)

- **主張は LR に限定されている。** batch size、warmup、weight decay など他のハイパラが同じように転移するかは、この abstract の範囲では言っていない。実務では LR だけ決まっても嬉しさは半分である。
- **R²=0.95 は回帰の当てはまりであって、hold-out の予測精度ではない。**外挿先 (10T トークン) の実測と突き合わせた数字ではない読み方もできる。ここは本文で確認する価値がある。
- **本番規模での検証は 155B モデル 1 本、つまり n=1 である。**「安定して学習できた」は、sweep した場合の最適値と一致したことの証明ではない。
- **コード公開の有無は abstract から不明。**μP は割り付け係数の実装ミスが起きやすく、論文の式だけで再現するのは骨が折れる部分がある。

## P1/P2/P3 への適用可能性

分野は大規模事前学習で、P1/P2/P3 のどれとも表面上は重ならない。それでも探索枠に採るのは、**この論文が「モデルを作る話」ではなく「実験計画をどう組むかの話」であり、そこが P2 の現在の弱点に直接刺さるからである。**

### P2 (FM 蒸留 + 適合) — 本日の主眼。R2 の実験計画の交絡を 1 本消せる

**R2 (蒸留の capacity gap 系統則) は、teacher と student の容量比を振って、蒸留が破綻する境界を探す実験である。**容量比を振るということは **student の width を何段階も変えて学習する**ということで、ここに**厄介な交絡がある** — width を変えると最適 LR も動くため、各点で LR を振り直す必要がある。

**ここで 2 通りのやり方があり、どちらも問題を抱えている。**
- 全点で同じ LR を使う → 大きい student には過大、小さい student には過小な LR になり、**「capacity gap の効果」として観測したものが、実は「LR がずれた効果」である可能性が残る。**
- 各点で LR を sweep する → 交絡は消えるが、**実験のコストが LR の点数だけ倍になる。**容量比 5 点 × LR 5 点 = 25 回の学習になり、これは着手を止めるのに十分な重さである。

**μP は第三の選択肢を出す — width を振っても LR を固定してよい、という保証である。**これが成り立てば R2 は **5 回の学習で済み**、しかも**測っているものが本当に capacity gap だけになる。**コストと交絡を同時に潰すので、R2 にとっては手法の話ではなく**実験が回るかどうかの話**である。

**ただし前提の確認が要る。**本論文の μP は MoE + MLA + Muon 用の導出であり、R2 の student が普通の dense transformer + Adam なら、**使うべきは本論文ではなく元の μP (Yang et al.) である。**本論文の価値は「μP という道具の存在を思い出させたこと」と「**現代的な構成に拡張するのは自明ではない**と示したこと」の 2 点にある。**自分の構成が素の dense + Adam から外れているなら、割り付けは自分で導き直す必要がある** — これが本論文の実質的な警告である。

**fine-tuning / PEFT 側への波及は、期待しすぎないほうがよい。**本論文は事前学習の話である。**LoRA (Low-Rank Adaptation; 重み行列に低ランクの差分行列だけを足して学習する代表的な PEFT 手法)** の最適 LR も rank に敏感であることは経験的に知られており、「rank を width と見立てて transfer できないか」は自然な発想だが、**本論文はそれを主張していないし、fine-tuning は事前学習と違って初期重みが情報を持っている**ため、μP の導出前提がそのまま成り立つとは限らない。**open question として書き留めるに留める。**

### P3 (次世代アーキテクチャ) — 該当はするが、優先度は高くない

topics.yaml の P3 の relevance_criteria には「スケール則・新しい構造・学習効率の改善も対象」とあり、本論文はここに正面から当たる。**VLA (Vision-Language-Action; 画像と言語を入力して行動を直接出力するモデル) を大きくしていく段になれば、MoE で総容量だけ増やして推論コストを抑える設計は現実的な選択肢であり、そのとき LR の決め方は必ず問題になる。**

**ただし P3 の高優先は VLA・world model・end-to-end 自動運転の構造そのものであり、本論文はその手前の学習手続きの話である。**今日の時点では「P3 がスケールの段に入ったときに読み返す論文」として置いておくのが正しい距離感で、**今すぐ R3 (VLA × world model の分類マップ) を進める材料にはならない。**

### P1 (Planner AI + 評価) — 該当なし

**無理に繋げない。**planner の評価指標にも closed-loop simulation にも関係しない。「小さい proxy で大きい系の挙動を予測する」という構造だけを取り出せば評価の sample efficiency と形が似ているが、**それは形の類似であって、この論文から持ってこられる中身はない。**

## 試すべき実験アイデア

**3 つとも、モデルを大きくする必要がない。**この論文の主張は小規模で検証できるように出来ている点が、実務上いちばんありがたいところである。

1. **LR transfer が自分の構成で成り立つかだけを見る (半日、最小)。**
   手持ちの student アーキテクチャで width を 3 段 (例 256 / 512 / 1024) 用意し、**標準のパラメータ化と μP の 2 系列**で LR を 5 点だけ sweep する。見るのは性能ではなく、**「最適 LR の位置が width を跨いで揃うか」の 1 点だけ。**揃えば R2 の実験計画に組み込んでよい、揃わなければ割り付けが間違っている。**学習は短くてよく (収束させる必要はない)、判定は目視のグラフ 1 枚で済む。**

2. **R2 の過去結果が LR ノイズだったかを直接問う (1 日)。**
   capacity gap 実験を **(a) 全点 LR 固定・素のパラメータ化**、**(b) μP で LR 固定**の 2 系列で回し、**破綻境界の位置がどれだけ動くか**を比べる。動かなければこれまでの R2 の結果はそのまま使える。**大きく動くなら、R2 の主張は書き直しになる** — これは早く知るほど得な種類の情報である。

3. **token 軸の外挿を自分の予算レンジで検証する (1 日、以後ずっと効く)。**
   論文は 10 兆トークンへ外挿しているが、**外挿が自分のレンジで成り立つかは自分で測るしかない。**小予算 3 点 (例 1B / 2B / 4B トークン) で最適 LR を測り、線形回帰で 16B トークンの LR を予測し、**実測と突き合わせる。**1 回やっておけば、以後 P2 の学習で **LR sweep という工程そのものが不要になる。**着手コストの割に、回収が長く続く。

**優先順位は 1 → 3 → 2。**1 は 3 と 2 の前提条件であり、成り立たなければ後の 2 つは意味がない。**そして 1 は半日で終わる。**
