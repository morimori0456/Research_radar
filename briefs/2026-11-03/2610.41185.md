# Mechanistic Interpretability for End-to-End Self-Driving (2610.41185)

- トピック: planner_ai (P1、planner の観測性) / P3 にも関連 / スコア 4.0 / RSS 回収分 (月曜 announce)
- URL: https://arxiv.org/abs/2610.41185
- 公開ページ (論文が示す): https://mgagvani.github.io/mechanistic-interpretability-for-e2e-driving/

## 何を解決する論文か

E2E (end-to-end; 画像から直接軌道を出す) 運転 model は planning の性能が高い一方で、内部が不透明で、なぜその軌道を出したかを確認できない。これを **mechanistic interpretability** (model の内部表現を人が読める部品に分解して、挙動の原因を調べる研究分野) の道具で調べる。対象は単眼 camera の単純な E2E 経路計画 model。

## 手法の核心

- **SAE (Sparse Autoencoder; 内部 activation を「ほとんどの要素が 0」の高次元な表現に分解する autoencoder)** を、planner の内部 activation に学習する。分解された各要素 (latent) が 1 つの概念に対応しやすくなる。
- SAE の latent を教師なしで clustering すると、route intent (進路の意図)・車速・ブレーキに対応する構造が出る。route intent は教師なしで 98.3% の精度で復元できる。
- **paired counterfactual image edits** (同じ場面で信号の状態や stop sign の有無だけを画像編集で変えた対) で、特定の latent が信号や stop sign に視覚的に結びついて反応することを確認する。
- **steering** (特定の latent の値を直接操作する介入): 1 つの latent を動かすと、横方向のずれ・曲率・ブレーキが予測どおり単調に変わる。
- 実用例として、SAE の latent で学習した軽量な adapter が、軌道の選択誤差を 3.44% 減らす。同じ規模で SAE latent を使わない adapter より良い。

## 適用可能性 (P1: Planner AI + 評価、P3 関連)

- planner の評価に「出力の良し悪し」だけでなく「内部が何を見て決めたか」の指標を足せる。たとえば、信号の状態に対応する latent が赤信号で反応しているかを確認する、という試験が書ける。閉ループの score が同じでも、理由が違う planner を区別できる。
- steering ができるので、planner に「この概念を強制したらどう出力が変わるか」という因果の介入試験が打てる。安全性の議論で、観察でなく介入の証拠を出せる。
- 注意点: 対象は単眼 camera の単純な model で、改善も 3.44% と小さい。複数 camera・LiDAR・巨大な model で同じように概念が分かれるかは別の問題。また、SAE の学習自体に追加の計算と調整が要る。

## 試すべき実験アイデア

1. 手元の planner の中間層 1〜2 層に SAE を学習し、速度・ブレーキ・route intent を教師なしで読み出せるかを測る。読めなければ、この方法の適用範囲の限界が最初に分かる。
2. 信号 / stop sign の counterfactual edit の対を数十組作り、対応する latent の反応と、planner の出力 (ブレーキ) の変化が一致する割合を出す。一致しない場面は、planner が信号を見ずに決めている疑いがある。
3. 特定の latent を steering して、閉ループの simulation で出力が単調に変わる範囲を測る。単調性が崩れる点が、その概念が使える範囲の目安になる。

## 注意

abstract のみに基づく。SAE の幅・層の位置・データ規模、検証した model の性能は未確認。
