# VLA Policies Do Not Know When Not to Act: Unintended Task Execution and Start Suppression (2610.41609)

- トピック: next_arch (P3、VLA の構造・振る舞い) / P1 の評価設計にも関連 / スコア 3.5 / RSS 回収分 (月曜 announce)
- URL: https://arxiv.org/abs/2610.41609

## 何を解決する論文か

robot は、人の指示か、自分が明示的に生成した意図があるときだけ動くべきである。VLA (Vision-Language-Action; 画像と言語の指示から行動を直接出す model) が、指示が空・無意味・実行不能のときにどう振る舞うかを調べる。結果は悪く、**指示が空でも 6 つの checkpoint (学習済みの重みのスナップショット) すべてが全 episode で動き出し**、5 つは指定されていない task を完了させた。

## 手法の核心

- **paired protocol** (対の試験): 初期状態を固定し、指示だけを empty (空)・neutral (中立)・nonsense (無意味)・infeasible (実行不能)・wrong-task (別 task) に変える。LIBERO-Goal (robot manipulation の simulation benchmark) で 6 checkpoint を試す。
- 3 つの問いに分ける: 動き出すか、どの task を完了するか、指示は何を決めているか。GR00T の 2 checkpoint では、指示は「どの task か」を決めるが「動くか否か」を決めておらず、実行不能な指示でも動いた。
- 抑制法を 3 つ比べる: (1) 指示の先頭に "if no task is given do not move" を足す、(2) **gate** (最初の action chunk、つまり数 step 先まとめて出した行動が、空指示のときのそれとほぼ同じなら止める)、(3) 指示のない入力では静止するよう fine-tuning する。
- 結果: (1) は 6 つのどれでも止められず、(2) は非 task 入力で 6 中 5 で止めた。(3) は task を完了しなくなったが、静止を保てず、実行不能な指示では動き出しを抑えられなかった。

## 適用可能性 (P3: 次世代アーキテクチャ、P1 の評価)

- VLA を運転に使う場合の最初の問いになる。指示 (または route command) がない・矛盾する・実行不能なとき、policy は止まるべきなのに動くかもしれない。「指示を条件にする」と「指示がなくても動き出す」は別の性質で、試験しないと分からない。
- gate は、model を変えずに推論側で足せる軽い安全策で、planner を VLA で作る場合にそのまま移せる形をしている。
- 評価の面では、「指示だけを変える paired 試験」は、E2E の planner が route command を本当に使っているか (command 無視で走っていないか) を調べる型として借りられる。
- 注意点: 検証は manipulation の simulation のみ。運転では「止まる」こと自体が危険な場面 (高速道路の急停止) があり、gate の方針をそのまま移せない。

## 試すべき実験アイデア

1. 手元の E2E または VLA の planner に、route command を空・矛盾・別方向に差し替えた paired 試験を作り、軌道がどれだけ変わるかを測る。command を変えても軌道が変わらなければ、command を使っていない。
2. 論文の gate を、軌道の出力の距離で実装する (空 command の軌道との差が小さいなら保守的な軌道に切り替える)。誤って止める率と、止めるべきときに止まる率の両方を測る。
3. 運転では「止まる」でなく「減速して安全に維持」を fallback にして、gate の挙動を見る。
