# WorkIng: A Real-World and Synthetic Highway Work-Zone Benchmark Dataset for Autonomous Navigation (2610.41772)

- トピック: planner_ai (P1、benchmark の新提案) / スコア 4.0 / RSS 回収分 (月曜 announce)
- URL: https://arxiv.org/abs/2610.41772
- Resources (論文が示す): https://github.com/cvims/WorkIng

## 何を解決する論文か

高速道路の工事区間 (work zone) は、自動運転にとって珍しい形状と、地域ごとに違う規則が重なる難しい edge case (まれだが重要な場面)。既存の dataset には、360° の multi-modal (camera・LiDAR など複数 sensor) で全体を 3D annotation したものが無い。また、1 つの実走行地点だけでは、必要なレイアウトと規則の変種を網羅できない。実走行と simulation の 2 つを組にした benchmark で、この両方を埋める。

## 手法の核心

- **WorkIng-Highway** (実走行): 128 channel LiDAR・6 台の RGB camera・RTK-GPS (Real-Time Kinematic GPS; cm 級の位置精度を出す GPS) を同期して 32 km を走行。12,000 frame 以上、tracking 付きの 3D bounding box 227,399 個を annotation。
- **WorkIng-CARLA** (simulation): CARLA (自動運転用のオープンな simulator) 上で、規則を反映した 24 scenario、6 種の canonical な道路 topology (標準的な道路の形)、6 つの国際的な交通規格を、100 以上の専用 3D asset で作る。
- 代表的な 3D detection と E2E planning の architecture を benchmark し、性能を左右するのは依然として実データであることを示す。
- scenario で層別した synthetic data の augmentation (追加) が、2D recognition・3D detection・trajectory planning のどれでも改善に効く。

## 適用可能性 (P1: Planner AI + 評価)

- planner の評価を「通常走行の平均」でなく「edge case を層別に」測る benchmark として使える。工事区間は、車線の規制・コーンの列・規制速度の変化が重なるので、planner が規則を読めているかを見る試験になる。
- 規則を変えた scenario (topology × 規格) が格子状に用意されているので、どの組み合わせで planner が崩れるかを切り分けやすい。
- synthetic の追加が trajectory planning にも効く、という結果は、実データが足りない edge case を simulation で補う方針の根拠になる。ただし実データが主因である点は変わらない。
- 注意点: 工事区間という 1 種類の edge case に限る。planner ごとの具体的な数値は abstract に無く、planner 側の指標 (衝突率、規則遵守) の定義は未確認。地域の規則は国ごとに違うので、そのまま持ち込めるかは別問題。

## 試すべき実験アイデア

1. 手元の planner を WorkIng-CARLA の 24 scenario で閉ループ評価し、topology × 規格の格子のどこで衝突率や規則違反が増えるかを表にする。
2. 実データと synthetic の比率を変えて fine-tuning し、実データが少ない段階で synthetic がどこまで補えるかの曲線を描く (論文の「実データが主因」の確認にもなる)。
3. 工事区間の frame だけで、planner の出力と、SAE などで読んだ内部の概念 (2610.41185) が一致するかを見る。評価と観測性を組み合わせる試し。
