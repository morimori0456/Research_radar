# The Teacher Is a Direction, Not a Destination: Extrapolating RL-Induced Representation Residuals in On-Policy Distillation (RIDE)

- arXiv: `2609.36484` / https://arxiv.org/abs/2609.36484
- 配属: **fm_distill_finetune (P2) に配属** (candidates.json では sns_wildcard)。topics.yaml の fm の keyword には 1 つも一致しない。abstract は蒸留を "on-policy distillation" とだけ呼び、"knowledge distillation" も "teacher student" (この語順の 2 語句) も出てこない。09-21 の `2609.20511` と同じ形で、keyword 追加 (欠陥③) の 2 例目。
- スコア: **P2 4.0** ・ hf_upvotes 373 (今日の 3 件で最多)

## 何を解決する論文か

OPD (on-policy distillation; student 自身が生成した系列の上で、teacher の次トークン分布に合わせる蒸留) には、student が teacher を超えるように拡張した変種がある。そうした変種は出力空間 (logit や log 確率) で「teacher の方向にさらに先まで外挿 (extrapolate)」する。しかしこの論文によると、teacher の hidden state (層ごとの内部表現) に起きた変化は、LM head (最終層の出力射影) を通る段階で方向ごとに不均一に縮み、logit にはごく一部しか届かない。さらに、サンプルしたトークンの log 確率比をそのまま外挿するとノイズが増幅され、学習が不安定になる。RIDE は外挿を出力空間でなく **表現空間 (hidden state) で行う** ことで、この 2 つを避ける。

## 手法の核心

- **観察:** RL (強化学習) で後学習したモデルは、RL 前の checkpoint と比べて内部表現がずれており、そのずれの方向は全層で測れる。
- **residual (残差) を target にする:** 各層・各トークン位置で「RL 後の teacher − RL 前の checkpoint」の residual を計算し、student の hidden state を「teacher を、この residual の方向にさらに先まで進めた点」に回帰させる (teacher そのものでなく、その少し先を target にする)。
- **解釈:** サンプルした系列を固定すると、この回帰は「residual 方向への線形の報酬を最大化する」ことと「teacher を中心にした二次のペナルティ」の和に等しい。つまり「RL が動かした方向へは進め、teacher からは離れすぎるな」が 1 本の loss で書ける。
- **結果:** 規模・構造・事前学習の系統が異なる 4 組の base / RL-teacher で検証した。RIDE は 4 組すべてで RL 済み teacher に迫るか上回り、平均で teacher を超えたのは RIDE だけだった。出力空間の外挿は、teacher が base に近い (RL による変化が小さい) 組で student を逆に悪化させた。
- 前提として、**同じ系統の RL 前 checkpoint が手元にある** ことが要る。teacher 単体しか無い場合は、そのままでは使えない。

## P2 への適用可能性

- **「teacher = 到達点」でなく「teacher = 方向」という見方。**P2 で、ある基盤モデルを fine-tuning して特化させた teacher (例: 運転データで適合させた版) から小さな student に蒸留する場合、fine-tuning 前の base checkpoint と後の teacher はどちらも手元にある。そのため、ここでの「RL 前 / RL 後」を「適合前 / 適合後」に置き換えれば、同じ residual が計算できる。ドメイン適合で変わった方向だけを student に強く押し込む、という capacity gap 対策 (student が小さくて teacher を丸ごとは真似できないときの工夫) として読める。
- **hidden state 間の蒸留には層の対応付けが要る。**teacher と student で層数や幅が違う場合、どの層をどこに対応させ、どう射影するかが別に必要になる。abstract を見る限り、論文の 4 組は student 側の構造も揃っている可能性が高い。P2 で幅の異なる student に移すときの射影の扱いは、本文で確認すること。
- **負の結果も使える:** 「teacher が base に近いと、出力空間の外挿は害になる」。軽い fine-tuning だけで作った teacher から logit 外挿付きで蒸留すると悪化しうる、という注意として P2 の recipe に書ける。
- **既読との関係:** 直近 2 週間で OPD の論文は 6 本以上読んでいる (09-30 の multi-teacher OPD `2609.35259`、10-02 の GFD-OPD `2609.39692`、10-03 の DriftOPD `2610.00317` など)。そのほとんどは「何を target にするか・誰のサンプルで学習するか」を変えるもので、**表現空間で teacher の先を狙う** のは RIDE が初めて。

## 試すべき実験アイデア

1. **(2D toy、CPU で数分) 「適合前 → 適合後」の residual を外挿して蒸留する:** 小さな MLP の base を、ドメイン A の 2D 分類で学習する。それを、ドメイン B (入力をずらした分布) で fine-tuning して teacher にする。幅を半分にした student に、(a) teacher の logit の KL、(b) teacher の hidden state の回帰、(c) RIDE 型 (teacher + α·(teacher − base) への回帰、α ∈ {0, 0.5, 1}) の 3 通りで蒸留し、ドメイン B の精度を比べる。比較の焦点は 2 つ。α > 0 が teacher を超えるか。fine-tuning の step を減らして teacher を base に近づけたとき、(c) の優位が保たれ、logit の外挿だけが崩れるか。
2. **(同じ toy) 層の対応付け:** student の幅が違う場合に、hidden state を線形射影で合わせる版と、最終層の 1 か所だけで合わせる版を比べる。層の対応付けにどれだけ敏感かを測る。P2 で構造の異なる student に移せるかの判断材料にする。
