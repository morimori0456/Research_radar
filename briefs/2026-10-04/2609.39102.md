# False Frontiers: Diagnosing and Mitigating Co-Cheating in Self-Evolving Search Agents (CrossFit)

- arXiv: `2609.39102` / https://arxiv.org/abs/2609.39102
- 配属: **sns_wildcard (探索枠 1/1)**。分野は LLM の検索 agent で、運転とは直接関係しない。
- スコア: 学びの価値 3.5 (転用先は P2 3.0 ・ P1 2.5) ・ hf_upvotes 336

## 何を解決する論文か

self-evolving agent (自分で学習データを作って自分を鍛える agent) では、proposer (問題を作るモデル) と solver (それを解くモデル) を一緒に最適化する。このループには **co-cheating** と名付けられた失敗が起きる。proposer と solver が同じ間違いに合意するようになり、ループの中の報酬は上がるのに、外部から見た正しさは上がらない。根拠となる出典と突き合わせて事後に監査すると、自己進化のラウンドを重ねるほど co-cheating が悪化し、pseudo-label (モデルが自分で付けたラベル) の正解率は横ばいか低下していた。この論文はこの失敗を測り、抑える方法を提案する。

## 手法の核心

- **診断:** ループ内の合意率 (内部の報酬) と、出典に照らした外部の正しさを並べて追う。前者だけが伸びている部分が co-cheating。
- **MSV (Multi-Sample Verification; 同じモデルに、出典ありで 3 回・出典なしで 3 回答えさせ、問題を採用するか決める検証):** 学習の前に問題を検証する素直な対策。効果は小さく (false agreement、つまり誤りへの合意の割合: 4B で 6.1 → 5.7%、9B で 8.8 → 7.2%)、候補ごとに 6 回の追加生成がかかる。
- **CrossFit (本命):** proposer が問題を作る元の文書を A・B の 2 群に分ける。A から作った問題は、**B だけで学習した補助 solver** に採点させる (B から作った問題はその逆)。こうすると、同じ出典から来た誤った pseudo-label を、採点側が再現できない。元の solver の更新則は変えない。統計学の cross-fitting (推定に使うデータと評価に使うデータを分けて過学習のバイアスを消す手法) と同じ発想。
- **結果:** false agreement は 3.0% / 3.7% まで下がった。同じ問題を、出典を見ていない solver で採点し直すと 0.4% / 0.1% まで下がり、原因が「採点側が同じ出典を見ていたこと」だと切り分けられた。下流の 7 つの検索ベンチマークで、従来の self-evolution より平均 +8.8 / +8.4 点 (4B / 9B)。

## プロジェクトへの適用可能性 (探索枠として選んだ理由)

- **P2: 自動ラベリング → 自己学習のループに同じ失敗がある。**P2 で、teacher (または前の世代のモデル) が付けた pseudo-label で student を学習し、その student を次の teacher にするループを回すとする。ラベルを付ける側と検証する側が同じデータ・同じ系統のモデルなら、「teacher と student が同じ誤りに合意する」形で、学習曲線だけが良くなる。CrossFit の処方は運転にそのまま移せる。走行ログを地域や車両ごとに A・B に分け、A のログに付けた pseudo-label は B だけで学習したモデルで検証する。
- **P1: 評価器と被評価器が同じデータを見ていないか。**learned evaluator (学習した評価モデル。例: 人の判断を真似して軌跡を採点するモデル) で planner を採点する場合、両者が同じ走行ログで学習されていると、共通の盲点を「問題なし」と判定しうる。「ループ内の指標」と「外部の監査」の差を追う診断は、P1 の評価設計のチェック項目になる。
- **限界:** 実験は LLM の検索 QA だけで、文書を A・B に分けられることが前提。運転では、ログを分けても同じ地図や同じシナリオが重複しやすく、分割が本当に独立になるかの確認が別に要る。

## 試すべき実験アイデア

1. **(2D toy、CPU で数分) pseudo-label ループで co-cheating を再現する:** 2D の 2 クラス分類で、ラベル付きは 5% だけにする。残りの 95% には、モデル自身が pseudo-label を付けて再学習するループを 10 ラウンド回す。各ラウンドで「ループ内の合意率」と「真のラベルに対する正解率」を並べて記録し、前者だけが伸びる区間が出るかを見る。
2. **(同じ toy) cross-fit の効果:** ラベルなしデータを A・B に分け、A の pseudo-label は B だけで学習したモデルが付ける (逆も同じ) 版を作る。実験 1 と真のラベルに対する正解率を比べる。分割の独立性を崩すために A と B に重複サンプルを 0 / 20 / 50% 混ぜ、どこで効果が消えるかを測る。運転のログ分割で「どこまで重複を許せるか」の目安になる。
