# SurgPace: Complexity-Aware Progressive Distillation for Surgical Multimodal Large Language Models (2611.03125)

- トピック: fm_distill_finetune (P2、distillation の recipe: curriculum と loss の schedule) / スコア 4.0
- URL: https://arxiv.org/abs/2611.03125

## 何を解決する論文か

手術支援向けの MLLM (Multimodal Large Language Model; 画像と言語を扱う大きな model) は、質問応答や場面理解に有望だが、計算コストが大きく臨床に載せにくい。knowledge distillation (大きな teacher の出力を小さな student に真似させる学習) で小型化するのが現実的だが、手術データは難易度や曖昧さの差が大きく、**全サンプルを同じ重みで teacher から写す方法は不安定**になる。さらに、学習の初期は teacher の指導が要り、後半は task の教師信号の比重を上げたほうがよい、という「supervision の役割が時間で変わる」問題がある。

## 手法の核心

- **SurgPace**: sample-level の curriculum (簡単なものから難しいものへ並べる学習) を continuous (連続的) に行う枠組み。
- 難易度の推定: sample ごとに predictive confidence (予測の確信度) と **Lorentz geometric consistency** (Lorentz model は双曲空間 (階層構造を表しやすい曲がった空間) の表現方式で、そこでの特徴の幾何的な整合性) を組み合わせた score を作り、それで easy-to-hard の順を決める。
- **hierarchical representation alignment**: student を teacher に feature・logit・probability の 3 つの水準で揃え、学習が進むほど「teacher の模倣」から「task の教師信号」へ重心を移す。
- 設計の要点は、sample-level の curriculum (どのデータをいつ使うか) と、objective-level の scheduling (どの loss をいつ重くするか) を**分離**していること。
- 評価は Surg-396K (4 つの公開手術データセットから作った benchmark、対話形式 5 種) で、強い MLLM 蒸留 baseline を上回る。decoding も速くなる。code は公開されている (https://github.com/hezhicheng2002/SurgPace)。

## 適用可能性 (P2: FM 蒸留)

- P2 の「蒸留プロセスを実務で回す」「新しい loss / capacity gap 対策」に近い。teacher と student の差が大きいとき、難しいサンプルを最初から課すと不安定、という問題の対処を、確信度ベースの curriculum と loss の重みの schedule という 2 つの独立した操作で与える。他の蒸留設定に移植しやすい部品である。
- 注意点: 手術の MLLM で、運転や制御の model には未検証。Lorentz geometric consistency は双曲空間の model が前提で、通常の Euclidean な特徴では別の難易度指標が要る。abstract には改善幅の数値がない。

## 試すべき実験アイデア

1. 手元の蒸留で 2×2 の ablation を回す: (a) 一様な重み、(b) 確信度による curriculum のみ、(c) loss の schedule (teacher 模倣 → task 教師) のみ、(d) 両方。どちらの効果が大きいかを分離する。
2. Lorentz の項を外し、teacher の予測確信度だけで難易度を決める簡易版を作る。簡易版で十分なら、実装が軽くなる。
3. feature・logit・probability の 3 水準の揃えを 1 つずつ外し、teacher と student の size 差が大きい (capacity gap が大きい) 設定ほど効果が出るかを見る。

## 注意

abstract のみに基づく。各 baseline との差、student のサイズ、難易度 score の寄与の分解は未確認。
