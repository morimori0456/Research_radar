# Dynamic Hazard 下の real-time motion planning: classical planner と learning-based planner を同条件で比べた benchmark

- 対象: P1 (Planner AI + 評価)
- 元論文: http://arxiv.org/abs/2610.12249v1
- 根拠: abstract のみ (本文・コード未確認)

## 何を解決する論文か
「classical planner (探索・最適化ベース) と learning-based planner (学習ベース) のどちらが良いか」は、環境・制約・観測の前提が論文ごとに違うため公平に比べにくい。本論文は新手法を出さず、回転する sprinkler 状の hazard (扇形の通行禁止領域が時間変化する) を置いた平面環境で、両方を同じ環境・運動制約・情報量・評価指標で比較する統一 benchmark を作った。

## 手法の核心
- 新 planner ではなく、比較条件を揃えた benchmark 設計そのものが貢献。
- deterministic な環境 (hazard の動きが既知): classical planner が成功率ほぼ 100% で path 品質も高い。ただし planning / replanning 時間が長くなる場合がある。
- stochastic な環境 (hazard の動きが確率的): online search は計算 budget に強く依存する。budget が低いと失敗が多く、高いと成功率は上がるが latency と path 長が悪化する。
- 同じシナリオ分布で学習した PPO (Proximal Policy Optimization; 代表的な policy gradient RL 手法) の policy は、stochastic 環境で latency・成功率・path 品質のすべてで上回る。
- 結論: planner の選択を分けるのは partial observability (部分観測) より obstacle dynamics の不確実性。

## 適用可能性 (P1)
- 評価設計として使える点: 「success rate を planning budget とセットで報告する」「環境の stochasticity を軸にして regime を切る」は、自社 planner の評価 protocol にそのまま持ち込める。
- 注意: 2D の toy 環境で、自動運転の interaction (他車の意図など) は含まない。結論が実運転に移るかは未検証。PPO 側の学習 budget も abstract からは不明。

## 試すべき実験
1. 手元の planner 評価で、closed-loop simulation の他車挙動を deterministic (log replay) と stochastic (ノイズ付き) に分け、planner の ranking が入れ替わるか確認する。
2. 探索ベース planner の計算 budget を 3 段階に振り、success-vs-latency 曲線を評価レポートに追加する。
3. 同じシナリオ分布で小さな RL policy を学習し、探索ベースとの regime 境界 (どの stochasticity 水準で逆転するか) を測る。
