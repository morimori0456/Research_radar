# ICDP: ego 軌道と周囲 agent の「組み合わせ」が logged data で支持されているかを制御する offline RL planner

- 対象: P1 (Planner AI + 評価) / P3 にもまたがる。candidates.json の topic は next_arch だが核は planner の学習・評価なので P1 枠で採用
- 元論文: http://arxiv.org/abs/2610.09763v1
- 根拠: abstract のみ (本文・コード未確認)

## 何を解決する論文か
offline RL (Reinforcement Learning; 固定データセットだけで方策を改善する強化学習) は、データに無い行動の価値推定が不正確になる distribution shift が課題。従来は ego 自身の action 空間でだけこれを抑えてきたが、自動運転では「ego 軌道単体はデータにあるが、周囲の車の動きとの組み合わせは logged data に無い」という interaction distribution shift (IDS) が起きる。本論文は IDS を明示的に抑える ICDP (Interaction-Constrained Drive Policy) を提案する。

## 手法の核心
- ego と周囲 agent の将来の joint 分布の支持度の低下を、ego 単体の支持度の低下 + 残りの interaction 成分、に厳密に分解する。
- 残りの interaction 成分は contrastive density-ratio estimation (正例と負例を見分ける分類器で密度比を推定する手法) で求める。joint 密度のモデル化も、周囲 agent の予測も要らない。
- 方策最適化中に reactive simulator (周囲が反応して動くシミュレータ) や learned world model の rollout を使わない。
- 評価は nuPlan, Interplan の closed-loop と実機トラック。「価値は高いが interaction の裏付けが無い軌道」の選択が抑えられ、interaction-critical なシナリオで改善と報告。

## 適用可能性 (P1 / P3)
- P1: 評価側に直接効く。planner が選んだ軌道の「interaction 支持度」を density-ratio で測れば、collision や L2 に出ない失敗予兆の指標になりうる。
- P3: E2E planner を offline で RL fine-tuning する際の安全弁として使える。
- 注意: 密度比の分類器は logged data のバイアスをそのまま引き継ぐ。abstract だけでは改善幅は不明。

## 試すべき実験
1. 手元の planner の出力軌道に対し、(ego 軌道, 周囲将来) の本物ペアと、別シーンの周囲将来を貼り替えた偽ペアを分類する小さな classifier を学習し、その score と closed-loop の失敗との相関を nuPlan で見る (評価指標の候補)。
2. 既存の offline RL (例: 価値最大化 + BC 正則化) に、その score を penalty として足すだけで interaction-critical シナリオの成績が変わるかを ablation する。
3. 貼り替え方 (同一 map 内 / 他 map) で density-ratio の識別性がどう変わるかを調べる。
