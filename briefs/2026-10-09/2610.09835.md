# 忘却は「データに現れない token」の output embedding に集中する — Adam の epsilon 1 行で抑える

- 対象: P2 (fine-tuning による他ドメイン適合)
- 元論文: http://arxiv.org/abs/2610.09835v1
- 根拠: abstract のみ (本文・コード未確認)

## 何を解決する論文か
LLM の continual pre-training や fine-tuning では catastrophic forgetting (新データを学ぶ間に元の能力が失われる現象) が起き、通常は元データの replay (混ぜ直し) で抑える。しかし元データは手に入らないことが多い。本論文は data-free の条件で、忘却がどこで何のために起きるかを解析し、optimizer の設定 1 つで大半を防げると示す。

## 手法の核心
- 層を系統的に freeze して調べると、忘却は「新 corpus にほぼ現れない token」の output embedding (最終層の語彙ごとの重み) に集中する。body 側の同じ帯域はほぼ不活性。
- 原因: 現れない token は softmax から一方向の勾配を受け続け、Adam の二次モーメント sqrt(v-hat) による正規化がそれを全幅の更新に増幅する。
- したがって token の出現数だけで、再学習前に忘却リスクを順位付けできる。
- 対策: 出力 projection だけ Adam の epsilon を大きくする。160M〜12B、4 つのモデル系列の 8 設定で、安定 7 設定の忘却を 39.4〜67.9% 削減し、target の学習は劣化しない。replay との併用で更に改善 (Qwen/韓国語で 79.8%)。
- 学習後に行を編集しても回復は 5% 未満なので、学習中に介入する必要がある。

## 適用可能性 (P2)
- fine-tuning で別ドメイン / 別言語へ基盤モデルを適合させる際の安全策として、コードが 1 行で済む。LoRA でも released-head の場合に忘却が 23 倍に増える点は、PEFT 運用の注意点。
- 対象は LLM。視覚の基盤モデルの蒸留 / fine-tuning に同じ機構があるかは未確認。

## 試すべき実験
1. 手元の fine-tuning で、新 corpus の token 出現数と元 benchmark の低下を token 単位で突き合わせ、集中を確認する。
2. 出力層のみ epsilon を 1e-8 → 大きい値へ動かして、忘却と target 性能の trade-off を描く。
3. LoRA で head を学習対象に入れた場合 / 凍結した場合を比べる。
