# GeoCoTDrive: VLA に「2D で注目 → 3D 幾何特徴を取り出す」chain-of-thought を入れる

- 対象: P3 (次世代アーキテクチャ: VLA / E2E)
- 元論文: http://arxiv.org/abs/2610.10390v1
- 根拠: abstract のみ (本文・コード未確認)

## 何を解決する論文か
VLA (Vision-Language-Action; 画像と言語から行動を直接出力するモデル) を自動運転に使うと、行動には正確な 3D 幾何が要るのに、視覚言語の推論は 2D の意味空間で行われるというミスマッチが生じる。GeoCoTDrive は、判断に重要な 2D 領域をまず特定し、その領域だけ geometric foundation model (3D 形状を推定する大規模モデル) から 3D 特徴を取って推論に差し込む。

## 手法の核心
- "think with 2D first, drive with dedicated 3D priors": 2D で判断に効く領域を grounding (言語と画像領域の対応付け) する。
- grounding した領域内だけ、geometric foundation model の特徴を sampling して取り出す (全画面の 3D 特徴は使わない)。
- 取り出した 3D 特徴を autoregressive な系列に interleave (交互に挟む) して軌道を生成する。
- planning-relevant grounding: ego の計画に直接効く局所手がかりに絞った領域 grounding の新タスクと、PlanningGrounding dataset を構築。
- 複数の E2E benchmark で safety-critical な計画性能が一貫して改善。

## 適用可能性 (P3 / P1)
- P3: VLA に 3D を入れる設計の一例。全域でなく局所のみにするので token 数が抑えられる。
- P1: PlanningGrounding のような「計画に効く手がかり」のラベルは、planner の失敗分析の語彙になりうる。
- 注意: 3D 特徴の取り出し分だけ推論が重くなる可能性。abstract に latency の記載なし。

## 試すべき実験
1. 手元の VLA で、全画面の 3D 特徴 vs grounding 領域のみの 3D 特徴を比べ、性能と token 数を測る。
2. grounding を GT でなく予測にしたとき、誤りがどれだけ計画に伝播するかを見る。
3. geometric foundation model を差し替え、性能の感度を調べる。
