# Intransigent Teacher — 教師を動かすのをやめたら、長い系列で壊れなくなった

**topic:** fm_distill_finetune / **project:** P2 / **hf_upvotes:** 0
**スコア:** P1 3.0 / P2 **4.5** / P3 2.0
**著者:** Damian Sójka, Marc Masana, Bartłomiej Twardowski, Sebastian Cygert / 2026-09-02 公開

## 何を解決する論文か

**TTA (Test-Time Adaptation; 配備先でラベル無しのまま、入力分布の変化に合わせてモデルを適合させ続ける手法)** では、**teacher-student 構成**がほぼ標準になっている。生徒が自分の予測を教師信号にすると誤りが自己増幅するので、**教師の重みを生徒の EMA (exponential moving average; 指数移動平均。生徒の重みをゆっくり追随させた平滑版)** にして、誤りの蓄積を抑える —— という組み立てである。

**本論文は、その「抑えられている」という前提を実際に確かめて、成り立っていないと報告する。**EMA 教師でも誤りの蓄積は起きる。**ただしそれは、通常この分野で使われている長さの系列では表に出ない。****もっと長い系列にして初めて見える。**

そして提案される修正が、拍子抜けするほど単純である —— **教師の重みを一切更新しない (intransigent teacher)。**

## 手法の核心

- **失敗の在り処が「手法」ではなく「評価の長さ」にあった。**EMA 教師の長期安定性は検証されずに前提とされてきた。**標準的な系列長では差が出ないので、誰も気づかなかった。**
- **stability-plasticity trade-off** (過去の知識を保つ安定性と、新しい分布に合わせる可塑性の綱引き) **として整理する。**EMA 教師は「ゆっくり動く」ことで両立を狙うが、**ゆっくりでも動く以上、生徒の誤りは教師に入り込み、それが生徒に返る。**
- **提案は教師の凍結。**重みを更新しない教師を使う。**生徒 → 教師 → 生徒 のフィードバック経路が切れる。**
- **結果: 長い系列のシナリオで複数データセットにわたり大幅に改善。**加えて **hyperparameter の変更に対する頑健性が上がる** —— 壊れやすさが調整で辛うじて抑えられていたことの傍証である。
- **適用範囲が広い。**アーキテクチャや実験設定を問わず、**semantic segmentation** にもそのまま乗る。
- **コード公開:** https://github.com/dmn-sjk/intransigent_teacher

## P1 / P2 / P3 への適用可能性

**P2 = R2 にとって、これは待っていた形の反例である。**

R2 の当初の前提「蒸留が破綻するのは容量差 (capacity gap) が原因」は、**容量比 1.0 でも蒸留が効く反例 5 本によって既に棄却されている。**残った説明候補は ① CLL の集中度 ② clipping で切り捨てられる推論 token の 2 本で、**どちらも「監督をどこに当てるか」の話だった。**

**本論文が足すのは、3 本目の軸である: 時間。**

- **容量でもなく、監督の配分でもない。****教師と生徒が時間をかけて結合していること自体が破綻の原因である。**
- **そして治療が「監督の当て方を変える」ではなく「教師を止める」。****R2 の既存 2 候補とは治療方向が独立である。**
- **R2 は既に「治療方向が正反対の 2 本を対照群として並べられる」構成を持っている。****ここに 3 本目として直交する軸が入ると、対照が 2 群から 3 群になる。**

**さらに、本日の他の 3 本と同じ形をしている。****[PDT](2609.02688.md) は「小さい窓でだけ有意になる」、[WM-LOCO](2609.02542.md) は「地形をまとめると全滅が見えない」、本論文は「短い系列では蓄積が見えない」。****3 本とも、測る範囲を狭く取ったせいで壊れているものが見えていない、と言っている。**これは R1 の主張そのものであり、**「これは運転固有の話ではない」という一節を書くための独立事例が、本日だけで 3 本揃った。**

**P1 は 3.0。**直接には使わないが、上の「独立事例」として RoboPAD の導入で 1 行引用する価値がある。

**P3 は 2.0。**アーキテクチャの主張はない。

### 試すべき実験アイデア

1. **【30〜60 分・R2。ただし 09-06 gate の後】過去の蒸留ログを、系列長 (学習ステップ) の関数として引き直す。**R2 の宿題は「CLL を後付けし、上位 1% 占有率が容量比とともに単調に動くか」だったが、**本論文が示唆するのは第 2 の軸である —— 同じ量を「学習の長さ」に対しても引く。****容量比では動かないのに長さで動くなら、R2 の主張の中心はそちらに移る。**既存ログの再プロットだけで済み、新規学習は要らない。
2. **【メモのみ】R2 の対照群設計に「教師を凍結する群」を 3 本目として追加。**治療方向が既存 2 候補と直交している点を明記。
3. **【要確認・15 分】「longer sequences」が具体的に何倍かを本文で確認する。**R2 で同じ現象を探すとき、**どこまで伸ばせば見えるのかの目安になる。**この数字が無いと、再プロットして「見えなかった」ときに、無いのか足りないのかが判別できない。
