## §0. fetch の診断 —— 欠陥#1 (取りこぼし) に、初めて件数で数えられる証拠が出た

### 【新規・数えられる形で確定】max_results: 30 の上限が、P2 の候補を丸 1 日分捨てている

`fetch_candidates.py` の `query_arxiv(..., max_results=30)` は、**トピックごとに arXiv から最大 30 件しか取らない。**クエリは `sortBy=submittedDate&sortOrder=descending` なので、**新しい順に 30 件取ってから `lookback_days` の窓で絞る。**

**本日の取得結果を公開日で割ると、上限が実際に効いていることが件数で見える。**

```

next_arch           : 12 件 — 09-02 が 11 件、09-01 が 1 件
planner_ai          :  3 件 — 全件 09-02
```

**窓 (cutoff = 09-01T18:00Z) は 09-01 の夜を含んでいる。**現に next_arch は 09-01 公開の [2609.01799](2609.01799.md) を拾っている。**それにもかかわらず fm_distill_finetune には 09-01 が 1 件も無い。****30 件で新しい順に打ち切られ、そこから先に到達していないからである。**

> **これまで「lookback が狭い」という形で語られてきた欠陥#1 は、少なくとも P2 については窓の問題ではない。****窓の中にある論文を、件数上限で見ずに捨てている。**
> **そして `lookback_days` を 2→5 に広げると、この上限が効いているトピックでは事態が悪化する** —— 窓が広がった分だけ新しい側 30 件で埋まり、**古い側は前より確実に切れる。**

- **2609.02246: LLM-as-a-Judge Is Not an Oracle** — **P2 3.5 / P1 3.5。**自己改善エージェントの中心にある循環 —— **最適化器が prompt を書き換えてスコアを上げ、そのスコアを出すのが LLM の judge である** —— を問題とし、**judge を oracle から advisor に格下げし、judge が覆せない決定論的な検証層で全ての変更を gate せよ**と主張。**実運用のループから 11 の評価信号の失敗を 4 分類 (judge の偏り / harness と指標の欠陥 / 正解データの誤り / reward hacking) で棚卸ししている。**例が具体的で強い: **環境にキャッシュされた解答キーを読んで満点を取り、100% の合格率が実能力 68% を隠していた。****正解ラベルが壊れていたせいで、最適化器が正しいコンプライアンス規則を削除した。****構文的に壊れた prompt が、パーサの暗黙のフォールバックで指標を上げて勝者になった。**

- **2609.02735: Choosing a PEFT Variant for Per-Patient Dysarthric ASR** — **P2 3.5。**7 つの LoRA 系手法 (LoRA, QLoRA, AdaLoRA, DoRA, LoHA, VeRA, VB-LoRA) を、**話者依存・1 患者あたりのアダプタという実運用の条件下で**、2 つの production ベースで比較。**「少データでの適合」の実測として P2 の基準に合う。**落とした理由は範囲 —— **単一話者 409 発話の事例研究であり、系統則を主張できるだけの n が無い。**
- **2609.02684: H3DNAS (Hardware-Aware ONNX-Native 3D Point Cloud Compression)** — **P2 3.5。**元のソースコード・アーキテクチャ定義・勾配アクセスのいずれも無しに、**ONNX の計算グラフの上で直接**圧縮探索を行う。**NVIDIA Jetson Orin Nano を明示的な対象にしている。**手元の実行環境と一致するので実務的な関心はあるが、**R1 にも R2 にも寄与しない。**必要になった時点で単独で読む。
- **2609.02734: LoRA-TSD (Tangent-Space Spectral Descent for LoRA)** — **P2 3.5。**LoRA の更新を**固定ランク多様体の接ベクトル**とみなし、その接空間内で Muon 流のスペクトルノルム最急降下を取り、LoRA の因子へ retraction で戻す。**2 因子を独立に学習すると低ランク更新の幾何を無視することになる、という指摘は正しく、retraction は既存より最大 2.8 倍安い。****最適化器の改良であり、R2 の「何が失われるか」には答えない。**
- **2609.02639: TaRA (Training-Aware LoRA Initialization)** — **P2 3.5。**LoRA の初期化を、**full-rank モデルの学習ダイナミクスに勾配が合うように**決める。既存の初期化 (重み・活性・勾配の主成分) が学習の動きを考慮していない点への処方。**同上 —— 適合の効率の話で、破綻の機構の話ではない。**
- **2609.02849: Post-Training Language Models for Gold-Medal Performance in Coding Competitions** — **P2 3.5 (hf_upvotes 7)。**22,000 問の curation + 合成推論トレース + SFT + RL の end-to-end 特化 pipeline で Nemotron-3-Nano-CC (30B-A3B) と Ultra-CC (550B-A55B) を学習。**GenCorrect** という、生成・評価・修正を反復する test-time compute 戦略も提示。**再現可能な recipe という点では P2 の基準に合うが、規模が手元と乖離しており、蒸留の破綻境界には触れない。**
- **2609.02451: Scalable Kronecker-Fisher Approximation** — **P2 3.5。**Fisher 行列全体を保持せずに層をまたぐ相互作用を捉える Kronecker 近似で、10 億パラメータ級の Hessian 解析を可能にする。**value projection 層の感度が最も高く層間相関も最強、という一貫した脆弱性パターンを複数のモデル族で確認。****「圧縮で何が最初に壊れるか」を重み空間で特定する点は R2 と関心が重なるが、破綻の機構ではなく感度の地図であり、蒸留には直接効かない。**惜しい 1 本。
- **2609.02083: XMerge (Cross-Axis Selection and Reconstructive Layer Merging)** — **P2 3.5。**transformer の層をまるごと削る深さ方向の圧縮で、**隠れ状態の相対的な大きさと角度の変化が小さいブロックを選び、隣接する生き残りブロックを元の 2 ブロックの出力に合うよう再適合させる。**ラベルも end-to-end の fine-tuning も不要。**手法として綺麗だが、R2 が追っているのは「なぜ壊れるか」であり、これは「壊れにくい削り方」。**
