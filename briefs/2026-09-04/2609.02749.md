# Repo-To-Skill — 「知っている」と「動かせる」の間にある層を、検証済みの skill として切り出す

## 何を解決する論文か

ML の研究を端から端まで自律的に回すエージェントは、**モデル本体 + harness (計画・実行・記憶・検証を回す外枠)** という構成をとる。本論文の主張は、**この構成には層が 1 つ欠けている**というものである。

欠けている層を著者は **operational knowledge (運用知識)** と呼ぶ —— **手法を「知っていること」と、それを「動かせること」を分ける know-how。**

**そしてこの知識は、分野に存在しないわけではない。**リポジトリと論文の中にある。**ただし人間の読者向けに書かれていて、タスクの最中に読み込むには大きすぎる。****圧縮して、動作検証済みの skill の形にしておけば、毎回発見し直す代わりに再利用できる。**

## 手法の核心

- **DisCo** —— skill を作り、研究中にそれを使うエージェント。**蒸留を 2 通り走らせる。**
  - **task-agnostic:** 分野で広く使われているリポジトリ群を、あらかじめ再利用可能な skill に凝縮しておく。
  - **task-oriented:** 目の前の具体的なタスクが要求する skill を、その場で作る。
- **AREX-Skill Library** —— 前者を open ecosystem 全体に適用した産物。**広く使われている ML リポジトリ 1,000 件から蒸留した 5,000 以上の検証済み skill を、20 領域・178 の capability family に整理。**
- **比較の条件を固定している点が重要。****backbone (GPT-5.5)・研究 harness・下流の実行予算をすべて据え置き、skill の有無だけを変えている。**つまり報告されている差は、**モデルを強くしたからでも、計算を増やしたからでもない。**
- **結果 (skill 無しの同一エージェント比の相対改善):** **MLE-bench +134.3% / PaperBench +34.4% / FrontierCS +9.2% / PassNet +14.0%。**
- **"verified" が効いている。**skill は動作検証を経てライブラリに入る。**検証されていない手順書は、この構成では skill として扱われない。**

> **引用前の注意:** 本エントリの abstract は取得時点で 1500 文字で切れており、**末尾の「これらの改善がどこから来たか」の分解は読めていない。****改善幅はすべて相対値であり、絶対スコアは確認していない。**数値を引く前に本文が要る。

## この loop への適用可能性

**P2 との接続は本物だが、細い。**「教師の中にある知識を、小さく検証可能な形に落として再利用する」という構図は蒸留そのものであり、**蒸留の対象がモデルの重みではなくリポジトリの運用知識になっているだけである。**R2 の系統則 (何が失われるか) には乗らないので、**P2 3.5 に留める。**

**探索枠としての学びは、そこではない。**

**本論文が測っているのは、「知識が足りないから進まない」のではなく「知識が使える形になっていないから進まない」という状況である。**そしてその状況は、**backbone を強くしても計算を増やしても解けない** —— 著者はその 2 つを固定して差を出している。

**この loop に当てはめると、9 週間動いていない R1 の作業は、こう分解できる。**

- **知識は足りている。**solvability の定義・摂動の張り方・検証の 6 条件は、**本日のブリーフ 4 本で出揃った。**
- **足りていないのは、[Versatile Samples](2609.01799.md) の「ログを読み、自車と周辺の軌跡を配列で取り出す」という、論文にならない部分である。**
- **W34 で「紙と電卓・1 時間」まで下げても動かなかったのは、下げた先が間違っていたからかもしれない。****軽くしたのは思考の量であって、手続きの立ち上げコストではなかった。**

**本論文の処方をそのまま読むなら、やるべきは「もっと軽い実験を考える」ではなく、「1 つの手続きを、次回そのまま呼べる形にして固定する」である。**

### 試すべき実験アイデア

1. **【1 時間・09-06 gate の直前作業として】走行ログ (or 2D toy) を読み込んで `(時刻, 自車状態, 周辺物体, 走行可能領域)` を返す関数を 1 つだけ書き、動くことを確認して置いておく。**論文的な価値はゼロだが、**[Versatile Samples](2609.01799.md) の実験アイデア 1 が動き出すのは、この関数が在るときだけである。**本論文の言う skill の最小単位がこれに当たる。
2. **【30 分・観測】その関数を書いたあと、図 1 の作業に着手できたかを記録する。****できたなら、この loop の詰まりは「手続きの立ち上げ」であって「時間」でも「アイデア」でもなかった、という 9 週ぶりの実測になる。****できなかったなら、原因は別にあり、来週の課題レーダーはそちらを追うべきである。**
3. **【やらないこと】AREX-Skill Library の再現や、DisCo の導入は追わない。**規模が違い、**この loop に必要なのは 5,000 個の skill ではなく 1 個である。**
