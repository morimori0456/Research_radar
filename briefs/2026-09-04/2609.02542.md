# WM-LOCO — 「足を置ける場所が数えるほどしかない」地形を、world model の先読みで歩く

**topic:** next_arch / **project:** P3 (+P1) / **hf_upvotes:** 0
**スコア:** P1 **4.0** / P2 2.0 / P3 **4.0**
**著者:** Yuxi Liu, Lijun Han, Ziming Wang, Ao Zhang, Cong Yang / 2026-09-02 公開

## 何を解決する論文か

**foothold-constrained terrain** —— 足を置ける接地点が疎で、途切れていて、幾何的に制限されている地形 (飛び石、隙間の跨ぎ越し、幅の狭い階段の踏面) —— では、**一度踏み外すと立て直す余地がほとんど残らない。**

いまの視覚ロコモーション方策の多くは、**その瞬間に見えている地形**を主な手がかりに足の置き場を決める。本論文の問いは単純である: **「近い将来の観測と報酬を要約した予測」を持たせれば、この地形で必要になる先読みが手に入るのか。**

答えとして提示されるのが **WM-LOCO** で、**recurrent world model と PPO** (Proximal Policy Optimization; 方策を大きく動かしすぎないよう制約をかける標準的な強化学習法) **の方策を同時に学習する。**入力は自己受容感覚 (関節角・姿勢などロボット自身の内部状態) と**単眼の深度画像 1 枚だけ**で、**足の置き場の正解ラベルは一切使わない。**

## 手法の核心

- **world model が出すのは画像ではなく、方策を導くための予測的な recurrent feature である。**「近い将来の観測と報酬の要約」を内部状態として持ち、それを方策に渡す。
- **foothold の明示的なラベルが要らない。**接地可能点を教師として与える従来路線と違い、**報酬と予測だけから先読みが立ち上がる。**
- **入力が薄い。**自己受容感覚 + 単眼深度 1 系統。高価な地形マップも複数カメラも使わない。
- **シミュレーションでの効き方が地形ごとに割れる。****隙間と飛び石では、条件を揃えたベースラインが完全に失敗する場面で成功する。**一方**階段では成功率はベースラインと同等**で、代わりに**歩幅効率が上がり、骨盤の加速度が下がる** (揺れが減る)。
- **実機に載る。****Unitree G1 (人型ロボット) に同じ方策をそのまま載せ、オンボードの自己受容感覚と深度 1 系統だけで 3 種類の地形を踏破。平均成功率 93.3%。**

## P1 / P2 / P3 への適用可能性

**P1 にとって、この論文は「先行研究の隣接領域」として重い。**

R1 の solvability は **「いまこの状態から、まだ助かる候補が何本残っているか」**である。**ロコモーションの側には、これと事実上同じ概念が、地形の性質として最初から存在している —— feasible foot contact の集合が疎であるという条件がそれである。**「一度踏み外すと立て直す余地がほとんど残らない」という本論文の 1 文は、**R1 が運転で言おうとしていることの、別ドメインでの言い換えである。**

**ここから 2 つ帰結する。**

1. **survey 上の宿題ができた。**R1 が「残っている選択肢の本数」を新しい量として出すなら、**foothold feasibility / reachability の系統を無視できない。**査読者に先に指摘されると、新規性の説明が後手に回る。**逆に、こちらから「歩行では地形の性質として扱われてきた量を、運転では方策の評価軸として立てる」と書けば、位置づけが強くなる。**
2. **R1 の差分がもう 1 つ明確になる。****WM-LOCO は先読みを「学習する」。**world model が暗黙に持つ内部状態として獲得し、**外からは読めない。****R1 は同じ情報を「計算する」** —— 状態から陽に候補を張って数える。**読めることが目的である。**[PDT Framework](2609.02688.md) との対比 (事後 vs 事前) と合わせると、**R1 の位置は「事前に・陽に・読める形で」の 3 語で書ける。**

**そして、指標の設計に対する経験的な援護がある。****ベースラインは隙間と飛び石で完全に失敗し、階段では同等だった。****もし 3 地形をまとめた平均成功率だけを報告していたら、「そこそこ劣る手法」に見えたはずである。****分けて見たから「特定の条件で全滅する」ことが見えた。**これは R1 が主張したい「集約は消えたものを隠す」の、本日 3 本目の独立事例である。

**P3 では、R3 の軸 ①(時間をどこに持つか) に対する具体例になる。**WM-LOCO は時間を **recurrent world model の内部状態**に持ち、**方策には要約済みの feature として渡す** —— 未来を明示的に展開しない。**実機で 93.3% という制約下の実測が付いている点が、この軸の値として貴重である。**ただし **R3 は今月着手しないので、記録のみ。**

### 試すべき実験アイデア

1. **【1 時間・survey。09-06 gate の後でよい】foothold feasibility / reachability set の系統から 3 本だけ引いて、R1 の related work に「隣接概念」の段落を作る。**目的は網羅ではなく、**「運転側にこの量が無い」ことを 1 文で言えるようにすること。**
2. **【30 分・言い換えの点検】R1 の solvability の定義を、この論文の語彙で書き直せるか試す。**「接地可能点の本数」→「衝突せず走行可能領域に留まる候補軌跡の本数」。**書き直せるなら、それは概念が既に確立していることの証拠であり、R1 の主張は「新しい量」ではなく「既知の量を、運転の閉ループ評価に持ち込んだ」に変わる。****これは弱くなるのではなく、通りやすくなる。**RoboPAD の 5 ページなら、こちらの方が安全である。
3. **【メモのみ・R3 用】軸 ① の値として「recurrent world model の内部状態に時間を持ち、未来を展開しない」を記録。実機 93.3% の制約付き実測という点も添える。**
