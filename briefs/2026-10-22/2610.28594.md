## 何を解決する論文か

複数カメラの映像から未来を予測する world model (環境の将来を予測・シミュレーションする model) は、カメラごとに見た目は自然でも、「同じ 3D シーンの続き」として整合しないことがある。この論文は、映像生成と同時に「シーン上の点が将来どう動くか」の 3D trajectory を予測させ、全カメラの出力を共通の 3D 運動に紐づける。

## 手法の核心

- **Video-Point Model (VPM)**: multi-view の映像履歴と言語指示を入力にして、任意の視点の未来映像と、持続するシーン点の 3D trajectory を同時に予測する world model。
- **構造**: 事前学習済みの world model に、camera-conditioned な multi-view 処理 (カメラ間で情報を統合する層) と、点が時間とともにどう動くかを出す trajectory head を足す。
- **point supervision**: 1 本の trajectory は全視点にわたって 1 つの点を追う。映像生成と一緒に学習することで、各カメラの見た目の変化が共有の 3D 運動で縛られる。
- **データと評価**: simulation で multi-view 映像と持続する点 trajectory を対にした VPM-Data と、simulation と実環境の両方にまたがる forecasting benchmark の VP-WorldBench を作った。
- **制御への拡張**: robot の action を token の 1 種類として generator に足し、未来映像と同時に denoise する (ノイズ除去で生成する)。policy が 3D 認識つきの表現を共有する形になり、manipulation の成功率が上がる。point supervision は、映像のみの版より映像の質も 3D 運動の精度も改善する。

## 適用可能性と実験アイデア

- **P3 (次世代 architecture)**: 運転は multi-camera が標準なので、カメラ間整合の問題は直接当てはまる。world model の学習に「点 trajectory を補助出力として足す」だけで、生成の質と policy の両方に効く、という構成は追試しやすい。
  - 実験案 1 (最小): 手元の world model / 映像予測 model に、点 trajectory (オプティカルフローや tracker 出力を擬似 label にしたもの) を補助 head として足し、映像のみの版と同じ step 数で比較する。
  - 実験案 2: action token を足す設計を運転の ego 軌道に置き換え、world model を policy の初期化に使えるかを見る。
  - 実験案 3: 3D 動きの精度を測る評価を作る。nuScenes / Waymo 系の log に対して、追跡した点の予測誤差を closed-loop simulation の質の指標に使えるか。
- **P1**: world model を closed-loop simulation の環境として使うとき、多視点整合と物体運動の正確さが、評価の信頼性を直接決める。VP-WorldBench のような forecasting benchmark の指標設計は参考になる。
- 注意: 実験の中心は robot manipulation と一般シーンで、運転の高速移動・遠距離・大きな ego motion では未検証。擬似 label の trajectory を実データに用意するコスト (tracker の精度) が、simulation の正解 trajectory に比べて不利になる点が最大の壁。
