# From Solver Trajectories to Teaching Trajectories: Cognition-Aligned Reasoning Distillation (2610.36445)

- トピック: fm_distill_finetune (P2) / スコア 4.0
- URL: https://arxiv.org/abs/2610.36445
- コード: https://github.com/LiteSSLHub/CARD

## 何を解決する論文か

大きい reasoning model (LRM; 長い推論の過程を出力する大規模 model) から小さい model への蒸留では、teacher の出力した推論の軌跡 (trajectory) をそのまま student の教師データにすることが多い。しかし teacher は RLHF (人間のフィードバックによる強化学習) のような reward-driven な post-training で「問題を解く solver」として最適化されており、「小さい model が学びやすい説明」を出すようには作られていない。student は teacher と能力 (論文の言う cognitive capacity) が違うので、solver の軌跡を真似るだけでは非効率で、大量の高品質サンプルが要る。この論文は、既存の軌跡を student に合った「教える軌跡」に変換する。

## 手法の核心

- **CARD (Cognition-Aligned Reasoning Distillation)**: solver の軌跡を teaching 用の軌跡に書き換える RL ベースの枠組み。teacher を再度 sampling し直さず、既存の軌跡を直接変換するので、resampling の cost を避ける。
- 変換 model を 2 つの reward で最適化する:
  - **Distribution Alignment Reward**: 変換後の軌跡が、student の予測分布に合うほど高い (student から見て「予測しやすい」説明にする)。
  - **Logical Coherence Reward**: 失敗した推論の筋道や、誤解を招く途中経過を減らす (論理が通っていない部分が student を惑わせるのを防ぐ)。
- 結果: 複数の student model と設定で、raw な teacher の軌跡からの蒸留を in-domain で上回り、out-of-distribution で特に大きく伸びる、と報告している。

## P2 への適用可能性

- P2 の capacity gap 対策として、loss ではなく**教師データの側を student に合わせる**アプローチ。MPOPD (2610.36477; rollout の分布を設計する) と対になる: 片方は student が作る出力の分布、もう片方は teacher が作る出力の形を、gap を埋める方向に直す。
- 蒸留を実務で回すときに「teacher の出力をそのまま使う」で止まっている場合、前処理 (teacher 出力の整形) だけで改善する余地を示す。既存データの変換で済むので、teacher の再 sampling が高い設定で特に効く。
- 注意点: 対象は LLM の text 推論で、視覚 model や運転 model ではない。「student の予測分布に合わせる」reward を作るには student 側の確率を使うので、蒸留のたびに変換 model を回し直す手間がある。abstract では、その追加 cost を含めた総 cost の比較が不明。

## 試すべき実験アイデア

1. 手元の蒸留で、teacher の出力のうち student の対数尤度が低い部分 (student にとって予測しにくい箇所) を数える。CARD の考え方が当てはまるほど gap があるかの診断になる。
2. 変換 model の学習をやめ、Logical Coherence に相当する簡易版 (teacher の軌跡のうち、最終答えにつながらない途中経過を除く rule-based な filter) だけを入れて蒸留し、効果の大きさを見る。
3. 運転では、teacher の軌道や reasoning の出力 (VLA が出す説明文など) を student 向けに整える形に読み替える。VLA の reasoning を蒸留する際に、長い説明を student の容量に合わせて削ると何が落ちるかを測る。

## 注意

abstract のみに基づく。student と teacher の組み合わせ、各 benchmark の数値、変換 model 自体の大きさと学習 cost は未確認。「out-of-distribution で大きく伸びる」は abstract の記述で、幅は分からない。
