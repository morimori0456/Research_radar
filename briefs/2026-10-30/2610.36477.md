# Proposing Better Rollouts for On-Policy Distillation (2610.36477)

- トピック: fm_distill_finetune (P2) / スコア 4.0
- URL: https://arxiv.org/abs/2610.36477

## 何を解決する論文か

OPD (On-Policy Distillation; student が自分で生成した出力に対して teacher が採点・supervision を与える蒸留。推論時の分布で学習できるので、teacher の出力を真似るだけの蒸留より train/test のずれが小さい) は、LLM の post-training で使われ始めている。ただし通常の OPD は、各 round の rollout (student が生成する出力列) を現在の student からそのまま sampling する。すると student が出した、teacher 自身には到達しにくい出力列にも teacher が supervision を付けることになり、その supervision は不安定で、時に誤誘導になる。その結果、繰り返し出力のような症状が student に残り、次の round の rollout にも引き継がれて増幅する。この論文は、distillation の loss ではなく rollout を作る policy そのものを最適化の対象にする、という見方を提案する。

## 手法の核心

- **MPOPD (Mixture Proposal On-Policy Distillation)**: rollout の分布を「student から離れすぎず、teacher が支持する方向に寄せる」ように設計する。
- 設計の根拠は local trust-region (今の student の近傍に限定して更新を許す制約) つきの目的関数。teacher の相対的な支持度 (student と比べて teacher がその出力をどれだけ好むか) に応じて分布を寄せる。
- 目的関数の解は、student と teacher の policy の **geometric mixture** (確率を重み付きで掛け合わせて正規化した混合) になる。
- geometric mixture を直接 sampling するには 2 つの model を token ごとに回す必要がある。そこで、その mixture に近づけた proposal policy を別に持ち、**1 回の forward pass で rollout を作れる**ようにしている。
- 結果: 数学・知識・医療の推論を扱う 16 benchmark で OPD と最近の改良版を上回る。数学 reasoning で、Qwen3-4B-Base の平均 accuracy が OPD より 6.91 点高く、平均の生成長が 41% 短い。

## P2 への適用可能性

- P2 の中心課題の 1 つは、蒸留を実務で回すときの capacity gap (teacher と student の能力差が大きいと student が teacher の出力を学べなくなる問題)。この論文は、gap が大きい状況で student 自身の rollout 上の teacher supervision が壊れる、という具体的な failure mode を挙げている。on-policy な蒸留を採る場合の現実的な落とし穴である。
- 対象は LLM の text reasoning で、foundation model の視覚側や運転 model への蒸留ではない。ただし「student の分布から離れた状態に teacher が supervision を付けると壊れる」問題は、driving policy や VLA の on-policy 蒸留 (student が closed-loop で自分の状態を訪れる設定) にも出る構造をしている。
- 注意点: 比較対象は OPD とその variant で、off-policy な通常の蒸留 (teacher の出力を固定して SFT) との比較は abstract に無い。accuracy の改善と生成長の短縮が同時に出ており、短くなったこと自体が accuracy を押し上げた可能性は切り分けが要る。

## 試すべき実験アイデア

1. 手元の蒸留 (あれば) で、student 単独 rollout の OPD と、「student と teacher の token 確率の geometric mixture から sampling する」素朴版を比べる (proposal policy を学習しない最小版。cost は 2 倍の forward だが、まず効果の有無を見る)。
2. teacher が student の rollout に付ける supervision の質を、teacher の対数尤度や teacher の entropy で測り、capacity gap が大きい組で劣化するかを確認する (論文の failure mode の再現)。
3. 運転 model への転用の第一歩として、teacher を大きい planner、student を小さい planner とし、student が closed-loop で訪れた状態に teacher の軌道を付ける DAgger 型の蒸留で、同じ mixture rollout が効くかを simulation で見る。

## 注意

abstract のみに基づく。trust-region の定式化の詳細、proposal policy の追加学習 cost、teacher と student の組み合わせの幅、16 benchmark それぞれの結果は未確認。+6.91 は平均で、benchmark ごとの差は分からない。
