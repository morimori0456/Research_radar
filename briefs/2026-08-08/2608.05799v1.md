# XEWorld: Can Action-Conditioned World Models Generalize to Unseen Robot Embodiments?

**topic:** next_arch (P3) ・ **arXiv:** 2608.05799v1 ・ **published:** 2026-08-06 ・ hf_upvotes: 0

## 何を解決する論文か
action-conditioned world model(行動を条件に未来の観測を予測するモデル)は「学習済みシミュレータ」として期待されているが、**評価が学習に使ったロボットの上でしか行われていない**。そのため「本当に物理を捉えたのか、単に見た目のパターンを覚えただけか」が区別できていなかった。XEWorld は **物理的に同一のシーンで、学習に使っていないロボット(held-out embodiment)だけを差し替える**統制テストベッドを作り、この問いに答える。結論は厳しく、**現行モデルは本質的に 2D の視覚パターンマッチャ**だという診断である。

## 手法の核心
- **統制されたテストベッド:** シーン・物理条件を完全に揃えたまま **embodiment(ロボットの機体)だけを held-out にする**設計。「汎化した」のか「似た見た目を再生した」のかを切り分けられる。
- **主要な診断1 — 汎化を決めるのは幾何ではなく見た目:** 未見ロボットへの汎化性能は、**kinematic(関節構造・可動域)の類似度ではなく visual similarity(見た目の近さ)に支配される**。物理を内在化していれば前者が効くはずで、そうなっていない。
- **主要な診断2 — 数値行動の視覚化に失敗:** **抽象的な数値の joint action(関節角の指令値)を、一貫した視覚的な軌道に翻訳できない**。また静止した初期観測だけからは動的変化を予測できない。
- **zero-shot に必要な条件:** 未見機体を zero-shot で描かせるには、**pixel-space action(行動を画像空間に描いて与える表現)と明示的な時空間 alignment** という「強く接地された手がかり」が必須。逆に言えば、数値行動をそのまま条件にする設計では届かない。
- **few-shot でも罠:** 少数サンプルで適合させて zero-shot の壁を越えても、**見た目を合わせにいく学習が既知機体の catastrophic forgetting(以前学んだことを忘れる現象)を引き起こす**。
- **結論:** 真の cross-embodiment 汎化には、**視覚的な見た目と物理ダイナミクスを分離するアーキテクチャ的な革新**が要る。

## 追っているプロジェクトへの適用可能性
- **P3(本命・警告として):** 我々が driving world model を「学習済みシミュレータ」として planner 評価に使う構想は、この論文の指摘を正面から食らう。**車種・センサ構成・カメラ搭載位置が変われば「未見 embodiment」そのもの**であり、見た目が近いだけで汎化しているように見えてしまう危険がある。**評価設計を先に直す**必要がある。
- **P3(設計指針):** 「**appearance と dynamics を別々の経路で扱え**」という要請は、同日の [LAWM-3D](2608.05706v1.md) の幾何接地、および 2026-07-25 に読んだ WorldWeaver の「状態推論と描画を別重みに分ける MoT」と一直線に繋がる。今日の3本を合わせると、**「状態(物理)を持つ枝」と「描画(見た目)を出す枝」を構造的に分離する**という設計方針がかなり固まる。
- **P1(評価設計):** XEWorld の統制手法そのものが我々に転用できる。**シーンを固定し ego 車両のパラメータ(車幅・ホイールベース・カメラ高さ)だけを差し替える held-out 評価**を作れば、planner/world model が物理を見ているか見た目を見ているかを分離できる。これは R1(HIL 評価 × 保証付き安全指標)の前段として必要な健全性チェック。
- **P2(適合の落とし穴):** few-shot 適合が既知機体の忘却を招くという報告は、我々の「他機種への適合」というテーマの直撃。**適合後に旧機体の性能を必ず再測する**という運用ルールを入れるべき根拠になる。

### 試すべき実験
1. **見た目 vs 幾何の切り分け:** 同一シーン・同一走行データで、**(a) 車両の見た目(色・車体形状)だけを変えた条件** と **(b) 幾何(ホイールベース・カメラ位置)だけを変えた条件** で予測誤差を比較。誤差が (a) に強く反応するなら、我々のモデルも 2D パターンマッチャ。
2. **行動条件の表現を替える:** 数値の steer/accel を条件にする現行方式 vs **pixel-space に描いた行動表現(例: 予定軌道を BEV や画像上に描画して条件にする)**を比較。XEWorld の主張どおりなら後者だけが未見構成に zero-shot で通る。
3. **忘却の測定:** 新しい車種へ few-shot 適合した後、**元の車種での予測誤差の劣化幅**を測る。劣化が大きければ、適合を LoRA(低ランクの追加パラメータのみ学習する PEFT 手法)等に閉じ込める、あるいは replay を混ぜる対策が要る。
4. **静止初期観測からの動的予測:** 停止フレーム1枚だけを与えて rollout させ、**動き出しが予測できるか**を単独で評価する診断項目を常設化する。ここが弱いモデルは closed-loop 評価に使えない。
