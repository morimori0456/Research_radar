# RST: Recursive Synthesis for Long-Horizon Terminal Tasks

**topic:** sns_wildcard (EXPLORE) ・ **arXiv:** 2608.05466 ・ **published:** 2026-08-04 ・ **hf_upvotes: 206**

> **wildcard 枠(分野外の探索枠)。** 本業は「ターミナル上で長時間作業する LLM agent の学習データ生成」で自動運転からは遠いが、**「タスク・正解手順・採点器を互いに整合させたまま自動生成する」**という方法論が、我々の closed-loop 評価シナリオ生成にそのまま移せると判断して採用。

## 何を解決する論文か
long-horizon(何十手も続く)エージェントタスクの学習データは**1タスクあたり数百〜数千ドル**かかる。理由は、**instruction(指示)・environment(環境)・reference solution(模範解答)・verifier(自動採点器)の4点が互いに矛盾しないよう保たなければならない**から。人手では規模が出ず、LLM に直接生成させるとこの依存関係が壊れる。RST は **検証済みのタスクを種にして再帰的に難化させる**ことで、整合性を保ったままスケールさせる。

## 手法の核心
- **再帰的な拡張ループ:** 検証済みの seed task から出発し、**(1) reference solution を延長 → (2) verifier と instruction を新しい手順に合わせて再整合 → (3) 新しい sandbox(隔離実行環境)で実際に走らせて検証 → (4) 合格したタスクを次ラウンドの seed にする**。**「作ってから検証」ではなく「検証を通ったものだけが次の種になる」**という選別が肝。
- **整合性の担保が構造に埋まっている:** verifier を毎回作り直すのではなく、**解答の延長に合わせて verifier を追従させる**ので、4点セットが壊れない。
- **難易度が自動で上がる:** 15 ラウンドで **37,484 タスクを 1件あたり約 $0.05** で生成。reference solution の中央値は **67行 → 374行**、実行コマンド数の中央値は **40 → 244** に増加。強力なモデルの pass@4 が **R1 の 90% から R15 の 2.5% まで落ちる**——つまり**現行モデルの限界を自動で追い越していく難易度カリキュラム**が出来ている。
- **学習に効くことの実証:** 生成タスク上で rejection sampling(生成候補のうち採点に通ったものだけ残す)したトラジェクトリで SFT すると、複数のベンチで最大 **+10 ポイント**。さらに agentic PPO(方策勾配系の強化学習)で上積み。

## 追っているプロジェクトへの適用可能性
- **P1(本命の転用先):** 我々の closed-loop 評価の最大のボトルネックは **「難しいシナリオ」と「そのシナリオ用の正しい評価指標」を対で用意するコスト**。RST の構造をそのまま写すと、**(シナリオ設定, 参照走行, 評価器) の三点セットを、検証済みのものだけ種にして再帰的に難化させる**パイプラインになる。**「planner が現状 90% 解ける難易度」から始めて、解けなくなるまで自動で難化させる**というカリキュラムは、飽和した既存ベンチ(planner がほぼ満点を取り差がつかない)問題への直接の回答。
- **P1(検証器の追従が要):** ここでの本質は「難しくすること」ではなく **「難しくしても採点が壊れないこと」**。我々の場合、シナリオを難しくすると **何をもって成功とするかの定義が曖昧になる**(例: 譲るべきか進むべきか)。RST の「解答を延ばしてから verifier を再整合させる」順序は、この曖昧さを扱う実務的なヒントになる。
- **P2(横断):** rejection sampling → SFT → RL という**データ生成から学習までの一気通貫レシピ**は、我々の蒸留パイプの構成としても参考になる。特に「生成したものを全部使わず、検証に通ったものだけ使う」選別の効き目が数字で出ている点。
- **注意点:** ターミナル環境は**決定的で verifier が書きやすい**という圧倒的に有利な条件がある。運転は連続・確率的・多目的なので、**verifier の自動再整合は素直には移らない**。ここを埋める工夫が我々側の研究余地になる。

### 試すべき実験
1. **最小の再帰ループを作る:** 既存の評価シナリオ 10 本を seed に、**「1手難しくする(割り込み車両を1台足す/視界遮蔽を1つ足す)→ 参照軌道を再生成 → 評価器の閾値を再整合 → シミュレータで実走検証」**を1ラウンドだけ手で回し、**壊れる箇所(たいてい評価器)がどこか**を特定する。
2. **難易度カリキュラムの測定:** 生成したシナリオ群に対する現行 planner の成功率を、ラウンドごとにプロット。**RST 同様に単調に落ちるか**を確認する。落ちないなら「難化」が形だけになっている。
3. **コストの実測:** 1シナリオあたりの生成コスト(計算時間 + 人手確認時間)を測る。RST の $0.05 に対して我々が何桁高いかが分かれば、**どこを自動化すべきか**が決まる。
4. **生成シナリオで学習:** 生成シナリオ上で rejection sampling した軌道で planner を fine-tuning し、**人手で作った既存ベンチ**での性能変化を測る(生成データが本物のベンチに効くか、という transfer の確認)。
