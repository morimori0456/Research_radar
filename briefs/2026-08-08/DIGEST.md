## 今日読むべき TOP3

### 1. Adaptive-WAM — 運転判断を出すのに、動画生成モデルはどこまで実行すればいいのか(P3 タグだが P1 直撃)
video diffusion(ノイズから動画を反復生成する拡散モデル)を土台にした運転 planner は、**実際に要るのは軌道1本なのに未来動画を作るコストを丸ごと払っている**。この論文はその無駄を実測で剥がした。結論が痛快で、**ノイズ除去の反復回数には性能がほとんど鈍感、backbone も最終層まで要らず中間層から既に良い軌道が読み出せる**。そこで DiT (Diffusion Transformer; 拡散モデルの backbone を transformer にしたもの)の複数の層に軌道生成ヘッドを付け、**軽量な採点器が「この軌道は十分良い」と判定したら即打ち切る**。deploy 時は反復 denoising も VAE decode も走らせない。NAVSIM(自動運転の閉ループ planner ベンチ)で **90.8 PDMS**(固定 exit + 64 候補なら 92.6)、**target domain の fine-tuning なしで nuScenes に転移**(L2 0.88m)、A100 で**平均 170ms**。「world model を生成器ではなく特徴抽出器として使う」割り切りと、**精度と latency を同じ表で報告する評価作法**の両方が持ち帰り。→ [ブリーフ](2608.06008v1.md)

### 2. LAWM-3D — 「multi-view を食わせれば 3D が分かる」は間違いだった、という negative result と、その処方(P2 本命)
行動ラベルなしの動画から world model を学ぶ **LAM (Latent Action Model; フレーム間で何が起きたかを潜在的な行動として自己教師あり学習する手法)** に、多視点動画を入れれば立体を理解するようになるか——著者らはまず**「ならない」**と示す。原因は **未来フレームの見た目がそのまま漏れてショートカット学習になる**ことと、カメラ間の見た目差。処方は3点セットで、**視点が変わっても同じ行動が同じ token になる tokenize**、**中間特徴を既存の 3D foundation model の特徴に固定するアンカー**(フル蒸留より遥かに軽い「部分蒸留」)、そして **RGB と depth を同時に、かつ出力から入力を一意に復元できない形で再構成させて見た目の覗き見を封じる**。**大量の無ラベル人間動画で pretrain → 少量のロボットデータで fine-tuning** という、P2 が探している「他ドメインからの適合 recipe」そのもの。我々に置き換えれば、無ラベルの車載動画を world model 学習に流し込む道になる。→ [ブリーフ](2608.05706v1.md)

### 3. XEWorld — 我々の world model は物理を見ているのか、見た目を見ているのか(P3、警告として)
行動を条件に未来を予測する world model を「学習済みシミュレータ」として使う構想への、正面からの冷や水。**シーンと物理を完全に固定し、ロボットの機体だけを未学習のものに差し替える**という統制テストを作ったところ、**汎化性能を決めていたのは関節構造の類似度ではなく見た目の近さ**だった。つまり現行モデルは本質的に **2D の視覚パターンマッチャ**で、数値の関節指令を一貫した視覚的な動きに翻訳できていない。さらに厳しいのは、少数サンプルで新機体に適合させると**既存機体を catastrophic forgetting(以前学んだことを忘れる現象)する**こと。**車種・カメラ搭載位置が変われば我々にとっても「未見の機体」**であり、この診断はそのまま我々に刺さる。処方は「見た目と物理ダイナミクスを構造的に分離せよ」で、これは 2 位の LAWM-3D の幾何接地、および 2026-07-25 の WorldWeaver(状態推論と描画を別重みに分ける)と一直線に繋がる。→ [ブリーフ](2608.05799v1.md)

## プロジェクト別の要点

- **P1(Planner AI + 評価):** 今日の収穫は手法より**評価軸**が 3 本立った点。(a) **計算予算あたりの性能** — Adaptive-WAM([[2608.06008]])が PDMS と end-to-end latency(170ms)を同じ表で報告している。我々の評価は精度に偏っており、**latency 予算を固定した PDMS** を常設指標に足すべき。(b) **エンティティ別に重み付けした被害期待値** — FailBench([[2608.05313]])の「確率 × 深刻度」分解は、歩行者と路側構造物を同じ衝突率で潰している現行指標への直接の批判で、**R1(過保守・介入頻度を保証付きで測る)の骨格そのもの**。しかも故障(センサ dropout・遅延・アクチュエータ劣化)を**制御可能な実験変数**にする発想が我々の評価基盤に欠けている。(c) **失敗の帰属** — INTraJ([[2608.05673]])の reference + residual 分解で、予測の失敗を「大枠の予期ミス」と「局所反応の見積もりミス」に切り分けられる。**明日できる:** 既存の閉ループ評価に深刻度重みテーブル(歩行者 ≫ 自転車 > 他車 > 路側物)を入れ、重み付き被害期待値と一律衝突率で **planner の順位が入れ替わるか**を確認する。入れ替わるなら、我々は今まで誤った planner を選んでいたことになる。

- **P2(FM 蒸留 + 適合):** 本枠は LAWM-3D([[2608.05706]])1 件のみ。持ち帰りは **「基盤モデルを丸ごと蒸留せず、中間特徴のアンカーとして使う」**という軽量な部分蒸留 — 既存 encoder に alignment loss を1本足すだけの最小変更で試せるので、着手コストが低い割にリターンが読みやすい。もう一つは **「データを増やす前に supervision が汚れていないか疑え」**(見た目の漏れによるショートカット)という順序の教訓。次点が今日は特に厚く渋滞している:**AgentOPSD([[2608.05987]], hf 63、teacher/student の log-prob 差から密な credit を作る)**、**RENDEQ([[2608.05670]]、自分の合意で fine-tuning すると 5/5 で精度が落ちるという強い負の結果)**、**BioKD([[2608.06023]]、教師の信頼度をサンプル単位で門にして negative transfer を抑える)**、**B300 field report([[2608.05944]]、GPU 使用率は NCCL ハング中も 100% なので消費電力で切り分けろ)**。特に最後の1本は**今日いちばん即物的**で、我々が多ノード fine-tuning を回す日には即読むべき。**明日できる:** 我々の world model 学習で未来フレームを入力から遮断する ablation を1本走らせ、性能低下が小さければ「見た目を覗いていた」証拠が取れる。

- **P3(次世代アーキ):** 今日は珍しく**主張が一方向に収束した**。**「world model に未来を描かせるな、状態を持たせろ」**——(a) 描画は推論から落とせる(Adaptive-WAM: 中間層で十分、denoising 反復にも鈍感)、(b) 描画を目的にすると見た目のショートカットを学ぶ(LAWM-3D: 非単射 RGB-D 再構成で封じる)、(c) その結果できたモデルは物理でなく見た目で汎化する(XEWorld: 未見機体で崩壊 + few-shot 適合で忘却)。2026-07-25 の WorldWeaver(状態推論と描画を別重みに分ける MoT)と合わせると、**「状態(物理)の枝」と「描画(見た目)の枝」を構造的に分離し、運用では前者だけ走らせる**という設計仮説がかなり固い。次点も豪華で枠が惜しい:**PhyLatent([[2608.05720]]、JEPA の潜在崩壊を防いでも物理状態は保存されないとして3つの失敗モードを定義)**は XEWorld の別解、**GAUGE([[2608.05948]]、物理エンジンと video world model を同じ土俵で診断。video world model は方程式の形は合うのに加速度と運動量移動が間違う)**は評価手法の新提案として本来高優先、**GeniWorld([[2608.06332]]、数値行動を URDF で視覚化して接地、policy evaluator として使える)**は XEWorld の処方の実装。**枠が空いたら PhyLatent → GAUGE → GeniWorld の順**で拾う。

- **EXPLORE(wildcard):** RST([[2608.05466]], hf 206)。ターミナル agent の学習データ生成という完全な分野外だが、**「タスク・環境・模範解答・採点器の4点を互いに整合させたまま自動生成する」**という方法論が刺さる。肝は「作ってから検証」ではなく **「検証を通ったものだけが次の種になる」**再帰構造で、15 ラウンドで難易度が自動的に上がり(模範解答の中央値 67 行 → 374 行、強モデルの pass@4 が 90% → 2.5%)、**1件あたり $0.05**。我々に写すと **(シナリオ, 参照走行, 評価器) の三点セットを再帰的に難化させる**パイプラインになり、**planner がほぼ満点を取って差がつかない飽和ベンチ**問題への回答になりうる。ただし**ターミナルは決定的で採点器が書きやすい**という圧倒的に有利な条件がある一方、運転は連続・確率的・多目的で「何をもって成功とするか」自体が曖昧 — **そこを埋めるのが我々側の研究余地**。
