# Adaptive-WAM: Quality-Guided Early-Exit Planning from Intermediate Video-Diffusion Features

**topic:** next_arch (P3) ・ **arXiv:** 2608.06008v1 ・ **published:** 2026-08-06 ・ hf_upvotes: 0

## 何を解決する論文か
video diffusion model(ノイズから動画を反復的に生成する拡散モデル)を土台にした world-action model は、自動運転の未来予測に強い prior を持つ一方、**実運用で必要なのは ego trajectory 1本だけなのに、未来動画の生成コストを丸ごと払っている**。本論文は「信頼できる運転判断を出すのに、video diffusion のどこまで実行すればいいのか?」を正面から測り、**軌道を出した時点で早期に打ち切る planner** を提案する。結論として、**denoising timestep(ノイズ除去の反復回数)には性能がほとんど鈍感で、DiT(Diffusion Transformer; 拡散モデルの backbone を transformer にしたもの)の中間層から既に強い軌道が読み出せる**ことを示した。

## 手法の核心
- **制御実験による観察:** video のノイズレベル(denoising timestep)を振っても planning 性能はほぼ変わらない。一方で **DiT の深さ**は効く——しかし最終層まで要らず、**中間層の hidden state から良い軌道がデコードできる**。つまり「未来動画を綺麗に作る計算」の大半は運転判断に不要。
- **multi-exit planner:** Wan2.2-5B(video diffusion backbone)の**選ばれた DiT ブロックに trajectory diffusion head(軌道を生成する小さな拡散ヘッド)を複数付ける**。浅い exit から順に軌道を出す。
- **quality-aware early exit:** 軽量な **trajectory-quality scorer(出た軌道の良さを推定する小さな採点器)** が閾値を超えたら即終了。超えなければ **キャッシュした hidden state から続きを計算**してより深い exit へ進む。つまり**シーンの難しさに応じて backbone の深さを動的に配分**する。
- **生成そのものを捨てる:** deploy 時は **classifier-free guidance の反復 denoising ループも VAE decode も実行しない**(どちらも未来動画の合成にしか要らない)。world model を「動画生成器」ではなく「特徴抽出器」として使う割り切り。
- **数値:** NAVSIM(自動運転の closed-loop planner ベンチ。PDMS = Predictive Driver Model Score、衝突・進行・快適性等の複合指標)で **adaptive 単一軌道 90.8 PDMS**、固定 exit + 64 proposal で **92.6 PDMS**、NAVSIM v2 で **89.9 EPDMS**——front-view video world-model planner 中で最良。**target domain の fine-tuning なしで nuScenes に転移**し L2 平均 0.88m / 衝突率 0.08%。A100 で **平均 170ms**(固定 block-15 の 190ms より約10%、full-depth 320ms より47%速い)。コード公開予定。

## 追っているプロジェクトへの適用可能性
- **P3(本命):** 「world model は未来を**描く**必要があるのか、**内部表現を持てば十分**なのか」に実測で答えている。我々が driving world model を planner に繋ぐとき、**pixel 再構成ヘッドを推論から外し、中間 latent を直接 policy に渡す**構成が第一候補になる。2026-07-25 に読んだ HyWorldVLA の「pre-train は pixel 接地・運用は latent 専用」と同じ方向を、**層方向(どこまで実行するか)**に拡張した結果と読める。
- **P1(直撃):** 170ms という **end-to-end planning latency を PDMS と同じ土俵で報告**している点が評価設計として重要。我々の planner 評価は精度指標に偏りがちだが、**「計算予算あたりの PDMS」**という軸を持てば、過保守/介入頻度の議論(R1)にも接続できる。さらに trajectory-quality scorer は **「この軌道は信用できるか」を軌道単位で出す**ので、conformal prediction(予測の外れ率を分布仮定なしで保証する統計手法)の非適合度スコアの候補にそのまま使える。
- **P2(横断):** 「大きい基盤モデルを別ドメインへ持っていく」典型 recipe として、**backbone 凍結 + 浅い層に task head を挿す**構成が nuScenes へ fine-tuning なしで転移している。蒸留の代替として **"深さの切り詰め" が実質的な圧縮になる**ことを示唆する。

### 試すべき実験
1. **どこまで実行すれば足りるかの再現:** 手持ちの driving video world model で、DiT 各ブロックの hidden state から軌道を linear probe(特徴を固定して線形層だけ学習する簡易評価)し、**深さ vs PDMS 曲線**を引く。飽和点が本論文同様に中間層なら、推論から後段を丸ごと落とせる。
2. **denoising timestep の感度確認:** ノイズレベルを振って planning 精度の変化を測る。もし本当に鈍感なら、**denoising ループを1ステップに固定**するだけで大きな latency 削減になる。
3. **quality scorer を conformal 化:** trajectory-quality score を非適合度スコアとして calibration set で閾値を較正し、**「早期 exit した軌道の失敗率が α 以下」を保証付きで**言えるか検証。early exit の安全性議論がこれで定量化できる。
4. **計算予算あたりの評価軸を導入:** 我々の planner ベンチに **latency 予算を固定した PDMS**(例: 100ms/200ms/400ms 予算での性能)を常設指標として追加し、adaptive routing の効き目をシーン難易度別(交差点・合流・直進)に分解する。
