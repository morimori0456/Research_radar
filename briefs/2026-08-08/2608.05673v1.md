# INTraJ: A Unified Framework for Trajectory Prediction with Explicit Planning and Reaction Decomposition

**topic:** planner_ai (P1) ・ **arXiv:** 2608.05673v1 ・ **published:** 2026-08-06 ・ hf_upvotes: 0

## 何を解決する論文か
trajectory prediction(周囲エージェントの未来軌道予測)は social interaction(他者との相互作用)を明示的に扱う方向へ進んできたが、**「他者の影響」がひとかたまりに扱われ、機能的な役割が区別されていない**。著者らは人の運転・歩行の実態から「**まず他者の未来を予期して計画を立て、その後に局所的な反応で微修正する**」という段階構造を見出し、social influence を **planning 段階と reaction 段階に分解**する枠組み INTraJ を提案する。

## 手法の核心
- **planning 段階:** **他者の未来情報(future social information)を使って reference trajectory(基準となる大枠の軌道)を構築**する。ここは「相手がこう動くだろうから自分はこう行く」という予期のレイヤ。
- **reaction 段階:** **full-context 予測と reference trajectory の残差(residual)から局所的な調整分を復元**する。つまり反応を「基準からのズレ」として明示的に切り出す。**予測を残差学習の形に落とし込んだ**のが構造上の肝。
- **段階順序の主張:** planning が reaction に先行する、という順番自体が性能に効くと主張(staged social modeling)。両者を同時に一つのモジュールで扱う既存手法との違いはここ。
- **multi-target / single-target の両対応:** 全エージェントを同時に予測する設定と、注目1体のみを予測する設定の**どちらのパラダイムにも同じ枠組みで対応**する。
- **検証:** **Argoverse 2**(自動運転の大規模軌道予測ベンチ)、Argoverse 2-ped(歩行者)、ETH/UCY、SDD の4ベンチで一貫した改善。特に **FDE (Final Displacement Error; 予測終端時刻での位置誤差) と long-horizon の一貫性**で効く。コード公開: https://github.com/11isnotavailable/INTraJ

## 追っているプロジェクトへの適用可能性
- **P1(本命):** 我々の planner は周囲車両の予測を入力に持つ。INTraJ の **「reference + residual」分解は、予測の解釈性をタダで上げる**——ある予測が外れたとき、**大枠の予期を間違えたのか(planning 段階)、局所反応の見積もりを外したのか(reaction 段階)**を分離できる。planner 評価で「なぜ落ちたか」を帰属させたい我々の課題(過去の DIGEST で繰り返し出ている「帰属の曖昧さ」)に直接効く。
- **P1(評価指標):** FDE と long-horizon 一貫性で効くという結果は重要。**planner が効く時間帯(3〜8秒先)はまさに long-horizon 側**なので、ADE(平均変位誤差)中心の評価では見落とす改善を拾っている。我々の評価も **段階別・時間帯別に分解した誤差**を出すべき。
- **P1(planner との結合):** planning 段階が「他者の未来」を使う設計は、**予測器と planner の間の相互依存(自車が動くと他車の予測も変わる)**をモデル内に取り込む形になっている。closed-loop 評価で予測器を固定して回す従来構成の限界を考え直す材料。
- **P3(横断):** 「大枠を先に出して残差で直す」構造は、world model の rollout にもそのまま移せる。**長期の粗い予測 + 短期の細かい補正**という二段構成は drift 抑制の定石になりうる。

### 試すべき実験
1. **残差分解の可視化:** 手持ちの予測器を INTraJ 風に **reference 枝と residual 枝に分けて再学習**し、失敗ケースを「reference が悪い / residual が悪い」に自動仕分けする。planner の失敗解析に、予測起因かどうかの一次切り分けが入る。
2. **段階順序の ablation:** planning→reaction の順序を入れ替える/同時にする条件を作り、**本当に順序が効くのか**を我々のデータで確認する。効かなければ単なる残差学習の効果であり、実装は軽くなる。
3. **時間帯別評価の常設化:** ADE/FDE を 1s/3s/5s/8s に分解して報告する形に評価スクリプトを変更。long-horizon の一貫性(軌道の折れ曲がり・時刻間の非整合)を測る指標を追加する。
4. **planner 下流での効き目:** 予測精度が上がっても planner の PDMS 相当指標が上がるとは限らない。**予測を INTraJ に差し替えたときの planner 側の指標変化**を測り、「予測精度 → planning 品質」の伝達率を実測する(ここが薄いなら予測改良への投資を止める判断材料になる)。
