# Flash-OPD: 軌跡ごとに「教師が信頼できる長さ」で打ち切る on-policy distillation

- 対象: P2 (Foundation Model 蒸留)
- 元論文: http://arxiv.org/abs/2610.06105v1 (Wei Chen ほか)
- 根拠: abstract のみ (本文・コード未確認)

## 何を解決する論文か
OPD (On-Policy Distillation; student 自身が生成した出力に対し、教師が token ごとに密な教師信号を与える蒸留) は効果的だが、長い rollout (生成) を作り教師で評価するコストが重い。既存の高速化は rollout 長を固定スケジュールや適応制御で決めるが、教師と student の「相性」が保たれる長さは軌跡ごとに違うため、短すぎると有用な信号を捨て、長すぎると計算を無駄にする。

## 手法の核心
- 発想: 信頼できる長さの境界は生成前には予測できないが、「境界に達したか」は生成済みの prefix から正確に判定できる。
- 信頼性を「教師と student の相性が低い event の累積が閾値に達する最初の時点 (first-passage)」として定義する。
- 生成 (cache を使う) と教師による verification を交互に行い、軌跡ごとに独立に打ち切る。rollout 長の制御から、軌跡単位の境界検証へ切り替える。
- verification のコスト削減には直近の event 発生率を使うが、使うのは「次にいつ検証するか」だけ。打ち切りの判断は常に正確な累積カウントで行う (推定誤差で早すぎる打ち切りが起きない)。
- 報告: 標準 OPD に対し 2.2〜7.5 倍の高速化、精度は維持または向上 (複数 dataset・教師-student 設定)。

## 適用可能性 (P2)
- 蒸留を実務で回す際の「コスト」側の recipe。OPD を使うなら rollout 長の無駄を減らす実装として直接効く可能性が高い。
- 注意: 評価は LLM 系の設定と思われる (abstract に明記なし、未確認)。画像/driving 向けの蒸留へ移すには「相性が低い event」の定義を作り直す必要がある。

## 試すべき実験
1. 手元の OPD (あれば) で、軌跡ごとの teacher-student の token レベル不一致率を記録し、長さに対してどこで急に悪化するかをヒストグラムにする (Flash-OPD の前提が自分の設定で成り立つかの確認)。
2. 固定長 rollout vs 累積 event カウントによる打ち切りを同じ予算で比較する小さな ablation。
3. 論文の event 定義 (本文で確認要) を自分のタスクの指標に差し替える。
