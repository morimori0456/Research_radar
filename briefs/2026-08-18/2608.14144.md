# S²VOPD: Self-Supervised Visual On-Policy Distillation

## 何を解決する論文か

**on-policy distillation (student 自身が生成した出力に対して teacher が評価を与える蒸留。固定データセット上で teacher の出力を真似る off-policy distillation と対になる)** は、**teacher が student より「多くを知っている」ことを前提に成り立つ。** その情報の差 —— 論文の言う **informative asymmetry** —— は、これまで 2 通りの方法でしか作られてこなかった: **より大きく強い teacher を用意するか、teacher にだけ privileged supervision (student には与えない特権情報。正解の答え、注目すべき領域の指定など) を渡すかである。**

**では、そのどちらも手に入らないときはどうするのか。** 強い teacher がない、正解アノテーションもない、報酬モデルもない —— 実務ではむしろこちらが普通である。

本論文の答えは **非対称性の作り方を反転させること**である。**teacher に情報を足すのではなく、student から情報を引く。** teacher には元の画像を見せ、student には**強く augment して劣化させた同じ画像**を見せて、teacher の分布を student に on-policy で蒸留する。**両者は同じモデルでよい。** それでも student 側だけが情報を欠いているので、**「student が持っていない情報を持つ teacher」と同じ学習信号が、追加コストゼロで発生する。**

## 手法の核心

- **非対称性の反転が唯一の中心アイデア。** teacher は original image を条件に、student は **strongly augmented view** を条件に、同じ入力ペアに対して分布を合わせる。**teacher と student のパラメータ差ではなく、入力の情報量差が学習信号の源になっている。** ground-truth annotation・reward・別途の強い teacher のいずれも不要。

- **知見 (1) 非対称性それ自体が効いている。** 試した **4 系統すべての augmentation で性能が向上**した。対して **symmetric self-distillation (teacher と student に同じ条件を与える自己蒸留) は性能を悪化させる。** つまり効いているのは augmentation による正則化ではなく、**非対称性そのもの**である。**この対照実験があることが本論文の価値の中心。**

- **知見 (2) 強度には最適点がある。** 性能は **moderate strength でピーク**を取る。弱すぎれば非対称性が足りず、強すぎれば壊れる。**単調ではない** —— つまり「とにかく強く壊せばよい」ではない。

- **知見 (3) 情報差は task-consistent でなければならない。** **question-relevant evidence (問いに答えるために必要な視覚的根拠) を完全に消してしまう augmentation は、大きな悪影響を招く。** 消してよいのは「あってもなくても答えが変わらない情報」だけで、**答えの根拠そのものを消すと、teacher の分布は student にとって到達不能な目標になる。** ここが強度に最適点が現れる理由でもある。

- **設計空間を体系的に走査したこと自体が成果。** 単一手法の提案ではなく、**augmentation の系統 × 強度**という 2 軸で網羅的に測っている。**recipe として輸入しやすい形になっている。**

> **注意: candidates.json 中の abstract は知見 (3) の途中 ("can induce large ") で切れており、末尾の定量結果・評価ベンチマーク・比較対象が読めない。** arXiv API も本日は応答がなかったため、**「どのタスクで、どの程度」の部分は未確認である。** 下の実験案は「機構が主張通りなら」という条件付きで書いている。**本文入手後に最初に確認すべきは、比較対象に「本物の強い teacher を使った通常の on-policy distillation」が含まれているか** —— これが無ければ、本手法は「teacher が無いときの代替」であって「teacher の代替」ではない。

## 追っているプロジェクトへの適用可能性

- **P2 / R2 —— 本命。「capacity gap」の定義そのものに疑いをかける 1 本。** R2 は **capacity gap (teacher と student の容量差が開くほど蒸留が破綻する現象) の系統則** を、**teacher/student の容量比を軸に**取りに行く計画だった。**本論文はこう言っている: 学習信号を決めているのは容量比ではなく、teacher と student が参照できる情報の差である。** 実際、容量比 1.0 (同一モデル) でも、入力側に差を作れば蒸留が成立する。**もし本当にそうなら、R2 の横軸は容量比ではなく「実効的な情報差」でなければならない。**

- **P2 —— 昨日の Alaya-EVOKE と合わせると、R2 の単一軸仮説は 2 日で 2 方向から攻撃されている。** 08-17 の [Alaya-EVOKE](../2026-08-17/2608.13546.md) は **「gap は teacher の監督 horizon で埋まる」** と主張した (時間方向の情報差)。本論文は **「gap は student の入力情報量で作れる」** と主張する (入力方向の情報差)。**両者は同じことを別の軸で言っている —— 支配変数は容量ではなく情報である。** **R2 の仮説を「容量比の系統則」のまま進めると、おそらく綺麗な法則は出ない。ここは早めに立て直したほうがよい。**

- **P2 —— 実務上の効果が大きい。** 蒸留を回すとき最大のコストは **「student より強い teacher を用意すること」**である。本手法が成り立つなら、**手元のモデル 1 つと augmentation だけで on-policy 蒸留のループが回る。** 少データ・アノテーション無しでのドメイン適合という、fm_distill_finetune の criteria 後半にもそのまま乗る。

- **P3 —— 運転の知覚モデルに直接移せる形をしている。** 入力が画像で、augmentation で情報を落とす、という構造は **カメラ入力の driving policy / perception にそのまま対応する。** 運転では「消してよい情報」と「消してはいけない情報」の区別が知見 (3) の意味で明確である —— **色調・天候・露出は消してよいが、前方車両そのものを隠したら答えの根拠が消える。** occlusion 系の augmentation は危険側、photometric 系は安全側、という予測が立つ。

- **P1 —— 直接の関係は薄い。** 評価指標の論文ではない。ただし後述の実験 3 は planner の頑健性評価に接続しうる。

- **留保:** (1) **視覚 VQA 系のタスクで検証されているように読めるが、切れた abstract からは対象タスクが確定できない。** (2) **「同一モデルで足りる」が成り立つ範囲が不明** —— student が既に強い場合、劣化入力から元の分布を復元するのは自明に近く、学習信号が枯れる可能性がある。(3) **回帰タスク (軌道予測など) に効くかは全く示されていない。** 分類・生成の分布合わせとは事情が違う。

### 試すべき実験

1. **symmetric vs asymmetric の対照を、手持ちの student で最小構成で再現する (最優先・1〜2 日)。** 同一モデルを teacher/student に置き、**(a) 同じ入力、(b) student 側のみ photometric augmentation** の 2 条件だけ回す。**本論文の主張が正しければ (a) は悪化し (b) は改善する。** 主張の中心はこの符号の違いに全部乗っているので、**ここが再現しなければ以降は不要。** 追加データもアノテーションも要らないのが利点。

2. **R2 の横軸を「容量比」から「情報差」に張り替えられるか検証する (R2 の設計に直結)。** 同一の student に対して、**(i) teacher の容量を変える、(ii) student の入力を augment 強度で劣化させる** の 2 系列で、**蒸留の効き方が同じ曲線に乗るかを見る。** **乗るなら、R2 は「情報差の系統則」という一段一般的な主張になり、論文としての強度が上がる。乗らないなら容量比は独立変数として生き残る。** どちらに転んでも R2 の骨格が決まるので、**これは仮説の分岐点として最も価値が高い。**

3. **運転ドメインでの「消してよい情報」の境界を測る。** 知見 (3) を運転で具体化する: **photometric (天候・露出・色調)、幾何 (crop・視野角)、occlusion (前方車両の遮蔽)** の 3 系統で強度を振り、**性能が向上から悪化へ反転する点を探す。** 反転点が「答えの根拠が消える点」と一致するなら、**これは augmentation 設計の指針としてそのまま使える** —— かつ、**P1 の頑健性評価 (どこまで情報が落ちたら planner が壊れるか) に読み替えられる。**

4. **回帰タスクへの拡張可否の確認 (優先度低・ただし外れれば早く分かる)。** 軌道予測 student で同じ非対称性を作る。**分布合わせが前提の手法なので、点推定の回帰では信号が弱い可能性が高い。** 期待値は低いが、確認コストも低い。**1〜3 を先に回すこと。**
