# OneStreamer: Unifying Perception, Memory, and Proactive Response in Streaming Video Interaction

- arXiv: `2610.01762` / https://arxiv.org/abs/2610.01762
- 配属: **sns_wildcard (探索枠 1/1)**。分野は streaming video LLM (動画を最後まで待たず、届いたフレームから順に理解・応答する LLM) で、運転ではない。
- スコア: 学びの価値 3.5 (転用先は P3 3.0 ・ P1 2.5) ・ hf_upvotes 164

## 何を解決する論文か

streaming video LLM は、「後で何を聞かれるか分からない段階」で、どの証拠を覚えておくかを決めなければならない。さらに、証拠がそろった時点で、聞かれる前に自分から応答する (proactive response) 必要もある。過去の映像の特徴をすべて持ち続けると重く、捨てると後の質問に答えられない。この論文は、モデル自身が時刻つきの caption (映像の内容を説明する短い文) を書き出して記憶にすることで、リアルタイムの知覚を落とさずに、再利用できる記憶を作る。

## 手法の核心

- **PHCM (Proactive Hierarchical Caption Memory):** 2 階層の caption を記憶として生成する。1 つは時刻つきの細部の caption、もう 1 つは「終わった出来事」の要約。推論時は、直近の映像の窓 (生の視覚特徴) と、モデルが書いた caption の記録を組み合わせて入力する。過去の視覚特徴を読み直す必要はない。
- **学習の監督:** 動画の途中までの区間 (prefix) ごとに、「ここまでで何が起きたか」の caption を正解として与える。これで、映像を見ながら記録を書く能力を学習する。
- **PSTL (Proactive State Transition Learning):** streaming の出力は、ほとんどの時刻で「まだ待つ」という同じ状態が続く。全部を監督すると、モデルがこの待機の状態ばかり学んでしまう。そこで、状態が変わる token (待機 → 応答など) と、状態が続く token の中から代表的なものを選んで監督する。**注釈のある状態 token のうち 27.5% だけを監督して、すべてを監督した場合 (dense supervision) を上回った**。
- **データ:** 出力の内容とタイミングを、その時点で手に入る証拠に合わせる合成パイプラインで、100 万件超の OneStreamer-1M を作った。4B のモデルで、8 つの streaming video ベンチマークのすべてで比較手法の中の最高。ablation (要素を 1 つずつ外して効果を測る実験) では、生成した caption を残すと、リアルタイムの知覚を落とさずに、過去についての QA が改善した。

## プロジェクトへの適用可能性 (探索枠として選んだ理由)

- **P3: 今日の AD-Memo と同じ答えに、別の分野から来た 2 本目。**AD-Memo (運転 VLA) も OneStreamer (動画 LLM) も、「過去の画像を持ち続ける代わりに、モデル自身が書いた文章を記憶にする」。2 つの分野が独立に同じ設計に着いたこと自体が、P3 で「時系列をどう持つか」を決める材料になる。OneStreamer は、AD-Memo に無い **2 階層 (細部の記録と、終わった出来事の要約)** を持つ。長い走行で記憶が伸び続ける問題への 1 つの答え。
- **P1/P3: PSTL の「状態が変わる時刻を重点的に監督する」は、運転の学習データの偏りにそのまま当てはまる。**運転のログのほとんどは「車線を維持して等速」で、学習すべき判断 (減速の開始、車線変更の開始、発進) はまれ。PSTL は、全部を同じ重みで学習するより、変化点と代表的な継続区間だけを選ぶ方が良いことを、27.5% の監督で示した。P1 の評価でも、「判断が切り替わる時刻」の指標を別に集計する考え方につながる。
- **限界:** 評価は動画の理解と QA だけで、行動 (制御) の出力は無い。caption を書くための追加の生成は遅延を生むが、その数値は abstract に無い。

## 試すべき実験アイデア

1. **(手元のログ、集計のみ) 状態の変化点の割合を数える:** 走行ログを、縦方向 (加速 / 等速 / 減速) と横方向 (維持 / 車線変更) の状態の列にする。「状態が変わる時刻」が全時刻の何 % かを数える。数 % 以下なら、PSTL 型の再重み付けを試す価値が高い。
2. **(2D toy、CPU で数分) 変化点の監督の比較:** 1D の追従走行 (前の車に合わせて加減速する) のシミュレーションで、行動の分類器を 3 通りに学習する: (a) 全時刻を同じ重みで学習、(b) 変化点の前後 ±k ステップと、継続区間からの一様サンプル (合計で全体の約 30%) だけで学習、(c) (b) で継続区間のサンプルを 0 にしたもの。「減速を始める時刻の誤差」と「等速区間での誤った減速の率」を比べる。(b) と (a) の差が PSTL の主張の再現、(c) の悪化が「継続区間も少しは残す」ことの必要性の確認になる。
3. **(P3 の設計検討) 記憶の token 予算の見積もり:** 自社の VLA 構想の入力で、「画像 N フレーム分の token 数」と「同じ区間を caption で書いた場合の token 数」を並べた表を 1 枚作る。AD-Memo と OneStreamer の方式で、どれだけの長さの過去を同じ予算で持てるかが分かる。
