# Vision-Language-Action Autonomous Driving Agent with Language-based Memory (AD-Memo)

## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語を入力に、行動 (運転なら軌跡) を出力する基盤モデル) は、画像 1 枚あたりの token 数が多いので、入力できるのは直近の数フレームだけになる。そのため、全方向一時停止 (all-way stop; 4 方向とも一時停止の交差点で、到着した順に発進する規則) の到着順のように「数秒〜数十秒前に見たこと」を覚えていないと解けない場面で失敗する。既存の対策は latent vector の記憶を cross-attention で読む方式だが、中身が読めず、別のモデルに持ち運べない。この論文は、記憶を **言語で書き出し、次の入力に戻す** ことで、この 2 つを解決する。

## 手法の核心

- **記憶 = CoT の延長:** モデルは CoT (Chain-of-Thought; 答えの前に推論の過程を文章で書き出す出力形式) の続きとして、運転に重要な周囲の物体の記録 (例: どの車がいつ停止線に着いたか) を文章で出力する。その文章を、次の時刻の入力の一部として戻す。記憶の読み書きに専用の module は無く、モデルの出力 token そのものが記憶になる。
- **データ:** 記憶が要る場面 (all-way stop など) のデータセットを作り、記憶のテキストの教師も用意した (作り方の詳細は本文で確認が要る)。
- **2 段の学習:** SFT (Supervised Fine-Tuning; 正解の出力を真似させる通常の fine-tuning) の後に、**Da Capo** と名付けた semi-closed-loop の RL (強化学習) を回す。abstract から読める範囲では、モデル自身が書いた記憶を次の時刻に戻して複数ステップを回す、という意味で「閉ループ」に近い。シーン自体は記録の再生 (他車は反応しない) と推測するが、本文で確認が要る。
- **credit assignment (報酬の良し悪しを、どの出力のおかげかに割り振ること) を 2 つに分ける:** 記憶の出力には軌跡単位の advantage (その出力がどれだけ平均より良かったかの推定) を、運転の出力にはステップ単位の advantage を使う。記憶の良し悪しは、何ステップも後にしか結果に現れないため。
- **結果 (abstract 記載):** all-way stop と一般の運転で、運転の質が上がった。運転シーンの QA の正答率も上がった。書き出した記憶を、**別のモデルの入力にそのまま挿しても効く (plug-and-play)**。数値は abstract に無い。

## プロジェクトへの適用可能性

- **P3 (高):** 「VLA に何フレーム見せるか」は、token の予算と記憶の長さのトレードオフになる。AD-Memo は第 3 の軸として、「過去のフレームを捨て、要点だけを文章で残す」を示した。E2E (end-to-end; センサ入力から軌跡まで 1 つのモデルで出す) の設計で、時系列の扱いを検討するときの比較対象になる。とくに、記憶が読める (人が検査・修正できる) ことと、別のモデルに移せることは、latent memory には無い性質。
- **P3: 記憶と行動で advantage の粒度を変える設計は、記憶に限らず使える。**「すぐ結果が出る出力」と「後で効く出力」が混ざるモデル (例: 意図の宣言と軌跡を両方出す VLA) を RL で後学習するとき、同じ考え方を当てはめられる。
- **P1 (補助):** 評価の観点で見ると、「記憶が要る場面」は、普通の open-loop の指標 (記録された軌跡との誤差) では差が出にくい。all-way stop のような場面を独立したシナリオ群として切り出して評価する、という作り方は、P1 のベンチマーク設計の参考になる。
- **限界:** 文章の記憶は、何を書くかを学習データが決める。データで想定していない種類の情報 (例: 遮蔽された歩行者の予想位置) は書かれない。推論のたびに記憶の token を生成するので、遅延も増える。これらの数値は abstract に無いので、本文の確認が要る。

## 試すべき実験アイデア

1. **(手元のログ、集計のみ) 記憶が要る場面の割合を数える:** 自社の走行ログで、「正しい行動が、直近 K フレーム (VLA の入力に入る長さ。例: 2 秒) より前の出来事に依存する」場面を、規則で拾って数える。対象は、全方向一時停止、遮蔽前に見えていた歩行者、合流の順番待ちなど。割合が 1% 未満なら P3 で記憶の設計を優先する理由は弱く、10% を超えるなら強い。学習を一切回さずに、設計の優先度を決められる。
2. **(2D toy、CPU で数分) 窓の長さと記憶の比較:** 4 方向から車が来る all-way stop の格子のシミュレーションを作る。方策は 3 種類にする: (a) 直近 K ステップの状態だけを見る MLP、(b) (a) に「到着順のリスト」を記憶として足したもの、(c) GRU (過去を latent で持つ RNN)。K を変えながら発進順の正解率を測り、(a) が破綻する K と、(b) と (c) の差を見る。さらに (b) の記憶を (c) の入力に挿して効くか (plug-and-play の再現) も試す。
3. **(RL を回している場合) advantage の粒度の比較:** 2 の toy で、記憶の出力もステップ単位の advantage で学習した版と、軌跡単位にした版を比べる。記憶の書き込みが「何ステップも後にしか効かない」状況で、Da Capo の分け方がどれだけ学習を速めるかの感触が得られる。
