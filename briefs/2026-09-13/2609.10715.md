## 何を解決する論文か

言語モデルの事前学習は、ほぼ例外なく **NTP (next-token prediction; 次の 1 トークンを当てる学習)** だけで行われる。NTP の問題は**予測の粒度が細かすぎること**にある —— 1 トークン先しか見ない目標は、「この段落で何を言うつもりか」に相当する、複数トークンにまたがる構造を明示的に学習させない。

NCP-ArchPreview は NTP を捨てずに、**その上に「概念」の予測を 1 段重ねる。**概念とは複数トークンにまたがる離散的な単位で、**モデル自身の hidden state から作った語彙**として定義される。これを当てる目標を **NCP (Next Concept Prediction)** と呼び、NTP と同時に学習する。結果として、**OLMo-3-7B (Allen AI の公開 LLM。学習データとレシピが全部公開されているため比較の基準に使いやすい) と同じ最終 pretraining loss に、学習トークンの 51.3% で到達した。**

## 手法の核心

- **概念の語彙は、外から持ち込まずモデル自身の hidden state から作る。**具体的には **product quantization (PQ; ベクトルを複数の小区間に分割し、各区間を別々の小さな codebook で離散化する量子化手法。区間ごとの組み合わせで、小さな codebook から巨大な語彙を作れる)** を hidden state に掛け、離散的な concept vocabulary を得る。**別の encoder も外部の tokenizer も要らない** —— ここが「latent space language model」と名乗る根拠。
- **専用の Concept Module が未来の概念を予測する。**予測の対象は次のトークンではなく、次に来る概念。
- **予測した概念を、トークン側に戻して以降の生成を誘導する。**上の層が「何を言うか」を粗く決め、下の層がトークンを出す、という 2 段構成になる。**NTP と NCP は end-to-end で同時に学習する** (概念の層を先に凍結してから言語モデルを載せる、という段階構成ではない)。
- **標準の token-level autoregressive generation はそのまま保たれる。**推論の形を変えない設計で、概念の層は学習時と生成の誘導に効く追加物として入る。
- **規模: 8.9B パラメータ / 5.73T トークン (Dolma-3、OLMo の公開事前学習コーパス)。**著者はこれを latent-space LM の最大規模の実証と位置づけている。
- **数字:** OLMo-3-7B の最終 pretraining loss に **51.3% のトークンで到達**。フル学習後は下流タスクの macro-average (タスクごとのスコアを単純平均した値) で **+2.45 点**、**GSM8K (小学校レベルの算数の文章題ベンチマーク。多段の推論が要る) で +5.99 点。**計算量を標準の 85% に抑えても、パラメータ数を揃えた 8.9B の baseline の loss に迫る。
- **利得の出所を切り分けている。**controlled experiment で、**「latent architecture そのもの」と「NCP という目標」の 2 つが別々に効いている**ことを示した。片方だけでは説明できない、という主張。

## 追っているプロジェクトへの適用可能性

### P3 — 「抽象の層を 1 枚挟む」系譜の、言語側からの強い実測

**この論文の賭けは、world model の賭けと同じ形をしている:「生の観測を 1 ステップ先まで当てる」のをやめ、抽象的な空間で、もっと先を当てる。**JEPA 系 (観測をそのまま再構成せず、潜在表現の側で予測する設計) の主張と構造的に同一で、違いは 2 点だけ:

1. **抽象空間を、自分の hidden state から PQ で作る。**別途 encoder を学習しない。
2. **抽象の層は NTP を置き換えず、補助として並走する。**推論時の生成の形は変わらない。

**P3 にとって重要なのは 2 つ目である。**運転の policy でも「行動を 1 ステップずつ出す head」を捨てるのは怖い (制御周期・安全層・既存の評価が全部そこに乗っている)。**この論文は「粗い層を足すが、細かい層は温存する」構成で、置き換えではなく追加として利得が出ることを 8.9B 規模で示した。**VLA の action chunk (複数ステップ分の行動をまとめて 1 回で出す、VLA で一般的な出力単位) は既に「複数ステップを 1 単位で扱う」設計だが、**chunk は出力の形式であって、学習目標として「次の chunk の抽象コードを当てる」形にはなっていない。**そこが空いている。

**09-11・09-12 の 3 本と並べると軸がはっきりする。**いずれも「生成モデルの上に明示的な抽象の層を置く」話で、**その層をどこから調達するかで分かれている:**

| 論文 | 抽象の層の正体 | 調達方法 |
|---|---|---|
| [Programmable World Model](../2026-09-11/2609.10540.md) | entity state と遷移規則 | **人が書く** (プログラム。学習は入らない) |
| [IMLE-VLA](../2026-09-12/2609.10915.md) | (層を足さず) 1 step の生成目標 | —— |
| **NCP-ArchPreview** | 複数トークンにまたがる離散概念 | **モデル自身の hidden state から PQ で学習** |

**PWM は「決定的に書けるものは書け」、本論文は「書かずに自分の内部状態から取れ」。**運転では両方に材料がある (交通規則は書ける / 他車の意図は書きにくい) ので、**どちらを選ぶかではなく「どこまでを書き、どこからを学習された離散コードに任せるか」が設計問題になる。**

### 試すべき実験アイデア — 事前学習を 1 回も回さずに、前提が成り立つかを確かめる

**この手法には、成立の前提が 1 つある: hidden state を離散化したコードが、複数ステップにまたがって持続し、かつ数ステップ先まで予測可能であること。**これが偽なら NCP の目標には学ぶものが無い。**前提の検査は学習なしでできる。**

1. **手元の軌跡予測モデルか driving policy を 1 つ選び、中間層の hidden state を全フレーム分吐き出す** (数千フレームで足りる)。
2. **PQ (または簡易に k-means) を掛けて離散コードを振る。**codebook は小さく (例: 4 区間 × 256) 始める。
3. **「1 つのコードが何フレーム続くか」の分布を出す。**フレームごとに切り替わるなら、そこに concept-level の構造は無い —— **この時点で NO が出る。**
4. **NO でなければ、h フレーム先のコードの予測精度を h = 1, 5, 10 で測り、コードの出現頻度から決まる chance level と比べる。**先まで当たるなら、抽象の層を足す余地がある。

> **判定は YES/NO で出て、学習は 1 回も要らない。**3 で切り替わりが速すぎる、という結果も収穫である (「運転の hidden state には言語の概念に当たる持続構造が無い」という negative result になる)。

### P2 — concept-level distillation という未使用の軸 (3.0)

蒸留の論点ではない論文だが、**一点だけ持ち帰れる:**PQ で作った概念コードは、**teacher と student の間で照合する単位の候補**になる。09-11 の [OnPoKD](../2026-09-11/2609.10321.md) と 09-12 の [per-token gating](../2026-09-12/2609.11768.md) は、どちらも**トークン単位**で教師信号の中身や距離の測り方を変える設計だった。**概念単位で照合すれば、目標は粗くなる代わりに分散が下がる。**ただし本論文は蒸留を一切やっていないので、これは着想であって裏付けではない。
