## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語から行動を出す model) は分布シフト (学習時と違う条件) で脆く、想定外の失敗が機器や人を傷つけうる。実運用には、早く検出でき、確率が較正されていて (calibrated; 警報の確率が実頻度と合う)、失敗の中身も分かり、edge 端末で動く軽さの runtime monitor が要る。既存手法はこの 4 点を満たせない、というのが問題設定である。

## 手法の核心

- **VLA-Tug**: VLA backbone の latent (中間層の表現) の上に載せる軽量な probe (小さい分類器)。推論の追加コストは最小。
- 失敗の**直前の区間**で supervision すると、同じ false positive 率での早期検出が最強の learned baseline より最大 30% 良い。
- missed-detection (見逃し) 率と false-alarm (誤警報) 率に bound (上限の保証) を付ける。未知 task へ shift しても、bound が成り立つ割合は最大 86% の run (baseline は最大 21%)。保証の作り方 (conformal prediction 系かなど) は abstract からは分からない。
- 失敗の**種類**も予測する。未知 task での top-3 accuracy が majority baseline より最大 44% 良い。
- 時機の良い probe の出力を使って軽い steering (行動の修正) をすると task 成功率が上がる。3,180 episode の annotation 付き manipulation dataset を公開。

## 適用可能性 (P3 / 副次的に P1)

- P3: 次世代アーキテクチャを車載に載せるとき、**backbone を変えずに後付けで safety monitor を足す**設計の参考になる。latent を読むだけなので推論コストが小さい。
- P1: 評価の観点では、「失敗が起きる前の区間」と「失敗の種類」を離散化して測る考え方が、planner の閉ループ評価で failure を分類する設計に近い。
- 注意: manipulation 限定。運転では失敗が稀で、失敗の定義 (衝突、逸脱、急制動) を先に決める必要がある。

## 試すべき実験アイデア

1. 手元の E2E planner の中間層に線形 probe を載せ、「n 秒以内に衝突・route 逸脱が起きるか」を予測させる。検出の早さと false positive 率を測る (最小の実験)。
2. 失敗の直前区間だけで supervision する場合と、episode 全体にラベルを付ける場合を比べる。
3. 学習に使わなかった地図・天候・都市で、保証 (見逃し率の上限) が成り立つ割合を測り、shift への頑健さを確認する。

## 注意

abstract のみに基づく。probe の構造、保証の算出法、対象の VLA backbone は未確認。
