# Model-Aware Generation of Safety-Critical Scenes for Robust End-to-End Driving via Distilled Planner Surrogates (2610.35448)

- トピック: fm_distill_finetune として届いたが、内容は P1 (planner の評価と改善) なので planner_ai の quota で採用 / スコア 4.5
- URL: https://arxiv.org/abs/2610.35448

## 何を解決する論文か

end-to-end driving model (カメラ画像から軌道まで 1 つの network で出す運転 model) は標準 benchmark では良いのに、衝突しやすい危険場面になると急に弱い。著者らは NeuroNCAP (closed-loop の衝突回避評価 benchmark) で DiffusionDrive の衝突の 95.9% が「検出はできているのに planning が避けられない」型だと切り分け、原因を、実走行 log に危険な交差場面がほとんど無く planner が学ぶ機会が無いデータ不足だと見る。そこで、特定の planner を狙い撃ちにした危険場面を自動生成し、その場面で fine-tuning する。

## 手法の核心

- **model-aware な attack**: 危険場面を、汎用ではなく特定の planner の弱点に合わせて作る。planner ごとに 50 scene を抽出する。
- **distilled planner surrogate (蒸留した代理 model)**: 攻撃は BEV (Bird's-Eye View; 真上から見た地図表現) の上で行い、planner の planning head から蒸留した微分可能な代理 model を相手にする。重い video renderer を攻撃の loop から外せるのが要点。
- **escape trajectory (安全な回避軌道) をラベルにする**: 各 scene は「攻撃 + 安全に逃げる軌道」の組で、これが fine-tuning のラベルになる。
- **quality-diversity search (品質と多様性を同時に探す探索)** で攻撃と回避の両方を自動生成し、バリエーションを人手で指定しない。
- 画像の rendering は選んだ scene だけに行うので、fine-tuning のコストが小さい。
- 結果は NeuroNCAP の closed-loop 衝突率が SparseDrive 28.0% → 12.2%、DiffusionDrive 37.5% → 19.2% (ほぼ半減) で、通常走行はおおむね維持。cross-planner transfer (他の planner 用に作った scene で fine-tuning) では効果が小さく、DiffusionDrive は SparseDrive 用 scene で衝突率の低下が 18.3 点のうち 6.7 点しか残らない = 効果は「その planner 専用」であることの証拠。

## P1 / P2 への適用可能性

- P1: 「衝突の 95.9% は planning failure」という切り分けは、評価の枠組みとしてそのまま使える。失敗を perception 側か planning 側かに分けて数えるだけで、改善の投資先が決まる。
- P1: planner ごとに専用の危険場面を作る、という考え方は、評価 (弱点の発見) と学習 (弱点の修正) を同じ道具でつなぐ。自前 planner の評価 set を「汎用の危険場面」だけにすると、その planner の本当の弱点を外す、という含意もある。
- P2: 重い model の挙動を、軽い蒸留 model で代理して探索を速くする使い方。蒸留を「小さくして配備する」目的以外 (探索の高速化) に使う例として読める。
- 未確認点: 代理 model が元の planner と食い違う程度 (攻撃が代理 model にだけ効いて本体に効かない割合) と、50 scene で足りる理由は abstract に無い。NeuroNCAP は評価と学習の scene が近い可能性があるので、別 benchmark での汎化は本文で確認が要る。

## 試すべき実験アイデア

1. 手元の planner の closed-loop 失敗を「検出はできている衝突」と「検出できていない衝突」に分けて数える。planning 側が支配的なら、この論文の道筋が当てはまる。
2. planner の出力 head から小さい代理 model を蒸留し、BEV 上で勾配を使って衝突しやすい他車の動きを探す最小版を作る。代理 model と本体で衝突率の相関を測れば、代理が使えるかが先に分かる。
3. 自前の planner A と別の planner B で、A 用の scene による fine-tuning が B にどこまで効くか (cross-planner の 18.3 → 6.7 の再現) を測る。評価 set の作り方に関わる。

## 注意

abstract のみに基づく。代理 model の蒸留 loss、quality-diversity search の具体的な手法 (MAP-Elites 系かは未確認)、通常走行の劣化の定量値は未確認。
