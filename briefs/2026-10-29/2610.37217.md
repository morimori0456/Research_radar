# KEPT: Conformal Keepouts Kept in Planning for Enclosed-Space Navigation in Degraded Sensing (2610.37217)

- トピック: planner_ai (P1) / スコア 4.0
- URL: https://arxiv.org/abs/2610.37217

## 何を解決する論文か

トンネルや鉱山のような閉空間を走る車両は、range map (距離センサーで作る周囲の地図) を頼りに壁から離れる。ところが煙・粉塵・霧で map の精度が落ちる。conformal prediction (予測の外れ率を分布仮定なしで保証する統計手法) で壁の周りに keepout (入ってはいけない領域) を作れば、「本当に危険な領域を確率 1-α で覆う」ことは保証できる。しかし planner はこの keepout をただ膨らませた障害物として扱うので、狭い通路では余白が通路を塞いで進めなくなる。さらに、センサー劣化が進んだときに keepout の手前で止まれる保証もない。従来は coverage level (覆う確率) を下げて通路を空けていたが、それは安全の保証を削ることになる。

## 手法の核心

- **severity-conditioned conformal margin**: 劣化の度合いをラベル無しで推定し (severity estimate)、その値に応じて conformal の余白を変える。劣化が変わっても coverage を目標付近に保つ。
- **braking-distance condition (制動距離の条件)**: 計画時と、毎回の指令の両方で「keepout の手前で止まれるか」を 1 つの条件として課す。
- この条件の余白には **実測した tracking residual (計画軌道と実際の軌道のずれ)** だけを使い、keepout 自体は書き換えない。安全の保証 (coverage) と到達性 (planner の余白) を分けて持つ設計。
- 検証は地上ロボットの煙中の recording (keepout の coverage) と、霧のトンネルでの quadrotor の closed-loop simulation (planner 込みの挙動) の 2 段。
- 結果: keepout への進入が大きく減り、到達した goal 数も標準構成より多い (pooled で +3.2 点)。ただし calibration regime ごとの信頼区間は 0 を含む。per-class keepout は held-out recording で coverage を目標付近に保つ。

## P1 への適用可能性

- 運転 planner の「perception の不確かさを、安全余白としてどう planner に渡すか」にそのまま対応する。evaluation 側でも、coverage を保ったまま到達性 (route が閉じない) を測る、という 2 軸の見方は使える。
- 「不確かさの推定 → 余白 → planner」の 3 層を分け、保証の対象 (coverage) と調整の対象 (tracking residual) を別にする設計は、運転の occupancy / 物体検出の不確かさにも移せる。
- 注意点: 対象は低速の閉空間ナビで、運転 (高速・多数の動く物体) とは動力学が違う。また到達率の改善は信頼区間が 0 を含み、統計的には有意と言えない。主張の中心は coverage の維持と進入の減少で、そちらを見るべき。

## 試すべき実験アイデア

1. 手元の perception 出力 (例: 物体位置の不確かさ) に対し、天候・照明などの劣化の指標を 1 つ決め、その指標で層別して conformal 余白を較正する。coverage が劣化度ごとに目標値に収まるかを held-out log で測る (planner 無しの最小版)。
2. 既存 planner の余白を「固定の膨張」から「severity-conditioned な余白」に差し替え、closed-loop simulation で「余白に入った回数」と「goal 到達率」を並べて見る。
3. braking-distance condition を planner の出力に対する単純な後段 filter として実装し、tracking residual の実測値だけで余白を決めたとき、急ブレーキの頻度がどう変わるかを比べる。

## 注意

abstract のみに基づく。severity estimate の具体的な作り方、比較した標準構成 (deployment pattern) の詳細、進入削減の数値は未確認。
