# Full-Weight VLA Fine-Tuning Without an fp32 Master Copy Silently Erases Most Updates (2610.31859)

- トピック: fm_distill_finetune (P2) / スコア 4.5 / 出所: RSS (cs.RO の new、candidates.json には無し)
- URL: https://arxiv.org/abs/2610.31859

## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語の入力からロボットの行動を出す model) を、学習対象の weight を bf16 (bfloat16; 16 bit の浮動小数点で、仮数部が短い) のまま、fp32 の master copy (更新を貯める 32 bit の重みの複製) 無しで fine-tuning すると、AdamW (Adam に weight decay を分離して足した標準 optimizer) の更新が bf16 に直接書き込まれる。weight の 1/512 より小さい更新は丸めで消えてしまう。この論文は、その消失が実際の公開 recipe で広く起きていて、成功率を大きく下げることを示す。

## 手法の核心 (新手法ではなく、測定と修正の提案)

- **原因の特定**: bf16 のまま更新を書くと、weight の 1/512 未満の更新は丸めで 0 になる。fine-tuning の後半や小さい learning rate では更新が小さいので、消える割合が大きい。
- **広がりの調査**: 12 の open VLA codebase のうち 9 で、default か文書化された recipe がこの学習方法になっている。そのうち 4 は weight 行列全体を bf16 で学習する (LeRobot の SmolVLA default と、π0 / π0.5 の guide を含む)。Hugging Face Hub のサンプルでは、full-weight の SmolVLA fine-tune の 99% が action expert を bf16 で保存している。
- **消失率の実測**: LIBERO (ロボット操作の simulation benchmark) の実行で、master copy 無しだと 100 step ごとの probe で bf16 weight への更新の 79% 以上が消えていた。
- **効果**: LIBERO-Object で、fp32 copy を付けると成功率が SmolVLA で 4.3% → 49.3%、π0.5 で 5.1% → 80.9% (learning rate を 1/10 にして、両 model がまだ学習不足の条件)。π0.5 の default の learning rate でも 89.0% → 97.7%。SmolVLA の default の learning rate では、50 action を open-loop で実行する設定で +10.2 点、10 action ごとに re-plan する設定では +4.2 点。
- **修正**: 学習対象の weight を fp32 で持つ。LeRobot の SmolVLA では 1 行の変更。

## P2 への適用可能性

- P2 は fine-tuning を「他機種・他ドメインへの適合」として使うので、**手元の fine-tuning script が同じ状態でないか**を確認する価値が最も高い。新しい手法を足す前に、適合の結果が「手法が効かない」のか「更新が消えているだけ」なのかを切り分ける材料になる。
- 小さい learning rate で少データの適合をするほど更新が小さくなり、消失の影響が大きくなる。P2 の想定 (少データ適合) と条件が重なる。
- 蒸留でも、student を bf16 で学習して更新が消えるなら student が teacher に近づけない原因になりうる。これは abstract にはない推測で、確認が要る。

## 試すべき実験アイデア

1. 手元の fine-tuning / 蒸留 script で、学習対象の param の dtype を一覧にする (`p.dtype for p in model.parameters() if p.requires_grad`)。bf16 で optimizer に渡っているものがあるか確かめる。
2. 論文と同じ probe を入れる: 100 step ごとに「更新前後で bf16 値が変わらなかった要素の割合」を数える。割合が 50% を超えたら、fp32 copy を足して同じ設定で比較する。
3. LoRA (Low-Rank Adaptation; 小さな低ランク行列だけを学習する PEFT 手法) の adapter を bf16 で持つ場合にも、同じ消失が起きるかを測る (論文は full-weight が対象で、LoRA は未検証。これは仮説)。
4. fp32 copy で増えるメモリ量を、Jetson Thor 上の学習設定で実測する (abstract にコストの記述は無い)。

## 注意

abstract のみに基づく。「消える割合」は更新の大きさの分布に依存し、optimizer state の dtype や mixed precision の設定によって変わる。論文の評価は LIBERO の操作 task で、運転や蒸留での効果は未検証。
