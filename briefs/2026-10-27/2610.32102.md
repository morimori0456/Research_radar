# Coupling Execution Horizon and Sampling Depth in Flow-Matching VLA Policies (2610.32102)

- トピック: next_arch (P3) / スコア 4.0 / 出所: RSS (cs.RO の new、candidates.json には無し)
- URL: https://arxiv.org/abs/2610.32102
- プロジェクトページ: https://jiabingyang01.github.io/Horizon-Depth-VLA/

## 何を解決する論文か

flow-matching VLA (Vision-Language-Action; 画像と言語から行動を出す model のうち、行動を flow matching という連続的な生成手法で出すもの) は表現力の高い軌道を生成できるが、反応の速さと実行の安定の両立が難しい。通常、numerical solver depth (行動を生成する積分の step 数) と execution horizon (1 回の予測を何 step 分そのまま実行し続けるか) は別々に選ばれる。この論文は、2 つが実は結び付いていて、組合せによって効果の向きが逆になることを示す。

## 手法の核心 (新 model ではなく deployment 上の発見)

- **符号の反転**: 粗い数値積分 (step 数を減らす) は、頻繁に re-plan する設定では精度を下げるが、長い open-loop 実行 (予測を再計算せずに続ける) では task 性能をむしろ大きく上げる。
- **理由の幾何的な説明**: 数値積分を打ち切ると、不変な軌道の重心の周りの横方向の action の分散が縮む。これが implicit regularizer (暗黙の正則化) として働き、open-loop 実行中に誤差が積み上がる drift を抑える。
- **training-free**: 再学習も architecture の変更も要らない。LIBERO、RoboTwin 2.0 (ロボット操作の simulation benchmark)、実機の Franka での操作で、π0、π0.5、GR00T を含む代表的な VLA backbone で一貫して成功率が上がり、推論 latency も大きく下がると報告している。
- 位置付け: solver の step 数を「固定の精度予算」でなく、deployment 時に調整する variance regulator (ばらつきの調整つまみ) として扱う。

## P3 への適用可能性

- P3 が狙う end-to-end / VLA 型の運転 model が、trajectory を diffusion や flow matching で出す構成なら、**step 数と re-plan 間隔の組合せを同時に振る**だけで latency と安定性が改善する可能性がある。再学習が要らないので試しやすい。
- 運転は通常 10 Hz 前後で re-plan するので、論文の言う「頻繁な re-plan」の側に入る可能性が高い。その場合、効果が逆向き (step 数を減らすと精度が落ちる) になる可能性もある。どちら側に入るかを測ること自体が実験になる。
- 論文の評価は操作 task で、運転での再現は未確認。

## 試すべき実験アイデア

1. 手元に flow matching / diffusion で軌道を出す policy (または公開 VLA) があれば、execution horizon H と solver step 数 K の格子 (例: H ∈ {1, 4, 8, 16}、K ∈ {1, 2, 5, 10}) で成功率と latency を測り、論文の符号反転が再現するか見る。
2. 運転 simulation で同じ格子を回し、運転が「頻繁な re-plan」側に入るかを確認する (入るなら K を減らす利点が無い)。
3. open-loop 区間での横方向の分散を、K ごとに可視化する (論文の幾何的な説明の確認)。

abstract のみに基づく。成功率の改善幅、solver の種類 (Euler か高次か)、latency の具体値は未確認。評価は操作 task のみ。
