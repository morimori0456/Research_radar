## 何を解決する論文か

映像生成モデルが、生成したフレームを通じて一種の zero-shot な視覚的推論を見せる、という報告が相次いでいる。だがそれを**信用してよいのかを測る方法が無い。**著者は評価ベンチマークが満たすべき条件を 3 つ挙げる — (1) 入力が現行の映像モデルの visual prior (モデルが学習を通じて持っている「映像とはこういうものだ」という事前の偏り) と噛み合っていること、(2) **最終フレームがもっともらしいかだけでなく、そこに至る過程が妥当であることを要求すること**、(3) 難易度が「難しすぎず、しかし解けてしまうほど易しくない」範囲に較正されていること。この 3 条件で 27 タスク・810 事例を組んだのが VGI-Bench で、**最強の Seedance 2.0 でも 51.0% に留まる。**

## 手法の核心

- **2 階層の taxonomy (分類体系) でタスクを整理する** — task domain (何についての問題か) と skill tag (どの能力を要求するか) を直交させ、どの能力が欠けているかを細粒度で読めるようにしている。総合スコア 1 つで丸めない設計。
- **「過程の妥当性」を採点対象に入れた点が本質。**最終状態だけを見る評価では、**途中を飛ばして正解の絵に着地したモデルが満点を取れてしまう。**推論の媒体として映像生成を使う以上、過程こそが推論そのものだ、という立場。
- **難易度の較正を明示的な設計要件として扱う。**全モデルが 0% または 100% を取るタスクは、モデル間の差を何も語らない。partly feasible (一部は解けるが完全ではない) の帯に収めることで、ベンチマークの寿命を確保している。
- **失敗の分析が 4 方向に分かれている** — 出力側の failure mode、入力条件への感度、synthetic な fine-tuning がどこまで転移するかの境界、そして denoising 過程の内部観察。
- **最も重い発見は最後の 1 つ:** denoising の後段ステップは**初期に立てた仮説を精緻化しているだけで、推論の誤りを訂正していない。**self-correction (生成の途中で自らの誤りに気づいて直す働き) が事実上ほとんど無い、という機序レベルの主張。

## P1 / P2 / P3 への適用可能性

**P3 (R3: VLA × world model 統合アーキテクチャ) にとって、self-correction の欠如は設計上の制約として効く。**映像生成モデルを world model として planner の内側に置く構成では、rollout (モデルに先の状態を順に生成させること) を長く回すほど誤差が積み上がる。**もし後段ステップが初期仮説を精緻化するだけなら、途中で経路がおかしくなっても最後まで「もっともらしく」おかしいまま進む。**これは「long-horizon の rollout を planner が信用してよいか」という R3 の中心的な問いに直接の否定材料を与える。08-29 の PAWBench が **分布 vs 1 本** という軸を立てたのに対し、**本論文は 過程 vs 終点、および 自己訂正の有無 という 2 本目・3 本目の軸を足す。**R3 の分類マップの列がこれで 3 本になった。

**P1 (R1: 過保守も含めた保証付き評価) には、指標の形として移せる。**「終点は正しいが過程が妥当でない」という失敗は、trajectory prediction にそのまま存在する — **最終位置の誤差 (ADE/FDE) は小さいのに、途中の経路が車両の運動学的に成立していない予測は珍しくない。**VGI-Bench の (2) をそのまま持ち込むと、R1 の指標に「過程の妥当性」の列が 1 つ増える。難易度較正の議論も、評価シーンの選び方の根拠として使える。

**P2 への寄与は薄い。**synthetic fine-tuning の転移境界の分析はドメイン適合の観点で読めなくはないが、映像生成に固有の話で、蒸留の recipe には落ちない。

### 試すべき実験アイデア

1. **【最優先・R3 の可否を分ける】手持ちの world model 候補に self-correction テストを当てる。**rollout の途中に**意図的に誤った状態を注入し**、以降のステップがそれを訂正するか、それとも誤りを前提に「もっともらしく」続けるかを見る。**訂正が起きないなら、その world model を閉ループの planner に入れる構成は成立しない** — R3 で world model を別立てにする論拠か、あるいは短い horizon に限る制約か、どちらかが確定する。**半日で判定できる形にできる。**
2. **【R1・ICRA 図の候補】trajectory prediction の評価に「過程の妥当性」列を足す。**既存の予測器の出力に対し、終点誤差とは独立に**中間状態の運動学的成立性 (曲率・加速度が車両の限界内か) を採点する。**終点誤差は小さいが過程が破綻している予測の割合を出せれば、**「既存指標が見落としている失敗の型」として第一図に載る。**08-29 に立てた mode coverage の実験と同じログで走るので、追加コストが小さい。
3. **PAWBench と本論文の軸を掛けて 2×2 の評価グリッドを作る** — 縦に「1 本 / 分布」、横に「終点のみ / 過程込み」。**手持ちの候補モデルをこのグリッドに置くだけで R3 の分類マップの骨格になる。**紙 1 枚、1〜2 時間。
