### 症状 1: 本枠 3 トピックの候補がゼロ件 (最重要)

**planner_ai / fm_distill_finetune / next_arch のすべてが 0 件。** 昨日は 41 件入っていた。**08-09〜08-11 に 3 日連続で起きた主症状の再発**であり、**昨日 DIGEST で確定させた「planner_ai のキーワード陳腐化」とは別の、より重い故障である** (キーワードの問題なら fm_distill と next_arch まで同時にゼロにはならない)。

**コード上の該当箇所は特定済み** (`fetch_candidates.py:135-140`):

```python
try:
    xml = query_arxiv(t["categories"], t["keywords"])
    entries = parse_entries(xml, cutoff)
except Exception as ex:
    print(f"[fetch]   error: {ex}", file=sys.stderr)
    entries = []
```

**arXiv API の呼び出しが失敗しても `entries = []` として処理が続き、candidates.json は正常に書き出される。** エラーは stderr にしか出ず、**成果物の側には「取得に失敗した」という情報が一切残らない。** その結果、**「新着が無かった日」と「取得が全滅した日」が下流から区別できない。** 本日の 3 トピック同時ゼロは、**新着ゼロよりも API 失敗のほうがはるかにありそうだが、証拠が残っていないので確定できない。** これが欠陥の本体である。

**最小の修正:** 取得結果を candidates.json に `fetch_status` として記録する (トピックごとに `ok` / エラー文字列と件数)。**選別の側は、全トピックがゼロなら「候補なし」ではなく「取得の異常」として扱えるようになる。**
