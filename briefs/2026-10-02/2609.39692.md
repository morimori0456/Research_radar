# GFD-OPD: Guidance-Folded On-Policy Distillation of Diffusion Models Across Scales

- arXiv: `2609.39692` / https://arxiv.org/abs/2609.39692
- 配属: fm_distill_finetune (P2) ・ candidates.json 内
- スコア: **P2 4.0** ・ hf_upvotes 0

## 何を解決する論文か

OPD (on-policy distillation; student 自身が生成した系列の上で、teacher が各ステップに密な教師信号を与える蒸留) は LLM で広く使われ、拡散モデルにも移植されている (DiffusionOPD)。ただし拡散モデルでの OPD は、同じ大きさのモデル同士を merge する用途がほとんどだった。この論文は、**大きい拡散モデルから小さい拡散モデルへ** OPD で蒸留すると、生成画像に破綻が出て失敗することを示し、原因を capacity gap (teacher と student の表現力の差) と CFG による誤差の増幅に分解して、対策を出した。

## 手法の核心

- **原因 1: capacity gap。**小さい student は大きい teacher の分布を完全には再現できない。これを測るため、**Fixed-State KL** を提案した。student 自身の生成軌跡は学習中に変わるので比較に使えない。代わりに、teacher の生成軌跡と実画像にノイズを加えた軌跡という固定の状態集合の上で、student と teacher の KL を測る。
- **原因 2: CFG による増幅。**CFG (classifier-free guidance; 条件ありと条件なしの 2 つの予測の差を拡大して、条件への忠実度を上げる推論時の手法) は、2 つの branch の誤差の差も拡大する。同じ大きさのモデルでは、2 つの branch の誤差が互いに打ち消し合う形に学習されるが、大→小の蒸留ではこの打ち消しが崩れて、誤差が増幅される (付録 B の分解)。2 つの branch を別々に監督する既存の改善策 (PDM・split-KL) は、各誤差を小さくする代わりに打ち消しも消してしまう。
- **GFD (Guidance Folding Distillation):** teacher の CFG を適用した後の出力 (guided velocity) を、student 側では CFG を使わずに直接合わせに行く。つまり guidance を student の重みに「折り込む」。推論時に 2 つの branch を合成しないので、増幅が起きない。teacher の目標は、reference モデルから teacher の方向に少し外挿したもの (reward extrapolation; teacher を越える方向に目標を置く手法) を使う。
- **結果:** SD3.5-Large → Medium、FLUX.2 の 9B / 32B → 4B で、DiffusionOPD・PDM より報酬指標と画質指標の両方が高い。1 タスクの学習は約 10 GPU 時間で、DiffusionOPD の 15、RL (Flow-GRPO) で直接学習する 160 より短い。

## P2 への適用可能性

- **拡散系の student を作るときの capacity gap 対策として直接使える。**P2 の観点の「capacity gap 対策は高優先」に当たる。運転では diffusion planner (DiffusionDrive など) や flow-matching の action head (Alpamayo など) の小型化が対象になる。これらも推論時に guidance を使う構成なら、「大→小の蒸留で、CFG の合成が誤差を増やしていないか」をまず確認すべき。
- **評価の作法: 学習中に動く分布ではなく、固定した状態集合で KL を測る。**Fixed-State KL の考え方は、拡散以外の OPD でも、「student がどれだけ teacher に近づいたか」を公平に比べる方法として使える。LLM の OPD 論文の多くは student 自身の軌跡上で KL を報告していて、手法間で比較ができない。
- **LLM の OPD の連続との関係:** 09-30・10-01 に読んだ LLM の OPD の論文 (KL の向き・段の順序) は LLM 専用の議論だった。この論文は「CFG のような推論時の合成が蒸留の目標と噛み合わない」という、拡散・flow 系に固有の問題を示している。
- **限界:** 評価は画像生成 (GenEval・OCR・PickScore) のみ。軌跡生成のように CFG をあまり使わない用途では、原因 2 は効かない可能性がある。

## 試すべき実験アイデア

1. **(2D toy・半日) 大→小の flow-matching 蒸留で CFG の増幅を再現:** 2D の混合ガウス分布を条件付きで生成する flow-matching モデルを、大 (MLP 4 層 512) と小 (2 層 64) で用意する。大を teacher にして、(a) 小の CFG 合成後の出力を teacher に合わせる、(b) 2 branch を別々に合わせる、(c) GFD 型 (CFG 無しで teacher の guided 出力に合わせる) の 3 通りで蒸留し、Fixed-State KL と、サンプルの条件への忠実度を比べる。
2. **(diffusion planner がある場合) guidance の有無の点検:** 小型化したい diffusion planner が推論時に guidance を使っているかを確認し、使っていれば、teacher の guided 出力を CFG 無しの student に直接合わせる蒸留を 1 本試す。
3. **Fixed-State KL を蒸留の標準の出力に:** 今後の蒸留実験では、student 自身の軌跡上の KL に加えて、固定の状態集合 (teacher の軌跡 + データにノイズを足したもの) 上の KL を記録する。
