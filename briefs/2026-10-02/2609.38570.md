## 何を解決する論文か

乗用車のデータで学習した運転 VLA (Vision-Language-Action model; 画像と言語の理解から直接、行動や軌跡を出すモデル) は、大型トラック (Class 8; 米国の最大重量区分のトレーラートラック) にはそのまま使えない。車体の大きさ・トレーラーの内輪差・運動特性・センサーの高さが違うためで、工事区間や事故現場のような long-tail (稀だが重要な) 場面で特にずれる。この論文は、公開の運転 VLA を、**数百場面の実データだけ**でトラックに適合させる 2 段階の recipe を示した。

## 手法の核心

- **ベースは NVIDIA の Alpamayo 1.5:** 8.2B の vision-language backbone (Cosmos-Reason2) と、2.3B の flow-matching (ノイズから目標の分布へ連続的に変換する生成手法。拡散モデルの一種) で軌跡を生成する Action Expert に分かれた公開モデル。
- **Stage I: adapt (Action Expert だけ fine-tuning):** backbone は凍結し、軌跡生成部だけを工事・事故の実トラック 229 場面で fine-tuning する。backbone を凍結したのは、「どこまでが行動側の適合だけで埋まるか」を切り分けるため。全 horizon (6.4 秒) の ADE / FDE (Average / Final Displacement Error; 予測軌跡と実際の軌跡の平均 / 終点の距離誤差) が base の半分以下になり、held-out の 26 場面すべてで改善した。
- **Stage II: steer (FVS: Flow Velocity Steering):** 適合後のモデルも凍結し、flow-matching の各生成ステップで「行動列をどちら向きに動かすか」の速度に、小さな残差モジュールで補正を足す。補正後の中間状態はまた凍結モデルに戻るので、早い段の補正が後の生成全体に効く。ADE をさらに 13.9%、FDE を 16.5% 削減。同じパラメータ数で「完成した軌跡に最後に補正を足す」方式より良い。
- **FVS の学習:** 各ステップで「残りの時間でこの方向に動けば正解に届く」という中間目標 (bridge target) と、最後まで生成した軌跡の模倣誤差の 2 つで学習する。自分の補正で生じた中間状態の上で学ぶので、学習時と推論時の状態分布のずれが小さい。凍結モデルより悪化した例には罰を与える。
- **データの選び方が量に勝つ:** 同じ場面数で比べると、目的の場面 (工事・事故) に絞ったデータは、一般的なトラック走行データより ADE が 19〜26% 低い。229 場面の targeted データで、約 65 倍 (14,891 場面) の一般データで fine-tuning したモデルと同等。一般データで学習してから targeted で追加学習しても、targeted だけより一貫して良くはならない。

## P2 への適用可能性

- **「他機種への適合」の recipe がほぼそのまま使える。**P2 の fine-tuning の評価観点 (少データでの適合・ドメインギャップ・効率的な適合) を 1 本で全部満たしている。**「backbone 凍結 + 行動の生成部だけ fine-tuning → さらに凍結して残差で補正」**は、乗用車 → 別の車種、別の国の道路、などに移すときの最初の baseline として使える。
- **データ収集の優先順位の根拠。**「一般データを大量に集める」より「対象の場面を数百集める」方が効く、という定量的な比較 (同じ場面数で 19〜26%、65 倍のデータと同等) は、他機種への適合でデータ収集の予算を決めるときにそのまま使える。
- **プロンプトの工夫では埋まらない。**トラック運転手の意見を反映したプロンプトを試したが、どれも ADE を改善しなかった。重みに触れない適合の限界を示す反例として有用。
- **限界:** すべて open-loop (ログ上の軌跡との距離) で、closed-loop の安全性は未評価。test は 26 場面と小さく、ばらつきは推論時の乱数の分だけで、場面の選び方によるばらつきは出ていない。単一の候補でなく best-of-16 で見ると、一般データで学習したモデルの方が良い指標もある。

## P3 への波及

- flow-matching の action head を持つ VLA では、**重みを変えずに生成の途中を steer できる**、という構造上の利点がある。今日の不採用の Toward Real-Time VLAs (`2609.39822`; flow のステップを 10 → 2 に減らす) と合わせると、flow-matching の action head は「速度」と「適合」の両方で、生成のステップ単位で手を入れる設計が主流になりつつある。

## 試すべき実験アイデア

1. **(2D toy) 「車種」の違いを残差で埋める:** 2D の点質量で、乗用車 (旋回半径小) のデータで flow-matching の軌跡生成器を学習し、旋回半径の大きい「トラック」の少数データ (10/50/200 本) で、(a) 全体 fine-tuning、(b) 出力層だけ、(c) 凍結 + FVS 型の残差、を比べる。データ数ごとの到達誤差の曲線を描く。
2. **(同じ toy) targeted vs general:** トラックの「狭い曲がり角」場面だけのデータと、一般走行のデータを同じ数ずつ用意し、狭い曲がり角の test での誤差を比べる。論文の「目的の場面に絞る方が効く」が、toy でも再現するかを見る。
3. **(社内に別車種のデータがある場合) 最小の適合実験:** 公開の Alpamayo 1.5 で、backbone 凍結・Action Expert のみ fine-tuning を、別車種の数百場面で行い、論文と同じ「場面数 vs ADE」の曲線を作る。適合に必要なデータ量の見積もりになる。
