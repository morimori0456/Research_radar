# Efficient Multi-Modal Planning with Reward-Guided Preference Optimization for Autonomous Driving (EMPlan)

- arXiv: `2609.38862` / https://arxiv.org/abs/2609.38862
- 配属: planner_ai (P1) ・ candidates.json 内
- スコア: **P1 4.0** (P3 3.0) ・ hf_upvotes 0

## 何を解決する論文か

E2E (end-to-end; カメラ画像から走行軌跡までを 1 つのモデルで出す) の運転 planner には 2 つの流れがある。軌跡の候補を多数用意して rule-based なスコアで採点・選択する方式は、候補が数千個になり遅い。人の好みのペア (良い軌跡 vs 悪い軌跡) で学ぶ preference 学習は、厳密なペアの注釈が必要でデータを使い切れない。EMPlan は、少数の候補軌跡を微調整する構造で速度を保ち、ペアにしなくてよい preference 学習で安全側の選択を学ばせる。

## 手法の核心

- **sparse anchors + offset:** 学習データの軌跡を k-means でまとめた少数の anchor (代表的な軌跡の候補; 数百個) を用意し、場面ごとに各 anchor への補正量 (offset) を予測する。数千個の anchor で網羅する方式 (Hydra-MDP など) より軽く、離散的な候補の粗さは offset で埋める。offset を足すだけで PDMS が 81 台 → 88 台に上がる。
- **2 段階の学習:** (1) 事前学習: 軌跡の模倣 + rule-based なスコアの教師 + BEV (Bird's-Eye View; 上から見下ろした地図状の特徴) の segmentation を補助タスクに。(2) fine-tuning: 推論時と同じ「候補の中から 1 本選ぶ」基準で、reward を使って policy を調整する。学習の目的と推論時の選択基準のずれを減らすのが狙い。
- **unpaired preference (ペアにしない好み):** KTO (Kahneman-Tversky Optimization; 「良い例」「悪い例」をペアにせず個別に与えて学べる preference 学習の手法。DPO の対になる注釈が不要) を候補選択型の planner に適用した。場面内の全候補に「望ましい / 望ましくない」の印を付けるだけで使える。
- **結果:** NAVSIM (実走行ログから作った運転 planner のベンチマーク。他車は反応しない non-reactive 設定) で PDMS (Predictive Driver Model Score; 衝突・走行可能領域・進行度・快適性などをまとめた NAVSIM の総合指標) 89 台。dense anchor 系より低遅延。

## P1 への適用可能性

- **「スコアを回帰する」から「選択の順位を学ぶ」への切り替え。**rule-based なスコアの絶対値を回帰させると、選択に必要な「どちらが良いか」の関係より値そのものを合わせに行く、という論文の指摘は、P1 の候補選択型 planner にもそのまま当てはまる。10-01 の World4Scorer (`2609.36438`; 採点器を simulator の結果ラベルで学習する) と並べると、「採点器を何で学習するか」の選択肢が、(a) simulator の結果、(b) rule スコア、(c) unpaired preference の 3 つになる。
- **候補の数と遅延のトレードオフの具体値。**anchor 数を 128 → 512 に増やしても PDMS はわずかしか上がらない (表 V)。車載の計算予算で anchor 数を決めるときの参考になる。
- **限界:** reward を作るのに simulator での評価が必要で、simulator の無いベンチマークには広げられない (著者も明記)。評価は non-reactive の NAVSIM のみ。P1 で重要な「他車が反応する」状況での挙動は未検証。改善幅は既存手法に対し 1 点前後で、主張の中心は精度より効率。

## 試すべき実験アイデア

1. **(既存 planner がある場合) 採点器の学習目標を差し替える:** 候補選択型の planner で、採点ヘッドの loss を (a) rule スコアの回帰、(b) 場面内の softmax で順位を学ぶ形、(c) KTO 型の unpaired preference、の 3 通りで学習し、「最良の候補を 1 位に選べた率」を planner 全体の成績と分けて測る。
2. **(2D toy) anchor 数 × offset の有無:** 2D の点質量環境で、軌跡の anchor 数を 8/32/128 に振り、offset の有無で到達率と計算時間を比べる。「少数の anchor + offset」が「多数の anchor」に追いつく点を探す。
3. **TrafficSignBench (`2609.38463`) と組で:** KTO の「望ましくない」印に「ルール違反」を使えば、ペアの注釈なしで rule-aware な fine-tuning ができるはず。公開データで SCD が上がるかを見る。
