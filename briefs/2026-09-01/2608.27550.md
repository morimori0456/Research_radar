# VLAct: Beyond Data Scaling — Representation-Centric Continued Pre-training for Vision-Language-Action Models

**topic:** sns_wildcard (**内容は next_arch。下記「分類について」参照**) / **project:** P3 (主) · P2 (副) / **hf_upvotes:** 54
**スコア:** P1 2.0 / P2 **4.5** / P3 **5.0**

> **分類について:** 本論文は `topic: sns_wildcard` として届いたが、abstract の第一文が "Vision-Language-Action (VLA) models" であり、**`topics.yaml` の next_arch キーワード (`VLA` / `vision language action`) に正面から一致する。**wildcard に落ちたのは分野外だからではなく、**公開が 5 日前で `lookback_days: 2` の窓から外れたためである** (末尾に検証)。**本ブリーフは next_arch (P3) の本流 1 件として扱う。**

## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語指示を入力し、ロボットの行動を直接出力するモデル) を汎用化させる標準路線は「ロボットの軌跡データをもっと集める」だが、**実機での収集は高価で、物理世界をまばらにしか覆えない。**web 上の画像-テキストのようにはスケールしない。そこで著者は問いを立て直す —— **ロボットデータの量が固定されているとき、律速は何か。**答えは表現の質である。continued pre-training (事前学習済みモデルに、本番の fine-tuning の前にもう一段の学習を挟む工程) は、**限られた軌跡を「行動に当てはめる」のではなく「転用可能な視覚-行動の知識に変える」ものでなければならない。**

提案する **VLAct** は、VLM (Vision-Language Model; 画像と言語を扱う基盤モデル) を backbone とし、**task-specific fine-tuning の手前に「多様な embodiment (ロボットの機体・形態) の混在データで学ぶ段」を挿入する。**主張の核心は最終性能そのものではなく、**未知の機体に対して下流データの 20% で、フルデータの baseline を上回った**点にある。

## 手法の核心

- **学習を 3 段に分ける: VLM 事前学習 → (新) 異種 embodiment 混在の continued pre-training → task-specific fine-tuning。**新しいのは真ん中の段で、**ここでは特定タスクに合わせず、機体をまたいで共通する行動の意味だけを取りに行く。**
- **VLM-prior preservation (元の VLM が持っていた視覚・言語の知識を壊さずに残す仕組み)。**ロボットデータで追加学習すると、汎用な視覚理解が catastrophic forgetting (追加学習で以前の能力が失われる現象) で削れていく。**著者はこれを明示的に守りに行っている —— つまり「ロボットデータで上書きする」のではなく「ロボットデータを既存の prior の上に載せる」設計である。**
- **multi-head continuous action co-supervision (複数の行動出力ヘッドを同時に教師あり学習する)。**機体ごとに自由度も関節構成も違うので、単一ヘッドに押し込むと衝突する。**複数ヘッドを並列に持たせ、同時に監督することで、共有 backbone 側に「機体に依存しない部分」が溜まる。**
- **partially unified cross-embodiment action layout (機体をまたいで行動空間の並びを部分的に揃える)。**ここが効きどころ。**完全統一 (全機体を無理やり同一の行動空間に射影する) でも完全分離 (機体ごとに独立) でもなく、「揃う部分だけ揃える」という中間を取っている。**共有できるところで転移を稼ぎ、共有できないところは分けて壊さない。
- **fine-tuning 時は task-specific action head を許す。**つまり**共有するのは表現であって、出力層ではない。**「どこまでを共有し、どこからを専用にするか」の線引きが、この論文の実質的な設計判断である。
- **結果: LIBERO-Plus 82.6% / RoboTwin 2.0 92.5%** (いずれもロボット操作の標準ベンチマーク) で、ABot-M0・LingBot-VLA といった実運用系 VLA を上回る。RoboDojo では全 policy 中 6 位ながら、**WAM (world-action model; 世界の遷移予測と行動生成を一体で持つモデル) と明示された全エントリを 2 指標とも上回った。**
- **最重要の数字: RoboCasa-GR1 (学習時に見ていない humanoid 機体) で、下流軌跡の 20% しか使わない VLAct が、フルデータの GR00T-N1.6 を上回った。**

## P1 / P2 / P3 への適用可能性

**この論文の一番強い主張を一文にすると「下流データを 5 倍集めるより、その手前の表現を作り直したほうが安い」である。**そして**それが成立したのは未知の機体 = ドメインギャップが最大の条件下**だった。

**P2 (R2: capacity gap 系統則) にとっての意味が大きい。**`topics.yaml` の P2 基準は「少データでの適合、ドメインギャップの克服、基盤モデルを別ドメインに転用する recipe」を高優先と明記しており、**20%-data で未知機体を上回るという結果は、その基準に対する直球の回答である。**しかも W35 が P2 について出した結論 —— **蒸留・適合の支配変数は loss ではなく周辺工程だった** ([PROOF-Gen](../2026-08-27/2608.23911.md) の teacher 歩留まり、[UC-MOPD](../2026-08-29/2608.26735.md) / [Echo-GRPO](../2026-08-29/2608.26684.md) の token 選択) —— と**同じ形をもう一段外側で言っている: 支配変数は fine-tuning の中身ですらなく、その手前に何を挟むかである。**

**ただし警戒すべき点が 1 つある。**「20% で勝った」は **VLAct と GR00T-N1.6 という別系統のモデルの比較**であって、**同一モデルに対する data-efficiency の ablation ではない。**continued pre-training の寄与なのか、単に backbone が強いだけなのかは、abstract の範囲では切り分けられない。**R2 が系統則を主張する立場である以上、ここは原論文で ablation を確認しない限り引用できない。**

**P3 (R3: VLA × world model 統合) には、W35 の収束点に対する反証寄りの材料として効く。**W35 は 5 本が独立に「**画素は world model の言語として粗すぎる**」へ収束したと結論した。**本論文はその隣で、別の主張をしている —— RoboDojo で VLAct は WAM 系エントリを全て上回った。**つまり**「世界の遷移を明示的にモデル化した系」より、「表現を鍛えた行動モデル」のほうが強かった、という 1 データ点である。**

**これは W35 の結論と矛盾しない。**W35 が言ったのは「画素予測が粗い」であって「world model が要らない」ではない。**しかし本論文は R3 に対して、避けられない問いを 1 つ突きつける —— world model を明示的に持つことの利得は、表現を良くすることの利得と、どこで分離できるのか。**RoboDojo の 1 位から 5 位が何だったかが分かれば答えに近づくが、**abstract には書かれていない (「6 位」とだけある)。原論文で確認すべき最優先事項はここである。**

**P1 は 2.0。**planner の評価指標そのものには触れないが、**「未知の機体への転移」を「未知の車種・未知の地域への転移」と読み替えると、R1 が評価すべき軸が 1 本増える** —— 学習ドメイン外での性能劣化を、評価側はどう測るのか。ただし本論文にその測り方は無い。

### 試すべき実験アイデア

1. **【最優先・紙のみ・1 時間】「どこまで共有し、どこから専用にするか」の線引きを、自分の対象に書き下す。**本論文の設計判断は **backbone は共有 / action head は専用 / action layout は部分的に共有** の 3 層である。**同じ表を、自分が扱う車種・センサ構成・地域について埋める。**何が機体不変で (車両運動の基本則、他車の挙動)、何が固有か (センサ配置、制御遅れ、法規)。**この 1 枚が埋まらないなら、cross-domain の recipe はそもそも設計できない。**前提条件ゼロで今日できる。
2. **【R2 の核心・原論文の確認が先】continued pre-training の寄与を分離する最小 ablation を設計する。**本論文の弱点はここなので、**まず原論文に (a) 同一 backbone で真ん中の段を抜いた条件、(b) 下流データ量を振った曲線、があるかを確認する。**無ければ**それを埋めること自体が R2 の貢献になる** —— 「continued pre-training は下流データを何倍分に相当するか」を 1 本の曲線で出す、という主張は分かりやすく、W34 が推薦して未着手の検出力計算とも道具が共通する。
3. **【R3・原論文の確認】RoboDojo の上位 5 件が何系統かを調べ、「WAM に勝った」の射程を確定する。**WAM 系を全部上回ったが総合 6 位ということは、**上位 5 件は WAM ではない別の何かである。**それが何かによって、R3 の設計判断 (world model を明示的に持つか、表現学習に寄せるか) の向きが変わる。**調べ物であって実験ではないので、30 分で終わる。**
