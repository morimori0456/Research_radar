# DART-SD: Diamond-topology Aware Retrieval and Tuning for Self-Distillation of Multi-Turn Tool-Calling Agents

**topic:** sns_wildcard (**内容は fm_distill_finetune。下記「分類について」参照**) / **project:** P2 (主) · P1 (副) / **hf_upvotes:** 60
**スコア:** P1 2.5 / P2 **4.0** / P3 2.0

> **分類について:** `topic: sns_wildcard` として届いたが、**手法の中身は self-distillation (自分自身の出力を教師データにして学習する蒸留) であり、fm_distill_finetune の対象そのものである。**wildcard に落ちた理由は分野外だからではなく、**公開が 12 日前で `lookback_days: 2` の窓を大きく外れたためである。**本ブリーフは fm_distill_finetune (P2) の本流 1 件として扱う。

## 何を解決する論文か

LLM に multi-turn tool-calling (複数ターンにわたって外部ツールを呼び出しながらタスクを進める能力) を仕込む標準手法は、**成功した完全な軌跡をまるごと模倣させること**である。著者はこれが原理的に頭打ちだと言う。理由は**タスクの構造**にある —— 順序を入れ替えても等価な sub-goal が複数あるとき、**最適解は 1 本の線ではなく、始点と終点を共有する無数の経路が張る格子 (著者の言う diamond lattice) になる。**

**この豊かな構造を 1 本の軌跡に押し込めて教師にすると、「正しいが順序が違うだけ」の経路まで一律に罰することになる。**著者はこれを **topological collapse** と呼び、**policy diversity (モデルが取りうる解法の多様性) が潰れる**ことを問題として特定する。DART-SD の答えは、**全体を正解に合わせに行く (global forcing) のをやめ、壊れた 1 点だけを直す (localized correction) こと。**

## 手法の核心

- **診断が主役である: 罰しているものが間違っている。**「失敗したから軌跡全体が悪い」ではなく、**失敗した軌跡の大部分は正しく、悪いのは分岐した 1 点だけ**という見立て。**この読み替えが手法のすべてを決めている。**
- **実行過程を ISTG (Interaction-State Transition Graph; ツール呼び出しの各ステップを状態、遷移を辺とするグラフ) としてモデル化する。**軌跡を系列ではなく**グラフ**として持つことで、**「順序違いの等価な経路」がグラフ上で同じ状態に合流する** —— つまり等価性が構造として表現され、別物として二重に数えられなくなる。成功経路と失敗経路の両方を同じグラフに載せる点が重要。
- **CTB (Critical Topological Breakpoint; 決定的な分岐点) を特定する。**自律 rollout (モデル自身に最後までやらせてみること) の中で、**「ここまでは正しく、ここから外れた」という 1 点**をグラフ上で探す。**失敗の責任をステップ単位に割り当てる操作である。**
- **CTB から先の復帰手順を、成功経路から retrieval で持ってくる。**外部に正解を用意するのではなく、**同じグラフ上にある成功例を参照して「そこからどう戻るか」の参照解を作る。**これが self-distillation の教師になる。
- **【本論文の一番の中身】loss を、生成された復帰ステップに対してのみ計算する。**CTB より手前の正しい推論 prefix には**勾配を一切通さない。**著者はこれを「valid reasoning prefix を破壊的な勾配更新から厳格に保護する」と表現する。**つまり制御変数は loss の関数形ではなく、loss を「どこに」当てるかである。**
- **progressive (段階的) に自己蒸留を回す。**rollout → CTB 特定 → 参照取得 → 局所監督、を繰り返して自分を押し上げる。

## P1 / P2 / P3 への適用可能性

**P2 (R2: capacity gap 系統則) にとって、これは W35 の結論の 3 例目である。**W35 は蒸留について **「支配変数は loss ではなく周辺工程だった」** と結論し、その根拠に [UC-MOPD](../2026-08-29/2608.26735.md) と [Echo-GRPO](../2026-08-29/2608.26684.md) の **「更新する token の選択」** を挙げた。**DART-SD は同じ主張を、別の分野で、より極端な形で言っている —— 更新する範囲を「復帰ステップだけ」に絞り、それ以外を明示的に凍結する。**

**3 本が独立に同じ場所に着地したことは、R2 にとって偶然ではなく、主張にできる強さである。**すなわち —— **蒸留の設計自由度は loss 関数ではなく「監督を当てる範囲」にあり、範囲を絞るほど強い。**W35 時点で R2 は「測る量」と「機序」が埋まった状態で止まっていたが、**本論文は 3 例目として、この命題を分野横断の観察に格上げする。**

**capacity gap への直接の含意も 1 つある。**capacity gap (教師と生徒の能力差が大きすぎて蒸留が効かなくなる現象) の標準的な説明は「生徒が教師の出力分布を表現しきれない」だが、**DART-SD の見立てを当てはめると別の読み方が出る —— 生徒が再現できないのは教師の「答え」ではなく、教師が通った「経路」かもしれない。**答えだけなら生徒にも出せるのに、経路をまるごと模倣させるせいで学習が壊れている、という筋である。**もしそうなら、capacity gap は容量の問題ではなく監督範囲の問題であり、R2 の系統則の独立変数が 1 本増える。**これは仮説だが、**検証は安い** (下記実験 2)。

**P1 への副次的な効き方が、実は面白い。**diamond lattice = **「始点と終点を共有する、複数の等価だが異なる経路」** という構造は、**軌跡計画でそのまま出てくる。**W35 の [Anytime GTMP](../2026-08-28/2608.25830.md) が扱った **homotopy class (障害物をどちら側から回避するか等で分類される、連続変形では移り合えない軌跡の族)** と **mode coverage** は、**まさに同じものを planner 側の語彙で言ったものである。**

**そして本論文は、そこに W35 が扱っていなかった側を足す —— 学習側。**W35 の P1 の軸は「1 本ではなく分布で**測れ**」 ([PAWBench](../2026-08-29/2608.27345.md)) だったが、**DART-SD は「1 本ではなく分布で**教えろ**」と言っている。**単一の expert trajectory を imitation learning (専門家の行動をそのまま真似る学習) の教師に使うことは、**等価に良い別の回避経路を罰することと同義である。**これは R1 の主張の前半 (評価が 1 本に偏っている) と**同じ穴の学習側の顔**であり、**R1 の第一図に「測る側」と「教える側」を並べる形が取れる。**

**P3 は 2.0。**構造としての示唆はあるが、VLA / world model の設計に直接落ちる材料は無い。

### 試すべき実験アイデア

1. **【最優先・紙と既存ログ・2 時間】自分の対象に diamond lattice があるかを、まず数える。**走行ログから同一の始点・終点区間を取り、**「等価に良いが異なる経路」が実際に何通りあるか**を homotopy class で数える。**W35 で計画済みの solvability 後付け計算と同じログ・同じ運動モデルで走るので、追加コストはほぼゼロ。**結果は 2 つに割れ、**どちらでも 1 つ決まる:** 大半の場面で 1 通りしか無いなら、この論文の問題意識は自動運転には効かない (そしてそれは R1 にとって朗報 —— 単一軌跡での評価が正当化される)。複数あるなら、**単一 expert 軌跡での模倣学習は等価解を罰しており、R1 の主張の学習側の根拠になる。**
2. **【R2 の核心・仮説検証・半日】capacity gap は「範囲」の問題かを、既存の蒸留設定で 1 回だけ試す。**同一の teacher / student ペアで、**監督を当てる範囲だけを 2 条件に振る:** (a) 教師軌跡の全 token、(b) student の出力が教師から乖離した箇所以降のみ。**loss 関数・データ・step 数はすべて固定する。**差の**符号**が出れば十分で、大きさは要らない。**「更新範囲が capacity gap の独立変数である」が支持されるか否かが、1 回の学習で分かる。**上の 3 本 (UC-MOPD / Echo-GRPO / 本論文) が同じ方向を指している以上、**当たる確率は高く、外れても「範囲では説明できない」という negative result が R2 の系統則を絞る。**
3. **【安い・1 時間】CTB の特定手続きだけを取り出して、走行ログの介入分析に流用する。**CTB = 「ここまでは正しく、ここから外れた」点の同定は、**08-31 の [RLHEV](../2026-08-31/2608.25518.md) から出た「engine チェックが全部 pass しているのに人が介入したケース」の抽出と、探している対象がほぼ同じである。**片方は学習の責任割り当て、もう片方は評価の責任割り当てだが、**手続きは共通化できる。**08-31 の実験 2 に着手する際、**この論文の CTB 定義を先に読んでから始めるだけで済む。**
