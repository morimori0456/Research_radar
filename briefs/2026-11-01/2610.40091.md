# Upcycling Language Models for Multiple Specialized Domains (2610.40091)

- トピック: fm_distill_finetune (P2) / スコア 4.0 / 10-31 の次点を繰り越し (candidates.json に無く、arXiv API で abstract を取得)
- URL: https://arxiv.org/abs/2610.40091

## 何を解決する論文か

複数のドメインに LLM を適合させるとき、ドメインごとに LoRA (Low-Rank Adaptation; 重みの差分を低ランク行列で持つ軽量 fine-tuning) の adapter を作って合成するのが主流である。ただし、入力のドメインに関係なく adapter を等しく重みづけするか、無関係な adapter まで全部動かす点と、低ランクゆえの性能上限が問題だった。この論文は、upcycling (dense な Transformer 層に expert と router を足して MoE (Mixture-of-Experts; 入力ごとに一部の expert だけ動かす構造) に拡張する手法) で容量を増やし、router がドメインを正しく選べるようにする。

## 手法の核心

- **DS-Upcycling (Domain-Specialized Upcycling)**: 既存の dense モデルに、ドメインごとの expert と router を追加する。
- **domain-aware supervision**: router がドメインを見分けるための新しい教師信号。これが無い router は「どの expert を使うか」を学べない。
- 新しいドメインを足すときは、そのドメインの expert と router だけを更新し、他のパラメータは凍結する。既存ドメインの性能を保ちやすい。
- 報告: router の教師に使うのは 1 ドメインあたり 256 例だけで、適合後の routing accuracy は 90-98%。この教師信号なしの router は 43-70%。
- 適合した各ドメインの平均性能は baseline で最高、かつ general な性能も維持したと報告している (具体的な数値は abstract に無い)。

## P2 への適用可能性

- P2 の「他機種・他ドメインへの適合」に直接対応する。LoRA の容量不足と、ドメインが増えるたびに起きる干渉 (忘却) の両方に答える設計である。
- 256 例で router が学べるという点は、少データでの適合という topics.yaml の高優先条件に合う。
- 注意点: 対象は LLM のみ。運転の認識 model (画像 backbone) や VLA に expert を足す形に移せるかは未検証。expert を足すと推論時のパラメータ数と memory が増えるので、edge 推論とのトレードオフが要る。

## 試すべき実験アイデア

1. 手元の小さい LLM (または VLM の言語部) で、2〜3 ドメインに DS-Upcycling と LoRA 合成を比較する。指標は各ドメインの精度と、既存ドメインの劣化量。
2. router 教師の例数を {32, 64, 256} と変え、routing accuracy が崩れる点を探す。少データ適合の実用下限が分かる。
3. 運転の perception で、天候や都市などのドメインごとに expert を足す版を、画像 backbone の FFN 層で試す。ここが論文の外側で最も価値のある拡張である。
