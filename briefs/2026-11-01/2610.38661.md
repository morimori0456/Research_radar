# Quantize by Doing: Task-Guided Mixed-Precision Quantization of Vision-Language-Action Models (2610.38661)

- トピック: next_arch (P3) / スコア 4.0 / 10-31 の次点を繰り越し (P2 の model compression にも近い)
- URL: https://arxiv.org/abs/2610.38661
- コード: https://github.com/jiuyixu25/QbD-VLA

## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語から行動を出す model) を PTQ (Post-Training Quantization; 学習後に重みや活性値のビット幅を落として memory と計算を減らす手法) で小さくしたい。既存手法は calibration data から求めた感度で層ごとのビット幅を決めるが、実際のタスク成功率は見ていない。成功率で決めたいが、closed-loop の評価は高価で、ある component の影響が他の component の精度に依存する、という難しさがあった。

## 手法の核心

- **QbD-VLA**: 短い closed-loop 評価の task 成功率を信号にして、component ごとに weight と activation のビット幅を割り当てる。
- component 同士の相互作用を考慮する。1 つずつ独立に感度を測る方式の弱点を直接扱う。
- 4 つの VLA モデルと LIBERO の 4 suite で、weight は平均約 4 bit、activation は 6 bit 未満でも良好な成功率と報告。
- SIMPLER (別の simulation benchmark) では uniform な量子化に対する gain は小さい。
- 実機 (Franka Research 3 のアーム) では、simulation で選んだ割り当てが X-VLA では成功率の低下なしだったが、π0.5 では失敗した。

## P3 / P2 への適用可能性

- 次世代アーキテクチャを車載に載せる段階では、VLA の量子化が必ず問題になる。「感度」でなく「closed-loop の成功率」で bit 幅を決める発想は、運転の closed-loop 評価と相性がよい。
- 結果が正直に書かれている点が価値である。simulation で選んだ割り当てが実機で壊れる例を示しており、運転でも「simulator での合格 = 実車で安全」とは言えない可能性を示す。
- 注意点: 対象は manipulation の VLA。運転は評価の分散が大きく、短い closed-loop で信号を取る前提が崩れるかもしれない。

## 試すべき実験アイデア

1. 公開 code で、LIBERO 上の VLA を一様 8 bit / 一様 4 bit / QbD の割り当てで比較し、論文の gain の大きさを自分の環境で再現する (P3 の入口として軽い)。
2. 「短い closed-loop」の長さを変えて、割り当ての安定性 (seed 間で同じ割り当てになるか) を測る。評価コストと信頼性の関係が分かる。
3. 運転の driving policy の量子化に移し、CARLA 等の少数 scene で成功率を信号にする。scene 数が少ないと割り当てがノイズに負けるか確認する。
