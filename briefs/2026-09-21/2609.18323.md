# MiniMax-H3 の物理world推論評価 — 「どの modality も証拠が半分しかない」状況を意図的に作る評価設計

**topic:** sns_wildcard 経由 → **next_arch (P3) の keyword `world model` に実際にヒットする** / **project: P3** (+**P1 が本命かもしれない**)
**hf_upvotes:** 97 / **公開 (HF の publishedAt):** 2026-09-15T20:00Z
**スコア:** **P3 4.0 / P1 3.5** / P2 1.0

## 何を解決する論文か

**Omni-Modal Generative Model (Omni-Model; text / image / video / audio を 1 つのモデルで理解も生成もする、統合型の生成モデル)** はここ 1 年で実用水準に乗り、**MiniMax-H3** は共有された latent 空間の上でマルチモーダル理解と音声・映像の同時生成を行う代表例である。ここで問うべきことは「もっともらしい映像を作れるか」ではなく、**「modality を束ねたことで、物理世界についての推論が実際に良くなったのか」**に移る。

この論文の批判は既存ベンチマークの設計に向いている: **video generation / world model の評価は、prompt が生成すべき映像の内容をほぼそのまま述べている設定が多い。**それでは**モデルは何も推論しなくてよく**、測っているのは描画の忠実度である。そこで本論文は、**どの単一 modality も出来事についての部分的な証拠しか与えない**タスク群を作った。517 問で MiniMax-H3 の総合成功率は **41.97%。**

## 手法の核心

- **設計原理が貢献の本体: prompt と target を意図的に食い違わせる。**「prompt が答えを書いてしまっている」評価を明示的に排除する。
- **4 つの入力シナリオ。**いずれも単一 modality では解けないように構成されている:
  - **implicit prompt + 複数フレーム** —— prompt はわざと不足した記述しかしない
  - **audio + image** —— 音が、静止画に写っていない出来事を示唆する
  - **prefix-video** —— 途中までの映像から続きを推す
  - **audio + video**
- **測る対象は pixel の忠実度ではなく、「latent event state (今どういう出来事が進行中か) と future dynamics (この先どうなるか)」の推定。**
- **4 つの相補的な次元**に整理された評価 framework であり、単一スコアではない。
- **517 instances / 総合 41.97%** —— 天井にも床にも貼り付いていないので、**モデル間の差を出せる** (評価として機能する)。

## 追っているプロジェクトへの適用可能性

### P1 / R1 — ここが本命。「衝突率の隣に置く量」に、occlusion から作れる候補が 1 つ出る

`RESEARCH_PIPELINE.md` の **R1 (閉ループ評価に「衝突率の隣に置く量」を定義する)** は **09-06 が gate だったが、自分で測った数字はまだゼロ**で、ターゲットは CVPR 2027 (2026-11-13 推定) に移っている。必要なのは**半日で図 1 が出る測定**である。

**本論文の中核操作は、運転の評価にほぼそのまま移る: 証拠を意図的に一部隠し、モデルが「推論したか」「無かったことにしたか」を測る。**運転における「証拠が部分的にしか無い状況」には既に名前がある —— **occlusion (遮蔽; 他車や建物の陰で、いるはずの交通参加者が観測できない状態)** である。

既存の指標はここで無力である。**衝突率は「遮蔽された歩行者と実際にぶつかったか」しか見ない**ので、(a) 推論して減速した planner と、(b) 何も考えず偶然当たらなかった planner を**区別しない。**本論文の設計は、この区別をつける測り方を示している。

### 試すべき実験 —— rollout 3 本 / シナリオ、新しい学習は無し

1. **2D toy か手元の走行ログから、遮蔽が起きるシナリオを集める** (交差点の右左折、駐車車両の陰など)。数十本で図になる。
2. **各シナリオを 3 条件で回す:**
   - **(F) full** —— 遮蔽なし。隠れていた agent が最初から見えている
   - **(O) occluded** —— 本来の遮蔽あり
   - **(A) absent** —— 遮蔽された agent を**シーンから削除する**
3. **planner の出力軌跡を 3 本得て、距離を測る。**核心の量は
   **`d(O, A) / (d(O, F) + d(O, A))`** ——
   **O の挙動が F 寄りなら「見えていないが、いる前提で動いた」= 推論している。A 寄りなら「いないものとして動いた」。**
4. **これを 1 本のスカラーにまとめたものを、衝突率の隣に置く候補とする:**
   **occlusion-conditioned inference rate = O が A よりも F に近いシナリオの割合。**
5. **図 1 の形:** 横軸に遮蔽の強さ (遮蔽継続時間、または隠れた agent の TTC (Time-to-Collision; 衝突までの残り時間))、縦軸にこの比。**衝突率を同じ図に重ねる。**主張は「**衝突率が同じ 2 つの planner で、この量は分かれる**」——分かれれば、衝突率が見落としている次元があることの直接証拠になり、それが R1 の論拠になる。

> **YES/NO が明確に出る:** 3 の比が全シナリオで 0.5 付近に潰れる、あるいは (F) と (A) で planner の出力がそもそも変わらないなら、**その planner は遮蔽を一切モデル化していない**ということであり、これも報告に値する negative result である。**学習は 1 回も要らず、必要なのは agent を 1 体消せるシミュレータだけ。**

### P3 / R3 — 分類マップの 4 本目の軸の候補、ただし「軸」ではなく「測り方」として

**R3 (VLA × world model 統合アーキテクチャ)** の分類マップは軸が 3 本確定している (① 時間をどこに持つか ② 未来を 1 本返すか分布か ③ 終点か過程か・自己訂正するか)。**本論文はアーキテクチャを提案していないので、4 本目の軸そのものにはならない。**

代わりに供給するのは**評価の protocol** である: **「入力の証拠が欠けたとき、モデルは推論するのか、それとも欠けていないかのように振る舞うのか」。**3 本の軸はどれも**構造**についての軸だが、この問いは**構造から直接は読めず、測らないと分からない。**分類マップに「実測列」を 1 本足すなら、ここが候補になる。

**ただし R3 は今月は着手しない方針 (2026-09 / R1 に絞る)** なので、**この論文の P3 側の価値は在庫に積むだけでよい。**上の P1 の実験と競合させない。

**注意点 (この論文の限界):** 対象は MiniMax-H3 **1 モデルのみ**で、41.97% という数字は比較対象が無いと解釈できない。**評価設計を借りるのが正しい使い方で、スコアを引用する使い方は現時点では意味が薄い。**
