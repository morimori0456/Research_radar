# Model Merging Does Not Require Uniform LoRA Ranks (2611.06486)

- トピック: fm_distill_finetune / プロジェクト: P2 / スコア 4.0
- URL: https://arxiv.org/abs/2611.06486

## 何を解決する論文か

model merging (別々に fine-tuning した複数の expert を、再学習なしで 1 つの model に束ねる手法) では、各 expert を LoRA (Low-Rank Adaptation; 重みの差分を低 rank の小さな行列で持つ軽量 fine-tuning) で学習し、**全 expert で同じ rank を使うのが標準**になっている。しかし domain ごとに最適な rank は違う。この論文は、rank を揃える必要があるのは merge 手法の性質であって merging 自体の制約ではない、と示す。

## 手法の核心

- 3 つの domain (数学、instruction following、多言語) × 4 つの rank × 3 つの model scale で 36 expert を学習し、6 つの merge 手法を、全部同じ rank の場合と domain ごとの最適 rank の場合で比べる。
- rank を domain ごとに変えても、単純平均 (averaging) と utility-based selection (有用度で選ぶ手法) は劣化せず、multi-domain accuracy が最大 1.8 pp 上がる。TIES など conflict-resolution 系 (expert 間の符号衝突を解く手法) は結果が不安定で、最大 4 pp 下がる。
- 原因: merge は束ねた spectral component (特異値分解した成分) の固定割合しか残さない。**大きさ (magnitude) で選ぶ手法は、特異値が小さい expert を丸ごと捨てる**。instruction adapter は特異値が最小で、IFEval が 16〜25 pp 落ちる。
- 対策: component を loss への効果で選ぶと 3 expert が全部残り、8 倍の rank 範囲で accuracy がほぼ平坦 (0.7 pp。4B 規模で TIES は 6.7 pp)。

## 適用可能性 (P2)

- P2 の「他ドメインへの適合」を、domain ごとに独立した LoRA で作って後で束ねる運用にするとき、rank 選択を domain ごとに最適化してよい根拠になる。
- 手元で複数 domain の adapter を束ねるなら、**magnitude で選ぶ merge は一部の adapter を暗黙に消す**可能性がある。merge 後に各 domain の評価を必ず見る理由になる。
- 注意: 実験は LLM (数学・指示追従・多言語) で、VLA や運転 model の LoRA に当てはまるかは未確認。

## 試すべき実験アイデア

1. 手元の 2〜3 domain の LoRA を、単純平均と magnitude 選択で merge し、各 domain の評価が片方だけ落ちていないか確認する (最小の確認)。
2. domain ごとに rank を 2 通り (小・大) 学習し、uniform と per-domain の merge 後の差を見る。
3. 各 adapter の特異値の大きさを並べ、他に比べて極端に小さいものがないか事前に調べる。
