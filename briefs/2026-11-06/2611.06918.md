## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語から行動を出す model) は、まず visual encoder で画像を圧縮し、その後で行動を推論する構成が普通である。しかし manipulation は、局所的な形状・境界・depth・微小な状態変化といった **encoder の圧縮でまさに失われやすい信号**に依存する。固定された encoder の出力を使うべきか、進行中の視覚の計算に直接アクセスさせるべきかを問う。

## 手法の核心

- NEO-VLA: encoder-free (専用の visual encoder を持たない) な VLA。画像は軽量な patch convolution で token 化され、言語と一緒に backbone 全体で進化する。
- flow-matching (ノイズから行動を少しずつ生成する生成手法) の action expert が、instruction で条件づけられた視覚表現を、**backbone の異なる深さから**引く。
- 統制した比較で、native 構成は encoder 付きの対照より強い。full fine-tuning で差は縮むが消えず、scale を増やしても埋まらない。
- layer-wise probing (各層の表現に簡単な model を載せ、情報量を測る検査) で、action に重要な信号は最終層の視覚表現よりずっと手前の層で peak になる。
- 多様な manipulation 設定と distribution shift で、より強く頑健な制御。

## 適用可能性 (P3 / P1)

- P3 の VLA 構造設計に直結する。「action head は最終層だけを読む」前提を疑う根拠で、中間層を引く設計は既存の VLA にも後付けで試せる。
- 運転では、局所的な境界 (車線、縁石、小さな物体) が encoder の圧縮で失われないかという同じ問題がある。
- 注意: 評価は manipulation が中心で、運転や高速での遅延 (encoder-free は backbone の token 数が増える) は abstract に無い。model 規模、benchmark 名も未確認。

## 試すべき実験アイデア

1. 手元の VLA / planner で、action expert が読む層を「最終層のみ」「複数層」で比べる (後付けの最小変更)。
2. layer-wise probe で、軌道に必要な情報 (自車の将来位置など) がどの層で最大かを測る。最終層より手前なら、NEO-VLA の主張が手元でも成り立つ指標になる。
3. encoder 付きと patch convolution のみで、同じ backbone・同じデータの小規模 pilot を回し、token 数が増える分の推論時間を測る。
