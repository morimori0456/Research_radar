# P^2-MOPD: Accelerating Multi-Teacher On-Policy Distillation via Parameter Priors (2611.03953)

- URL: https://arxiv.org/abs/2611.03953
- 備考: 蒸留の recipe に当たるので、wildcard 枠でなく本流の quota に置いた (keyword "distillation" に一致)。published は 11-02。

## 何を解決する論文か

複数の domain ごとに専門化した expert model の能力を、1 つの student に統合したい。multi-teacher on-policy distillation (MOPD; student 自身が生成した出力に対して teacher が supervision を与える蒸留を、複数の teacher で行う) は student の分布に沿って学べる一方、学習が遅い。逆に task arithmetic (expert と元 model の重みの差分を足し引きして能力を合成する、学習なしの手法) は速いが、結果が student と expert の重みが張る線形空間の中に閉じてしまう。この論文は両者を組み合わせ、MOPD を速く・バランスよく収束させる。

## 手法の核心

- student と expert の重みの **線形結合そのものを 1 つの微分可能な model** とみなす。
- 混合係数 (mixing coefficients) と student の重みを、**同じ on-policy distillation の objective で同時に最適化**する。
- task arithmetic と違い student は学習可能のまま。expert は「重みに関する prior (parameter priors)」として働き、線形結合の張る空間に student を閉じ込めない。
- 4 つの domain、1.7B と 4B の規模で評価。同じ初期値から MOPD より速く、domain 間のバランスよく回復する。MOPD の最終的な平均 recovery (abstract から、各 domain で expert の性能にどこまで戻したかの指標と読める) を、**半分の学習 step で超える**。
- 終了時の 1.7B model の平均 recovery は 94.7%、MOPD は 80.9%。

## 適用可能性 (P2)

- 複数の専門 model (たとえば別機種・別 domain に適合させた複数の fine-tuned model) を 1 つに蒸留する場面で、学習時間を削る recipe として使える。P2 の「蒸留プロセスを実務で回す」に直接対応する。
- 「重みの統合 (merge) を初期値や prior として使い、そこから学習を続ける」設計は、capacity gap (student が小さすぎて teacher を再現しきれない差) の対策としても読める。
- 注意: 評価は LLM (1.7B / 4B) の domain 統合。vision / driving の model で同じ効果が出るかは abstract から分からない。teacher の重みが student と同じ構造であることが前提に見える (異なる構造の teacher には使えない可能性)。

## 試すべき実験アイデア

1. 手元に同じ base から fine-tuning した expert が 2〜3 個あるなら、(a) task arithmetic のみ、(b) 通常の multi-teacher distillation、(c) 混合係数を学習可能にして student も更新する版、の 3 つを同じ step 数で比べる (最小の実験)。
2. 混合係数を層ごと / 全体で 1 つの 2 通りにして、学習後の係数が domain ごとにどう偏るかを見る。偏りは、どの expert が student に効いたかの診断になる。
3. 学習 step が半分で MOPD の最終値に届くという主張を、手元の予算 (GPU 時間) で再現できるか確認する。
