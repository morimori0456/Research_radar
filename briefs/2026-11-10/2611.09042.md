# Failure Profiling and Reachable Trajectory Selection for Reasoning Distillation (2611.09042)

- トピック: fm_distill_finetune / プロジェクト: P2 / スコア 4.0
- URL: https://arxiv.org/abs/2611.09042

## 何を解決する論文か

大きい teacher model が生成した数学の推論過程で、小さい student を学習させる蒸留は標準的だが、student は teacher の出力分布に過適合し、推論時に自分の挙動が学習データからずれると汎化しない。失敗例 (error data) を足す手法もあるが、修正後の軌跡は teacher の推論パターンのままで、student が再現できないので分布のずれが残る。この論文は、**student が何で失敗するか**と**student が現実に再現できるか**の両方で学習データを選ぶ。

## 手法の核心

- **Failure profiling**: 同じ問題を student に繰り返し sampling させ、error rate (間違える割合) と error consistency (毎回同じ間違え方をするか) で失敗の型を分ける。型ごとに必要な学習 signal が違う、という立場。
- 診断した型に応じて、teacher からの候補生成の prompting strategy を変える。
- 正解した候補の中から、**分岐点 (student の誤りが始まる点) の直後の数 step を student が最も再現しやすいもの**を選ぶ (reachable trajectory selection)。
- 理由: 最初の修正 step が bottleneck で、その後は修正された文脈の続きなので継続しやすい。軌跡全体を採点する reranking (候補の順位付け) は、この重要な遷移の signal を薄めてしまう、と主張。
- 2 つの student backbone、5 つの benchmark で SOTA (state-of-the-art; 現時点の最高性能) と報告。

## 適用可能性 (P2)

- capacity gap 対策を「teacher の出力のうち student が届く部分だけを学習 data にする」という data 選択で行う recipe。loss や architecture に手を入れず、data pipeline だけで回せるので、既存の蒸留に差し込みやすい。
- 「student を sampling して失敗を診断してから teacher data を作る」という順序は、LLM 以外 (たとえば vision model の蒸留で、student が外す sample を診断して teacher の出力を選ぶ) にも一般化できる発想。
- 注意: 対象は数学の推論で、正解判定が機械的にできる task。judge が曖昧な task では failure profiling の前提 (error rate の測定) が崩れる。

## 試すべき実験アイデア

1. 手元の蒸留 task で student を各入力 8〜16 回 sampling し、error rate と error consistency の 2 軸で入力を分類する (最小の実験)。分類しただけで、どの型に data が足りないかが見える。
2. 全 sample を同じ重みで使う baseline と、「student の失敗型ごとに teacher 候補を選び直す」版を、同じ data 量で比べる。
3. 候補選択で「student の log-likelihood が最も高い候補」を代理指標にして、分岐点直後の数 step だけで採点する版と、全体で採点する版を比べる (論文の主張の再現確認)。

## 注意

abstract のみに基づく。「再現しやすさ」の具体的な測り方、student のサイズ、5 つの benchmark の名前と改善幅は未確認。
