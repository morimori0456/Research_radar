# FactorDrive: Adaptive Multi-Step Reasoning Driven by Planning-Critical Factors for End-to-End Autonomous Driving

**topic:** next_arch (P3) ・ **arXiv:** 2608.09591 ・ **published:** 2026-08-10 ・ **hf_upvotes: 0**

> **P3 と P1 の両方に効く唯一の本枠論文。** 中身は「VLM で運転を考えさせる」系だが、**post-training の設計 (reasoning path を報酬で選ぶ) にまで踏み込んでいる**のが他と違う点。nuScenes (open-loop) と NAVSIM (closed-loop 志向) の両方で SOTA を主張。
>
> 著者: Guolei Huang, Tengfei She, Yuxuan Lu, Yao Huang, Yuqi Ye ほか。

## 何を解決する論文か

**VLM (vision-language model; 画像と言語を同時に扱うモデル)** を end-to-end 自動運転に持ち込む研究は、シーンを言葉で説明させ、その説明を根拠に軌道を出す形で進んできた。本論文が指摘する不満は 3 つある。(a) 推論の中に **spatial-physical evidence (距離・相対速度・到達時間といった、軌道を決めるのに実際に必要な物理量)** が十分に入っておらず、言葉が軌道と地続きになっていない。(b) **シーンごとに必要な思考の深さが違うのに、推論の粒度が一律**である —— 直線の空いた道と、遮蔽のある交差点で同じ長さの推論をするのは無駄でもあり不足でもある。(c) そもそも **「どの推論経路がより良い軌道を生むか」を目的に post-training する研究がほぼ無い**。

FactorDrive はこれを **PCF (Planning-Critical Factor; その場面で計画を左右する要因)** という単位で組み直す。まず運転ドメインの大規模 instruction tuning で土台を作り、次に PCF を軸に構成した **CoT (chain-of-thought; 結論に至る途中の思考を明示的に生成させる方式)** データで推論の形を教え、最後に**軌道の良さを報酬にして推論経路そのものを最適化する**。

## 手法の核心

- **推論を「場面ごとに必要な要因」で組む (PCF-CoT)。** 汎用の CoT データではなく、**軌道に関係する空間的・物理的な根拠に接地した** CoT を作る。しかも**シーンごとの PCF を軸に推論を編成する**ので、**推論の構成と深さが場面に応じて変わる** —— 単純な場面では短く、複雑な場面では深くなる。**「思考の長さを固定しない」**が設計の中心。

- **QS-GRPO が本論文で最も新しい部分。** **GRPO (Group Relative Policy Optimization; PPO を簡略化した RL 手法で、複数の出力候補を生成して互いの相対的な良さで方策を更新する。LLM の RL 学習で標準的に使われる)** に、**MCTS (Monte Carlo Tree Search; 有望な枝を優先しながら探索木を伸ばして良い手を見つける探索法)** を組み合わせる。ポイントは **MCTS を軌道レベルの計画報酬でガイドしている**こと —— 言語としての尤もらしさではなく、**その推論経路が最終的にどれだけ良い軌道を生んだか**で探索を導く。見つかった良い経路を GRPO の学習データにする。

- **つまり「良い思考」を人手で定義していない。** ここが持ち帰りの本体。CoT の質を人間が採点するのではなく、**下流の軌道品質から逆算して定義している**。**言語による説明が、飾りではなく最適化の対象になっている。**

- **3 段構えのパイプライン。** (1) ドメイン instruction tuning で運転の基礎知識、(2) PCF-CoT で推論の形、(3) QS-GRPO で推論の質。**各段の役割が分離しているので、どこが効いたかを ablation で切り分けられる**構成になっている (本文で確認すべき点でもある)。

- **評価が open-loop と closed-loop 志向の両方。** nuScenes だけで語らず NAVSIM も出しているのは、この分野の最近の作法として妥当。**nuScenes の open-loop 指標だけで勝つのは容易**なことが知られているため、NAVSIM 側の数字が主張の実体になる。

## 追っているプロジェクトへの適用可能性

- **P1 / アイデア R1 (HIL 評価 × 保証付き安全指標) —— PCF は評価軸の候補そのもの。** R1 で我々は「衝突率だけでなく、過保守さや介入頻度を測る」ことを考えていた。**PCF は「その場面で planner に問われている判断」を列挙する概念**であり、08-11 の brief で書いた「シナリオを見た目ではなく要求される判断で分類し直す」という話と**同じ物を別方向から掴んでいる**。**評価スイートの分類軸として PCF の定義をそのまま借りられる可能性がある** —— 本文で PCF の taxonomy がどう作られているか (人手か、自動抽出か) は必読。

- **P1 / 評価指標としての「推論の妥当性」。** QS-GRPO は**推論経路を軌道品質で採点する仕組み**を持っている。これを学習ではなく**評価**に転用すると、**「planner の説明が、その planner の実際の判断を説明できているか」を測る指標**になる。説明可能性を主観評価ではなく数値で語れるので、R1 の figure として筋が良い。

- **P3 / R3 (VLA × world model 統合マップ) の中の位置づけ。** FactorDrive は **world model を持たない側の代表例** —— 未来を予測せず、**言語による推論で planning-critical な要因を明示化する**ことで同じ役割を果たそうとしている。本日の LDR (2608.09926) や ELWM (2608.09876) が「latent に物理を入れる」側だとすると、**FactorDrive は「言語に物理を入れる」側**。**R3 のマップにはこの対比を明示的に載せるべき。** 同じ「spatial-physical evidence を planning に接地する」という目的に、表現の異なる 2 つの解がある。

- **P2 への波及。** 3 段パイプラインの構造 (ドメイン instruction tuning → CoT で形を与える → RL で質を上げる) は、**基盤モデルを別ドメインに転用する recipe** として P2 の関心にも合う。特に **(1) の「ドメイン instruction tuning」だけで既にどこまで行くか**は、我々が知りたい「少データ適合の下限」に近い問い。ablation でここが分かるなら価値が高い。

- **注意点:** (1) **部品が多く、全体を再現する価値は低い。** 大規模 instruction tuning + CoT データ構築 + MCTS + GRPO を全部積むのは我々の予算では非現実的。**取るべきは「軌道品質で推論を採点する」という 1 点**に絞る。(2) **nuScenes の open-loop SOTA は主張として弱い** —— この指標は自車の過去軌道の外挿だけでかなり稼げることが知られている。**NAVSIM の数字と、その ablation だけを見る。** (3) **PCF が人手定義なら、本論文の本体は「良いラベル設計をした」という話**になり、手法としての一般性は落ちる。ここの読み方で評価が変わる。(4) MCTS を回すコストが post-training 全体でどれくらいかは abstract に無い。実務的にはここが採否を決める。

### 試すべき実験

1. **本文で PCF の作り方だけ先に確認する。** 人手 taxonomy か、データからの自動抽出か。**自動なら我々のシナリオ集合にそのまま回せて、P1 の評価軸の自動生成という話になる。** 人手なら考え方だけ借りる。判断はこの 1 節で決まる。

2. **PCF を評価スイートのタグとして試す (P1・既存資産で完結)。** 手持ちの評価シナリオ 20〜30 本に、本論文の PCF 定義でタグを付ける。**08-11 に書いた「要求される判断でシナリオを分類し直す」の具体的な語彙として PCF を使う。** ゼロから taxonomy を作らずに済むなら着手コストが一段下がる。

3. **「軌道品質で説明を採点する」を評価指標として実装する。** 我々の planner に説明を出させ、**同じ場面で説明が指した要因を無効化した (見えなくした) ときに軌道がどれだけ変わるか**を測る。変わらないなら**その説明は後付けであり、判断を説明していない**。QS-GRPO の逆向きの使い方で、実装は軽い。

4. **推論の長さを場面で変えることの効果だけを切り出す。** FactorDrive 全体ではなく、**「単純な場面では推論を短くする」**だけを既存モデルに入れて、**平均レイテンシと難所での性能**を測る。closed-loop では推論時間そのものが挙動を変えるので、**精度とレイテンシを同じ図に描く** (08-11 の SimWAM から持ち帰った作法)。

5. **ablation の (1) 段目だけを見る。** ドメイン instruction tuning のみでの数字が本文にあるなら、それは **「CoT も RL も無しで、適合だけでどこまで行くか」** の答えであり、P2 にとっては本論文で最も価値のある 1 行になる。
