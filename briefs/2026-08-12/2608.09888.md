# BDH-CQ: In-Context Learning with Recurrent Latent Reasoning

**topic:** sns_wildcard (EXPLORE) ・ **arXiv:** 2608.09888 ・ **published:** 2026-08-09 ・ **hf_upvotes: 207 (本日最高)**

> **wildcard 枠 (分野外だが注目度が高い探索枠、上限 1 件) として採用。** 本日の候補 52 件で最多の 207 upvotes、2 位以下 (146 / 115) にも差をつけている。題材は ARC-AGI という抽象推論パズルで、自動運転からは遠い。
>
> **採用理由は 2 つ。** (1) **150M パラメータで 29.5% pass@2、1 タスクあたり $0.0007** —— 既報の cost-accuracy Pareto 曲線を破ったと主張しており、**「小さいモデルが構造で勝つ」の実例**として本日の LDR (2608.09926, パラメータ 1/26 で勝つ) と同じ方向を指している。**大規模事前学習を回せない我々にとって、勝てる土俵の話。** (2) **推論を言語化せず latent 空間の反復計算でやる**という設計が、**CoT を前提にした本日の FactorDrive (2608.09591) の正反対**にあり、2 本を並べると設計空間の両端が見える。

## 何を解決する論文か

いま「推論する LLM」の主流は **CoT (chain-of-thought; 考えた過程を言葉として出力させ、その長さで計算量を稼ぐ方式)** である。しかしこれは**思考を言語として書き出すぶんだけ token を消費する**ので、難しい問題ほど推論コストが跳ね上がる。

BDH-CQ が採る道は違う。**in-context learning (推論時に与えられた例から、重みを更新せずにその場でタスクを学ぶこと)** と **recurrent latent reasoning (中間の思考を言葉にせず、高次元の latent 空間の中で反復計算として回す方式)** を組み合わせる。推論時に提示された入力は**モデルの recurrent memory (再帰的に保持される内部状態) を継続的に更新**し、モデルはその上で**言語化しない反復計算**によってクエリに答える。

評価は **ARC-AGI-1 (Abstraction and Reasoning Corpus; 少数の入出力例を見て背後の変換規則を推測し、新しい入力に適用する抽象推論ベンチ。「少数例からルールを掴む」能力を測る)** の公開評価セット。加えて、**ARC 風の統制された介入**を自作して、「例から何を学んでいるか」「推測した変換をどれだけ一貫して適用できるか」「どの概念が苦手か」を分析している。

## 手法の核心

- **推論の計算量を「token 数」から「latent の反復回数」へ移した。** ここが設計の中心。CoT は思考 1 ステップごとに token を生成するので、**計算量が出力長に縛られる**。latent で反復すれば、**出力を伸ばさずに計算だけ深くできる**。**$0.0007/task という桁違いのコストはこの構造から出ている**と読める。

- **in-context の例を「文脈」ではなく「memory の更新」として扱う。** 提示された例を prompt に並べて attention で参照するのではなく、**recurrent memory を継続的に書き換える**。長い文脈を毎回読み直すコストが消え、**例が増えても推論コストが線形に増えない**構造になる。

- **主張の単位が精度ではなく「コスト対精度」。** 29.5% pass@2 という絶対値は、大規模モデルの ARC-AGI スコアと比べて高くはない。**論文が主張しているのは Pareto frontier の突破** —— 同じコストなら誰よりも正確、同じ精度ならはるかに安い、という位置。**評価軸の取り方そのものが持ち帰る対象。**

- **統制された介入で「何を学んだか」を調べている。** ベンチのスコアだけで終わらせず、ARC 風の人工課題を作って**推測した変換規則の適用の一貫性**を測っている。**モデルが規則を掴んだのか、パターンを当てただけなのか**を切り分けようとする姿勢は、本日の LDR の分布外テストと同じ思想。

- **150M という規模。** 実験を回すのに大規模クラスタが要らない。**再現性という点で、本日の 6 本で最も手が届く。**

## 追っているプロジェクトへの適用可能性

- **P3 / R3 (次世代アーキテクチャ) —— 設計空間の見落としていた端。** 我々の R3 のマップは「VLA か world model か」「生成するかしないか」で組まれていた。BDH-CQ が突きつけるのは **「そもそも思考を言語化する必要があるのか」** という別の軸である。**FactorDrive (本日採用) は言語化する側の最先端、BDH-CQ は言語化しない側**。運転は**リアルタイム制約が厳しく、CoT の token 生成コストが直接レイテンシになる**ので、**「latent で反復して計算量を稼ぐ」は我々のドメインでこそ筋が良い可能性がある。** ここは R3 のマップに軸として追加する価値がある。

- **P3 / 「推論の深さを場面で変える」の別実装。** FactorDrive は推論の**長さ**を場面に応じて変えることで適応的な計算量を実現していた。BDH-CQ の枠組みなら、同じことが **latent の反復回数**でできる —— **出力の形式を一切変えずに、難所だけ計算を深くする**。closed-loop の planner にとって、これは実装上かなり嬉しい性質。**同じ目的に 2 つの実装がある**という整理ができる。

- **P2 / 「小さいモデルで構造で勝つ」の 2 例目。** 本日の LDR (パラメータ 1/26、速度 143 倍) と合わせて、**本日 2 本が独立に「規模ではなく構造」を主張している**。P2 の蒸留の文脈では、これは **「student を小さくしても、構造を変えれば teacher に迫れる場面がある」**という仮説の傍証になる。ただし**傍証以上ではない** —— どちらもタスクが特殊。

- **P1 への適用: ほぼ無い。** 評価指標の作法として「コスト対精度の Pareto で語る」を借りるくらい。ただしこれは我々にとっても正しい作法で、**planner の評価で精度とレイテンシを同じ図に描く**という 08-11 からの持ち帰りと完全に一致する。

- **注意点 (wildcard なので厳しめに):** (1) **ARC-AGI という単一ベンチへの依存が強い。** ARC は「少数例から規則を掴む」に特化した課題で、**この形に合わせて設計したモデルが強いのは当然**という批判が常に付く。汎用性の主張は本文で慎重に確認すること。(2) **upvotes 207 は「コスト効率の SOTA」という見出しの強さによる部分が大きい** —— コミュニティ注目度は relevance を上書きしない、という原則どおり、**注目度ではなく上記の構造的な理由で採用している**。(3) **latent reasoning は解釈性を捨てる。** 我々のドメインは説明可能性の要求が強く、**「何を考えたか出力されない」は実運用上のマイナス**になりうる。FactorDrive と正反対なのはここでもある。(4) **150M で 29.5% は、絶対性能としては実用域から遠い。** 持ち帰るのは仕組みであって、モデルそのものではない。

### 試すべき実験

1. **深追いしない、という判断を先に置く。** wildcard 枠であり、**本日の 6 本で我々の実務からの距離は最も遠い**。投資するのは**読む時間 30 分と、下の 2. の思考実験まで**。実装に手を出すのは、R3 のマップを描き直した結果この軸が重要だと分かってからでよい。

2. **R3 のマップに「思考を言語化するか」の軸を足す (机上・30 分)。** 既存のマップ (学習時/推論時に生成するか × latent にどれだけ構造を入れるか) に 3 本目の軸として追加し、**手持ちの手法を再配置してみる**。空白のセルが見つかれば、それが我々の研究の隙間になる。**本日の FactorDrive と BDH-CQ が両端に置ける**ので、軸として機能するかはすぐ判定できる。

3. **「反復回数で計算量を可変にする」を planner で考える。** 我々の planner に、**難所でだけ内部の反復を増やす**機構を入れたらどうなるか。既存の推論時 refinement (軌道を反復的に修正する仕組み) と何が違うのかを整理するだけでも価値がある。**実は既にやっていることの言い換えかもしれない**ので、そこの見極めが先。

4. **本文で確認すべき 1 点だけ決めておく。** **「recurrent memory の更新は学習で得た仕組みか、それとも手で設計した更新則か」**。前者なら我々のドメインにも学習で持ち込めるが、後者なら ARC に合わせた作り込みであり、移植価値は大きく下がる。
