# Learning How the World Evolves: Extrapolative Video World Models via Latent Dynamics Reasoning

**topic:** next_arch (P3) ・ **arXiv:** 2608.09926 ・ **published:** 2026-08-10 ・ **hf_upvotes: 0**

> **本日で最も「主張が大きい」1 本。** 「学習分布の外に外挿できた video world model は我々の知る限り初」と明言している。数字の出し方も強気で、**分布内と分布外の誤差の差が baseline の 1/20、パラメータ 1/26、速度 143 倍**。ただし検証は白箱の物理ベンチに閉じている (後述の注意点)。project page: https://lat-dyn-reason.github.io/

> 著者: Haodong Li, Shaoteng Liu, Tianyu Wang, Chongjian Ge, Sihui Ji ほか。

## 何を解決する論文か

現在の video world model (行動や条件を与えて未来の映像を生成するモデル) の主流は video diffusion で、**pixel を当てにいく**ように学習される。結果として**見た目はもっともらしいが、物理法則には従っていない**フレームを吐く。より本質的な問題は**外挿できない**ことで、学習で見た速度・見た物体の範囲を出た瞬間に予測が崩れる。世界モデルを planner の中で使いたい側から見ると、これは致命的である —— **planner が探索するのは、たいてい学習分布の縁か外だから。**

本論文の提案 **LDR (Latent Dynamics Reasoning)** は、latent 空間での時間遷移を「ニューラルネットが自由に学ぶ関数」ではなく、**明示的な kinematic integration (運動学的な数値積分。位置は速度の積分、速度は加速度の積分…という積み上げ)** として書く。低次の項 (位置・速度・加速度) は**数値積分で決め打ちし、ネットワークには 3 次以上の残差だけを回帰させる**。「世界が従う構造はハードコードし、残りだけ学習する」という発想。

## 手法の核心

- **latent transition を「学習する」から「積分する」へ変えた。** ここが全て。従来の latent world model は $z_{t+1} = f_\theta(z_t, a_t)$ をまるごと学習する。LDR は $z_{t+1}$ を**位置・速度・加速度の数値積分で構成し、ネットワークは jerk 以上 (3 次以上) の残差項だけを出力する**。学習させる量が小さくなるほど、**外挿は「関数の外挿」ではなく「積分の続行」になる** —— これが外挿性能の源泉。

- **積分する場所を structured latent に置いた。** 積分を **dense convolutional feature (畳み込みが出す高次元の特徴マップ)** の上でやっても効かない、と著者は明言する。**そこには「位置」に相当する量が素直に入っていないから**である。積分が意味を持つように**構造化された latent** の上で回す。**「どの空間で微分方程式を書くか」が性能を決める**という主張で、ここが再現の要になる。

- **評価を白箱の物理ベンチに絞った (PhyWorld 準拠)。** uniform motion / parabola / collision / bouncing / looming の 5 タスク。**正解の法則が既知なので、「本当に法則を学んだか」を分布外で直接テストできる**。曖昧さを排すための意図的な設計。

- **主結果は「分布内と分布外の誤差の差」。** 絶対誤差ではなく**ギャップ**で語っているのが正しい。**baseline (video diffusion) の 20 分の 1 未満**。単一タスク学習でも複数タスク同時学習でも、256×256 で成立。

- **効率が桁で違う。** **パラメータ 26 分の 1、実行 143 倍速。** planner のループに入れることを考えると、この差は「性能が良い」ではなく「**使えるかどうか**」の差になる。

- **一般化の質が定性的にも異常。** **赤い球が左→右に動く映像だけで学習して、青い四角が右→左に動く運動を正しく予測する**。見た目・色・形・向きを全部変えて成立するということは、**モデルが持っているのは見た目の記憶ではなく運動の規則**である、ということの直接的な証拠になっている。

## 追っているプロジェクトへの適用可能性

- **P3 / アイデア R3 (VLA × world model 統合の分類マップ) —— 軸が 1 本増える。** 昨日 (08-11) の SimWAM から我々は「**学習時に生成するか / 推論時に生成するか**」という軸を得た。LDR が足すのは **「latent の遷移をどれだけハードコードするか」** という直交軸である。両端は「全部学習 (video diffusion, DINO-WM 系)」と「低次は積分・残差だけ学習 (LDR)」。**R3 のマップはこの 2 軸で描き直すべき。**

- **P3 / driving policy への直接の翻訳が効く。** 自動運転は **LDR の前提が最初から成立している稀な領域**である —— 他車も自車も**位置・速度・加速度が意味を持つ物理量として存在し、しかも観測できる**。「latent に位置と速度の構造を持たせる」は、汎用の embodied 設定では難しいが**我々のドメインでは自然**。本日の 2608.09876 (ELWM) が energy/momentum を latent に持たせているのと同じ方向で、**本日 2 本が独立に「latent に物理構造を入れろ」と言っている**のは注目に値する。

- **P1 / 評価の作法として持ち帰る。** **「分布内の誤差」ではなく「分布内と分布外の誤差のギャップ」で報告する**という指標の立て方は、我々の trajectory prediction / planner 評価にそのまま使える。**分布内の誤差だけを競うと、暗記したモデルが勝つ。** closed-loop 評価では planner が分布の外に出るのが常なので、**ギャップを主指標にするのは我々の主張としても筋が良い。**

- **P3 / 計算予算の話として。** 26 分の 1 のパラメータで勝つという結果は、**world model の性能はスケールではなく構造で決まる場面がある**ことを示している。我々のリソース制約 (大規模事前学習を回せない) からすると、**この方向は「勝てる可能性のある土俵」**として重要。

- **注意点 (重い):** (1) **検証が完全に白箱の合成ベンチに閉じている。** PhyWorld の 5 タスクは背景も剛体運動もクリーンで、実世界の映像は一切入っていない。**「初の外挿する world model」という主張は、この設定の中での話**として読むこと。実写・多物体・遮蔽・非剛体で同じ分解が成立する保証はどこにもない。(2) **structured latent の定義が abstract に無い。** ここが手法の当たり外れを全部決める。**本文で最初に読むべきはこの 1 節。** 手作りの構造なら我々のドメインへの移植は自前設計になり、学習で得られる構造なら移植は容易になる。(3) **3 次以上の残差という切り方の妥当性**が、接触・衝突のような不連続現象でどうなるか。collision と bouncing がタスクに含まれてはいるが、**不連続を積分で扱うのは原理的に無理があるはず**で、本文の該当箇所は疑って読む。

### 試すべき実験

1. **本文で structured latent の定義だけ先に確認する (30 分)。** ここが手作りなら翻訳コストが大きく、学習ベースなら小さい。**以降の投資判断がこの 1 節で決まる**ので、他を読む前にここへ行く。

2. **我々の trajectory prediction を「積分 + 残差」に書き換える最小実験。** 既存の予測モデルの出力を、位置の直接回帰から **「速度・加速度を積分した項 + ネットワークが出す残差」** に変える。モデルもデータも変えず**出力パラメータ化だけ**を変える。これは数日で終わり、しかも LDR の主張の核だけを取り出せる。

3. **分布内/分布外ギャップで評価する (2. の評価軸)。** 学習を通常の速度域に絞り、**高速域・急減速域を held-out にして**、通常のモデルと 2. のモデルでギャップを比較する。**改善するのがギャップであって分布内誤差ではない**、という点を最初から測りにいく。

4. **不連続現象で壊れるかを狙って見る。** カットイン、急制動、他車との接触寸前のような**加速度が飛ぶ場面**だけを取り出して 2. を評価する。**滑らかな運動でだけ効くのか、不連続でも効くのか**は、我々にとって最も重要な区別。論文が答えていないところでもある。

5. **効率を我々の環境で実測する。** 143 倍という数字ではなく、**自前の planner ループに入れたときの 1 step あたりの実時間**を測る。world model を推論時に使う設計 (SimWAM とは逆側) が現実的になるかどうかの分水嶺。
