# Mismatch Matters: On-Policy Distillation Beyond Token Agreement

**topic:** fm_distill_finetune (P2) ・ **arXiv:** 2608.09836 ・ **published:** 2026-08-10 ・ **hf_upvotes: 0**

> **本日の最有力。** 我々が追っているアイデア R2 (蒸留の capacity gap 系統則 —— teacher/student の容量比と破綻境界) に、**本日の候補 52 件で唯一まっすぐ刺さる**論文。しかも著者自身が「**teacher と student の乖離が大きいときほど効果が大きい**」と主張しており、**capacity gap がまさに主戦場**になっている。コードも公開済み (github.com/yzc-666/TIDE)。
>
> 著者: Zichao Yu, Chengzhi Yu, Shengze Xu, Yujin Han, Bingqing Jiang ほか。

## 何を解決する論文か

**on-policy distillation (OPD; student 自身が生成した文に対して teacher の確率を教師信号として与える蒸留。teacher の生成文を真似させる従来の off-policy 蒸留と違い、student が実際に踏む分布の上で矯正できる)** は、いまや LLM の post-training で標準部品になっている。本論文はその OPD に **degenerate agreement (見せかけの一致)** という失敗モードがあることを指摘する —— **student が同じフレーズを延々とループさせると、teacher との token 一致度は極めて高くなる**。teacher も「いま出ている繰り返しの続き」としては同じ token を高確率で予測するからだ。応答全体としては壊れているのに、指標上はほぼ完璧に見える。

そこで著者は視点を「一致 (agreement) を最大化する」から「**mismatch (teacher と student の不一致) をどう扱うか**」に切り替える。mismatch を 2 種類に分解し、それぞれ別々の壊れ方をすることを示したうえで、両方に個別の対処を当てる **TIDE (Token-level Independent Deficit-Excess correction)** を提案する。

## 手法の核心

- **mismatch を 2 方向に分解したのが本体。** 従来は「teacher と違う」を一つの誤差として扱っていたが、方向によって病理がまったく違う。
  - **student-excess token**: student が出しているのに teacher はほぼ確率ゼロを割り当てる token。**log 比 (teacher/student の確率の対数比) が下に発散する**ため、この 1 token が勾配を支配して更新が壊れる。**害は「学習が不安定になること」。**
  - **student-deficit token**: teacher は出したいのに student がほとんどサンプルしない token。**そもそもサンプルされないので学習信号に現れない**。**害は「teacher の推論パターンが永久に伝わらないこと」。** on-policy が構造的に抱える穴で、student のサンプルだけを見ている限り原理的に埋まらない。

- **excess 側は Hellinger shaping で bounded にする。** **Hellinger distance (2 つの確率分布の差を測る距離の一種で、上限が有界)** を使った重み付けに置き換えることで、log 比が発散しても補正量が青天井にならないようにする。**「外れ値 token 1 個で更新が飛ぶ」を構造的に殺す**、という発想。

- **deficit 側は teacher の top-K を解析的に注入する。** サンプルされるのを待たずに、**teacher の上位 K 個の token の確率質量を直接 loss に入れる**。ここが賢い点で、**「サンプルされないから学べない」という on-policy の原理的な穴を、サンプリングを介さない項を足すことで回避している**。K 個ぶんの teacher 確率は forward 1 回で取れるので、追加コストはほぼ無い。

- **2 つの補正を独立に (Independent) 当てる。** 名前の I がそれ。単一の重み付け関数で両方を面倒見ようとせず、原因が違うものは別々に直す。**実装として素直で、片方だけを ablation で外せる**のが実務的に有難い。

- **効果が「乖離が大きいほど大きい」。** 強い mismatch の設定で **Avg@8 が 6.9% → 20.3%** (約 3 倍)、同時に**応答長が 1/3.6 に短縮**、format 崩れも大幅減。**応答長が縮んでいるのは degenerate agreement (ループ) が実際に潰れた直接の証拠**で、主張と数字が噛み合っている。検証は Qwen3 系の複数 teacher-student ペア × 数学推論ベンチ。

## 追っているプロジェクトへの適用可能性

- **P2 / アイデア R2 (capacity gap の系統則) —— ここが本命。** R2 は「teacher と student の容量比を振ったときに、どこで蒸留が破綻するか」を系統的に測る話だった。**本論文はその破綻の機序に名前を与えている**: 破綻は「student が teacher を再現できないこと」一般ではなく、**excess 側 (発散する勾配) と deficit 側 (伝わらない知識) という 2 つの別々の量**である。つまり **R2 の測定軸が 1 本から 2 本に増える**。容量比を振りながら excess 量と deficit 量を別々にプロットすれば、**「どちらが先に効いてくるか」で破綻境界を説明できる**可能性がある。これは R2 の figure としてかなり強い。

- **P2 / 他機種・他ドメインへの適合。** 我々の設定での「強い mismatch」は容量差だけではない。**teacher と student が別ドメイン (別機種・別センサ構成) を見ている**ときも、student は teacher が確率ゼロを振る出力を平気で出す。**TIDE の bounded shaping は、この「ドメインずれ由来の excess」にもそのまま効くはず**で、蒸留と domain adaptation の境目に置ける道具になる。

- **P2 / 実務上の即効性。** 我々の蒸留パイプラインが OPD 系なら、**追加するのは loss の 2 項だけ**。データ収集も報酬設計も rollout の変更も要らない。**投資対効果が本日の 6 本で最も高い。**

- **P3 への波及 (間接的)。** VLA や driving policy の蒸留では出力が離散 token ではなく連続な軌道であることが多く、**top-K 注入がそのままでは使えない**。ただし excess/deficit の分解自体は連続分布でも定義できる (student の density が高く teacher が低い領域 = excess)。**概念の移植は効くが、実装は書き直しになる**という距離感。

- **注意点:** (1) 検証が**数学推論ベンチと Qwen3 系に閉じている**。degenerate agreement は「繰り返しが自然な言語生成」で起きやすい病理で、**我々のタスクで同じ形で出るとは限らない**。(2) **top-K の K と Hellinger の温度が新しいハイパーパラメータとして増える**。この 2 つに敏感なら実務での再現性が落ちるので、本文の sensitivity の節を必ず見る。(3) 「6.9% → 20.3%」は**強い mismatch という著者が選んだ設定での数字**であり、通常設定での改善幅は本文の表で別途確認すること。

### 試すべき実験

1. **まず診断だけやる (最優先・半日)。** 既存の蒸留 run のログから、**student が生成した token のうち teacher 確率が閾値以下のもの (excess) の割合**と、**teacher top-K に入っているのに student が一度もサンプルしなかった token の割合 (deficit)** を数えるだけ。**この 2 つの数字が小さければ、我々の設定に TIDE の前提は無く、以降は不要。** 処方より先に診断。

2. **degenerate agreement が自分の run で起きているか確認する。** 蒸留中の **応答長の推移**と **token 一致率の推移**を同じ図に重ねる。**一致率が上がりながら応答長も伸びていたら、ループで稼いでいる**。この 1 枚で失敗モードの有無が分かる。

3. **capacity gap を振って excess/deficit を別々に測る (R2 の本体)。** teacher を固定し student サイズを数点振って、1. の 2 指標を容量比の関数としてプロットする。**片方だけが先に立ち上がるなら、破綻境界の説明変数が特定できた**ことになり、これが R2 の中心 figure になる。

4. **2 項を別々に ablation する。** TIDE をそのまま入れるのではなく、**Hellinger shaping だけ / top-K 注入だけ**を先に試す。3. で excess が支配的なら前者だけで足りるはずで、**予測が当たれば機序の理解が正しいことの検証にもなる**。

5. **ドメインずれ mismatch でも成立するか。** 容量は同じで**ドメインだけずらした** teacher-student ペアを作り、excess/deficit の分解が同じ形で出るか見る。出るなら P2 の「他機種への適合」に蒸留の道具をそのまま持ち込める。
