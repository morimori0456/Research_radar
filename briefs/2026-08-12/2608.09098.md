# UnsDrive: Towards Robust End-to-End Autonomous Driving in Unstructured Scenes

**topic:** planner_ai (P1) ・ **arXiv:** 2608.09098 ・ **published:** 2026-08-10 ・ **hf_upvotes: 0**

> **P1 の本枠として本日唯一の採用。** 採用理由は手法そのものより **「新しい closed-loop simulator (MineLoop) を出している」**点 —— topics.yaml の relevance_criteria が「ベンチマーク/評価手法の新提案は特に高優先」と明示している枠にまっすぐ当たる。加えて **unknown space (まだ観測できていない領域) を明示的に表現に持つ**という設計は、都市部の planner にもそのまま効く。

> 著者: Nanxin Zeng, Ruiqi Song, Xiangyu Guo, Baiyong Ding, Yunfeng Ai。

## 何を解決する論文か

end-to-end の planner (認識から軌道生成までを 1 つのネットワークで学習する方式) は都市部の**構造化された道路**を前提に作られてきた。車線があり、境界が明確で、地図と対応が付く世界である。本論文が対象にするのは**鉱山のような非構造環境** —— 車線が無いか曖昧で、地形の起伏で視界が遮られ、砂塵で見通しが悪く、**そもそもシーンの大部分が「観測できていない」**。この条件では既存手法の一般化が崩れる。

UnsDrive の中心的な主張は、**「見えていない」を「何も無い」と同一視するのをやめろ**、というものである。占有格子を **occupied (何かある) / free (空いている) / unknown (観測できていない)** の 3 状態で持ち、この表現を条件として軌道を生成する。加えて評価のために **MineLoop** という鉱山向け closed-loop simulator を作った。

## 手法の核心

- **unknown-aware occupancy が本体。** 通常の occupancy 表現は「占有」と「非占有」の 2 値 (または占有確率) で、**「見ていないから分からない」が「空いている」に潰れる**。UnsDrive は **multi-frame visibility cue (複数フレームにわたる「どこが見えていたか」の情報)** を使って unknown を第 3 の状態として明示的に持つ。**認識の不確かさを、planner が読める形の空間表現に変換している**のがポイント。

- **flow-matching planner で多峰の軌道を出す。** **flow matching (ノイズから目標分布へ連続的に変換する経路を学習する生成手法。diffusion に近いが、少ないステップで生成できることが多い)** を occupancy 表現で条件付けし、**複数の将来軌道候補**を生成する。非構造環境では「正解の 1 本」が定まらないので、多峰にするのは設計として自然。

- **occupancy trajectory consistency loss。** 生成した軌道と occupancy 表現の**整合を loss として直接課す**。「表現は unknown を知っているのに、軌道生成器がそれを無視する」ことを防ぐ仕掛け。**表現を持つことと、それが使われることは別問題**という認識が入っている。

- **uncertainty-aware trajectory scorer。** 生成された候補軌道を採点する段で、**非走行可能領域だけでなく unknown 領域に踏み込む軌道にもペナルティ**を与える。**「見えていない場所には入らない」を、報酬ではなくスコアリングで実装している**。ここは我々の設定でもそのまま流用できる形。

- **MineLoop (closed-loop simulator)。** 不規則な路面形状、視界劣化、大型車両との相互作用、鉱山特有の運用制約を再現する。**open-loop と closed-loop の両方で評価**し、軌道精度・衝突回避・長時間走行の頑健性で baseline を上回ったと報告。

## 追っているプロジェクトへの適用可能性

- **P1 / 「見えていない」を planner の入力にする —— 本日一番の持ち帰り。** 我々の planner 評価で扱いにくかったのは**遮蔽下の判断**である (08-11 の brief でも「オクルージョン下の推定」を評価軸候補に挙げた)。UnsDrive は**その扱い方の実装を 1 つ提示している**: 3 値の occupancy + unknown へのペナルティ。**鉱山という設定は我々から遠いが、この部品は都市部でもそのまま意味を持つ** —— 駐車車両の陰、交差点の建物の陰は、まさに unknown である。

- **P1 / アイデア R1 (保証付き安全指標) との接続。** R1 は「衝突率だけでなく**過保守さ**も測る」話だった。**unknown へのペナルティは、過保守さを直接生み出すつまみ**である —— ペナルティを上げれば安全になるが、遅く・臆病になる。**このつまみを振って「衝突率 vs 過保守さ」の曲線を描けば、R1 の中心 figure がそのまま作れる。** 本論文自体はこのトレードオフを主題にしていないので、**空いている**。

- **P1 / 評価の作法。** 新しい simulator を出す論文の常として、**MineLoop がどう検証されているか**は我々にとって教材になる。R1 で評価手法を提案するなら、「その評価が現実と対応していること」をどう示すかが最大の争点になる。**本文の simulator の節は、手法の節より我々にとって価値がある可能性が高い。**

- **P3 への接続 (弱い)。** occupancy を中間表現として持ち、そこから flow matching で軌道を出す構成は、E2E アーキテクチャの一系統として R3 のマップに置ける。ただし **world model (未来を予測する) ではなく現在の空間表現**なので、位置づけは周辺。

- **注意点:** (1) **ドメインが遠い。** 鉱山環境固有の設計 (地形起伏、大型車両、運用制約) が混ざっており、**どこまでが unknown-aware の効果で、どこからが鉱山向けチューニングか**を切り分ける必要がある。ablation を見る。(2) **MineLoop が公開されるかどうか**が価値を大きく左右する。非公開なら、我々が使えるのは設計の考え方だけ。(3) **baseline が都市向け手法なら、非構造環境で負けるのは当然**であり、比較として弱い。**「都市データでも同等以上か」が書かれているか**を確認すること。書かれていなければ、主張は「鉱山では効く」に留まる。(4) hf_upvotes 0、著者グループも大手ではない。**数字を鵜呑みにせず、部品として読む。**

### 試すべき実験

1. **既存の planner の occupancy 表現を 3 値化する (最小改造)。** 現在 2 値 (または占有確率) で持っているものに **unknown を第 3 状態として足すだけ**。可視性の計算は既存のセンサ幾何から出せる。**表現を変えるだけで挙動が変わるか**を、遮蔽のあるシナリオに絞って見る。

2. **unknown ペナルティの強さを振って「衝突率 vs 過保守さ」の曲線を描く (R1 の本体・最優先)。** 過保守さの代理指標は**平均速度・不要な減速回数・到達時間の悪化**。**この 1 枚の図が R1 の主張の核**になり、しかも本論文が提供していない図である。既存資産だけで作れる。

3. **遮蔽シナリオだけを抜き出して評価を分離する。** 全体平均で語ると unknown の効果は薄まる。**遮蔽の有無でシナリオを二分し、それぞれで指標を出す。** 効果が遮蔽側にだけ出るなら機序の説明として綺麗で、出ないなら我々の実装が unknown を使えていない証拠になる。

4. **scorer だけを既存の planner に後付けする。** 学習を伴わない **uncertainty-aware trajectory scorer** は、候補軌道を出す既存の planner に**推論時だけ足せる**。学習コストゼロで効果が見えるので、1. より先にこちらを試してもよい。

5. **MineLoop の公開状況と、simulator の妥当性検証の節を確認する。** R1 で評価手法を提案する立場としては、**「新しい simulator の正当性をどう論証したか」が最も学ぶべき部分**。公開されていれば、非構造環境という別ドメインでの planner 評価の追試にも使える。
