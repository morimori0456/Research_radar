# Real Data Closes Synthetic-to-Real Gap in Optical Chemical Structure Recognition

**topic:** fm_distill_finetune (P2) ・ **arXiv:** 2608.09100 ・ **published:** 2026-08-10 ・ **hf_upvotes: 0**

> **題材 (化学構造式の読み取り) は我々から最も遠いが、本日で最も「実務に効く数字」を持っている 1 本。** 21 個の recognizer を fine-tuning して、**(a) 実データの混ぜる比率、(b) base model の選択、(c) vision tower を LoRA で適合させるか**の 3 つを系統的に振っている。P2 の関心 —— 少データでのドメイン適合、synthetic-to-real gap、PEFT の効き方 —— に対して、**「うちのデータで試したらこうだった」ではない、条件を振った実測**が並んでいる。
>
> 著者: Yani Guan, Dengpan Dong, Zi Wei, Shuang Luo, Dan Hannah ほか。**著者自身が最後に「この結論は化学に限らない」と書いており、手書き数式→LaTeX と図表→表の 2 タスクで追試している。**

## 何を解決する論文か

**OCSR (Optical Chemical Structure Recognition; 論文や特許に画像として載っている化学構造の図を、機械可読な構造式に変換するタスク)** は、**合成画像 (レンダリングして作った綺麗な図) ではほぼ解けている**ことになっている。ところが実文書では壊滅する —— 出発点の Qwen2.5-VL-7B は**合成レンダリングで 91% 超、実文書の 3 ベンチで 16% 未満**。この **75 ポイントの落差**が問題設定である。

著者は「何が効くのか」を当てるために、**VLM の base model × 実データ比率 × vision tower の適合戦略**を組み合わせて 21 個を fine-tuning し、**寄与を分離した**。結論は身も蓋もない: **効いたのは「ラベル付きの実データを少し混ぜること」で、しかもごく少量から効く。**

## 手法の核心

- **手法ではなく統制実験である、というのが本論文の性格。** 新しい loss も新しい構造も出てこない。**「どの適合の打ち手が、どれだけ効くか」を条件を振って測った**だけ。だからこそ recipe としてそのまま読める。

- **実データはごく少量から効く。** Qwen2.5-VL で ACS ベンチの exact match が **実データ 0% で 0.15 → 9.5% 混ぜて 0.37 → 50.2% 混ぜて 0.46**。**最初の 9.5% が改善のほとんど (0.22 のうち 0.15 弱) を持っていく**。以降は伸びが鈍る。**「少データでの適合」の効き方として、これはかなり強い実証。** 3 つの base model を使った統制実験で同じ傾向を再現している。

- **vision tower への LoRA は base model 次第で意味が変わる (本論文で最も面白い結果)。** **LoRA (Low-Rank Adaptation; 元の重みを凍結し、低ランクの差分行列だけを学習する代表的な PEFT (parameter-efficient fine-tuning) 手法)** を**画像側のエンコーダ**に当てたときの効果が、base model によって**まったく違う**:
  - Qwen2.5-VL: **+0.00** (対応のある検定で p=1.00 —— 完全に無効)
  - InternVL3-8B: **+22.8 〜 +34.6 ポイント**
  - GLM-4.1V-9B: **+1.0 〜 +9.6 ポイント**
  
  **同じ PEFT の打ち手が、片方では最大級の効果、片方ではゼロ。** 「vision tower も適合させるべきか」という問いに**普遍的な答えは無い**、というのが結論。

- **base model の順位が実データ比率で入れ替わる。** base model 間の差は**実データ無しで最大 (0.21) → 実データ 70% で 0.06 に縮み、しかも順位が変わる**。つまり **「まず base model を選び、次に適合方法を決める」という手順そのものが間違っている。** 両者は相互作用するので**同時に選ぶ必要がある**。

- **結論の一般性を自分で試している。** 化学だけの話ではないかと疑われることを見越して、**手書き画像→LaTeX** と **図表→表** で小規模に追試し、**base model の順位がタスクによって変わる**ことを確認している。主張の書き方として誠実。

## 追っているプロジェクトへの適用可能性

- **P2 / 「synthetic で学習して real に持っていく」の投資配分 —— ここが直撃。** 我々の設定でも**シミュレータで作ったデータ**と**実車で取ったラベル付きデータ**の混合比は常に問題になる。本論文の答えは明確で、**実データは「少し」で大きく効き、増やしてもすぐ鈍る**。これが我々のドメインでも成立するなら、**「実データのラベル付けをどこまでやるか」という高コストの意思決定に、飽和点という判断基準が入る。**

- **P2 / PEFT の当て方について。** 我々は「LoRA をどこに当てるか (言語側か、視覚側か、両方か)」を経験と勘で決めがちだが、本論文は **その答えが base model 依存であり、移植できない**ことを示した。**持ち帰るべきは「vision tower にも当てろ」ではなく、「base model を変えたら当て方の実験をやり直せ」**。これは我々の実験計画に直接効く (=過去の結論を新しい backbone にそのまま流用してはいけない)。

- **P2 / 実験設計の作法。** **base model × 適合戦略 × データ混合比を独立に選ばず、交互作用として扱う**という設計は、我々の適合実験の組み方をそのまま是正する。**1 変数ずつ振って最良を積み上げる (greedy な探索) と、順位が入れ替わる領域で必ず間違える。**

- **P1 / P3 への波及。** 直接は薄い。ただし **「合成データで測った性能は、実データでの性能をまったく予測しない (91% vs 16%)」** という落差は、closed-loop simulator で planner を評価する我々にとって**警告として読む価値がある** —— 本日採用の UnsDrive (2608.09098) が新しい simulator を出していることと並べて読むと効く。

- **注意点:** (1) **タスクが構造化された記号出力 (構造式・LaTeX・表)** で、我々の連続値の軌道出力とは性質が違う。**「実データが少量で効く」の量的な結論 (9.5% という数字) は移植しない。** 移植するのは**「飽和点を測れ」という方法論**の方。(2) exact match という厳しい指標なので、改善幅が大きく見えやすい。(3) **base model の依存性が強すぎる**ため、本論文の個別の数字はどれも我々の base model には当てはまらない。**この論文の価値は数字ではなく、「数字が移植できないことを示した」点にある。**

### 試すべき実験

1. **自分たちの synthetic-to-real gap を 1 つの数字にする (半日)。** 合成データのみで学習したモデルを、**合成の held-out と実データの held-out の両方で評価**して、落差を測る。**この落差が小さいなら、以下は全部不要。** 大きいなら、それが我々の 91%→16% であり、投資判断の起点になる。

2. **実データ比率の飽和曲線を描く (最優先)。** 実データを 0 / 5 / 10 / 25 / 50% と混ぜて、**実データ評価での性能をプロットする**。**膝がどこに来るか**が、ラベル付け予算の答えになる。本論文が「最初の 10% で大半が取れる」と言っているので、**低い比率を細かく刻む**のが正しい設計。

3. **vision tower LoRA の有無を、我々の base model で測り直す。** 本論文の結論は「効果は base model 依存」なので、**他所の結果を引用せず自分で測るしかない**。逆に言えば、これは 1 回測れば以後の設計が固定できる、費用対効果の高い実験。

4. **base model × 実データ比率の交互作用を見る (2. と 3. の統合)。** 候補 base model を 2 つに絞り、**それぞれで 2. の曲線を描く**。**曲線が交差するなら**、「どの base model が良いか」は実データ量を決めるまで答えられない、ということが我々の設定でも成立する。**交差の有無だけを見る実験**なので点数は粗くてよい。

5. **合成データの「質」ではなく「比率」に議論を移す。** 我々はしばしば synthetic の忠実度を上げる方向に投資するが、本論文の結果は**少量の実データの方が安く効く**可能性を示している。**同じ工数を「合成の質を上げる」と「実データを 10% 用意する」に配分して比較する**のが、最も判断を変える実験。
