## 何を解決する論文か

video world model (行動やカメラ操作を条件に、次のフレームを生成して環境をシミュレートする動画生成モデル) は、長く動かすと前に見た場所の見た目を忘れる。同じ場所に戻ったり視点を変えたりすると、建物の形や物の配置が変わってしまう。この論文は、過去の観測を「これから見たい視点」に合わせて圧縮して保持する memory を入れ、分単位の探索でも一貫性を保てるようにした。

## 手法の核心

- **camera-queryable な memory:** 過去の観測をすべて保持するのではなく、**次に生成したいカメラ姿勢 (位置と向き) を query にして**、その視点に関係する情報だけを読み出す。
- **target view-specific tokens (生成先の視点専用の固定数の token):** 複数の過去フレームにまたがる情報を、memory encoder と pose-conditioned readout (カメラ姿勢を条件にした読み出し器) が**固定数の token にまとめる**。まとめるのは denoising (拡散モデルがノイズを除いて画像を作る生成過程) の前である。生成器が扱える token 数には上限がある。その枠に何を詰めるかを「どこを見たいか」で決める、というのが論文の主張の中心。
- **明示的な 3D を使わない:** depth (深度) 推定や点群による対応付けはしない。3D の整合は、生成器と memory を同時に学習させることで暗黙に獲得させる ("implicit 3D-aware")。
- **短期と長期を分ける:** 直近のフレーム (temporal context) は別経路で入れ、memory は長期の整合だけを担当する (推測: 動きの連続性は直近フレームで、場所の一貫性は memory で、という役割分担)。
- **few-step distillation:** 多数ステップで生成する teacher を、数ステップで生成する student に蒸留する。これで streaming (生成しながら逐次表示する) 探索を実時間に近づけている。単一画像かテキストから始められる。

## プロジェクトへの適用可能性

### P3 (次世代アーキテクチャ) — 3.5: R3 の軸 ①「時間をどこに持つか」に、新しい 1 点を足す

R3 (VLA × world model 統合アーキテクチャ) の分類マップには、軸 ①「時間をどこに持つか」がある。**WorldCrafter の memory は、時刻ではなく空間 (視点) で索引を引く。**過去を「いつ見たか」ではなく「どこから見たか」で引き出す設計である。運転の world model は普通、直近 N フレームの時間窓で過去を持つ。この設計だと、交差点を一周して戻ったときに以前の見た目を保証できない。

**R3 は今月は着手しない方針なので、実験は積まない。**分類マップを作るときに、軸 ① の候補として「空間索引の memory」を 1 行足すだけにする。

**実験アイデア (R3 再開時・GPU 要):** 公開されている driving world model で、**ループ軌跡 (同じ地点に戻る経路) を与えて 1 周目と 2 周目の同地点フレームを比較する** (LPIPS 等の知覚的な画像距離、または物体検出結果の一致率)。時間窓型の memory でどれだけ崩れるかを測れば、空間索引の memory が必要かどうかの根拠になる。

### P1 (Planner AI + 評価) — 2.0: 生成型シミュレータで閉ループ評価をするときの前提条件

world model をシミュレータにして planner を閉ループで評価する場合、**planner が元のログから外れて同じ場所を別の角度から見ると、world model が世界を作り変えてしまう。**これは planner の良し悪しではなくシミュレータの欠陥による失敗で、R1 の「抜け穴監査 (分母の健全性)」の対象になる。ただし R1 は今は 2D toy で進めているので、直接は効かない。

### P2 (蒸留 + fine-tuning) — 1.5

few-step distillation は使っているが、abstract には recipe の詳細が無い。拡散モデルのステップ数蒸留は、P2 が扱う「大きいモデルから小さいモデルへ」の蒸留とは目的が違う。P2 の実務に移る知見は無いと判断した。
