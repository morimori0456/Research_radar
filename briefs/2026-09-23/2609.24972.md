> 本ブリーフは abstract のみに基づく (abstract は末尾 "while pr" で切れている)。critic と pruner の判定基準、各 benchmark の内訳は abstract に無い。書いていない部分は「推測」と明記した。

## 何を解決する論文か

LLM agent の性能は、backbone (中核の LLM) を包む harness (prompt、制御フロー、ツール、memory、context 管理の総称) に大きく左右される。最近はこの harness を自動で改良する手法が増えた。「編集案を出す → benchmark で試す → 良ければ採用」を繰り返す、agent 版の RSI (recursive self-improvement; システムが自分自身を反復的に改良すること) である。この論文の問題提起は、**この反復が学習用タスクに overfit する**ことだ。改良に使ったタスクでは点が大きく上がるが、OOD (out-of-distribution; 改良に使っていない種類の) benchmark ではその伸びが縮むか消える。そこで、機械学習の regularization (過学習を抑える制約) の考え方を、編集案の「提案」と「選択」の両方に入れた。

## 手法の核心

- **提案側: 編集の予算を時間とともに絞る** (temporally annealed budget)。1 つの候補に束ねてよい編集の数に上限を設け、反復が進むほど上限を下げる。一度に大量の変更を入れて、たまたま点が上がる候補を作れないようにする。
- **提案側: 未探索の方向を優遇する。**進化の履歴を見て、まだ試していない変更の方向を促す。同じ方向の微修正ばかりになるのを防ぐ。
- **選択側の critic:** 「この benchmark でしか効かなさそうな」編集案 (benchmark-specific proposal) を、採用前にふるい落とす (判定方法は abstract に無い。推測: LLM に「この変更は他のタスクでも意味があるか」を判定させる)。
- **選択側の pruner:** 効果が小さすぎる変更、コストが高すぎる変更、途中から役に立たなくなった変更を取り除く。
- **結果:** coding・agentic workspace・工学設計の 8 benchmark で評価した。改良に使った split では最大 +14.1 point。**改良に使っていない 5 benchmark でも最大 +4.7 point。**つまり「使い回せる仕組み」が残った、という主張である。

## プロジェクトへの適用可能性

### P1 (Planner AI + 評価) — 3.0: 「同じシナリオ集合で planner を反復調整すると何が起きるか」を測る枠組み

planner の開発も、同じ構造の反復である。閉ループ benchmark で planner のパラメータやルールを直し、点が上がれば採用する。これを繰り返すと、**benchmark のシナリオに固有の癖に合わせた変更**が混ざる。RRSI の「改良に使った split での伸び」と「使っていない split での伸び」の差は、そのまま **planner 評価における benchmark overfit の大きさ**の測り方になる。

R1 (閉ループ評価で「衝突率の隣に置く量」を定義する) との接点は 2 つある:
1. R1 の新しい指標も、同じシナリオ集合で定義・調整すれば同じ overfit を受ける。**指標を作った split と検証する split を分ける**ことは、R1 の論文で必ず聞かれる。
2. critic の「benchmark 固有の変更をふるい落とす」は、R1 の抜け穴監査 (分母の健全性) と同じ問いを、改良の手順側から見たものである。

**実験アイデア (半日・GPU 不要・2D toy で可):**
1. 2D toy のシナリオ集合を split A (調整用) と split B (検証用) に分ける。B は A と分布をずらす (障害物密度や速度を変える)。
2. パラメータ付きのルールベース planner を用意し、A の衝突率が下がる変更だけを採用する greedy な反復探索を N 回回す。
3. 反復回数ごとに **A の衝突率改善 と B の衝突率改善** を 2 本の線でプロットする。
4. RRSI の制約を 1 つだけ入れる: **1 反復で変えてよいパラメータ数を 1 個に絞り、反復が進むほど変更幅も小さくする。**
5. **判定:** 制約ありで A と B の差 (overfit) が縮めば、「反復調整の手順自体が評価を歪める」ことを toy で示せる。R1 の本文で「指標の妥当性は split を分けて確認した」と書く根拠になる。差が縮まなければ、toy の分布ずれが小さすぎる可能性がある。その場合は B のずらし方を強めて再確認する。

### P2 / P3 — 1.0

harness の改良は、モデルの重みを変えない。蒸留にも fine-tuning にもアーキテクチャにも移る部分は無い。
