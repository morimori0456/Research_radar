## 今日読むべき TOP3

### 1. [RRSI](2609.24972.md) — 同じ benchmark で改良を繰り返すと、その benchmark に合わせ込む (**P1 3.0**、探索枠)

**なぜ読むか: planner を閉ループ benchmark で調整し続けることの危うさを、測れる形にしているから。**

論文は LLM agent の harness (prompt やツールなど、モデルの外側の仕組み一式) を自動で改良し続ける話である。改良に使ったタスクでは大きく点が上がるが、使っていないタスクではその伸びが縮む。そこで、1 回に入れてよい変更の数を絞るなど、「使い回せる変更だけが残る」制約を入れた。

**planner 開発も同じ構造をしている。**同じシナリオ集合で「点が上がる変更だけ採用」を繰り返せば、シナリオ固有の癖に合わせた変更が混ざる。R1 で作る新しい指標も、同じ集合で作って同じ集合で確かめれば同じ罠に落ちる。

**試すこと (半日・GPU 不要):** 2D toy でシナリオを調整用と検証用に分け、ルールベース planner を greedy に反復調整する。反復回数ごとに 2 つの split での改善幅をプロットする。「1 回に変えるパラメータは 1 個」という制約で差が縮むかを見る。

### 2. [WorldCrafter](2609.24984.md) — 過去を「いつ見たか」ではなく「どこから見たか」で思い出す world model (**P3 3.5**)

**なぜ読むか: world model の記憶の持ち方に、R3 の分類マップに無かった選択肢を 1 つ足すから。**

video world model (カメラ操作などを条件に次のフレームを生成してシミュレーションする動画生成モデル) は、長く動かすと前に見た景色を忘れ、同じ場所に戻ると違う景色を描く。WorldCrafter は、次に見たいカメラ位置を手がかりに、過去の観測から必要な部分だけを固定数の token に詰めて生成器に渡す。

運転の world model は普通、直近の数フレームという時間の窓で過去を持つ。この論文の memory は空間 (視点) で過去を引く。**R3 は今月は着手しない方針なので、分類マップの軸 ①「時間をどこに持つか」に 1 行メモを足すだけにする。**スコアは本日最高だが、今月の優先 (R1) との近さで RRSI を 1 位にした。
