# An Omitted Mode Is a Rare Rule: The Sampling-Verification Danger Law in Continuous Code World Models

**topic:** next_arch (P3) ・ **arXiv:** 2608.17956 ・ **published:** 2026-08-18 ・ **hf_upvotes: 0** ・ **relevance 4.5 / 5**

> **主張を一行で:** **「N 回サンプリングして矛盾が出なかったから、このモデルは正しい」という検証が実際に保証している量は、閉じた式で書ける —— そしてそれは、我々が期待しているものよりはるかに小さい。**
>
> **なぜ重要か:** **R1 は「保証付きの評価指標」を目指している。本論文は、保証を主張する前に必ず通らねばならない反例を与える。** **確率 r の稀な臨界事象を、N 回の独立なロールアウトが全て見逃す確率はちょうど (1-r)^N である。** **閉ループシミュレーションで N シナリオ走らせて衝突しなかったことが何を意味するか、という R1 の最も基礎的な問いに、そのまま答えている式である。** **論文の対象 (LLM が合成するコード world model) は我々の領域ではない。移すのは式と論法である。**

## 何を解決する論文か

**Code World Model (CWM) と呼ばれる枠組みでは、LLM が実行可能な world model —— 環境の遷移をコードとして書き下したもの —— を合成し、その上を古典的な planner が探索する。** **合成されたモデルは、サンプリングした遷移を再現できたときに「受理」される。**

**本論文の問いはひとつ:** **その受理は、連続制御において何を証明しているのか。**

**答えは「サンプルとの整合性を証明しているだけで、それ以上ではない」。** そして **その「それ以上ではない」の大きさが、正確に測られている。**

## 手法の核心

- **danger law が閉じた式で書ける。** **危険を期待リスクとして定義したとき、その因子は厳密に (1-r)^N** —— **確率 r の臨界事象を、N 本の独立な gate rollout (受理判定用の試行) が全て取り逃す確率。** **独立な受理サンプルを足すと、その予算は指数にそのまま加算される。** **単純だが、これが「サンプルで検証する」あらゆる手続きの上限を与える。**

- **実害が構成されている。** **3 つの hybrid instrument (連続ダイナミクスに離散的なモード切替が混ざった系) において、受理された mode-blind なモデル —— モードの存在を見落としたモデル —— が planner に食い破られる。** **planner はモード境界に張り付き、達成可能なリターンのほぼ全量に相当する regret を負う。** **「検証を通ったモデルが、通ったからこそ危険な使われ方をする」という筋書きになっている。**

- **なぜサンプリングで見つからないかを、定量的に説明する localization budget。** **Lipschitz 定数が L 以下で、ある点で η だけ食い違う 2 つのモデルは、体積 κ((η-ε)/L)^(d+m) 以上の領域で許容誤差 ε を超えて食い違う。** **つまり滑らかな食い違いは必ず「広がり」を持つので、ランダムサンプリングでいずれ当たる。** **ところが本論文が扱う不連続な reset mode は、この予算を一切払わない —— 食い違いが体積を持たないため、サンプリングでは原理的に当たらない。** **「稀だから見つからない」のではなく、「測度が無いから見つからない」。**

- **実際の LLM 合成でも検証している。** **GPT-5.x は 1 次元の clamp (値を範囲に収める処理) の欠落を、モードを含む 111 回の試行のうち 105 回で修復する。** **ところが 2 次元領域では 156 回中 0 回、どの生成物も規則を復元しない。** **8 種類の狙い撃ちの介入を入れても失敗は残る。** **positive control が原因を特定する: 規則の形と位置を与えれば定数は正確に埋まる。つまり規則を「帰納できない」のであって、「表現できない」のではない。**

- **identifiability (同定可能性) は仮説クラスに相対的である、と version-space certificate で示す。** **さらに「あらゆるサンプルと厳密に整合するが、実際の運用では無害な entry rule のクラス」を構成してみせる** —— **したがって「サンプルで区別できるか」は、モデルではなく instrument 側の測定可能な性質である。** **全 1034 個の生成物を独立サンプルで再採点した結果、受理はサンプル整合性しか保証しないことが確認され、gate が証明可能に有意な場面でも、食い破る planner の照会のうち約 2% しかカバーしていない。**

## 追っているプロジェクトへの適用可能性

- **P1 / R1 —— 本日いちばん「効く」というより、R1 が避けて通れなくなった論文。** **R1 は保証付きの評価指標を掲げる以上、「N 本のシナリオで衝突が出なかった」が何を保証するかに答えねばならない。本論文の (1-r)^N は、その答えを一行で与える。** **たとえば r = 10^-3 の臨界事象に対して N = 1,000 本走らせても、全て見逃す確率は約 37% である。** **これは R1 の導入部にそのまま書ける数字であり、W34 の課題カード群が繰り返している「測れない」に、初めて定量的な下限を与える。**

- **P1 / R1 —— さらに重要なのは、その先の主張である。** **「サンプル数を増やせば解決する」は、滑らかな食い違いに対してのみ正しい。** **不連続なモード —— 運転で言えば、ある条件を跨いだ瞬間に挙動が切り替わる領域 —— に対しては、サンプリング量では埋まらない。** **R1 が conformal prediction (予測の外れ率を分布の仮定なしに保証する統計手法) で被覆保証を付けようとするとき、この区別は決定的である:** **conformal の保証は交換可能性の下での平均的な被覆であって、測度ゼロの臨界集合を捕まえるものではない。** **R1 は「何を保証しないか」を明示できて初めて、保証を名乗れる。本論文はその文言を書くための材料である。**

- **P1 / R1 —— 「identifiability は instrument の測定可能な性質」という定式化が、評価プロトコル設計の指針になる。** **「このベンチマークは、そもそもこの種の欠陥を検出しうるか」を、走らせる前に問える形にしている。** **08-19 の CaliBench が「検出力の限界を自分で明示する」作法を示したが、本論文はそれを一段強く「検出可能性そのものを証明対象にする」ところまで持っていっている。** **R1 のベンチマーク設計に、この節を置くべきである。**

- **P3 / R3 —— world model の受理基準という、分類マップに無い軸を持ち込む。** **R3 のマップは「world model をいつ使うか / 内部表現は何か」で組んでいるが、本論文が問うのは「その world model を、何をもって信頼するのか」である。** **本日の [Calibrated Predictive Safety](2608.17496.md) が「学習した予測は順位付けにしか使わない」という設計で応えているのに対し、本論文は「サンプルによる受理では足りない」という否定側から同じ問題に触れている。** **2 本を並べると、「world model を安全判断に使うなら、受理基準を別に設計せねばならない」という共通の結論になる。マップに 3 本目の軸として立てる価値がある。**

- **P2 —— 直接の関係は薄い。ただし「teacher の出力を N 個サンプリングして student が一致したから蒸留成功」という判定にも、同じ (1-r)^N が効く。** **稀な入力での teacher/student の乖離は、評価サンプルでは見つからない。** R2 が破綻境界を測るとき、**「破綻していないと判定した」の信頼性そのものが、この式で制限される。**

- **留保:** (1) **本論文の対象は LLM が合成するコード形式の world model であり、我々が扱う学習済みニューラル world model とは、モデルクラスも失敗の出方も違う。** **移せるのは (1-r)^N と localization budget の論法であって、GPT-5.x の修復率のような具体的数値ではない。** (2) **abstract の密度が非常に高く、記号の定義 (κ, d, m, η, ε) が読み切れない。** **式を R1 で引用するなら、本文で定義を確認してからにすること。** (3) **「不連続モードは予算を払わない」は連続制御の設定に強く依存する。** 運転の場面でどの失敗が不連続モードに当たるかは、我々が自分で対応付けねばならない。

### 試すべき実験

1. **R1 の導入部に「N シナリオで無事故が保証する量」を数値で書く (最優先・所要 1 時間・紙の上)。** **(1-r)^N に、実際の robotaxi の運用規模を入れる。** **W34 が記録している「完全自律の robotaxi 乗車は週 70 万回超」という数字と、SGO (NHTSA の標準事故報告) に現れる事象率を組み合わせれば、「現行の走行量が何を検出できて何を検出できないか」が計算できる。** **これは R1 の figure 1 の隣に置く表になる。**

2. **運転における「不連続モード」の候補を列挙する (優先度高・所要半日・紙の上)。** **本論文の主張が我々に効くのは、planner の挙動に測度ゼロに近い切替境界が存在する場合だけである。** **候補: 信号の黄→赤の判断境界、割り込みへの譲る/譲らないの切替、緊急ブレーキの発動閾値。** **これらが「境界の近傍でランダムサンプリングに当たらない」性質を持つかを検討する。持つなら、R1 は「サンプリング型評価では原理的に届かない領域がある」という強い主張を持てる。**

3. **既存の閉ループベンチマークの検出力を、事後ではなく事前に計算する (優先度高)。** **nuPlan / CARLA / Bench2Drive のシナリオ数 N に対し、検出したい事象率 r を仮定して (1-r)^N を出す。** **「このベンチマークは r ≥ x の事象しか検出できない」という一文が各ベンチマークに付けられるなら、それ自体が R1 の貢献になりうる。** 本日採用の [ControlledShifts](2608.17882.md) の枠組みと組み合わせると、**「どの軸を、どの解像度まで検出できるか」という 2 次元の表が書ける。**

4. **「受理基準」を shield 設計に持ち込めるか検討する (優先度中・P3 側)。** **本日の [Calibrated Predictive Safety](2608.17496.md) の shield は決定論的なので (1-r)^N の対象外だが、その上の risk head の較正はサンプルで検証されている。** **較正の検証自体が本論文の批判の射程に入らないかを確認する。** 入るなら、**「較正の保証は、較正データが臨界事象を含んでいた場合にのみ成立する」という留保を R1 側で明文化する必要がある。**
