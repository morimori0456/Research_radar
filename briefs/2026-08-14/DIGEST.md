## 今日読むべき TOP3

### 1. How Can Driving World Models Do Counterfactual Prediction? — 「もし別の操作をしていたら」に、world model は答えていない

**P1 と P3 の両方に同時に刺さる、本日唯一の論文。** そして **我々が world model に期待している使い方そのものを、原理のところで否定している。**

**まず何が主張されているか。** driving world model (走行シーンの未来の見え方を予測する生成モデル) は、**counterfactual simulator (反実仮想シミュレータ: 実際の走行ログに対して「もしここで別の操作をしていたらどうなっていたか」を答えるもの)** として使われることを期待されている。planner の評価も事故の再検証もログの上で回せるので、当然そうしたくなる。

**著者の指摘は単純で、そして避けようがない。** 標準的な使い方 —— **分岐点までの履歴と、代替の action を入力して未来を生成する** —— は、**分岐点より後に実際に観測されたものを一切使っていない。** だから出てくるのは「その履歴と行動からありうる未来のひとつ」であって、**「このエピソードで実際に成立していた条件のもとでの未来」ではない。**

**因果推論の言葉で言うと、3 段のうち 1 段目が抜けている。** 反実仮想を計算する古典的な手順は **abduction (観測された事実から、裏で効いていた説明されない要因を逆算して固定する)** → **action (行動を差し替える)** → **prediction (固定した要因のもとで再計算する)** の順に進む。**現行の world model は abduction を持っていない。** 一言でいえば **「何が起きたかを見ずに、別の未来を想像している」。**

**論文として偉いのは、測れる形にしたこと。** 反実仮想は定義上、実データでは正解が存在しない。そこで著者は **事実側の結果と、それに対応する「action だけ差し替えた正解」を対で持つシミュレーション環境**を作り、**代表的な world model 2 つが実際に正解から外れることを示した。** この環境を作ったこと自体が貢献の半分である。

**処方が安いのも良い。学習は一切しない。** 事実側の続きに含まれる情報を反実仮想側に移し替え、**残りの不明部分だけを凍結したモデルに埋めさせる。** これだけで**正解の回収率が大幅に上がる。** 著者自身「意図的に単純な構成」と書いていて、SOTA の主張ではなく **分析が正しいことの構成的な裏付け**として置かれている。

**我々にとっての痛みどころは、log-replay 評価である。** 「実際の走行ログに対して、我々の planner ならどうしていたか」は R1 の評価基盤の中核にある発想で、**本論文はそれが world model を使う限り体系的に甘くなると言っている。** planner の良し悪しが、生成側のばらつきに埋もれる。

**留保も明確。** 対象は **代替 action が周囲の車の挙動を変えない程度の短い区間**に限定されている。**我々が本当に評価したい割り込みや譲り合いは、その外側にある。** ただしそれは弱点であると同時に、**素直な拡張の余地**でもある。→ [ブリーフ](2608.11601.md)

### 2. G0.5 — 行動を別モジュールに追い出した瞬間、VLM は意思決定者でなくなる

**R3 (VLA × world model 統合アーキテクチャ) のマップの主軸を、本日ひっくり返しにきた 1 本。** R3 の次アクションは「既存統合手法の分類マップ作成」だったが、**本論文は分類の第一軸そのものを提示している。**

**現在の VLA (Vision-Language-Action; 画像と言語指示からロボットの行動を直接出力するモデル) の標準構成は「事前学習済み VLM + 別に学習した action expert」である。** action expert には **flow matching (ノイズから目標分布へ連続的に輸送する経路を学ぶ生成手法。diffusion の親戚で、少ないステップで滑らかな連続値が出せる)** がよく使われる。

**著者の批判は構造的だ。** この分け方だと **VLM は文脈を埋め込むだけの装置に格下げされ、実際に「どう動くか」を決めているのは別学習された小さな expert の側**になる。だから **VLM が持っていたはずの指示追従能力や未知シーンへの対処が、身体の振る舞いに乗ってこない。**

**G0.5 の解は、1 つの transformer decoder が推論トークンと行動トークンを同じ目的関数のもとで吐くこと。** 成立させている部品は 3 つ: **機種ごとにバラバラな行動を共通の離散語彙に写す cross-embodiment action tokenizer**、**タスク分解・物体の指示対象特定・行動のヒントを action token と交互に織り込む CoT (Chain-of-Thought; 答えの前に思考過程を明示的に生成させる手法) の流れ**、**数秒分の履歴を vision encoder 経由で注入する visual memory**。

**そして重みを共有していることの効果が、本論文で一番面白い部分。** **追加学習なしに、プロンプトを書き換えるだけで動作の粒度・タスクの長さ・未知シーンでの振る舞いが変わる。** これは「性能が上がった」とは質の違う主張である。

**数字は広い。7 つの独立した評価体系で SOTA を主張。** 実機 fine-tuning で **76.7% 対 π0.5 の 53.3%・GR00T-N1.7 の 24.4%**、**BEHAVIOR Challenge 2025** (50 個の長期の家庭内移動マニピュレーション) で **31.4% 対 π0.5 の 26.3%・優勝者の 26.1%**、DROID 学習後に未知環境・未知物体へ zero-shot 転移して **82.5%**。ほか LIBERO 98.9%、RoboTwin 2.0 93.3%、SimplerEnv-Bridge 87.3%。

**ただし読み方には注意が要る。** LIBERO の 98.9% は**既に飽和域**なので差の根拠にならないし、BEHAVIOR の 31.4% は**勝ってはいるが解けてはいない**水準である。そして **abstract からはモデルサイズも学習コストも読めない** —— **「統合したから強い」のか「単に大きいから強い」のかは、本文の ablation を見ないと切り分けられない。ここが最初に確認すべき点で、30 分で判定できる。**

**R3 にとって最も価値があるのは、空き地が見えたこと。** G0.5 は **未来の観測を予測しない** —— 推論と行動の統合であって、予測の統合ではない。**08-13 の 4D-WAM は world model と planning の統合、本論文は reasoning と action の統合。R3 が主張しうるのは 3 者の統合であり、そこは現時点で埋まっていないように見える。** → [ブリーフ](2608.11739.md)

### 3. How Far from Clinical Deployment? — 良いモデルは出来ている。選べていないだけだ

**題材は医療画像だが、中身は完全にドメイン非依存で、明日の運用が最も直接変わる 1 本。** そして **証拠の厚さが本日で群を抜いている —— 8 万個以上の学習済みモデルを実際に評価している。**

**扱っているのは UDA (Unsupervised Domain Adaptation; 教師なしドメイン適合。ラベル付きの元ドメインで学習したモデルを、ラベルが一切ない目標ドメインへ適合させる枠組み) の出口である。** 我々が P2 でやろうとしている「基盤モデルを他機種・他ドメインへラベル無しで適合させる」の、そのまま最後の一歩。

**問題設定が痛いところを突いている。** 目標ドメインにはラベルが無い。**つまり目標ドメインでの性能を直接測れない。** 検証セットが作れないので、**通常なら当たり前にやっている「validation で一番良いものを選ぶ」が原理的に使えない。** 既存の UDA 研究はここを素通りし、暗黙に「目標の正解で最良を選んだ場合」の数字を報告してきた。

**著者は適合と選択を切り離さず、パイプライン全体で測る。** 9 個の医療画像データセットから 11 個のドメイン間シナリオ、10 個の UDA アルゴリズム、**13 個の label-free validator (目標ラベル無しでモデルの良し悪しを推定する手法。予測の確信度や特徴分布の一致度を使う)** の総当たり。

**結論は 3 つで、順番が効いている。**

1. **良いモデルは、たいてい存在している。** 適合アルゴリズムは仕事をしていて、十分な性能のモデルはちゃんと生まれている。**適合能力の不足が主問題ではない。**
2. **それを選び出せない。** validator が選んだモデルと実際の最良の間には **大きく、かつ構造的な**ギャップが残る。「構造的」が重要で、**運悪く外れるのではなく系統的に外す。しかも 13 個のうち一貫して信頼できるものは 1 つも無かった。**
3. **緩和策は効くが閉じない。** ensembling (選ぶのを諦めて平均する) と少量の目標ラベル予算。どちらも縮めるが埋めきらない。**解決を主張していないのが誠実。**

**そして最も費用対効果の高い含意はここ:** **新しい適合アルゴリズムを作るより、選択の手続きを直す方が安く効く。**

**我々にとっての具体的な痛み。** 基盤モデルを別のセンサ構成・別の車種・別の地域へ適合させるとき、目標側にラベルが無いのは常態である。**そして「どのチェックポイントを出荷するか」の根拠が、もし「source の validation loss が一番低いもの」なら、本論文が否定した validator の 1 つを使っていることになる。** これは実験ではなく **30 分の棚卸しで判定できる。**

**R1 への転用も効く。** 「良いモデルは存在するが選べない」は、そのまま **「安全な planner は存在するが、どれが安全か検証できない」**に写る。**ラベル無しのモデル選択に保証を付ける**という問題設定は conformal prediction (予測の外れ率を分布仮定なしで保証する統計手法) の自然な適用先で、**本論文が「既存 13 個はどれも保証を持たない」と示したことは、R1 の新規性の議論をそのまま補強する。**

**留保:** 題材は医療画像で、分類・セグメンテーションが中心と思われる。**我々の回帰的・時系列的なタスクで同じ結論になるかは未検証だが、こちらの方が validator を作りにくいので、悲観側に外れる可能性が高い。** → [ブリーフ](2608.12035.md)

**本日、その定義の候補が初めて具体的に出てきた。** 2608.12037 の多峰性の議論から: **過保守さとは、真の分布に存在したモードのうち、planner が候補として保持しなかったものの割合**と定義できる。**これは平均速度の低下や介入頻度より因果的に上流の量**で、「なぜ遅くなったか」を説明できる。**却下率・介入時の挙動変化・平均速度の低下・到達時間の悪化**と並べて、**モード取り逃し率を第一候補に置く。**

**評価の作法についての警告が本日また 1 つ増えた。** 2608.12198 は open-loop (ログ再生、自車の判断が世界に影響しない) と closed-loop を明確に分けて報告しているが、**08-13 の VIScore と本日の 2608.11601 が繰り返し言っているのは「上流の一致は下流の成功を意味しない」。** **open-loop の数値を closed-loop 性能の代理として読まないこと。** 我々自身の報告でも同じ規律を敷く。

### P2 — Foundation Model 蒸留 + 適合

**本日は 3 日ぶりに「適合」側が入った。** 08-12・08-13 は蒸留に偏っていたが、**topics.yaml が明示している「他機種・他ドメインへの適合」の観点が 2608.12035 で埋まった。**

**そして 2608.12035 が突きつけたのは、我々が問題設定を 1 段間違えていた可能性である。** P2 は暗黙に **「どうやってうまく適合させるか」**を課題として立てていた。**本論文は、8 万モデルの証拠で「適合はだいたい成功している。壊れているのは選択の方だ」と言っている。** もしこれが我々のドメインでも成り立つなら、**手法探しに使っている時間の一部は、選択手続きの設計に回すべきということになる。**

**その判定は 30 分でできる:** 現在の適合ワークフローで **「どのチェックポイントを出荷するか」をどう決めているか明文化する。** 根拠が「source の validation loss が最小」なら、本論文が否定した validator を使っている。実験不要。

**蒸留側は、失敗モードの地図が本日 5 つ目まで埋まった。**

| # | 失敗の形 | 出典 |
|---|---|---|
| 1 | **伝わらない** —— 特徴を合わせているのに inductive bias が渡らない (pooling と flatten が空間格子を壊す) | iBKD (08-13) |
| 2 | **伝わりすぎて上書きする** —— teacher 特徴に寄せると student 元来の視覚・言語対応が壊れる | MVRD (08-13) |
| 3 | **発散 / 欠損** —— 更新を壊す excess と、サンプルされず伝わらない deficit | TIDE (08-12) |
| 4 | **そもそも teacher が要るのか** —— 外部監督ゼロの自己蒸留が正解ラベルありを上回る | U-OPSD (08-13) |
| 5 | **teacher が捨てたものが伝わらない** —— 引力だけの蒸留に構造的に欠けている穴 | **ASD (本日)** |

**ASD の価値は、手法そのものより実験の形にある。** **13 組の teacher-student ペアを横断して報告し、「どのペアで最も効いたか」を主張の一部にしている。** これは 08-13 の iBKD の「データが減るほど優位が広がる」という傾きでの報告と同じ作法で、**2 日連続で同じ報告形式が推奨されている。R2 の図は、単一の勝敗ではなくペアの集合上の傾向として描くこと。**

**R2 の測定軸が本日また 1 本増えた。** 08-13 で「容量比」だけでなく **「inductive bias の不一致」**が要ると分かった。**本日 ASD が足すのは「何で測るか」の側である** —— **cross-architecture ペアで最も効いたのが clean 精度ではなく頑健性 (mCE) だった。** つまり **bias が不一致なペアでは、壊れるのは平均精度ではなく頑健性かもしれない。** **これは R2 の「破綻境界」の定義に直接効く: clean 精度だけで測っていると、境界を見逃す。破損ベンチを 1 つ常設すること。**

**実装コストの面で ASD は本日最良。** 必要なのは **teacher の学習途中のチェックポイント 1 つ**だけで、追加学習も追加データも要らない。既存パイプラインに loss を足すだけで試せる。

**weekly で必ず拾い直す 1 本: 落選した 2608.11937 (TREX)。** **teacher に長い軌道を rollout させて合成データを作り、student を学習する。** 狙いが上手く、**student が autoregressive に予測するときに実際に出会う状態 (自分の誤差が乗った状態) と、そこからの復帰の仕方を teacher から直接見せられる。** 結果は **パラメータ数を数桁減らして teacher に匹敵、推論は 1 桁以上高速** —— **R2 にそのままデータ点になる数字。** 題材は PDE だが、**機構は autoregressive な予測モデル一般 —— つまり world model —— にそのまま移る。** P2 の 2 枠目を ASD と最後まで争った。

**取得側について、本日コードを読んで新しい欠陥を 1 つ確認した。** fm_distill_finetune が 3 日連続で正確に 30 件だったので `fetch_candidates.py` を確認したところ、**`query_arxiv(..., max_results=30)` の 30 が既定値のまま一度も上書きされていない** (`:45` と `:135`)。しかも順序が逆で、**「窓の中の全件を取って 30 で切る」のではなく「新しい順に 30 件だけ取って、その中から窓の中のものを残す」。**

**そして fm_distill_finetune は cutoff 通過後も 30 件残っている —— 取得した 30 件が 1 件も窓から落ちなかったということで、31 件目以降が存在するのに取得されていないことの証拠である。3 日連続で正確に 30 なので、3 日とも切り捨てが起きている。**

**これは既知の 3 欠陥とは別の 4 つ目で、症状が静かなのが厄介。** 「候補が 30 件あった」という健全に見える出力を出しながら、**最も候補数の多いトピックだけが恒常的に切り捨てられる。** next_arch (8 件) と planner_ai (2 件) は上限に届かないので影響を受けず、**最も豊かなトピックだけが選択的に劣化する**という、最も気づきにくい形になっている。**修正は `max_results` を上げるだけで 1 行。** 併せて **cutoff で落ちた件数をログに出す**べきで、それがあれば「30 取って 30 残った = 上限に当たっている」が即座に分かる。

**加えて 30 件のうち、手法として蒸留・適合を論じているのは 8 件程度**で、残りは「abstract に fine-tuning という語が入っているだけ」の応用論文。**上限 30 の枠を応用論文が 22 件占めている**ということでもあり、**キーワードを手法語に寄せる調整は、上限を上げなくても効く。3 日連続の同じ症状なので今週決めるべき。**

### P3 — 次世代アーキテクチャ (VLA / World Model / E2E)

**候補が 16 → 8 に半減したが、密度は本日が最も高い。8 件中 2 採用、惜しい落選 4。**

**R3 (VLA × world model 統合アーキテクチャ) にとって、本日は「マップの主軸と、空き地の位置が同時に決まった日」である。**

**主軸 (G0.5 から):** **行動を別モジュールに出すか (π0.5 / GR00T 型)、1 本の autoregressive stream に統合するか (G0.5 型)。** しかもこの軸に沿って**明確な性能差が主張されている**ので、R3 のマップは単なる整理ではなく **「どちらが勝っているか」という主張を持てる。** これは新規性の議論を一段強くする。

**空き地 (G0.5 と 4D-WAM の差分から):** **G0.5 は未来の観測を予測しない** —— 推論と行動の統合であって、予測の統合ではない。**08-13 の 4D-WAM は world model と planning の統合。両者を並べると、reasoning・action・prediction の 3 者を 1 本の stream に統合した構成は、現時点で見当たらない。R3 が主張しうるのはそこである。**

**もう 1 本の軸 (2608.11601 から):** **「その world model は反実仮想として使えるのか、それとも前向きの生成にしか使えないのか」。** これは論文を読むだけで埋まる列で、**しかもほとんどの論文が答えを書いていないはずなので、埋めた時点で情報になる。**

**そして本日、R3 にとって最も面白い衝突が起きている。** 落選させた **2608.12078 (Better Slots, Better Worlds)** は、object-centric world model (シーンを物体ごとの slot に分解してから予測するモデル) を統制実験で検証し、**「planning の成功は slot の品質指標と正に相関する。ただし高品質域で飽和する」**と報告している。

**これは 08-13 の VIScore の主張 —— 「表現指標は planning 成功を説明しない」—— と力点が逆である。** 真っ向から矛盾はしない (飽和するなら、高品質域では確かに説明力を失う) が、**低品質域では表現指標が効いていることになる。** **この 2 本を突き合わせて「表現指標はどの範囲で有効か」を決めるのは、R3 にとって本命の作業。** 落とすのが本日最も惜しかった 1 本で、**weekly で必ず拾うこと。**

**もう 1 つ 2608.12078 が置いていった刺のある所見:** **未知の分布シフト下での頑健性は、object-centric という構造ではなく、凍結した事前学習特徴の方が主因かもしれない** (DINO-WM が同等に強い)。**「構造の工夫だと思っていたものが、実は事前学習特徴の効果だった」は、R3 のマップを作るときに常に疑うべき交絡である。**

**設計パターンとして持ち帰るもの (落選論文から 2 つ):**
