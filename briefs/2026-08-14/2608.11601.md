# How Can Driving World Models Do Counterfactual Prediction?

**topic:** next_arch (P3) ・ **arXiv:** 2608.11601 ・ **published:** 2026-08-12 ・ **hf_upvotes: 0**

> **本日の最有力。** 「driving world model を反実仮想シミュレータとして使う」という、我々が P1 (planner 評価) でも P3 (次世代アーキテクチャ) でも当てにしている使い方に対して、**そのままでは原理的に成立していない**と言っている。
>
> **主張を一行で:** 「もし別の行動を取っていたら何が起きたか」を world model に action を差し替えて生成させると、**もっともらしい未来は出るが、それは「このエピソードで実際に起きたこと」を保存していない。** 別の未来であって、反実仮想ではない。

## 何を解決する論文か

**driving world model (走行シーンの未来の見え方を予測する生成モデル。ego の action で条件付けられるものが多い)** は、しばしば **counterfactual simulator (反実仮想シミュレータ: 実際に記録された走行ログに対して「もしここで別の操作をしていたら、どうなっていたか」を答えるもの)** として解釈される。planner の評価や事故の再検証をログの上で回せるので、実用上きわめて魅力的な使い方である。

著者は、この目標と **action-conditioned prediction (行動条件付き予測: 過去の履歴と行動を入力して未来を生成する、world model の標準的な使い方)** の間に **原理的なズレ**があると指摘する。直接予測が使う入力は「分岐点までの共通の履歴」と「代替の action」だけで、**分岐点より後に実際に観測された continuation (事実側の続き) を一切使っていない。** その結果、生成されるのは「その履歴と行動からありうる未来のひとつ」であって、**「このエピソードで実際に起きていた条件のもとでの未来」ではない。** 見た目はもっともらしいまま、欲しかったものが手に入っていない。

論文はこのズレを因果推論の言葉で定式化し、測定可能な形にして、簡単な処方まで出す。

## 手法の核心

- **ズレを abduction / action / prediction の 3 段で定式化する。** これは反実仮想を計算する古典的な手順で、**abduction (遡及推論: 観測された事実から、その裏で効いていた説明できない要因の値を逆算して固定する)** → **action (行動を代替のものに差し替える)** → **prediction (固定した要因のもとで未来を再計算する)** の順に進む。**現行の直接予測は 1 段目の abduction が丸ごと抜けている** —— これが「事実側の続きを使っていない」ことの正体である。

- **成立条件を短い時間horizonに限定して、問題を切り分けている。** 対象を **代替の ego action が周囲の車の挙動を変えない程度に短い区間**に限定する。周囲が反応し始めると「実際に起きたこと」を持ち込む正当性が崩れるため、**まず崩れない範囲で問題を可視化する**という切り方。**設定を狭めたことを明示している点は誠実だが、我々が本当に評価したい割り込みや譲り合いはこの外側にある**ので、そこは留保が要る。

- **測るための controlled benchmark を自分で作っている。** 反実仮想は定義上「実際には観測できない」ので、実データでは正解が存在しない。そこでシミュレーション上に **factual outcome (事実側の結果) と、それに対応する matched counterfactual outcome (同じ条件で action だけ差し替えた正解)** を対で用意する。**この対がある環境を作ったこと自体が本論文の実質的な貢献の半分**で、主張が検証可能になっている。

- **2 つの代表的な world model で、直接予測は正解に一致しないことを実証。** 「理論的にズレている」で終わらず、既存モデルで実際に外れることを示している。

- **処方は驚くほど安い —— training-free で、モデルは凍結したまま。** 観測済みの evidence (事実側の続きに含まれる情報) を反実仮想側のビューに移し替え、**残りの不明部分だけを凍結済みモデルに埋めさせる。** これで **正解を回収できた割合が大幅に上がり、正解との知覚的な距離も縮む。** 著者自身が「意図的に単純な構成」と書いており、**SOTA を主張する論文ではなく、分析が正しいことの構成的な裏付けとして置かれている。**

## 追っているプロジェクトへの適用可能性

- **P1 / R1 (保証付き安全指標) —— ここが一番効く。** planner を「ログの上で反実仮想的に評価する」(実際の走行ログに対して、我々の planner ならどうしていたか) は、log-replay 評価の中核にある発想である。**本論文はその評価が、world model を使う限り体系的に甘くなることを示している** —— 生成された未来は「ありうる未来」であって「あのとき起きたはずの未来」ではないので、**planner の良し悪しが、生成側のばらつきに埋もれる。** R1 が評価手法を提案するなら、**「その評価が反実仮想として妥当か」は避けて通れない前提条件になる。**

- **P3 / R3 (VLA × world model 統合アーキテクチャ) —— マップの軸がもう 1 本増えた。** 08-13 の VIScore は「表現の綺麗さは planning 成功を説明しない」と言い、本論文は「予測のもっともらしさは反実仮想の正しさを意味しない」と言う。**どちらも同じ形 —— 出力は健全に見えるのに、必要な性質を満たしていない。** R3 のマップに **「その world model は反実仮想として使えるのか、それとも前向きの生成にしか使えないのか」** という列を足すべきで、これは論文を読むだけで埋まる。

- **P3 / 設計への持ち帰り。** 「abduction 段を明示的に持つか」は world model のアーキテクチャ設計の選択肢である。**観測された未来を latent に押し込んでから action を差し替える**構造 (posterior を推論してから介入する) は、既存の VAE 系 world model なら追加学習なしに近い形で試せる可能性がある。本論文の training-free パイプラインは事実上その最小実装と読める。

- **P2 への波及は薄い。** 蒸留とは直接繋がらない。ただし **「teacher の出力がもっともらしいことと、正しい条件付き分布であることは別」**という形は、08-13 の TIDE / MVRD の議論と同じ骨格をしている。

- **注意点:** (1) **短 horizon かつ周囲が反応しない設定に限定**されており、我々が知りたい相互作用のある場面には未検証。(2) **回収率は「大幅に上がる」だけで完全ではない** —— 数値は本文で確認が要る。(3) 検証は**シミュレーションのみ**で、実写ログでの妥当性は未証明 (そもそも正解が作れないため、原理的に難しい)。

### 試すべき実験

1. **手持ちの action-conditioned な予測モデルで、同じ壊れ方が起きるか 1 日で確かめる (最優先)。** シミュレータで同一履歴から 2 本の走行を生成し、片方を「事実」、もう片方を「正解の反実仮想」とする。**モデルに事実側の続きを見せずに代替 action だけで予測させ、正解の反実仮想とどれだけズレるかを測る。** ズレが小さければ我々のドメインではこの問題は無い。

2. **log-replay 評価の主張を棚卸しする。** 現在「ログ上で planner を評価した」と言っている結果のうち、**どれが反実仮想を前提にしているか**を洗い出す。**前提にしているものは、本論文の指摘を受けて主張を弱めるか、abduction を足す必要がある。** 実験不要、読み直すだけ。

3. **training-free パイプラインを既存モデルに移植する。** モデル凍結・追加学習ゼロなので、**実装コストがそのまま試行コスト**になる。効けば R1 の評価基盤がそのまま強くなる。

4. **周囲が反応する区間で壊れ方を測る。** 著者が避けた領域が、我々にとって本命である。**horizon を伸ばしながら回収率がどこで落ちるかを引けば、それ自体が本論文への素直な拡張**であり、R1 の新規性の議論にも使える。
