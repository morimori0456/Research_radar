# G0.5: One Autoregressive Stream for Robot Reasoning and Action

**topic:** next_arch (P3) ・ **arXiv:** 2608.11739 ・ **published:** 2026-08-12 ・ **hf_upvotes: 0**

> **R3 (VLA × world model 統合アーキテクチャ) のマップの、主軸をひっくり返しにきた 1 本。** 現在の VLA の標準構成である「VLM 本体 + 別途学習した action expert」を名指しで否定し、**推論も行動も 1 本の autoregressive stream に統合する**方式で、π0.5 や GR00T-N1.7 を 7 つの評価体系で上回っている。
>
> **主張を一行で:** action を別モジュールに追い出すと、**VLM は意思決定者ではなく単なる文脈エンコーダに格下げされる。** 重みを共有すれば VLM の能力がそのまま身体の振る舞いに乗る。

## 何を解決する論文か

**VLA (Vision-Language-Action; 画像と言語指示を受け取ってロボットの行動を直接出力するモデル)** の主流レシピは、**事前学習済みの VLM (Vision-Language Model; 画像と文章を一緒に扱えるモデル) に、別に学習した action expert を接ぐ**というものだった。action expert には **flow matching (ノイズから目標分布へ連続的に輸送する経路を学ぶ生成手法。diffusion の親戚で、少ないステップで滑らかな連続値を出せるため、連続的な関節角の生成に向く)** がよく使われる。

著者の問題意識は構造的である。この分け方だと **VLM は文脈を埋め込むだけの装置になり、実際に「どう動くか」を決めているのは別に学習された小さな expert の側**になる。だから **VLM が持っていたはずの指示追従能力や未知シーンへの対処能力が、身体の振る舞いに乗ってこない。**

G0.5 は、**1 つの transformer decoder が、推論のトークンと行動のトークンを同じ目的関数のもとで吐く**構成にすることでこれを解く。**推論と行動が同じ重みを共有しているので、VLM 側の能力がそのまま行動に転移する** —— 指示に忠実に従い、**プロンプトを書き換えるだけで動作の粒度・タスクの長さ・未知シーンでの振る舞いを制御できる (追加学習なしで)。**

## 手法の核心

- **cross-embodiment action tokenizer —— 学習可能な行動の語彙。** ロボットごとに自由度も単位もバラバラな行動を、**共通の離散語彙に写す tokenizer を学習する。** これが無いと 1 本の autoregressive stream に行動を流し込めない。**「機種が違うデータを 1 つのモデルで食う」という、我々の P2 (他機種への適合) の問題設定そのものに対する 1 つの答え**でもある。

- **native chain-of-thought stream —— 推論を後付けの飾りではなく本流に置く。** **CoT (Chain-of-Thought; 答えを出す前に途中の思考過程を明示的に生成させる手法)** を、**タスク分解・物体の指示対象の特定 (grounding)・行動のヒント**として、**action token と交互に織り込んで生成する。** 「まず全部考えてから動く」ではなく「考えと動きが同じ列の中で交互に出る」形。

- **visual memory module —— 数秒分の履歴を vision encoder 経由で注入する。** 単フレームでは決まらない (今つかんでいるのか、さっき失敗したのか) 情報を持ち込む。**08-13 の DriveVLA-M0 の latent memory と同じ問題意識**だが、あちらが失敗事例の検索なのに対し、こちらは直近の履歴の常時注入である。

- **事前学習に VQA を混ぜている。** ロボットのデータ集合だけでなく **VQA (Visual Question Answering; 画像について質問に答えるタスク) のサンプルを一緒に学習**することで、言語・視覚側の能力の劣化を防いでいると読める。**08-12 に落選した「action post-training をすると VLM の深度推定能力が全層で劣化する」という観察に対する、実践的な対策の一形態。**

- **数字が広い。7 つの独立した評価体系で SOTA を主張している。** 実機 fine-tuning (R1lite / R1pro) で **76.7% 対 π0.5 の 53.3%・GR00T-N1.7 の 24.4%**。**BEHAVIOR Challenge 2025** (50 個の長期の家庭内移動マニピュレーション) で generalist policy として **31.4% 対 π0.5 の 26.3%・チャレンジ優勝者の 26.1%**。**DROID で post-training した後、未知の環境と未知の物体へ zero-shot 転移して 82.5%**。ほか **LIBERO 98.9%**、**RoboTwin 2.0 93.3%**、**SimplerEnv-Bridge 87.3%**。(LIBERO / RoboTwin / SimplerEnv はいずれもロボット操作の標準ベンチマーク群。**LIBERO の 98.9% は既に飽和域**なので、差が出ているのは BEHAVIOR と実機の側。)

## 追っているプロジェクトへの適用可能性

- **P3 / R3 —— マップの主軸がこれで決まる。** R3 は「既存の統合手法の分類マップ」を作るのが次アクションだった。**本論文は分類の第一軸を提示している: 「行動を別モジュールに出すか (π0.5 / GR00T 型)、1 本の autoregressive stream に統合するか (G0.5 型)」。** そして **その軸に沿って明確な性能差を主張している**ので、マップは単なる整理ではなく **「どちらが勝っているか」という主張を持てる。** これは R3 の新規性の議論を一段強くする。

- **P3 / 運転への移植で最初に効くのは action tokenizer の議論。** 運転の行動 (連続的な軌道) を **離散トークンに落とすか、連続値のまま出すか**は、E2E 自動運転でも未決着の設計選択である。**本論文は「離散化しても、むしろ統合の利益の方が大きい」側に票を投じている。** 我々が E2E アーキテクチャを設計するとき、この主張は検証すべき仮説として扱える。

- **P3 / ただし world model は入っていない。** R3 が狙うのは **VLA と world model の統合**だが、G0.5 は **未来の観測を予測しない** —— 推論と行動の統合であって、予測の統合ではない。**逆に言えば R3 の空き地がどこかを教えてくれる:** 本論文の単一 stream に「未来の観測トークン」を第 3 の種類として足す構成は、**現時点で誰も埋めていない位置**に見える。**08-13 の 4D-WAM は world model + planning の統合、本論文は reasoning + action の統合。R3 が主張しうるのは 3 者の統合である。**

- **P2 / 適合の観点。** **「1 つの base を凍結せず、機種横断の語彙で吸収する」**というアプローチは、08-13 に 3 回目の遭遇となった Mixture-of-LoRA 型 (機種ごとに adapter を用意して切り替える) の**対極**にある。**同じ「他機種への適合」問題に、正反対の 2 つの設計が出ている**ので、P2 の設計判断としてこの対立は記録しておく価値がある。

- **注意点 (重要):** (1) **我々には再現できない。** foundation-model スケールの事前学習を前提としており、**手元で検証できるのはアーキテクチャの思想だけ。** 数字を信じるかどうかは別の判断になる。(2) **abstract からはモデルサイズも学習コストも読めない。** 「1 本の stream に統合した方が良い」が本質的な利益なのか、単に計算量が多いからなのかは、**本文の ablation を見ないと切り分けられない。ここが最初に確認すべき点。** (3) 比較対象の π0.5 / GR00T-N1.7 が**同条件で学習されたものかどうか**が不明。事前学習データが違うなら、アーキテクチャの比較にはならない。(4) **BEHAVIOR での 31.4% は絶対値としては低い** —— 長期タスクは全員が苦戦している段階であり、勝っていても解けてはいない。

### 試すべき実験

1. **R3 のマップに「統合の度合い」列を作り、収集済みの手法を並べ直す (最優先・実験不要)。** 軸は **(a) 行動は別 expert か同一 stream か、(b) 推論を明示的に生成するか、(c) 未来の観測を予測するか**。**3 列目が空いている行が多いなら、そこが R3 の主張になる。**

2. **本文の ablation だけを先に読み、「統合の利益」と「規模の利益」を切り分ける。** 論文全体を読む前にここだけ確認すれば、**我々のスケールで持ち帰れる知見があるかが 30 分で判定できる。**

3. **行動の離散化を、手元の小さな設定で検証する。** 軌道を離散トークンに落として autoregressive に生成する構成と、連続値を回帰する構成を、**同じデータ・同じ容量で比較する。** 本論文の主張が我々の規模でも成立するかは、これで初めて言える。

4. **プロンプトで挙動が変わるという主張を、評価指標として使う。** 「追加学習なしにプロンプトで動作の粒度や horizon が変わる」は、**評価軸として面白い** —— 我々の planner が同じ意味で「操作可能」かを測る指標は今のところ無い。R1 の指標群への候補として記録する。
