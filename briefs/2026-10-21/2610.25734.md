# 2610.25734 — Think Densely, Act Sparsely: Latent Expert Cognitive Chains for VLA Autonomous Driving (LECDrive)

- 元論文: https://arxiv.org/abs/2610.25734
- トピック: next_arch (P3) / 評価 5.0 / hf_upvotes 0
- 根拠: abstract のみ。数値表・ablation・計算コストの詳細、コード公開の有無は未確認

## 何を解決する論文か

VLA (Vision-Language-Action; 画像と指示を入力に行動・軌道を直接出すモデル) を運転に使うと、教師信号が「言語の指示」や「軌道」といった疎な情報だけになり、シーンの細かい情報をモデルが捨ててしまう、というのが著者の見立て。容量不足ではなく、密なシーン表現を latent 空間に作らせる仕組みがないことが原因だと主張し、VLM の中に latent token を挿して外部の vision foundation model の知識を取り込ませる LECDrive を提案する。

## 手法の核心

- **latent token を「expert の窓口」にする**: タスクごとに少数の latent token を VLM に追加し、各 token が外部 foundation model の出力を内部化する。推論時に外部 model を呼ぶのではなく、学習時に知識を移す (distillation に近い) ので推論は軽いまま、と主張している。
- **3 種類の expert**: DINOv3 (自己教師あり学習の汎用視覚特徴)、SAM3 (Segment Anything の後継; 物体領域の分割)、DepthAnything3 (単眼画像から奥行きを推定) の 3 つ。順に「見た目の表現 → 意味構造 → 空間の幾何」を担当する。
- **cognitive chain (expert 同士の依存関係)**: token を並列でなく連鎖させ、前段の結果を後段が使う。人間の知覚が低次から高次へ進む順を模したもの。
- **curriculum learning (易しい目標から段階的に難しい目標へ進める学習順)**: 教師信号を representation → semantics → geometry の順に追加していく。
- **評価**: object perception、state prediction、trajectory planning の複数の運転 benchmark で、土台の VLM を一貫して改善したと報告 (どの benchmark か、closed-loop かは abstract では不明)。

## 適用可能性と実験アイデア

- **P3 (次世代アーキテクチャ)**: 直接の対象。「疎な trajectory 教師だけでは VLA が scene 情報を捨てる」という主張は、手元の E2E / VLA の学習設計をそのまま疑える。
  - 実験案 1 (最小): 既存の VLM ベース planner に latent token を追加し、DepthAnything3 の depth だけを auxiliary loss (補助的な教師信号) で蒸留する。depth なし / あり で open-loop の軌道誤差と、closed-loop simulation の衝突率を比べる。3 expert 全部を入れる前に、効果の大半がどの expert 由来かを切り分ける。
  - 実験案 2: curriculum の順序を入れ替える (geometry 先行 / 全部同時) ablation。著者の「順序が効く」主張が自分の設定で再現するかの確認。
- **P2 (蒸留 + 適合)**: 外部 foundation model から latent token へ知識を移す点は、feature distillation の一種として読める。teacher が複数ある場合の loss の重み付け (今日の Nash-MOPD 2610.26124 は teacher が複数ある別設定だが、重みの動的調整という発想は共通) を試す余地がある。
- **P1 (Planner AI + 評価)**: 「state prediction」が評価に入っているので、planner の評価指標として使えるか確認する価値がある。ただし abstract だけでは評価の詳細が分からない。
- 注意: 改善幅が abstract に無い。ベースが VLM 単体なので、既存の強い E2E planner に対する優位は未確認。3 つの foundation model を学習時に回すコスト (teacher の前向き計算) も確認が必要。
