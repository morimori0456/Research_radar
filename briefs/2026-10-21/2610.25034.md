## 何を解決する論文か

OPD (On-Policy Distillation; student 自身が生成した軌跡の上で、stronger な teacher が各 step の確率分布を教える蒸留) を multi-turn の agent 課題で回すと、student が teacher を一度追い越し、その後 distillation を続けるほど成績が落ちる、という現象を著者は見つけ、distillation overshoot と名付けた。この論文は原因を分解し、追い越した分を保つ手法 SPOD を提案する。

## 手法の核心

- **原因の分解**: OPD には 2 つの効果が同時に働く。(a) repair: student の弱い判断を teacher が直す。(b) erosion: teacher が好まないが実は成功していた student の選択を、teacher が削ってしまう。序盤は repair が勝ち、student が teacher を超える。続けると erosion が勝って利得が消える。
- **Success-Preserving On-Policy Distillation (SPOD)**: 成功した episode の中で、teacher の supervision が student の選択と衝突する部分を mask する。さらに student の確率に soft probability floor (下限) を入れて erosion を抑える。それ以外では teacher の指導をそのまま使う。
- **追加情報が少ない**: 必要なのは episode 単位の成功/失敗の 2 値と、OPD の中で既に計算している確率だけ。reward model や追加 rollout は要らない。
- **結果**: 2 つの model family と 3 つの agentic benchmark で、通常の OPD より最終成功率が最大 +15.2 ポイント、teacher を最大 +20.0 ポイント上回る。SPOD の最終 checkpoint は、通常の OPD の「途中の最良 checkpoint」よりも 6 設定すべてで良い。

## 適用可能性と実験アイデア

- **P2 (蒸留 + 適合)**: 実務への効きが大きい。「蒸留は長く回すほど良い」という前提を疑い、途中の checkpoint の方が良い現象を見たことがあるなら、原因はおそらくこの erosion。OPD を回している設定があれば、実装は masking と floor の追加だけで済む。
  - 実験案 1 (最小): 手元の蒸留 run で、student の checkpoint ごとに「teacher と student が食い違い、かつ student が正解していた token / step の割合」を数える。この割合が学習とともに減るなら erosion が起きている。
  - 実験案 2: その上で SPOD 相当の mask (成功 episode のみ、衝突部分のみ) を入れた版と通常版を、同じ step 数で比較する。評価は最終 checkpoint と途中の最良 checkpoint の差。
- **P3 / P1**: 運転の policy distillation (大きい planner を小さい planner へ) でも、teacher が好まない運転スタイルで成功していた student の挙動を消してしまうことはあり得る。閉ループ成功率の episode 単位の 2 値があるので、同じ形で試せる。
- 注意: 対象は LLM の multi-turn agent で、運転や連続制御ではない。「成功/失敗の 2 値」を運転でどう定義するか (衝突なしで到達、など) を先に決める必要がある。teacher を超える現象が小さい student でだけ起きるのかは abstract から不明。
- 関連: 今日の Nash-MOPD (2610.26124) は teacher が複数ある場合の domain 配分の話で、本論文は teacher が 1 つの場合の erosion の話。両者は直交していて併用できる。
