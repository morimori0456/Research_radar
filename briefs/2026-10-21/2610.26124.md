- 元論文: https://arxiv.org/abs/2610.26124
- トピック: fm_distill_finetune (P2) / 評価 4.5 / hf_upvotes 0

## 何を解決する論文か

MOPD (Multi-teacher On-Policy Distillation; 複数の domain 専門 teacher の能力を、student 自身の生成の上で 1 つの student に集める蒸留) では、全 domain が student の限られた学習 step と rollout 数を取り合う。各 domain にどれだけ prompt を割り当てるかが問題で、固定比率 (corpus サイズ比) だと domain の難しさを無視し、先行手法の D$^3$-MOPD (reverse-KL の減少量で比率を調整) だと、すでに早く伸びている domain にさらに配分が偏り、伸びの遅い domain が取り残される。Nash-MOPD はこの配分を game の均衡で決める。

## 手法の核心

- **reverse-KL (student の分布から見た teacher とのずれ) をそのまま使う**: 既に計算している teacher-student の reverse-KL の統計だけを使う。teacher への追加 query も追加 rollout も要らない。
- **local minimax game (局所的な最小最大化問題) として配分を決める**: 現在の局所モデルの下で「予測される比例的な KL 低下」のうち最小のものを最大化する配分を選ぶ。つまり最も改善が遅い domain を底上げする。
- **均衡の効果**: 同じだけ改善するために多くの例が必要な domain に、多くの prompt が回る。学習の進み具合が変わるたびに配分も追従する。
- **結果**: step 100 の時点で、DeepSeek-R1-Distill-Qwen-1.5B では数学・code の両方で、2 つの baseline (Fixed と D$^3$-MOPD) の最終 checkpoint の成績を超え、Qwen3-8B-Base では Fixed の最終成績に届く。9 つの報告 metric のうち 8 つで首位、数学と code の 6 つの accuracy metric では首位か同率首位。

## 適用可能性と実験アイデア

- **P2 (蒸留 + 適合)**: capacity gap (student が小さくて teacher の能力を全部は吸収できない問題) の下で、能力の取り合いを配分で緩和する recipe。複数の専門 teacher を 1 つの小さい model にまとめる運用なら、scheduler の差し替えで済む点が実務向き。
  - 実験案 1 (最小): 手元の蒸留で domain が 2 つ以上あるなら、まず Fixed 比率のまま、domain ごとの reverse-KL の推移を step ごとにログに取る。伸びの遅い domain が残っているかを見るだけで、手法の前提 (配分の偏りが問題になっているか) を確認できる。
  - 実験案 2: それから Nash-MOPD 流の配分 (最も遅い domain を優先) を入れ、同じ予算での domain 別の最終成績を比べる。
- **P3 / P1**: 運転の場合の「domain」は、シナリオ種別 (交差点・車線変更・歩行者など) と読める。シナリオ別の専門 planner を 1 つにまとめる際の配分の指針として使えるが、LLM の math/code 以外での有効性は、この abstract からは分からない。
- 注意: 対象は LLM の推論課題 (math / code) で、評価も accuracy。baseline が 2 つだけ (Fixed と D$^3$-MOPD) で、他の配分手法との比較は abstract に無い。
