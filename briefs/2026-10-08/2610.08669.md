# MemFLoRA: activation メモリを下げる CNN 向け LoRA でエッジ適応

- 対象: P2 (fine-tuning による他ドメイン適合)
- 元論文: http://arxiv.org/abs/2610.08669v1
- 根拠: abstract のみ (本文・コード未確認)

## 何を解決する論文か
デプロイ後にユーザ・センサ・環境が変わる (domain shift) とき、端末上で学習し直したい。CNN の PEFT (Parameter-Efficient Fine-Tuning; 少数のパラメータだけ学習する手法) では、律速は学習パラメータ数でなく、backward まで保持する activation (中間出力) のメモリである。transformer 向け LoRA (Low-Rank Adaptation; 重みの更新を低ランク行列で表す) をそのまま CNN に使うとこの点で効かない。

## 手法の核心
- activation-memory-floor criterion: 学習対象の backward 計算が layer の full-width な入力に依存してはならない、という設計基準。
- down-projection を凍結し、scale-matched な up-projection のみを学習する。
- backbone の normalization を eval mode にし、activation を最小限しか保存しない backward rule を使う。保存状態は低ランク枝だけになる。
- 3 つの HAR (Human Activity Recognition) データセット × 2 CNN で、subject/body-location/sensor-placement の shift を評価。saved-activation メモリ 98.5–98.7%、peak 学習状態メモリ 94.9–97.3% 削減 (対 full fine-tuning)。精度は CNN PEFT baseline と同等以上。

## 適用可能性 (P2)
- Jetson 等の端末で、他機種・他センサへ少量データで適合する recipe。メモリ律速という視点が実務的。
- 注意: 評価は HAR (時系列センサ) で、画像検出や driving の CNN で同じ削減率が出るかは不明。

## 試すべき実験
1. 手元の CNN で full fine-tuning / 通常 LoRA / 同等構成の MemFLoRA の peak メモリを実測する。
2. 別センサ (別カメラ) への適合で、少データ (数百枚) の精度を PEFT baseline と比較する。
