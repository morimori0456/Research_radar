# Query-Based Cost Learning: waypoint を回帰せず「到達可能な ego 軌道」のコストを学習する E2E planner

- 対象: P1 (Planner AI + 評価) / P3 (E2E 自動運転) にもまたがる。candidates.json の topic は fm_distill_finetune だが内容は P1 なので P1 枠で採用
- 元論文: http://arxiv.org/abs/2610.08123v1
- 根拠: abstract のみ (本文・コード未確認)

## 何を解決する論文か
waypoint regression (将来の走行点列を直接回帰する方式) の E2E (End-to-End; センサ入力から計画まで一気通貫) planner は open-loop の精度は高いが、expert の幾何形状を真似るだけで、デプロイ時に安全制約を後から足すのが難しい。本論文は、力学的に到達可能な ego 軌道 query ごとに「有界なコスト」を推定する方式に替え、コストを介して安全性を調整できるようにする。

## 手法の核心
- dense な BEV (Bird's-Eye View; 俯瞰) セルや少数の回帰軌道ではなく、到達可能な ego 軌道の query にコストを割り当てる。
- compact な joint scene token で、他 agent の multimodal (複数の起こりうる) な将来を整合的に表現する。
- contingency-aware cost aggregation: 他 agent の将来の分岐ごとのコストを集約する。
- MPPI (Model Predictive Path Integral; サンプリングしたコスト重み付き平均で軌道を作る制御手法) をクラスタ内で cost-guided に混合し、実行可能な plan に変換する。
- 報告: nuScenes で ST-P3・NMP より改善、collision rate は多くの regression baseline より低く L2 は同等。実走行ログでは SparseDrive・Alpamayo より collision rate が低い (fine-tuning なし)。

## 適用可能性 (P1 / P3)
- planner が「コストの形」を出力するので、評価指標 (collision, TTC など) をコスト項として後から差し込める。planner 評価の観点では、regression 型の planner との差が open-loop L2 に出にくい点が示唆的。
- 注意: 評価は nuScenes の open-loop が中心とみられ、closed-loop での優位は abstract からは分からない。

## 試すべき実験
1. 手元の planner の出力軌道を、論文と同様の「軌道 query + コスト」で再採点し、collision rate と L2 の順位が入れ替わるかを見る (評価の盲点の確認)。
2. コスト項に追加の安全制約 (例: 最小車間) を足すだけで collision rate が下がるかを、再学習なしで確認する。
3. MPPI mixing の有無で軌道の diversity と collision rate を ablation する。
