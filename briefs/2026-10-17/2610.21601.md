# 2610.21601 — Waypoint-OPD: Transferring RL-Induced Policy Shifts via Gated On-Policy Distillation

- 元論文: https://arxiv.org/abs/2610.21601

## 何を解決する論文か

RL (reinforcement learning) で強化した teacher LLM の「RL 前後の log probability の差」(policy shift) を、student が自分で生成した trajectory 上の教師信号として再利用する蒸留 (policy-shift distillation) がある。ただし RL 開始点と終点の差だけでは、学習の途中で好みが一貫して変わったのか、前半と後半で逆向きに動いて打ち消し合ったのかが区別できない。本論文は、その不整合な shift を転送しないよう選別する。

## 手法の核心

- Waypoint-OPD (Waypoint-guided On-Policy Distillation; student 自身の生成した系列上で teacher から学ぶ on-policy distillation に、途中 checkpoint で shift を選別する gate を足した手法)。
- 同じ RL run の中間 teacher checkpoint (waypoint) を使い、「初期→中間」と「中間→終点」の 2 つの shift を作る。
- student が訪れた prefix ごとに、2 つの shift が相対的な action preference (どの token を相対的に好むか) の向きで一致するかを見る。
- 一致度に応じて endpoint shift に gate をかける。逆向きなら抑制する。
- 追加コストは frozen teacher の scoring pass 1 回のみ。
- 実験: RL 済み Qwen3-4B を teacher に、student は Qwen3-8B / 14B / 30B-A3B。数学・コード推論の 6 設定すべてで比較手法中の domain-average が最高。Qwen3-8B での ablation では gate を外す/シャッフルすると数学が低下。

## 適用可能性と実験アイデア

- **P2 (FM 蒸留)**: 蒸留 recipe に「teacher の学習履歴 (中間 checkpoint) を使う」という軸を足せる。teacher を自前で RL/fine-tuning する場合、中間 checkpoint を 1 本保存しておくだけで試せる。
- 実験案 1: 手元の teacher の fine-tuning run で中間 checkpoint を保存し、2 つの shift の符号一致率が prefix 間でどれだけ分布するかをまず可視化する (一致率がほぼ 1 なら gate の効果は薄いと予想できる)。
- 実験案 2: 既存の on-policy distillation 設定に gate を後付けし、gate あり/なし/シャッフルの 3 条件を同じ seed で比較する。
- 注意: 評価は数学・コード推論の LLM のみ。運転 (P1/P3) への直接転用は未検証。teacher と student が同系統 (Qwen3) 前提の可能性があり、本文で確認したい。
