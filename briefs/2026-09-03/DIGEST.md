## 今日読むべき TOP3

**本日の採用 6 本は、1 つの問いの変奏である —— 「モデルを別のものに変換したあと、何が残っていて、何が消えたのか」。**変換の中身は圧縮・蒸留・視覚への適合・運転への適合とばらばらだが、**6 本すべてが「集約された 1 つの数字は、消えたものを隠す」と言い、その代わりに何を見るかを提案している。****これは R1 が書こうとしている論文の主張そのものである。**TOP3 は **09-06 gate の作業を動かす順**に並べた。

### 1. [圧縮した運転方策を、集約スコアではなく「できなくなった運転」で受け入れ判定する](2609.00718.md) — P1 **5.0**

**理由: R1 の図 1 の「作り方」が、運転・閉ループ・実際の圧縮パイプラインという、R1 が想定している場所そのもので実演されている。しかも代替指標が「新しいスカラー」ではなく「表」なので、定義の議論が要らない。**

著者がやったことは単純である。**運転方策を PPO (Proximal Policy Optimization; 方策を大きく動かしすぎないよう制約をかける標準的な強化学習法) で学習し、そこから actor だけを取り出して、圧縮を 1 段ずつ適用する。**そして各段階の出力を **5 つの driving curricula (要求される挙動が異なる 5 種類の走行課題)** で **closed-loop evaluation** (実際に走らせる評価。1 フレームずつ正解軌跡と比べる open-loop evaluation の対義語) にかける。

**見えた形が、集約スコアでは絶対に出てこない。**

- **運転能力が最初に失われるのは structured pruning (チャンネルや層をまとめて削る枝刈り) の段階である。**
- **distillation は pruning 後の方策を回復させるが、回復幅は rehearsal data (復習用データ) の被覆で頭打ちになる。**
- **回復後に integer quantization (重みを低ビット整数に落とす) をかけると、「一旦停止して再発進する」ことを要求する curriculum だけが落ちる。**
- **そして pruning を通さずに同じ手順を踏むと、5 つ全部が残る。**つまり**損失は quantization 単体ではなく、pruning が先に壊した上に乗った合成である。段階を混ぜていたら分離できなかった。**

**W36 の課題レーダーが拾った ASCEND (NHTSA × SAE ITC の 3 年 $5M コンソーシアム) の 3 要件と突き合わせると、R1 の立ち位置が 1 行で言える。**本論文は **objective (二値で数えられる)** と **repeatable (公開シミュレータで再実行できる)** を満たすが、**proactive (事故が起きる前に測る) を満たしていない** —— 失敗が起きてから数えているからである。**R1 の solvability (いまこの状態から、まだ助かる候補が何本残っているか) は、まさにその 3 つ目を埋める量である。**

> **競合ではなく、最も都合のよい配置である。**同じ方向の独立した証拠が先にあり、**自分の差分が 1 行で書ける。**

### 2. [VLM の中身を触らずに運転を足し、3 段階の閉ループで測った](2609.00111.md) — P1 **4.5** / P3 **4.5** (hf_upvotes **335**)

**理由: R1 の実験節で「どの段で測るのか」が未決のままである。この論文の 3 段の梯子を借りれば、その 1 行が今日決まる。**

Qwen-Drive-1.0 は、事前学習済み **VLM (Vision-Language Model; 画像と言語を同じモデルで扱う基盤モデル)** の構造をそのまま保ったまま、3D 知覚・視覚的な問答・軌跡生成を 1 つの枠組みに統合する。**設計上いちばん面白いのは、外付けの BEV (Bird's-Eye-View; 真上から見下ろした平面図の表現) head の置き方である —— 性能を上げる部品としてではなく、「共有表現からどれだけ 3D 情報が取り出せるか」を測る probe (探り針) として置かれている。**中間表現を外から検査できるようにすること自体が設計目標になっている。

**そして R1 にとって重要なのは評価の側である。****open-loop / pseudo-closed-loop / closed-loop の 3 段を、1 本の論文の中で全部走らせている。**

**R1 は「衝突率の隣に置く量」を提案する論文なので、その量をどの段で測るかを明示しないと、査読で最初にそこを突かれる。**本論文の 3 段構成を骨組みとして借り、**「R1 はここで測る」と 1 行書くだけで済む。**これは図 1 の作業とは独立で、**30 分で終わる。**

### 3. [蒸留は推論を伸ばす裏で、事実の記憶を遅らせていた](2609.01532.md) — P2 **5.0**

**理由: R2 の「監督を当てる範囲が支配変数」に 5 例目が付き、しかも「範囲」に時間軸が加わった。加えて、今日の 1 本目とまったく同じ隠れ方をしている。**

**mid-training (事前学習と post-training の間に、精選コーパスで自己教師あり学習を続ける中間段階)** に絞って統制実験をすると、**forward KL 蒸留 (教師分布 → 生徒分布の向きに Kullback-Leibler divergence を最小化する標準的な蒸留)** の効果の符号が変わる。**pre-training 中は推論も事実記憶も同時に伸びるのに、mid-training では推論だけ伸びて事実記憶の獲得が遅くなる。**

**原因は 2 つの非対称性の掛け算である。****教師は手続き的なデータでは自信が高く、知識が要るデータでは自信が低い。一方で生徒は、事実知識を学習の早い段階で獲得する。**つまり mid-training の時点では、**生徒がちょうど事実を覚えている最中なのに、教師はその領域で曖昧な分布を返している。**

対策は拍子抜けするほど単純で、**教師が自信を持っている token でだけ蒸留し、それ以外は通常の cross-entropy に戻す。**判定に使うのは **teacher predictive entropy (教師の予測分布のエントロピー。低いほど確信がある) だけ**で、追加のモデルもアノテーションも要らない。

**そして本日の 1 本目と、隠れ方が同型である。**

| | 変換 | 平均は何と言うか | 実際に消えたもの |
|---|---|---|---|
| [圧縮運転方策](2609.00718.md) | pruning → distill → quantize | スコアは概ね維持 | **特定の運転 curriculum が丸ごと** |
| **本論文** | mid-training の蒸留 | 平均性能は改善 | **事実記憶だけが遅延** |

**分野は無関係なのに、同じ形をしている。**

## プロジェクト別の要点

### P1 — planner 評価 (R1: 衝突率の隣に置く量)

**本日、R1 の主張の後ろ盾が 2 方向から増えた。そして片方は、R1 がまだ持っていなかった「学習側の証拠」である。**

R1 の主張は **「集約された評価指標は、方策が失った能力を隠す」**である。W35 まで、この主張の証拠はすべて**評価側**から集めてきた ([Driving on Memory](../2026-09-02/2608.31029.md) / [Intervention Gap](../2026-09-02/2608.29998.md) など)。

**本日 [IMPACT](2609.00161.md) が、同じ失敗が学習側でも起きていることを示した。**全体で平均を取る MSE の denoising objective (拡散モデルでノイズを除去する学習目標) の下では、**画面の大半を占める静止した内容が最適化の信号を支配し、面積は小さいが相互作用にとって決定的な動的物体の領域が、不釣り合いに学習されない。**

> **評価: 集約された指標は、稀だが決定的な部分を隠す。**
> **学習: 集約された目標は、稀だが決定的な部分を学ばせない。**

**この対応が R1 の導入を強くする。**評価の側だけで論じると「指標の設計が下手だっただけでは」と読まれる余地があるが、**学習の側でも独立に報告されているなら、これは設計の巧拙ではなく、平均を取るという操作そのものの性質だと言える。****引用 1 本で主張の一般性が上がる。**

**そして IMPACT は、R1 の作業そのものに警告を出している。****走行ログで solvability を集計するとき、大半の時間は「逃げ道が十分ある」状態のはずである。そのまま平均すれば、決定的な数秒が薄まる。****R1 は自分の指標の集計側で、IMPACT と全く同じ罠を踏みうる。****図 1 を作る前に気づいたほうがよい。**

もう 1 つの後ろ盾が [圧縮運転方策の閉ループ評価](2609.00718.md) で、**ASCEND の 3 要件のうち 2 つを先に埋めており、残る 1 つ (proactive) が R1 の差分になる。**

### P2 — 蒸留と適合 (R2: 蒸留の破綻境界)

**W35 の結論「蒸留・適合の支配変数は loss の関数形ではなく、監督を当てる範囲である」が、本日 6 例目に達し、ついに言語モデルの外に出た。**

| 分野 | 論文 | 監督をどう配るか |
|---|---|---|
| LLM 蒸留 | [UC-MOPD](../2026-08-29/2608.26735.md) / [Echo-GRPO](../2026-08-29/2608.26684.md) | 更新する token を選ぶ |
| 音声/生成 | [DART-SD](../2026-09-01/2608.18524.md) | loss を当てる位置を選ぶ |
| RL 蒸留 | [OPD の分解](../2026-09-02/2608.31046.md) | 基準そのものが不要 |
| LLM 蒸留 | [Switch Distillation](2609.01532.md) | **教師の entropy で選ぶ。かつ「いつ」当てるかで符号が変わる** |
| **拡散 world model** | **[IMPACT](2609.00161.md)** | **loss を当てる空間領域を選ぶ** |

**5 例が言語モデル周辺に固まっていた間は「LLM 特有の現象」という反論があり得た。分野が離れた 6 例目が出たことで、R2 は「監督配分」を分野横断の変数として主張できる。**

**そして本日、R2 に初めて「事前に測る」型が入った。**[Sink Strength](2609.00746.md) は、**base LLM だけで GPU 1 枚・数秒で計算できるスカラー 1 つが、VL 適合後にどれだけ言語能力が壊れるかを予測する。**学習を 1 ステップも回さない。

**これが R2 のコスト構造を変えうる。**R2 の中心問題「蒸留・適合がいつ破綻するか」を確かめるには、これまで**破綻するまで走らせる**必要があった。**base モデル側だけで計算できる量が予兆になるなら、探索のコストが桁で下がる。**Sink Strength そのものが蒸留に効くかは未知だが、**問いの立て方はそのまま移植できる。**

**さらに本日の 3 本 ([Switch Distillation](2609.01532.md) の teacher entropy / [Sink Strength](2609.00746.md) の attention sink / [IMPACT](2609.00161.md) の cross-attention) は、すべて追加学習なしにモデル内部から取れる信号で、監督や劣化を制御している。****「内部信号で決める」が、R2 の系統則を書くときの軸になる。**

**ただし 09 月は R1 に絞る方針である** ([RESEARCH_PIPELINE.md](../../RESEARCH_PIPELINE.md))**。P2 の実験は 10 月以降。今月やるのは、過去の蒸留ログを「どの段階で蒸留したか」で並べ直す 1 時間の机上作業だけ。**

### P3 — 次世代アーキテクチャ (R3: VLA × world model 統合)

**R3 の分類マップの軸 ①「時間をどこに持つか」に、新しい象限が入った。**

W35 の収束点は **「画素は world model の言語として粗すぎる」**で、09-02 はそこに**「粗いのではなく、勾配が一度も届いていない」**という機構レベルの理由を足した。**解き方はどれも「表現の粒度を上げる」方向だった。**

**[ZimaBlue](2609.00188.md) は別の方向に解く —— 粗い表現を遅い側に置き、速い側を別に用意する。****Slow 側は大容量の world model で一般化する時空間表現を供給し、Fast 側は軽量な分岐で行動を出す。両者が非同期に動く。**その結果 **RTX 4090 という単体の民生 GPU 上で 30 Hz の行動予測**が出ている。生成的な world model を実時間制御に載せるという、ふつう成立しない条件を通した。

**そして数字が主張の中心にある。****行動ラベルの無い一人称視点動画を 12 万時間超足すと、対象ロボットのデータだけの 36.1% が 77.8% になる。**効果は未見のタスクで特に大きい。**スケールが効いているのは記憶ではなく一般化の側である。**

**この Slow-Fast 非同期は、R2 にとっても 3 つ目の選択肢になる。**capacity gap (教師と生徒の能力差が大きすぎて蒸留が効かなくなる現象) への対処として、既存の 2 つは**「教師を下げる」** ([Knowledge-Aligned SFT](../2026-09-02/2608.30987.md)) と**「教師は要らない」** ([OPD](../2026-09-02/2608.31046.md))。**3 つ目は「移すのをやめて、非同期に参照する」。**

**次点の [H3-World](rejected.md) (hf_upvotes 40 = next_arch 内最高) も同じ軸に値を足すが、ZimaBlue に枠を譲った。**33B の動画生成モデルを、行動モジュールを新設せずに **LoRA で学習パラメータ 0.199%・8,000 サンプル**だけ動かして対話的な world model に変える、という報告である。**R3 に着手する 10 月には必ず読む。**

**R3 は今月着手しない方針を維持する。軸の値を記録するだけで、手は動かさない。**
