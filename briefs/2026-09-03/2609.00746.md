# Text Capability Loss in Vision-Language Adaptation — 学習する前に、壊れる量が予測できる

**topic:** fm_distill_finetune / **project:** P2 (主) / **hf_upvotes:** 0
**スコア:** P1 2.5 / P2 **4.5** / P3 3.0
著者: Minsik Choi, Geewook Kim, Young Geun Kim

## 何を解決する論文か

事前学習済み LLM を fine-tuning して **VLM (Vision-Language Model)** にすると、**元の言語能力が削れる。**しかもその損害は一様ではなく、**「出力の形式を厳密に守ること」を要求するタスクに集中する** —— instruction following、最終解答を厳格にパースして採点する chain-of-thought (途中の推論過程を出力させる方式)、その他 grader が厳しい評価がこれに当たる。

**著者はこの劣化を attention-sink corruption として説明する。****attention sink (アテンション・シンク)** とは、**系列の先頭付近の特定位置に attention の確率質量が大量に集まる現象**で、多くの LLM が内部的にこれを「置き場」として使っている。**VL fine-tuning はこの sink の位置を乱し、乱れの大きさが失われる能力の量と対応する。**

**そして実用上の核心はここ —— 壊れ方が、VL 学習を一切行わずに予測できる。**

## 手法の核心

- **劣化の所在を特定する: VL fine-tuning が early sink position (アテンションの大部分を受け止めている先頭付近の位置) を摂動する。**base LLM がこの sink をどれだけ保てるかが、**適合後にどれだけ能力が生き残るかを追跡する。**
- **Sink Strength という単一のスカラーを定義する。****base LLM のみに対して、GPU 1 枚・数秒で計算できる。**VL 学習は不要。
- **この 1 つの数字が、6 組の VLM-LLM ペアと複数の形式厳守タスクにわたって、劣化の相対的な大きさを一貫して追跡する。**
- **negative result 1: QK-RMSNorm (query と key に RMS 正規化を挟む構造。sink の暴走を抑える効果があるとされる) を事前学習後に後付けで注入しても、最初から組み込まれていた場合の保護は再現されない。**
- **negative result 2: 出来合いの weight merging (適合前後の重みを混ぜて能力を取り戻す手法) の設定をいくつか試しても、VL 学習後に失われた能力は回復しない。**
- **結論の向きが実務的である —— 事後に治すのは難しい。だから VL 学習の前に Sink Strength で backbone を選別せよ。**そして介入の探索範囲は **head-selective な学習時保護 (どのアテンションヘッドを守るかを選ぶ方式)** に絞られる。

> **引用前の注意:** **6 ペアという規模は、傾向を示すには足りるが法則を主張するには小さい。**また「相対的な劣化を追跡する」であって、**劣化量を絶対値で予測するとは書かれていない。**選別 (ランキング) には使えるが、**「この backbone なら何点落ちる」という見積もりには使えない。**

## P1 / P2 / P3 への適用可能性

**P2 にとって、これは「事前に測る」型の初めての例である。**

R2 がこれまで集めてきた 5 本は全部**事後**の話だった —— どの token を更新するか、どこに loss を当てるか、教師の信号が要るのか。**本論文だけが、学習を 1 ステップも回さずに結果を予測している。**

**この違いが R2 にとって大きい理由は、コストである。**R2 の中心問題「蒸留・適合がいつ破綻するか」を実験で確かめるには、**破綻するまで走らせる必要がある。**もし **base モデル側だけで計算できる量が破綻の予兆になるなら、探索のコストが桁で下がる。**Sink Strength そのものが蒸留に効くかは分からないが、**「base モデルの内部統計から適合後の劣化を予測する」という問いの立て方は、そのまま R2 に移植できる。**

**そして本日の 3 本と、きれいに 1 本の線に乗る。**

| 論文 | 変換 | 何が失われたか | どう検出したか |
|---|---|---|---|
| [圧縮運転方策](2609.00718.md) | pruning → distill → quantize | 特定の運転 curriculum | **段階を分けて閉ループで走らせる (事後)** |
| [Switch Distillation](2609.01532.md) | mid-training の蒸留 | 事実記憶だけ | **能力を分けて測る (事後)** |
| **本論文** | VL 適合 | 形式厳守の言語能力 | **base モデルのスカラー 1 つ (事前)** |
| [Qwen-Drive-1.0](2609.00111.md) | 運転への適合 | (汎用 VL 能力を保てたと報告) | **汎用ベンチマークを併走 (事後)** |

**4 本とも「変換の後に何が残っているか」を問うている。違うのは、測るタイミングと粒度だけである。**

**R1 への含意が 1 つある (P1 2.5)。**R1 は **「衝突率の隣に置く量」**を提案する予定だが、**その量を「事後に測る量」として出すか「事前に予測する量」として出すかで、主張の強さが変わる。**本論文の型を借りれば、**「走らせる前に、この planner がどの状況で逃げ道を失うかを予測する量」**という形が視野に入る。**ただし 09-06 gate までにこれを足すのは無理である。図 1 は事後の測定で出す。**

**P3 は 3.0。**attention sink は VLA や world model の backbone でも同じ構造で起きうるが、確認された報告は本論文の範囲外。

### 試すべき実験アイデア

1. **【R2・10 月以降・半日】手元の蒸留・適合の記録に、base モデル側だけで計算できる統計を後付けする。**Sink Strength をそのまま使う必要はない。**要は「適合前の base モデルの内部統計」と「適合後の劣化」の相関を 1 枚の散布図にすること。**相関があれば、**R2 の探索が「回して確かめる」から「事前に選別する」に変わる。**
2. **【1 時間・机上】自分が過去に「なぜかこの backbone だと蒸留が効かない」と感じた事例を洗い出す。**本論文の主張が正しければ、**それは蒸留手法の問題ではなく backbone の選択の問題だった可能性がある。**説明が入れ替わるだけで、**R2 の独立変数が 1 本増える。**
3. **【メモのみ】negative result 2 (weight merging では治らない) を記録しておく。**「適合で壊れた能力を後から混ぜて戻す」は安直に思いつく対策なので、**効かないと報告されている事実自体が時間の節約になる。**
