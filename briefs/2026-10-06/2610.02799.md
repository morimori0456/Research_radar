# FUSEye: Training-Light Fisheye Detection with Overlapping Views and Zero-Initialized Adapters

- arXiv: `2610.02799` / https://arxiv.org/abs/2610.02799
- 配属: **fm_distill_finetune (P2)**。keyword `fine-tuning` に一致。「基盤モデルを別ドメイン・別センサーへ少データで適合」の観点で採点。
- スコア: P2 4.0 ・ P3 2.5
- 入手経路: fetch は 0 件。**RSS 回収分** (10-05 announce)

## 何を解決する論文か

COCO (一般画像の物体検出データセット) で学習済みの検出器は、fisheye (魚眼; 視野が広い代わりに強く歪むカメラ) の画像ではほとんど動かない。歪みで局所の形が崩れ、画像の端では物体が極端に小さくなるため。全体を fine-tuning すれば改善するが、fisheye のラベルと計算資源が大量に要る。FUSEye は、凍結 (frozen; 重みを更新しない) した検出器に約 22.7 万パラメータだけを足して、fisheye に適合させる。

## 手法の核心

- **ベース:** COCO 学習済みの YOLO26-x (YOLO 系の物体検出器) の backbone を凍結。追加した modules と検出 head だけを更新する。
- **GridViews (入力レベル):** 1 枚の画像を重なりのあるグリッドの複数ビューに切り、box を座標変換で対応づける。圧縮された画像の端を拡大して見せる。
- **Z-Adapters (特徴レベル):** zero-initialized residual adapters。adapter の出力層を 0 で初期化し、学習開始時は元の検出器と完全に同じ出力になるようにして、歪みによる特徴のずれだけを徐々に補正する。
- **AgreeFusion (判断レベル):** 複数ビューで一貫して見えた低信頼の検出だけを、信頼度を上げて採用する。ビュー間の一致を学習で融合する。
- **結果:** WoodScape (車載 surround-view fisheye のベンチマーク) で mAP50 (IoU 0.5 で数える検出精度) が 0.148 → 0.266。全体 fine-tuning の 84.3% を保持。**ラベルを 25% に減らしても 0.2597 (全ラベル時の 97.6%)**。YOLOv8〜11 でも改善し、recipe は検出器の種類に依らないと主張している。

## プロジェクトへの適用可能性

- **P2 の「他機種への適合」の具体例。**センサー (カメラ) が変わると基盤モデルが壊れる、という実務でよくある問題に対し、少量パラメータ + 少量ラベルで戻す recipe。Z-Adapters の「0 初期化で元の出力を保ったまま始める」は、LoRA 的な適合を試す際にそのまま流用できる。
- **P3: 車載の surround-view を扱う場合の前処理。**GridViews は検出向けだが、「歪みの強い端を別ビューで見せる」考え方は、周囲カメラを入力にする E2E driving の前処理で検討できる。
- **限界:** 絶対値は mAP50 0.266 と低く、「全体 fine-tuning に近づく」ことが主張で、実用精度ではない。評価は検出のみで、運転タスクの成績は無い。

## 試すべき実験アイデア

1. **(手元のデータ、集計のみ) 適合の効きを見る:** 他機種のカメラ画像が少量でもあれば、凍結した現行の検出器で mAP を測り、基盤モデルがどこまで落ちるかを先に確認する (論文の 0.148 に相当する数)。
2. **(toy、CPU で数分) 0 初期化 adapter の性質の確認:** 小さな CNN を 1 つのドメイン (通常の画像) で学習し、radial な歪みをかけた画像を別ドメインとする。凍結 + (a) 通常初期化の adapter、(b) 0 初期化の adapter を比べ、学習の初期の損失の振れと最終精度を見る。
3. **(P2) ラベル量の曲線:** 5%, 10%, 25%, 100% のラベルで adapter 適合を回し、「何 % で全ラベル時の 95% に届くか」を自分の機種で出す。論文の 25% → 97.6% と比較できる。
