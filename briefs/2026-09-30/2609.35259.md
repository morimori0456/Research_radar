# On-Policy or Off-Policy Learning? A Systematic Study of Distillation Dynamics

- arXiv: `2609.35259` / https://arxiv.org/abs/2609.35259
- 配属: fm_distill_finetune (P2)
- スコア: **P2 4.5** ・ hf_upvotes 0

## 何を解決する論文か

蒸留では「student 自身が生成したデータで学ぶ (on-policy) 方が、忘却が少なく汎化する」とよく言われる。しかし既存の比較は SFT と RL のように多くの条件を同時に変えており、「rollout を誰が生成したか」だけの効果は分かっていなかった。この論文は、強い teacher から弱い student への蒸留で、**rollout policy・token 単位の KL の向き・学習率の 3 つを独立に振って**効果を切り分け、主役は rollout policy ではないことを示した。

## 手法の核心

- 用語: **on-policy** = student 自身の生成した系列に対して teacher の確率を当てて学ぶ。**off-policy** = teacher が生成した系列 (または固定データ) で学ぶ。**forward KL** (KL(teacher‖student); teacher が確率を置く所すべてに student も確率を置こうとする = 広く覆う) と **reverse KL** (KL(student‖teacher); student が確率を置く所で teacher と一致させる = 一つの山に絞る) は、蒸留 loss の 2 つの向き。
- **統制実験:** Llama3 / Qwen2.5 の 2 系列 × 科学・医療・算数の推論タスクで、rollout policy (student ↔ teacher を連続的に混ぜた中間も含む)、KL の向き、学習率を独立に変える。
- **結論 1 — 性能と出力の多様性を決めるのは KL の向き。**forward KL は rollout policy をどう変えても性能が安定して高い。reverse KL は rollout policy に敏感で、student 生成の rollout を好む。つまり「on-policy が効く」は **reverse KL を使うときの話**。
- **結論 2 — 忘却と更新の疎さ (更新されるパラメータの少なさ) を決めるのは学習率。**「on-policy だと忘却が少ない」とされてきた効果は、主に学習率で説明できる。
- **結論 3 — on-policy の汎化の利点は限定的。**Countdown (算数パズル) の難しい変種への汎化は両方の KL で on-policy が良いが、その後に RLVR (Reinforcement Learning with Verifiable Rewards; 正誤を自動判定できる報酬での RL) をかけると利点は安定して残らない。gradient clipping を外しても、KL を sampling で推定しても、長い推論でも結論は変わらない。

## P2 への適用可能性

- **蒸留 recipe を決めるときの優先順位が変わる。**「on-policy にするか」(rollout 生成のコストが高い) より先に、「KL の向き」と「学習率」を振るべき、という実務上の指示になる。on-policy rollout は student の推論を回す分だけ高くつくので、**forward KL + off-policy で足りるなら計算コストが大きく下がる。**
- **忘却の対策は学習率で。**他ドメインへの適合 (P2 の fine-tuning 軸) で元の能力が壊れる問題に対し、手法を足す前に学習率スイープで忘却と適合の trade-off を描くのが先、という根拠になる。
- **これまでの P2 の読みとの関係:** 09-01 の DART-SD や 09-02 の OPD で「on-policy + 監督を当てる範囲」を重視してきたが、本論文はその前提 (on-policy が本質) を条件付きにする。R2 の主張「支配変数は loss でなく監督を当てる範囲」を書くときに、**KL の向きを固定した比較か**を確認すべき反例候補として引く。
- 限界: 言語モデルの推論タスクのみ。画像の特徴量蒸留 (連続値の回帰 loss) では「KL の向き」に直接対応するものがないので、そのまま移すには置き換え (例: 回帰 loss の非対称な重み付け) が要る。

## 試すべき実験アイデア

1. **(半日) 2×2 の最小再現:** 小さな teacher/student (例: 2 層 MLP の分類器、出力はクラス分布) で `{forward KL, reverse KL} × {teacher が生成したデータ, student が生成したデータ}` を回し、student の精度と出力分布のエントロピーを並べる。「forward KL は rollout 源に鈍感」が toy でも出るかを見る。
2. **(1 日) 学習率スイープで忘却を測る:** 手元の fine-tuning タスクで学習率を 4 点振り、新ドメインの精度と元ドメインの精度を 2 軸で描く。on-policy / off-policy をそれぞれ重ねて、曲線が学習率でほぼ決まるかを確認する。
3. **(蒸留の本番前) KL の向きの事前選定:** 本番の LLM 系蒸留で、まず off-policy の forward KL を baseline にし、on-policy の reverse KL がそれを上回るかだけを確認する。上回らなければ on-policy rollout のインフラを作らずに済む。
