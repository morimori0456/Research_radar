# RefineDrive: Reliable Failure-Guided Learning for Vision-Language-Action Driving

- arXiv: `2609.35078` / https://arxiv.org/abs/2609.35078
- 配属: **planner_ai (P1) に再分類** (candidates.json 上は next_arch。planner_ai の 3 件がいずれも運転と無関係で、P1 基準で 4.0 以上の他トピック候補に限り P1 枠を使う運用による)
- スコア: **P1 4.0 / P3 4.0** ・ hf_upvotes 0

## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語を入力に行動を直接出力する大規模モデル) の運転 policy は、成功した人間の走行データを真似て学習するため、自分がどう失敗するかを学ぶ機会がない。失敗から学ぼうとしても、(1) 何が悪かったかの診断が不確か、(2) 「正解」として与える修正軌跡が失敗した場面に合っていない、(3) 報酬が粗い、の 3 点で詰まる。この論文は、simulator の状態から検証可能な形で失敗を診断し、その場面で安全な最小限の修正軌跡を引いてきて学習に使う post-training を提案し、NAVSIM v1 で 4B モデルの PDMS を 87.7 → 91.7 に上げた。

## 手法の核心

- **Reliable Diagnosis**: 衝突・走行可能領域からのはみ出しを、言語モデルに判定させるのではなく **simulator の状態から直接** 計算する。診断が「検証可能な事実」になるので、学習信号にノイズが乗らない。
- **Minimum-Correction Target Retrieval**: 人間の走行軌跡をクラスタリングした bank から、「今の場面で hard safety 制約 (衝突なし・領域内) を満たし、かつ失敗した予測の動き方に最も近い」軌跡を探して修正目標にする。**失敗から遠い模範解答ではなく、失敗のすぐ隣にある安全な軌跡**を教える、という設計。
- **Correction SFT**: 走行文脈と失敗軌跡を入力に、「診断 → 修正軌跡」を生成させる補助タスク。**学習時だけ**使い、推論時は診断も修正も出さず軌跡を直接予測する (推論コストは増えない)。
- **GRPO + Safety-Layered Reward**: GRPO (Group Relative Policy Optimization; 同じ入力から複数の出力を生成してグループ内の相対的な良さで更新する、PPO の簡略版) を使う。報酬は階層的で、hard safety を満たさない軌跡には進捗報酬を与えず、安全を満たして初めて前進量を評価する。安全違反の度合いは連続値で残すので、「全部 0 点」で勾配が消えることはない。
- 結果: NAVSIM v1 で PDMS (Predictive Driver Model Score; NAVSIM の総合スコアで、衝突・領域逸脱・快適性・進捗などを掛け合わせたもの) 87.7 → 91.7。同じ checkpoint で NAVSIM v2 の拡張指標 EPDMS 89.4。

## P1 への適用可能性

- **評価指標の設計に直接使える部分: 「失敗を simulator の状態から構造化して記録する」こと自体。**P1 の planner 評価で失敗を「スコアが低い」の 1 数値で終わらせず、`{衝突, 領域逸脱, その他}` × 発生時刻のラベルとして残せば、学習にも回帰テストにも使える形になる。
- **Minimum-Correction の考え方は評価側にも転用できる。**「失敗軌跡から最小何 m ずらせば安全な軌跡になったか」は、失敗の「惜しさ」を測る連続指標になる。二値の collision 率よりも planner 間の差を細かく出せる。
- **09-29 の RSS 繰り越し 2 本との関係:** `2609.30818` (候補の中に良い軌跡があるのに選択で失敗する) と `2609.31383` (ECO; 終点を固定して途中の点を後処理で整える) と並べると、「失敗は生成・選択・追従のどこで起きているか」を切り分ける 3 本組になる。RefineDrive は **生成の側を学習で直す**立場。
- **注意:** 修正目標を人間軌跡 bank から引くので、bank に無い場面 (珍しい交差点形状など) では修正目標自体が見つからないはず。abstract では見つからなかった場合の扱いが不明で、原論文の確認が必要。

## P3 への適用可能性

- VLA の post-training で「成功例の模倣 → 失敗の診断付き SFT → 安全階層報酬の RL」という 3 段が、4B 規模で 4 pt 効いたという実例。P3 で VLA 運転モデルを組むときの学習 recipe の比較対象になる。
- 「診断を学習時だけの補助タスクにして推論時は捨てる」は、言語の推論過程を出力させる VLA で推論コストを増やさずに言語の利点だけを取る設計として参考になる。

## 試すべき実験アイデア

1. **(半日・2D toy) 失敗ラベルの構造化:** 既存の 2D toy planner の評価ループに、失敗エピソードごとに `failure_type` と `first_violation_step` を記録する 1 関数を足す。スコアと並べて「どの種類の失敗が支配的か」をヒストグラムにする。W39 の推薦 (CodeMidas ヒストグラム) と同じ形の 1 commit で済む。
2. **(1 日) 最小修正距離の指標化:** 失敗した軌跡それぞれについて、事前に集めた安全軌跡の集合から最も近いものまでの距離 (例: 平均 L2) を計算し、「修正距離」として二値の collision 率と並べて planner 間で比較する。planner の順位が変わるかを見る。
3. **(RL を回せる段になったら) 報酬の階層化の ablation:** 「安全を満たしたときだけ進捗報酬」と「安全と進捗の重み付き和」を同条件で比べ、進捗を稼ぐために安全を犠牲にする挙動が減るかを見る。
