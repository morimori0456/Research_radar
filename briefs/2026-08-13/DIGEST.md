## 今日読むべき TOP3

### 1. VIScore — 「表現が綺麗になった」では planning が良くなったことにならない

**本日の 53 件で、P3 (次世代アーキテクチャ) と P1 (planner 評価) の両方に同時に刺さる唯一の論文。** 追っているアイデア **R3 (VLA × world model 統合アーキテクチャ)** の、調査を始める前の前提 ——「**そもそも出来上がった world model の良し悪しを何で測るのか**」—— に答えている。

**最初に効くのは手法ではなく、著者が突きつける不都合な事実の方。** world model の latent 空間を等方な正規分布に整えるのは定石だが、**同じ分布を目標にする 2 つの正則化を比べると、片方は planning をまったく助けず、もう片方は助ける。** 目標分布が同じなのに結果が割れる以上、**「表現が目標分布に近い」という指標は planning の成否について何も言っていない。** しかも助けなかった方は、表現学習の文脈では有益とされてきた手法である。

**我々が痛いのは、否定された指標の中に自分たちが使っているものが入っていること。** 著者が比較対象に挙げた 3 つ —— 軌跡の直線性、**latent から位置や速度を線形に読み出せるか (probing)**、その状態から到達できる未来の多様さ —— のうち、**probing は我々が世界モデルの品質確認に真っ先に使う手口**である。

処方の筋も通っている。**測る場所を latent だけから 3 段に広げる**: encoder が出した特徴から **predictor が本当に正しい未来に届くか**、**どれだけ多様な未来を出し分けられるか**、そして **planner が「到達できない未来を到達できると信じ込んだ」量**。**encoder が良くても predictor が届かなければ planning は失敗する、という当たり前の経路が、既存指標では丸ごと抜けていた。**

**検証の出し方も指標論文として正しい。** 見たことのあるモデル・データセットでも見たことのないものでも順位相関 0.75 超を保ち、さらに **「指標値から予測した成功率と実際のズレ」が、定数を当てはめただけのモデルを下回った唯一の指標**だった。**後者が効いていて、「順位は当たるが値は無意味」という指標の逃げ道を塞いでいる。**

**明日から動ける形になっているのが良い。** 新しい指標を実装する前に、**手持ちのチェックポイントで「予測誤差 / probing の精度」と「closed-loop 成功率」を散布図にするだけ**でいい。**相関が出てしまえば我々のドメインにこの問題は無く、以降は不要。** 処方より先に診断。→ [ブリーフ](2608.11174.md)

### 2. 4D-WAM — 幾何の知識を、推論に一切触らずに入れる

**P3 の実務側の主力で、本日で最も「明日の設計に効く型」を持っている 1 本。** 自動運転の world-action model (未来のシーン変化の予測と軌道 planning を 1 つのモデルで学習する枠組み) を、NAVSIM の v1・v2 の両方で SOTA に押し上げている。

**問題の立て方が明快。** WAM の学習データは動画、つまり**立体的な世界を平面に投影したもの**しかない。だから WAM は空間の構造を理解しないまま学習され、**見た目はもっともらしいのに辻褄が合っていない未来**を作る —— フレーム間で奥行きが揺れる、他車の大きさが物理的にありえない変化をする。**そして下流の planning がその破綻した未来を真に受ける。**

**処方が上手いのは、幾何を「アーキテクチャ」ではなく「loss」として入れたところ。** 3D 幾何を推定する事前学習済みモデルを持ち込むが、**呼ぶのは学習時だけ**。生成された未来フレームをそのモデルに食わせ、返ってきた応答の時間的な整合性を loss にする。**デプロイされるのは元の WAM のままで、推論コストの増加はゼロ。** 加えて **4D の正解データを新たに用意する必要が無い** —— 幾何モデルが事実上の疑似ラベル器として働く。**車載を前提にする我々にとって、この形は決定的に重要。**

**もう一つの発見が独立して価値がある。** 生成は粗い段階から細かい段階へ進むが、著者は **運転の決定 (曲がるか、止まるか) は早い粗い段階でほぼ確定している**ことを見つけた。**だから細部を綺麗にする後半に監督を厚くしても planning は良くならない。** 処方は「同じ loss を、効く区間に配り直す」だけで、追加コストは無い。

**そして我々にとって最も価値があるのは、この論文の一般形の方。** 「**foundation model を推論に入れず、学習時の採点者としてだけ使う**」は 4D 幾何に限らない —— **交通ルールの検証器、他車の挙動予測器、地図の整合性チェッカ**、どれも同じ形で「生成された未来を採点させて loss にする」ことができる。**本論文はそのテンプレートとして読むのが一番得。**

**留保も明確にしておく。** NAVSIM は他車が反応しない設定であり、**ここでの SOTA が本当の closed-loop での優位を意味しない**のは従来通り。また推論コストがゼロなのは正しいが、**学習は確実に重くなる** (生成フレームを毎回幾何モデルに通す)。→ [ブリーフ](2608.10107.md)

### 3. U-OPSD — 正解ラベルを全部捨てたら、正解ラベルありに勝った

**wildcard 枠での採用だが、正直に書くと分野外ではない。実質 P2 の論文である。** 本日の wildcard 3 件のうち 2 件が既処理で、**新規はこれだけ**だった。**quota の趣旨からすると P2 に 3 枠目を与えたに等しい**ので、そこは自覚したうえでの採用。中身が **R2 (蒸留の capacity gap 系統則)** に効きすぎるため採った。

**昨日の TOP1 が TIDE (student 自身の生成に teacher の確率を当てる蒸留の失敗モードの解剖) で、本日がその「教師信号を全部消したらどうなるか」。2 日で同じ問題圏の両端が揃った。**

**著者の出発点は辛辣な指摘。** いま「自己蒸留」と呼ばれている手法は、結局どこかで外から正解をもらっている —— 正解ラベル、環境からのフィードバック、より大きいモデルの指示。**外から正解が来るなら、それは自己蒸留ではない。**

**やっていることは驚くほど素直。** 同じ問題を何度も解かせて**多数決で疑似的な正解を作る** (票が割れた問題は捨てる)。次に**その疑似正解で条件付けた分布**を作り、**多数決から外れた生成に対して自分自身を蒸留する。** 要するに **「答えを見た自分」が「答えを見ていない自分」を教えている** —— **外部知識を一切足さずに、情報の非対称性だけを作り出しているのが賢い。** 狙いも明確で、**モデルが自信を持って間違えている箇所にピンポイントで信号を当てる。**

**結果が直感に反する。** 5 つの数学ベンチで、**正解ラベルを使う既存の自己蒸留を平均で上回り、GRPO (PPO を簡略化した LLM 向けの強化学習手法。複数出力の相対比較で優劣を決めるので価値関数モデルが要らない) も上回る。** 説明は付く —— **正解ラベルは「合っているか」しか教えないが、疑似解による条件付けは「どう考えれば辿り着くか」の分布を渡している。** 情報の種類が違う。ただしこれは読み手側の解釈で、論文がそう論証しているかは本文で要確認。

**R2 にとっての意味は、スイープの端に基準線が引けること。** teacher を用意する前に、**student を自分自身で蒸留したときの改善幅**を測っておく。**R2 のすべての結果は、この線からの上積みとして報告すべき** —— **この基準線が無いと、R2 は「大きい teacher は良い」という当たり前の話に見えてしまう。** 本日の 6 本で最も安く、最も効く実験。

**弱点も著者の数字が示している。** 改善幅は **thinking モードではほぼ消える** —— **既に強いモデルには効かない**。「弱いモデルを底上げする手法」という読み方が正確。また多数決が定義できる**離散的で正誤が決まる出力に閉じている**ので、軌道のような連続出力への移植は自明ではない。→ [ブリーフ](2608.06296.md)

### P1 — Planner AI + 評価

**本日の入力は 1 本だけ。候補 4 件のうち転用可能なのが実質 2 件という薄さで、2 枠目は空けた。** planner_ai は 08-12 も 4 件で、**慢性的に薄い状態が続いている。** しかも**本日 planner に最も関係が深かった論文 (4D-WAM、DriveVLA-M0、Dreamer-SAC) は全部 next_arch に分類されていた** —— 問題は分野の実態ではなく**キーワード設計**である可能性が高い。

**採用した DPC の論文が R1 (保証付き安全指標) にもたらしたものは、手法ではなく立ち位置の確定である。** 保証の出し方には 2 型あることがはっきりした:

| | 保証の種類 | 要求すること | モデル誤差への強さ |
|---|---|---|---|
| **conformal 型** (R1 の想定) | 確率的 (1-α で成立) | 何も要求しない (黒箱でよい) | 校正データが現実を代表していれば強い |
| **本論文型** | 決定論的・厳密 | **planner が白箱の model-based であること** | **モデルが正しい前提でのみ成立** |

**そして重要なのは、著者自身が「RL や supervised な近似 MPC のような黒箱手法では、この保証は構造的に得られない」と明言していること。** これは **R1 の存在理由をそのまま補強する** —— 我々が評価したい E2E の学習型 planner はまさに黒箱側にあり、**そこには確率的保証しか置けない。R1 の introduction の論理は、この論文を引くことで一段強くなる。**

**さらに大きいのは、隣に空き地が見えたこと。** 本論文は **feasibility (制約を破らないこと) しか測っていない。** だが**制約を破らないポリシーは、止まり続けることで自明に達成できる。** **「保証を強くするほど過保守になる」というトレードオフを、この論文は測っていない。R1 が主張したかったのはまさにそこである。** RESEARCH_PIPELINE にある R1 の次アクション「既存評価指標のサーベイと新規性の確認」に対して、**本日で最も直接的な収穫。**

**具体的な行動は 2 日連続で同じものが要求されている:** 08-12 の UnsDrive のブリーフでも、本日の DPC のブリーフでも、結論は **「過保守さを測る量を先に定義せよ」** だった —— 平均速度の低下、不要な減速の回数、到達時間の悪化、介入頻度。**2 日続けて同じ部品が要求されている以上、これが R1 の最初の実装物である。**

**週次で拾い直すべき 1 本:** 落選した **2608.10145 (LeWorldModel の独立再現)**。**評価プロトコルの違いだけで、著者自身の重みが同一 50 エピソードで 84.0% にも 8.0% にもなる。** 論文の appendix とリポジトリの設定が別々の値を指定しており、片方でしか報告値が再現しない。**結果を決める 4 つの慣行はどの設定ファイルにも書かれていない。** **「評価手法を提案する」という R1 をやるなら、この論文が突きつけている問いは避けて通れない。** しかも **$25 の借りた計算資源とノート PC 1 台**でやっている —— **予算で殴れない我々にとっては、手法以上に方法論の手本。**

### P2 — Foundation Model 蒸留 + 適合

**本日は 3 本入った (本枠 2 + wildcard 1)。3 本が、蒸留の壊れ方を 3 つの別々の顔として見せている。**

1. **伝わらない** (iBKD): 特徴を合わせているのに inductive bias は渡っていない。**pooling と flatten が空間格子を壊しているから。**
2. **伝わりすぎて上書きする** (MVRD): teacher 特徴に寄せると、**student が元から持っていた視覚と言語の対応が壊れる。**
3. **そもそも teacher が要るのか** (U-OPSD): 外部監督ゼロの自己蒸留が、**正解ラベルありの手法を上回る。**

**昨日の TIDE が加えた 2 つ (発散して更新を壊す excess / サンプルされず伝わらない deficit) と合わせると、2 日で「蒸留の失敗モード」の地図がかなり埋まった。** **R2 (capacity gap 系統則) の測定軸は、当初想定していた「容量比」1 本から明確に増えている。**

**特に iBKD の指摘は R2 の設計に直接影響する:** **同じ容量比でも、CNN→CNN なら伝わり CNN→ViT なら伝わらない。** つまり破綻を支配する変数は容量比だけではなく **inductive bias の不一致**もある。**R2 の図は「容量比 × 破綻」の 1 次元ではなく、「容量比 × bias 不一致 × データ量」の面かもしれない。** これは新規性を上げる方向だが、同時に**実験計画が重くなる方向**でもあるので、quarterly で 1 本に絞るときの判断材料として扱う。

**そして iBKD の報告の仕方こそが R2 の作法である。** 「新手法が勝った」ではなく **「データが減るほど優位が広がる」という傾きで報告している。** **R2 が出したい主張は「どこで壊れるかを予測できる」であって、勝ち負けではない。実験設計をこの形に合わせるだけで主張の強さが変わる。**

**明日の最優先は U-OPSD の基準線。** teacher を用意する前に、**自己蒸留だけでどこまで行くか**を測る。**R2 のすべての結果はこの線からの上積みとして報告すべきで、これが無いと R2 は「大きい teacher は良い」という当たり前の話に見えてしまう。**

**なお 08-12 に続き、fm_distill_finetune は 30 件中 24 件が「LLM/VLM を何かに fine-tuning してみた」応用論文だった。2 日連続の同じ症状で、topics.yaml のキーワードの問題である** (rejected.md の調整メモを参照)。**本日は SQuaT (量子化と蒸留の組み合わせに理論的な下限が張り付く問題を解く) と BPG (ドメインごとに adapter を用意して推論時に混ぜる) が、quota ではなく分類の粗さで埋もれた。**

### P3 — 次世代アーキテクチャ (VLA / World Model / E2E)

**本日の最激戦区で、候補 16 件のうち採用 2・惜しい落選 4。** そして **R3 (VLA × world model 統合アーキテクチャ) の調査にとって、本日は「マップの縦軸が決まった日」**である。

**VIScore が言っているのは、要するに R3 の比較軸の話である。** 現状 world model の論文は「予測画像が綺麗」「表現から物理量が読める」で良し悪しを主張しているが、**その両方が planning 成功と繋がっていない。** **R3 のマップを作るなら、各手法を「planning に効く証拠を出しているか / 表現の綺麗さだけで主張しているか」で分類するのが正しい。これは論文を読むだけで作れて、しかも R3 の新規性の議論に直結する。**

**そして同じ結論に、まったく別の道から到達している論文が同日に落ちている。** 落選した 2608.10145 は再現実験から、**「1 ステップ予測誤差が 7 倍の幅を持つ 3 つのチェックポイントで、短期の成功は単調に順位付けできたのに長期は全く順位付けできなかった」**と報告している。**指標設計と再現実験という別々の営みが同じ日に同じ結論に着いたのは、方向として無視できない信号。**

**本日もう一つ記録すべき収束:「失敗を捨てずに資産にする」論文が 2 本、独立に出た。**
- **DriveVLA-M0** (落選・惜しい): 失敗事例を latent memory として貯め、**静的な道路構造と動的な agent 相互作用を分離した retrieval** で引き当て、推論時に LoRA で注入する。**memory を増やすだけで学習無しに伸びる**という主張。コード公開。
- **FACT** (落選): 実行した action で条件付けて未来を予測することで、**失敗 rollout を捨てずに教師信号として使える**ようにする。**失敗データを入れるほど良くなる。**

**「同じ失敗を繰り返す」は我々の実運用でも最も痛い形の弱点**であり、**2 本が同時に出たということは、この方向が定着しつつある。** 両方とも R3 のマップに載せる。

**設計思想として持ち帰る最大のものは、4D-WAM と MVRD に共通する原則:** **teacher から渡すのは、teacher の出力そのものではなく、teacher が満たしている性質にせよ。** 4D-WAM は幾何モデルの特徴ではなく「4D 整合しているか」という判定だけを loss で渡し、MVRD は teacher 特徴ではなく patch 間の類似関係だけを渡す。**別分野の 2 本が同じ原則に到達しており、しかもどちらも「制約を緩くした方が壊れない」という同じ理由を挙げている。**

**最も面白い組み合わせ仮説 (本日拾える中で一番):** 08-12 に落選した論文が **「action post-training (VLA 化) をすると VLM の深度推定能力が全層で劣化する」** と報告していた。**行動を学ばせると空間理解が削れる。** **MVRD の関係蒸留は、削れた幾何をコストを増やさずに戻せる可能性がある。** これは既知の観察に対する初めての処方候補であり、**R3 の中で我々が独自に出せる主張になりうる。**

## 明日の最初の 30 分ですること

**すべて「測るだけ」で、学習は要らない。** 本日の採用 6 本のうち 5 本が、この形の第一歩を持っている。

1. **手持ちの world model チェックポイントで「予測誤差 / probing 精度」と「closed-loop 成功率」を散布図にする。** 相関が出れば VIScore の問題は我々に無く、以降は不要。出なければ本日の TOP1 が効く。(VIScore)
2. **生成を途中で打ち切って軌道を読み出し、最終出力との一致率を timestep の関数でプロットする。** 早い段階で飽和すれば early-decision があり、監督の配り方を変える価値がある。推論だけで済む。(4D-WAM)
3. **蒸留パイプラインのコードを読んで、特徴を合わせる前に pooling / flatten を挟んでいないか確認する。** 実験すら要らない。挟んでいれば iBKD の問題が我々にも存在する。(iBKD)
4. **現行の蒸留 run の前後で「狙った能力」と「壊れうる能力」の両方を測る習慣を作る。** 副作用が観測されなければ MVRD の問題は我々に無い。(MVRD)
5. **student を自分自身で蒸留したときの改善幅を測り、R2 の基準線にする。** (U-OPSD)
6. **「過保守さ」を測る量を定義する** —— 平均速度の低下、不要な減速回数、到達時間の悪化、介入頻度。**2 日連続で要求されており、R1 の最初の実装物。** (DPC / 08-12 の UnsDrive)
