## 何を解決する論文か

**OPD (On-Policy Distillation; student 自身が生成した文に対して teacher の確率を教師信号として与える蒸留。teacher の生成文を真似させる従来の off-policy 蒸留と違い、student が実際に踏む分布の上で矯正できる)** と、その自己版である **OPSD (On-Policy Self-Distillation; teacher と student が同一モデル)** は、LLM の post-training で強い手法として定着しつつある。

しかし著者の指摘は辛辣で、**現行の「self」distillation は名前負けしている**。既存手法は結局どこかで外部の監督に頼っている —— **ground truth の正解ラベル、環境からのフィードバック、あるいはより大きいモデルからの指示**。**外から正解が来るなら、それは自己蒸留ではない。**

U-OPSD は、**モデル自身の生成だけを使って、内部の一貫性 (internal consistency) から教師信号を作る。** 外部監督を完全にゼロにする。

## 手法の核心

- **多数決で疑似正解を作る。** 同じ問題に対して **複数の rollout (生成) をサンプル**し、**self-consistency の閾値の下で多数決を取って pseudo solution (疑似解) を構成する**。閾値を置いているのが要点で、**票が割れている = モデルが自信を持って収束していない問題は、疑似正解を作らずに捨てる。** **「自信を持って一貫している所だけを教師にする」**という選別が入っている。

- **疑似解で条件付けてから、外れた生成に蒸留する。** ここが手法の芯。まずモデルの分布を**疑似解で条件付ける** (答えを知っている状態の分布を作る)。そのうえで、**多数決から外れた生成 (disagreeing completions) に対して、自分自身を蒸留する。**

- **「自信を持って間違えている所」だけを正す、という狙いが明快。** 全体を一様に強化するのではなく、**モデルが確信を持って外している箇所を特定して、そこにピンポイントで信号を当てる。** 疑似解による条件付けは、いわば **「答えを見た自分」が「答えを見ていない自分」を教える**構図であり、**外部知識を一切足さずに情報の非対称性を作り出しているのが賢い点。**

- **数字が「監督ありに並ぶ」ところまで来ている。** 5 つの数学推論ベンチ (AIME24, AIME25, HMMT25, MATH500, AMC23) で、**Qwen3 の non-thinking モードにおいて base model から 4B で +8.5%、8B で +10.7%**。同じ設定で **正解ラベルを使う OPSD を平均 3.2% / 2.3% 上回る。** thinking モードでは OPSD と互角 (4B で +0.9%、8B で同等)、**GRPO (Group Relative Policy Optimization; PPO を簡略化した、LLM の強化学習で標準的に使われる手法。複数出力の相対比較で優劣を決めるので価値関数モデルが要らない) に対しても +0.7% / +1.1%。**

- **「正解ラベル無しが、正解ラベルありを上回る」が最も驚く点。** 直感に反するが、説明は付く —— **ground truth は「答えが合っているか」しか教えないのに対し、疑似解による条件付けは「どう考えれば辿り着くか」の分布を渡している。** 情報量の種類が違う。**ただしこれは筆者の解釈であり、論文がそう論証しているかは本文で確認が要る。**

## 追っているプロジェクトへの適用可能性

- **P2 / アイデア R2 —— teacher が居ない極限として。** R2 は「teacher/student の容量比と破綻境界」だった。**U-OPSD は容量比 = 1 の極限点**である。**R2 のスイープの端に、意味のある基準線が 1 本引ける** —— 「teacher を大きくしていったときの利得は、**自己蒸留で得られる分を超えているか**」。**この基準線が無いと、R2 の主張は「大きい teacher は良い」という当たり前の話に見えてしまう。** 本日の収穫として実は最も効く指摘かもしれない。

- **P2 / ラベルが無い現場への直撃。** 我々のドメインで蒸留の教師信号を作るのは高い —— 正解軌道のアノテーション、シナリオごとの正解判定。**「モデル自身の一貫性を教師信号にする」が成立するなら、ラベル無しの走行ログをそのまま学習に使える。** これは適用できたときの効き幅が大きい。

- **P2 / 昨日の TIDE との関係が具体的。** TIDE は **mismatch を excess (発散して更新を壊す) と deficit (サンプルされず伝わらない) に分解して直す**話だった。**U-OPSD では teacher と student が同一なので、excess は原理的にほとんど発生しない** (自分が出す物に自分がゼロ確率を振ることは無い)。**残るのは deficit 側だけ。** つまり **U-OPSD は TIDE が指摘した 2 つの病理のうち片方を構造的に消している**と読める。**この対応関係が正しいなら、2 本を合わせて「on-policy 蒸留の失敗モードの地図」が描ける。** 検証する価値が高い。

- **P1/P3 への転用は素直ではない。** 多数決による疑似正解は、**離散的で正誤が決まる出力 (数学の答え) だからこそ成立する。** 軌道のような連続出力では「多数決」を何で取るのか自明でない。**クラスタリングして最大クラスタの中心を取る、といった置き換えが要り、そこは論文の外。** ただし **「複数 rollout の一貫性を自信の代理とする」という考え方は、planner の不確実性推定にそのまま効く** —— これは R1 とも接続する。

- **注意点:** (1) **検証が数学推論に完全に閉じている。** 正解が一意に決まり、多数決が定義できる領域。**これが本手法の適用範囲そのものである可能性が高く、一般化の主張は割り引いて読むこと。** (2) **モデルが「一貫して間違えている」問題には原理的に無力**で、むしろ間違いを強化しうる。**self-consistency 閾値がその防波堤だが、閾値の感度は必ず本文で確認する。** (3) 改善幅が **thinking モードでは +0.9%〜0 とほぼ消える** —— **既に強いモデルには効かない**ことを著者自身の数字が示している。**「弱いモデルを底上げする手法」という読み方が正確。** (4) **rollout を複数取るので学習コストは素直に増える。** (5) hf_upvotes 183 は注目度の指標であって品質の保証ではない。

### 試すべき実験

1. **R2 の基準線として、自己蒸留を先に測る (最優先・R2 に直結)。** teacher を用意する前に、**student を自分自身で蒸留したときの改善幅**を測る。**R2 のスイープはすべてこの線からの上積みとして報告すべき**であり、**この 1 本があるかないかで R2 の主張の説得力が変わる。** 本日の 6 本で最も安く、最も効く実験。

2. **TIDE の分解と突き合わせる。** 上の 1. の run で、TIDE の excess / deficit を測る (08-12 のブリーフの実験 1 と同じ計測)。**予想通り excess がほぼゼロになるかを確認する。** なれば「自己蒸留 = excess を構造的に消す手法」という整理が立ち、**2 本を統合した理解が得られる。予測が当たること自体が機序の理解の検証になる。**

3. **一貫して間違える問題で何が起きるか、意図的に見る。** モデルが自信を持って誤答する問題群を選び、U-OPSD を回して**誤りが強化されるか**を測る。**論文が触れていない最大のリスクであり、我々の設定で使うかどうかの判断はここで決まる。**

4. **self-consistency 閾値を振る。** 閾値を上げると教師にする問題が減って安全になり、同時に学習信号も減る。**「安全さ vs 信号量」のトレードオフ曲線**を描く。**論文が閾値の感度を出していなければ、ここは我々の側の小さな貢献になりうる。**

5. **連続出力への移植を小さく試す (探索枠)。** 軌道予測で複数 rollout を取り、**クラスタリングで疑似正解を作って同じ手続きを回す。** 成立するか自体が不明なので、**時間を区切って失敗を許容する**枠として扱うこと。成立すれば「ラベル無し走行ログで planner を改善する」という大きい話に繋がる。
