# Topological Feasibility Guarantees for Differentiable Predictive Control

**topic:** planner_ai (P1) ・ **arXiv:** 2608.10332 ・ **published:** 2026-08-11 ・ **hf_upvotes: 0**

> **本日 planner_ai 唯一の採用。** 候補 4 件のうち転用可能なのが実質 2 件という薄い日で、その中で選んだ 1 本。
>
> **なぜこれかというと、追っているアイデア R1 (保証付きの安全指標) の「保証」の部分に、我々が想定していたのとは別の答えを出しているから。** R1 は **conformal prediction (予測の外れ率を分布仮定なしで確率的に保証する統計手法)** による確率的保証を想定していた。本論文は **確率的でない、決定論的な保証**を、学習されたポリシーに対して与えられると主張する。**R1 の設計判断に直接影響する。**

## 何を解決する論文か

**MPC (Model Predictive Control; モデル予測制御。現在の状態から未来を予測し、制約を満たす最適な行動列をその場で解いて、最初の 1 手だけ実行し次の時刻でまた解き直す制御方式)** は制約を明示的に扱えるので安全な制御の定番だが、**毎時刻オンラインで最適化を解くので重い。**

**DPC (Differentiable Predictive Control; 微分可能予測制御)** はこれを、**MPC の解を再現するポリシーを事前に学習しておく**ことで回避する。特徴的なのは学習の仕方で、**微分可能な系のダイナミクスを計算グラフの中に直接埋め込み**、ラベル無し (self-supervised) でポリシーを最適化する。オンラインの最適化が消えるので**計算コストが劇的に下がる。**

問題は保証である。**安全な制御に不可欠な feasibility (実行可能性; ポリシーが出す行動が制約を破らないこと) の保証**が、DPC では今のところ **確率的にしか与えられない**か、あるいは **online safety filter (実行時にポリシーの出力を検査し、危なければ安全な行動に差し替える追加の層)** に頼るしかない。**オフラインでポリシーを最適化した時点で厳密な保証を出す**のは未解決だった。

本論文は、**DPC が誘導する reachable safe set (そのポリシーの下で到達しうる、かつ安全な状態の集合) の位相的 (topological) な解析**によって、**safety filter 無しで決定論的な feasibility 保証**を与える。

## 手法の核心

- **保証が出せる根拠は「DPC が白箱であること」。** ここが全体の要。DPC は**微分可能なダイナミクスが計算グラフの中に入っている model-based な手法**なので、学習されたポリシーと、それが生む状態の集合を**位相的・幾何的に解析できる**。**RL や supervised な approximate MPC のような黒箱手法では構造的に不可能**だと著者は明言している。**「学習しつつ解析可能性を捨てない」という設計選択が、そのまま保証に化けている。**

- **解析が先、手法が後という順序。** 位相的解析をやった結果として「こういう性質を持たせれば保証が出る」が分かり、**その性質を促す学習法を後から設計している**。理論が飾りではなく処方を導いている構成。

- **CBF を proxy loss として使う。** **CBF (Control Barrier Function; 制御バリア関数。「安全な領域から出ない」ことを、ある関数の値が減らないという条件に翻訳する道具)** を loss の代理項として self-supervised なオフライン学習に組み込む。**これが学習を改善するだけでなく、有限個の学習サンプルから厳密な保証を導く鍵にもなっている。**

- **「有限サンプルからの決定論的保証」が主張の核。** 無限データの漸近論ではなく、**実際に使った有限個の訓練サンプルに対して strict かつ deterministic な保証**が出る、と述べている。**conformal prediction 型の「確率 1-α で成り立つ」とは保証の種類が違う。**

- **実験の出し方が主張と噛み合っている。** closed-loop シミュレーションで、**訓練サンプル数を増やすと制約違反が単調に減って 0 に至る**。「理論通りに単調に消える」という形で見せているのは、理論論文の検証として正しい作法。

## 追っているプロジェクトへの適用可能性

- **P1 / アイデア R1 —— ここが採用理由。** R1 は「衝突率だけでなく、**過保守さ (不要な減速、介入頻度)** も保証付きで測る」だった。本論文は **保証の出し方に 2 つの選択肢がある**ことを突きつける:
  - **conformal 型 (確率的・手法非依存)**: どんな黒箱 planner にも後付けできる。代わりに保証は確率的で、**校正用データの分布に依存する。**
  - **本論文型 (決定論的・構造依存)**: 保証は強いが、**planner が白箱の model-based であることを要求する。** 我々が評価したい E2E の学習型 planner には**そのままでは使えない。**

  **R1 の立ち位置を決めるうえで、この対比は極めて有用。** むしろ **「黒箱 planner には決定論的保証が構造的に出せない」という本論文の指摘が、R1 (conformal 型) の存在理由を補強している** —— **R1 の introduction の論理は、この論文を引くことで一段強くなる。**

- **P1 / 過保守さの測定という空き地。** 本論文は **feasibility (制約を破らないこと) しか見ていない。** 制約を破らないポリシーは、**何もしない (止まり続ける) ことで自明に達成できる。** **保証を強くするほど過保守になるというトレードオフを、本論文は測っていない。** **R1 が主張したかったのはまさにそこ**であり、**この論文の隣に空いている場所が R1 の場所である**ことがはっきりした。**新規性の確認という R1 の次のアクションに対する、本日で最も直接的な収穫。**

- **P1 / safety filter を外せるかという実務的論点。** 我々の系でも学習型の出力に安全層を被せる構成は現実的な選択肢だが、**フィルタが介入した回数は planner の性能評価を汚す** (フィルタのおかげで衝突していないのか、planner が良いのか区別できない)。**「フィルタ無しで保証が出る」という方向は、評価の清潔さという意味でも価値がある。**

- **P3 との距離は遠い。** E2E の学習型アーキテクチャは本論文が「保証が構造的に出せない」と名指しした側にある。**P3 と P1 の保証は当面両立しない**という認識を持っておくのが正しく、**むしろその緊張自体が論文の主題になりうる。**

- **注意点:** (1) **DPC の適用範囲が本質的な制約。** 微分可能なダイナミクスが書けることが前提で、**他車が反応する交通環境をそう書けるかは全く別問題。** 本論文の実験系の規模と次元は本文で必ず確認すること —— **低次元の制御系だけなら、我々の設定への距離はかなり遠い。** (2) 「決定論的保証」は**モデルが正しいという前提の下での保証**である。**モデル誤差がある現実では保証は保証でなくなる**ので、主張の射程を読み違えないこと。ここは conformal 型の方が強い部分でもある。(3) **closed-loop シミュレーションのみ**で、実機やそれに準じる評価は無い。(4) CBF は設計に職人芸が要る道具として知られており、**「CBF をどう作るか」が実務の主戦場になる**可能性が高い。

### 試すべき実験

1. **R1 の新規性チェックに直接使う (最優先・実験不要)。** RESEARCH_PIPELINE の R1 の次アクションは「既存評価指標のサーベイと新規性の確認」だった。**本論文は「feasibility の保証は既にある / 過保守さの保証は無い」という切り分けを一発で与える。** R1 のポジションを「**保証の対象を安全性から過保守さに移す**」と書き直せるか、今日中に判断できる。

2. **保証の 2 型を並べた表を作る (R1 の資料になる)。** 縦に手法 (conformal / 本論文型 / safety filter / 確率的 DPC)、横に **保証の種類・要求する planner の性質・モデル誤差への頑健性・過保守さを測れるか** を取る。**最後の列が全部「否」になるはずで、それが R1 の主張の図になる。**

3. **過保守さの指標を先に定義してしまう。** 保証の話に踏み込む前に、**「過保守さ」を測る量を決める** —— 平均速度の低下、不要な減速の回数、到達時間の悪化、介入頻度。**08-12 の UnsDrive のブリーフでも同じ結論に至っており、2 日連続で同じ物が要求されている。** これは R1 の実装として最初に着手すべき部品。

4. **小さい系で DPC を実際に回してみる。** 低次元の縦方向制御 (先行車追従) だけで DPC を実装し、**訓練サンプル数を振って制約違反が単調に減るかを再現する。** 再現できたら、**同じスイープで「平均速度」も一緒にプロットする** —— **安全が単調に良くなる裏で過保守さが単調に悪化していれば、R1 の中心 figure がその 1 枚で出る。** 本論文が測っていない軸を足すだけなので、実装コストに対して主張の増分が大きい。

5. **CBF の設計感度を確かめる。** 4. で CBF を数種類変えて、保証と性能がどれだけ動くかを見る。**大きく動くなら「保証」は CBF 設計者の腕の言い換えであり、その事実自体が R1 の論点になる。**
