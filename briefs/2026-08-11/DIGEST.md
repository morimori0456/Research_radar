## 今日読むべき TOP3

### 1. SimWAM — world model を「推論時に使わない」という第三の選択肢

我々が world model を検討するとき、想定はほぼ常に **「未来を予測して、それを見て運転を決める」** だった。だから重い。この論文は **「予測できるように学習させる。ただし決めるときには予測を見ない」** をやる。映像生成の枝と軌道予測の枝を一緒に学習させておき、**学習が終わったら映像側を丸ごと捨てて、軌道を直接吐く planner だけを残す**。それで NAVSIM の総合スコアで既存の同系統手法を上回り、しかも推論は大幅に速い。

読む価値が高い最大の理由は、**「捨てても壊れない」を根性ではなく構造で保証している**点。単に補助タスクを足しただけなら、軌道側は未来映像の情報に頼るように育ってしまい、外した瞬間に落ちる。この論文は **attention の参照関係そのものを禁止して、依存すること自体を不可能にしている**。ここが持ち帰りの本体で、**「学習時にはあるが本番には無い情報」を使い切る一般的な道具**になる —— 我々で言えば他車の未来軌道の正解や、後知恵で計算した最適軌道がそれに当たる。**未来映像である必然性はどこにもない。**

もう一つ実務的な理由として、**本日の 3 本で唯一コードと重みが公開済み**で、明日そのまま動かせる。ただし読むときに最初に探すべき表がある —— **「映像側を一切使わずに軌道側だけ学習した場合」との差**。ここが小さければ主張は成立しない。→ [ブリーフ](2608.07468.md)

### 2. SFT Conflicts, RL Coexists — 「順番に適合させると前が壊れる」の理由がやっと分かる

機種 A に合わせ、次に機種 B に合わせると、A の性能が落ちる。我々が経験的に知っているこの現象について、この論文は **なぜ起きるかを勾配の干渉として説明した**。結論は、**通常の教師あり微調整では干渉が「勾配の大きさ」に比例して効くのに対し、RL では「勾配のばらつき」で抑えられる**ため、タスクごとの更新方向が互いにほぼ直交して共存できる、というもの。

ただし **この論文を「だから RL にしよう」と読むと転用を誤る。** 効いているのは RL という手法ではなく、RL の中に副作用として入っていた**正規化処理**である、というのが著者の特定した機序。**そう読むと自然に出てくる問いが「では通常の微調整の側で同じ正規化をかけたらどうなるのか」で、これは論文が答えていない。** RL 化は報酬設計も rollout も必要で重いが、この問いなら**既存のパイプラインに数行足すだけで検証できる**。もし効くなら投資対効果が桁違いで、しかも我々の設定固有の知見になる。

**着手の順番だけ注意。** いきなり処方を試さず、**まず自分のパイプラインで「ドメイン間の勾配が本当に打ち消し合っているか」を測る**こと。既に直交しているなら我々には問題が無く、以降は全部不要になる。この判定は数日で終わる。→ [ブリーフ](2608.03573.md)

### 3. Beyond Simply Environment Scaling — 「シナリオを増やす」の投資判断を止める材料

学習用の環境を大量に集めるのが近年の主流だが、この論文は **数を増やしても効かなくなる領域がある**ことを実験で示し、代わりに **何を基準に選ぶか** を提案する。要点は多様性の定義を変えたところで、**環境の見た目(ドメイン・画面・アプリ)で多様性を測ると、同じ能力しか要求しない環境が並んでいても「多様」と誤判定する**。だから**エージェント側から見て何ができる必要があるか**を軸に取り直して選ぶ。

我々への読み替えは評価側が一番効く。**closed-loop 評価のシナリオを本数で語るのをやめ、「交差点・合流・雨天」ではなく「譲る判断・オクルージョン下の推定・優先権の解釈」で分類し直す** ということ。うまくいけば「1000 本」ではなく **「要求される判断を N 種類カバーした 200 本」** という形で評価スイートを主張できる。

3 本の中では**最も転用先が遠く、持ち帰るのは実装ではなく設計の作法**なので過度な投資はしない。ただし **1 つだけ今すぐやる価値のある実験がある** —— 手持ちのシナリオを N 本サンプリングして、N を増やしたときに planner 間の順位がどこで安定するかを見る。**既に安定しているなら収集を止める根拠になる。** この 1 枚の図で議論が終わる。→ [ブリーフ](2608.03571.md)

## プロジェクト別の要点

- **P1(Planner AI + 評価):** **本枠候補は 3 日連続でゼロ**、直接の入力なし。ただし間接的な入力は 2 本ある。(a) SimWAM の報告の作法 —— **精度とレイテンシを同じ図に描く**。closed-loop では推論時間そのものが挙動を変えるので、片方だけ報告するのは我々の評価でも不誠実になる。加えて NAVSIM だけでなく nuScenes への **zero-shot 転移で示す**という主張の立て方は真似る価値がある。(b) Environment Scaling の**評価スイートへの読み替え** —— 本数ではなく「要求される判断のカバー率」で語る。
  **明日できる:** 手持ちの評価シナリオを N 本ランダムサンプリングして評価し、**N に対して planner 間の順位が安定する点**を描く。既に飽和していれば、収集の追加投資を止める根拠が 1 枚の図で出る。既存資産だけで完結する。

- **P2(FM 蒸留 + 適合):** 本日の実質的な本命は 2608.03573。持ち帰りは **「逐次適合が壊れる原因は勾配の大きさであって、手法の種類ではない」**。ここから 2 つの処方が出る —— 独立に学習して合成する形(機種ごとの LoRA を並列に学習して統合)と、**通常の微調整に per-sample の勾配正規化を足すだけの形**。後者は論文が言っていないが理論から自然に出る系で、**RL 化の投資を丸ごと回避できる可能性がある**ので先に試す。副次的に SimWAM も P2 として読める —— **出力を合わせに行かない蒸留**(未来を知っている枝から、知らない枝へ、distillation loss なしで移す)の実例で、08-08 の LAWM-3D の教訓と同じ方向の 2 例目。
  **明日できる:** 適合パイプラインで **ドメイン A と B の勾配の cosine similarity を層ごとに記録するだけ**。負の値が出る層があれば干渉は実在し、処方に進む根拠になる。ほぼゼロなら我々に問題は無く、この論文の話は丸ごと不要と判定できる。**処方より先に診断。**

- **P3(次世代アーキテクチャ):** **3 日ぶりに質の高い入力が入った。** SimWAM の持ち帰りは R3(VLA × world model 統合)の分類軸そのもので、**これまで「生成するか否か」で切っていたマップを「学習時に生成するか / 推論時に生成するか」の 2 軸に割り直すべき**だと分かる。表現学習としての world model と、推論時プランナーとしての world model は別物として扱う。加えて Environment Scaling の HDC の 2 軸分解(**補助を外す方向**と**問題規模を上げる方向**を混ぜない)は、driving policy の curriculum 設計にそのまま翻訳できる。
  **明日できる:** SimWAM の公開重みを落として、**自前の推論環境でレイテンシを実測する**。論文の数字ではなく我々の環境での値が実用域に入るかで、以降の投資判断が決まる。同時に nuScenes zero-shot も追試して転移の実在を自分の目で確認する。
