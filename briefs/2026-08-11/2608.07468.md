## 何を解決する論文か

**WAM (World-Action Model; 「次に何が見えるか」を予測する world model と「次にどう動くか」を出す action model を一体で学習させたモデル)** は、映像の中の物理・動きの規則性 (video dynamics prior) を行動予測に流し込むことで end-to-end 自動運転を改善してきた。**しかし既存手法は推論時にも未来フレームを生成する必要があり**、映像生成は重いので走行時のレイテンシが実用域から外れる —— これが WAM 系が「論文では強いが車に載らない」最大の理由だった。

SimWAM の主張は **「未来生成は学習時にだけ要る。推論時には要らない」**。video expert (映像生成側) と軽量な action expert (軌道予測側) を joint flow matching で co-train し、**attention mask の設計によって action 側が未来フレームに一切依存しないように強制する**。その結果、学習が終わったら **video branch を丸ごと捨てられ**、残るのは軌道を直接吐く自己完結型の planner だけになる。NAVSIM で **91.5 PDMS**、既存の WAM ベース planner を上回りつつレイテンシは大幅に低く、nuScenes へ zero-shot で転移する。

## 手法の核心

- **生成を「推論時の機能」から「学習時の信号」に降格させた。** これが本論文の一行要約。既存 WAM は未来フレームを生成し、それを見てから行動を決める (生成が推論経路の中にある)。SimWAM は生成を**補助タスクとしてのみ**使い、学習が終われば切り離す。**性能は貰うがコストは払わない**という交換で、WAM 系の実用化における最大の障害を構造で回避している。

- **isolated attention mask —— 「捨てられる」ことを保証する仕掛け。** ここが技術的な要。単に補助タスクを足しただけなら、action 側は未来フレームの情報に依存するように学習してしまい、推論時に video branch を外すと性能が落ちる。SimWAM は **attention mask で「action token は未来フレーム token を参照できない」を明示的に禁止**する。**依存が構造的に不可能**なので、切り離しても壊れない。「学習時だけ使える情報 (privileged information) を、推論時に無いまま使い切る」という一般問題に対する、**loss ではなくアーキテクチャによる解**になっている。

- **joint flow matching で両者を同じ目的関数に載せる。** flow matching は **ノイズから目的の分布へ連続的に運ぶ速度場を学習する生成手法** (diffusion の親戚だが、少ないステップで安定してサンプリングできる)。映像生成と軌道生成という**単位も次元もまるで違う 2 つの出力を、同じ「速度場を回帰する」形式に揃えて 1 つの目的で共学習**している。マルチタスクの重み調整に悩まずに済む設計。

- **パラメータを共有しない二本立て。** 2 つの expert は**パラメータを一切共有せず、attention interface だけで相互作用する**。この分離のおかげで **(a) video backbone を別のものに差し替えられ、(b) action expert だけを独立にスケールでき**、どちらも学習目的や推論経路を書き換えずに済む。**映像生成モデルの進歩をそのまま取り込める設計**であることを著者は明示的に売りにしている (「video generation の進歩から自動的に恩恵を受ける baseline」)。

- **imitation の先へ —— compositional driving reward による RL。** 軌道の模倣だけでは「デモと似ているが安全ではない」挙動が残る。SimWAM は複数の運転上の望ましさを合成した報酬で RL による追い込みをかけている。**imitation で土台を作り、RL で指標を直接最適化する**という、現行の end-to-end 系の標準構成を WAM に持ち込んだ形。

## 追っているプロジェクトへの適用可能性

- **P3 (本命・アーキテクチャの原則として持ち帰る):** 我々が world model を検討するときの想定はほぼ常に「予測して、それを見て決める」だが、本論文は **「予測できるように学習させる。ただし決めるときには予測を見ない」**という第三の選択肢を示している。**表現学習としての world model と、推論時プランナーとしての world model を分離する**という整理で、これは R3 (VLA × world model 統合) の分類軸そのものになる。現状 R3 のマップは「生成するか否か」で切っていたが、**「学習時に生成するか / 推論時に生成するか」の 2 軸に割るべき**だと分かる。

- **P3 (差し替え可能性が効く):** 「video backbone を差し替えられる」は論文の宣伝文句に見えて、**我々の事情では実利が大きい**。自前ドメインの映像で事前学習した生成モデルを持っているなら、action expert の学習パイプラインを触らずに backbone だけ載せ替えられる。逆に言えば、**この論文を読む価値の半分は「自前の video 事前学習資産を planner に接続する配管」**にある。

- **P1 (評価・レイテンシ):** NAVSIM で **PDMS (Predictive Driver Model Score; 非反応型シミュレーション上で、衝突回避・走行可能領域の維持・自車の進捗・快適性などのサブスコアを重み付きで合成した総合指標)** 91.5 という数字より、**「WAM 系の SOTA をレイテンシ大幅減で上回った」というトレードオフの形のほうが我々には重要**。closed-loop 評価では推論時間そのものが挙動を変えるので、**精度とレイテンシを同じ図に描く**という報告の作法をこちらの評価にも入れたい。加えて **zero-shot で nuScenes に転移**しているのは、NAVSIM 特化のオーバーフィットではないことの傍証で、**転移で示す**という主張の立て方は我々の論文でも真似る価値がある。

- **P2 (蒸留として読み直すと、これは非対称な teacher-student):** video expert は事実上「未来を知っている teacher」で、action expert は「未来を見られない student」。ただし **distillation loss を明示的に置かず、共有 attention と共通の flow matching 目的だけで知識を移している**。P2 の関心事である capacity gap (teacher と student の容量差が大きいと student が真似きれず学習が崩れる問題) に対して、**「出力を合わせに行かない蒸留」**という緩め方の実例になる。08-08 の LAWM-3D の教訓 (基盤モデルを丸ごと蒸留せず中間特徴のアンカーとして使う) と**同じ方向で 2 例目**。

- **注意点:** (1) **PDMS を報酬に近い形で最適化していないかを本文で確認すること。** compositional driving reward の中身が PDMS のサブスコアと重なっているなら、NAVSIM の数字は指標への最適化の結果であり、**別ドメインでの一般化を過大評価する危険がある** (nuScenes 転移が効いているのはこの懸念をある程度打ち消すが、確認は要る)。(2) **「video branch を捨てても落ちない」は、裏を返せば video branch が大して効いていない可能性も含む。** ablation で「video expert 無しで最初から action expert だけを学習した場合」との差がどれだけ出ているかが本論文の生命線で、ここが小さいなら主張は成立しない。**読むときに最初に探すべき表。** (3) NAVSIM は**非反応型** (他車が自車に反応しない) のシミュレーションなので、インタラクションが本質の場面での強さは分からない。

### 試すべき実験

1. **まず公開重みで再現し、レイテンシを自前の計測系で測る (最優先・数日)。** コードと重みが出ているので、**論文の数字ではなく我々の推論環境での実測値**を取る。ここが実用域に入らないなら以降の投資判断が変わる。同時に nuScenes zero-shot も追試して、**転移が本当に効いているか**を自分の目で確認する。

2. **isolated attention mask の ablation を自分で回す。** mask を外して (= action が未来フレームを参照できる状態にして) 学習し、**推論時に video branch を切ったときの劣化幅**を測る。mask 有りでは劣化ゼロ、mask 無しでは大きく劣化する、が予想される絵。**この差こそが本論文の技術的な中身**で、ここを自分で確認できれば「学習時だけ使える情報を構造で使い切る」という道具を他の場面にも自信を持って持ち出せる。

3. **その道具を我々の privileged information に転用する (ここが一番の持ち帰り)。** 我々の設定で「学習時にはあるが推論時には無い」情報 —— 他車の未来軌道の正解、HD 地図の完全版、後知恵で計算した最適軌道 —— を video expert の位置に置き、**isolated attention mask で同じ構造を作る**。**未来フレーム生成である必然性はどこにもない**というのが本論文の一般化で、我々にとってはこちらのほうが価値が高い可能性がある。

4. **video backbone の差し替えを 1 回やる。** 自前ドメインの映像で事前学習した生成モデル (無ければ公開の別モデル) に載せ替え、**action expert 側を一切変えずに済むか**を確認する。ここが本当に配管として機能するなら、以後の生成モデルの進歩を取り込み続けられる。

5. **RL 部分は後回しにして、報酬の中身だけ先に読む。** compositional reward の項目を我々の評価指標と突き合わせ、**PDMS のサブスコアとどれだけ重なっているか**を表にする。重なりが大きければ「指標最適化」であり、我々が RL を入れるときは**評価に使わない項目で報酬を組む**という設計判断が必要になる (P1 の評価と P3 の学習を分離する話)。
