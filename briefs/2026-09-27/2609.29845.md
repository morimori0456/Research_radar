## 何を解決する論文か

2 つの無関係な文章の token embedding (各 token を表すベクトル) を位置ごとに平均し、LLM に 1 回だけ通す。すると出力の次 token 分布に、2 つの文章それぞれの正解がかなりの確率で残っている。この論文はこれを「Transformer は入出力の関係として近似的に線形に振る舞う」という仮説 (Superposition Linearity Hypothesis) として定式化し、その性質の強さを測った。さらに、fine-tuning でこの性質を強められるか、混ぜた 1 回の forward pass から 2 本の続きを別々に生成できるか、を調べている。

**結論を先に書くと、現象の観察は面白いが、実用 (推論を 2 倍速くする) にはまだ届いていない。**速度の比較相手が「2 本を順番に実行」になっており、普通の batch size 2 と比べると速度は同じだった (後述)。

---

## 手法の核心

- **現象の測り方。** 入力は `e_t = (E(x_t) + E(y_t)) / 2` (2 本の文章の t 番目の token embedding の平均)。これを凍結した既製の LLM (Pythia / Qwen2.5 / Llama / OLMo / Gemma) に通す。単独で通したときの 1 位 token が、混ぜた出力で何位に来るかを数える。語彙は 5 万以上あるが、**上位 10 位以内に残るのが 30〜40%、100 位以内が 60〜65%** だった。対照として、無関係な文章の予測にもう一方の正解が偶然 10 位以内に入る率も測っていて、こちらは 2.6% しかない。
- **性質は学習で身に付くのではなく、学習で失われる。**Pythia の途中 checkpoint を順に調べると、「混ぜた入力の hidden state (中間層の表現)」と「2 本の hidden state の和」のずれは、学習初期が最小で、学習が進むほど単調に大きくなった。つまり線形性は architecture 由来で、pre-training (事前学習) が壊していく方向に働く。層ごとに見ると、深い層 (全体の 2/3 より後) はほぼ線形のまま残っていた。
- **fine-tuning で線形性を戻す = 一種の self-distillation (同じモデルの凍結コピーを teacher にした蒸留)。**teacher に 2 本を別々に通し、その確率分布の算術平均を目標にする。student には混ぜた入力を通し、`KL(P_target ‖ student(z))` を最小化する (KL divergence; 2 つの確率分布のずれの尺度)。Pythia-2.8B では KL が 1.86 から 0.27 に下がり、正解が上位 5 位に入る率も約 30% から 60% 超に上がった。**ただし、単独の文章に対する性能は大きく落ちる。**LAMBADA (文脈の最後の 1 語を当てる benchmark) は 0.544 から 0.357 に下がり、FineWeb での perplexity (PPL; 低いほど良い言語モデルの指標) は Qwen2.5-3B で 12.4 から 65.5 に悪化した。abstract は「lightweight」と書くが、実際には A100 2 枚で 114〜132 時間かかっている。
- **「logit の平均 = 確率の幾何平均」という障害。**混ぜた出力の logit (softmax 前のスコア) がほぼ 2 本の logit の平均になるとすると、確率は `√(P_A · P_B)` に比例する。したがって、「片方でだけ確率が高い token」は強く抑え込まれる。両方の正解が上位 5 位に残っていても、そのまま sampling すると 2 本の文脈を行き来する支離滅裂な文になる。
- **分離のための decoding は proof of concept (実現可能性を示す試作) にとどまる。**Joint Contrastive decoding では、小さな補助モデルを各 stream に別々に通し、その logit を足し引きして 2 本を分離する。Llama-3.2-3B で両 stream の LAMBADA 平均正答率は 0.18 から 0.43 に上がった。しかし、**補助モデル (Llama-3.2-1B) を単独で走らせたときの 0.54 にも届かない。**速度も比べられていて、補助モデルなしで 2 本を分離する方式は約 110 token/s (Pythia-2.8B)。普通の batch size 2 の 113 token/s と同等で、「約 2 倍」なのは 2 本を順番に実行する場合との比較だけである。しかもこの方式 (Two-Head) は、Llama-3.2-3B での両 stream の LAMBADA 平均正答率が 0.105 だった。何も fine-tuning しない場合の 0.182 よりも低い (付録 Table 6)。

## プロジェクトへの適用可能性

**分野は LLM の解釈可能性 (interpretability) と推論効率で、P1〜P3 のどれにも直接はつながらない。**探索枠で採用したのは、次の 2 点が P2 の蒸留設計に持ち帰れる学びだからである。

### P2 (蒸留) —— 複数 teacher の出力を「どう平均するか」で目標分布が変わる

この論文の障害の話は、そのまま multi-teacher distillation (複数の teacher の出力を合わせて student に教える蒸留) の設計論になる。teacher の logit を平均して softmax した目標は、確率の幾何平均になる。すると「どれか 1 つの teacher だけが強く推す答え」が消える。確率を算術平均した目標なら、その答えは残る。運転の軌跡予測のように、正解の候補が複数に分かれる (multi-modal) 課題では、この差が「少数派の mode を student が学ぶか」を左右しうる。

**実験アイデア 1 (半日):** 手元に teacher が 2 つ以上あれば (seed 違いや checkpoint 違いでよい)、同じ student を 2 通りの目標で蒸留する。
- (a) `softmax(mean(logits))`
- (b) `mean(softmax(logits))`

評価は通常の精度に加え、「teacher のうち 1 つだけが上位に置いた mode」を student が上位 k 位に残す率で行う。(a) でこの率が明確に落ちれば、P2 の multi-teacher の既定値を (b) にする根拠になる。

**実験アイデア 2 (既存の recipe の点検、1 時間):** P2 の蒸留で mixup (2 つの入力を混ぜ、目標も同じ比で混ぜる data augmentation) を使っているなら、単独入力での指標を別に記録しているか確認する。この論文の self-distillation は、混ぜた入力に対する目標と整合させるほど、単独入力の性能を大きく落とした (PPL 12.4 → 65.5)。mixup-KD で同じ競合が起きていないかは、単独入力の指標を別に取らないと見えない。

### P3 (次世代アーキテクチャ) —— 自前モデルの「線形性」を無料で測れる

学習ゼロで回せる診断として使える。

**実験アイデア 3 (半日、学習不要):** 手元の軌跡生成 Transformer (planner でも E2E モデルでもよい) に、2 つの場面の入力 token 列を位置ごとに平均して通す。出力の軌跡候補の中に、それぞれの場面を単独で入れたときの予測に近いもの (ADE = Average Displacement Error; 予測軌跡と基準軌跡の平均距離、が小さいもの) が残るかを測る。**あわせて、無関係な場面同士で偶然近くなる率 (論文の Appendix B と同じ対照) を必ず取る。**画像や LiDAR の token を混ぜる設定は、論文の Limitations で「未検証」と明記されている。そのため結果がどちらに出ても新しい情報になる。ただし、これが直接モデル改善につながるわけではない。優先度は低い。

## 注意点

- 分析は文脈長 128 (一部 512) の短い英語テキストだけ。長い文脈、多言語、multimodal では検証されていない。
- 「2 倍の throughput」「KV cache (生成中に過去 token の key/value を保持するメモリ) の半減」は結論節の主張である。実測 (Table 9) では、補助モデルなしの分離方式は batch size 2 と同じ速度で、精度は fine-tuning 前より低く、メモリは単独の forward pass より多かった (Llama-3B で 9.26 GB 対 6.72 GB)。batch size 2 のときのメモリは表に無い。
