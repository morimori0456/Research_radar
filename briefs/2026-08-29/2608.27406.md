# CLAP: Cross-Embodiment Video World Models are Zero-Shot Physical Simulators

**topic:** next_arch / **project:** P3 (主) · P2 (副)
**スコア:** P1 2.5 / P2 **3.8** / P3 **4.5**

## 何を解決する論文か

action-conditioned video model (行動を条件に与えると、その行動をとった場合の映像を生成するモデル) は world model の有力な実装だが、現状はほぼ全て**単一の embodiment (身体; ロボットの機種・形態) に閉じている。**ロボット A のデータで学習したモデルはロボット B に使えず、まして人間の動画は使えない。**その結果、インターネット規模の映像という最大のデータ資源が丸ごと死んでいる。**CLAP は「物理法則は誰が動かしても同じ」という前提に立ち、人間動画と複数機種のロボット動画を混ぜて 1 つの world model を学習する枠組みを出した。DROID のような難しい環境で、**単一 embodiment 専用の最先端モデルに匹敵または上回る。**

## 手法の核心

- **機種ごとにバラバラな action space (行動の表現形式; 関節角なのか手先座標なのか、次元数もスケールも違う) を 3 つの共通表現に寄せる** — **end-effector pose (手先の位置姿勢; 機構が違っても手先は共通に定義できる)**、言語指示、そして **latent action (潜在行動; 連続する 2 フレームの差から「何が起きたか」を教師なしで抽出した符号。行動ラベルの無い人間動画にも付けられる)。**
- **学習を 2 段の curriculum (簡単な段階から順に学ばせる学習計画) にする。**第 1 段は**ラベルの無い大量の映像に latent action を使って物理の事前知識を入れる。**第 2 段でそれを end-effector 座標系に**接地 (grounding; 抽象的な表現を、実際に指令として使える物理量に対応づけること)** させ、実機へ zero-shot で持っていく。**latent action は大量に作れるが指令に使えない、end-effector は指令に使えるがデータが少ない — この 2 つの欠点を段階で埋め合わせている。**
- **few-shot adaptation で効果が累積する。**cross-embodiment で事前学習したモデルを少量の対象機種データで適合させると、単一 embodiment で最初から学習するより良くなる。**つまり cross-embodiment 学習は、単一機種モデルの新しい作り方でもある。**
- 公開範囲が広い — cross-embodiment / DROID / Bridge / 双腕 YAM / G1 humanoid、条件付けは end-effector・言語・latent の 3 通り。**コードとモデルを全て公開。**

## P1 / P2 / P3 への適用可能性

**P3 (R3) にとっては、world model 側の「データをどう集めるか」の答えの 1 つとして分類マップに入る。**08-28 で立った軸が「時間をどこに持つか」、08-29 の PAWBench が「1 本を返すか分布を返すか」、そして**この論文は 3 本目の軸 — 「行動をどの座標系で表現するか」。**VLA と world model を統合するとき、両者が同じ action 表現を共有できるかどうかは設計の根幹であり、CLAP の「latent → end-effector の 2 段」はそこへの具体的な回答になっている。

**P2 にとっては、これは domain adaptation の論文として読める。**topics.yaml の「基盤モデルを別ドメインに転用する recipe」に当たる。ただし**転用の単位がドメインではなく身体である**点が新しい。**注目すべきは、共通表現を「機種によらず定義できる物理量 (手先の姿勢)」に選んだこと** — 蒸留・適合で「何を共通の足場にするか」を選ぶときの、良い判断例である。

**P1 への効きは間接的。**ただし AD にも同型の問題がある — **車種・センサ構成・搭載位置が違うと、収集済みのログが使い回せない。**CLAP の言い方に直せば「AD には embodiment gap がある」。**手先姿勢に相当する「機種によらず定義できる物理量」が AD で何かを 1 つ決めれば、同じ設計が成立する** (候補: 車両重心の軌跡、あるいは曲率と加速度の系列)。

### 試すべき実験アイデア

1. **【R3・低コスト】分類マップに「action 表現の共通化」の列を足す。**2 時間。CLAP / 08-28 の StreamPI / PredVLA (本日不採用) を並べると、**「共通化しない (機種専用)」「潜在で共通化」「物理量で共通化」の 3 値で埋まる。**空白セルが研究機会。
2. **【P1・半日】手持ちの走行ログを 2 つ以上の車種で分け、曲率・加速度の系列だけを共通表現として片方で学習・他方で評価する。**性能が落ちる幅が、AD における embodiment gap の実測値になる。**落ちなければ「AD に embodiment gap は無い」と言えて、それはそれで R3 の主張を 1 つ絞れる。**
3. **【P2】latent action の抽出器だけを取り出して、走行ログに適用してみる。**行動ラベルの無い車載映像 (公開データセットで大量にある) から latent action を取れるなら、**「ラベルの無い映像で事前学習 → 少量のラベル付きログで接地」という CLAP の 2 段構成が AD にそのまま移る。**まずは latent action が意味のあるクラスタになるかだけを見る。
