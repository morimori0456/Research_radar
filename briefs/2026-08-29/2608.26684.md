# Echo-GRPO / VideoEcho-R1: 教師の推論を student 自身の語彙に書き直してから蒸留する

**原題:** Reason in the Words You Speak: Idiolectal Paraphrasing Off-Policy Traces for Reasoning Distillation in VideoLLMs
**topic:** fm_distill_finetune / **project:** P2
**スコア:** P1 1.5 / P2 **4.2** / P3 2.5

## 何を解決する論文か

**GRPO (Group Relative Policy Optimization; PPO を簡略化した、LLM の強化学習で広く使われる手法。同じ問いに複数回答えさせ、その群の中での相対的な良し悪しで更新する)** は、モデル自身が生成した軌跡だけで学習する **on-policy (方策内; 学習対象のモデル自身が作ったデータで学ぶこと)** な手法なので、**すでに出せる推論の範囲を超えられない。**そこで強い教師の推論トレースを外から注入する研究があるが、そのトレースは student にとって **off-policy (方策外; 別のモデルが作ったデータ)** であり分布がずれている。**著者はここで具体的な故障機序を特定した — 分布外のトークンは確率比が大きく外れるため GRPO の gradient clipping (更新幅が大きすぎる勾配を切り詰める安全装置) に引っかかり、切り捨てられる。しかもそれが起きるのは、意味的に最も重要な推論トークンである。**結果として**「答えは合うが、その答えを支える推論は学習されていない」**という状態になる。

## 手法の核心

- **診断が先にあり、手法はその帰結として出てくる。**「off-policy トレースを混ぜると効きが悪い」を「clipping が意味的に重要な token を選択的に殺している」まで落としたのが本論文の主な貢献。**症状ではなく機序を書いている。**
- **idiolect (個人語; ある話者に固有の語彙選択と言い回しの癖) という概念を student のモデルに持ち込む。**教師のトレースをそのまま模倣させるのではなく、**意味を保ったまま student が普段使う言い回しに翻訳してから与える。**分布のずれを、データ側で消しにいく。
- **Dual-Reference Decoding** — 書き換えの際、教師トレースの意味と student の言語習慣の両方を参照しながらデコードする。**意味を保つ制約が無いと、書き換えは単なる劣化になる。**この 2 参照が、翻訳が中身を壊さないための担保。
- **plug-in として成立することを示している。**GRPO だけでなく通常の supervised fine-tuning に対しても、idiolectal paraphrasing を挟むと改善する。**3 つの multimodal LLM backbone × 5 ベンチマークで一貫。**「policy-aligned supervision」という原理が GRPO 固有ではないことの実証。

## P1 / P2 / P3 への適用可能性

**R2 (蒸留の capacity gap の系統則) に対して、これは「なぜ capacity gap が破綻を生むのか」の機序候補を 1 つ与える論文である。**

R2 が説明したい現象は「teacher と student の容量比が開くと、ある境界で蒸留が破綻する」。**本論文の機序を当てはめると、その理由の一部が説明できる — 容量差が開くほど教師のトレースは student にとって分布外になり、分布外の度合いが clipping の閾値を超えた token が増える。**閾値を超えた token は学習されないので、**容量比に対して「学習される token の割合」が階段的に落ちる。破綻の境界とは、この割合が有効な学習に足りなくなる点ではないか。**

**08-28 に立てた「勾配が一部の token に集中する」という仮説と、本論文の「clipping で一部の token が切り捨てられる」は、同じコインの裏表である。**集中した勾配は大きく、大きい勾配は切られる。**同じ日に読んだ [UC-MOPD](2608.26735.md) が「教師が確信していない token を捨てる」のに対し、本論文は「捨てられている token を救う」。R2 の実験系では、この 2 つを対照群として並べられる。**

**P2 の実務側 (蒸留 recipe) にとっての持ち帰りは 1 行で書ける — 教師の出力をそのまま SFT データにするな。**student に一度言い換えさせてから使う。**追加コストは推論 1 回分で、実装も既存パイプラインの前段に挟むだけである。**

### 試すべき実験アイデア

1. **【R2・半日】過去の蒸留ログで、clipping が発動した token の割合を容量比ごとに数える。**再学習不要。ログに確率比が残っていれば集計だけで済む。**容量比に対して単調に増えるか、どこかで折れるか。折れる点があれば、それが破綻境界の候補である。**上の CLL 集中度と同じログから両方取れるので、[UC-MOPD](2608.26735.md) の実験 1 と同時に走らせられる。
2. **最小構成の idiolectal paraphrasing を試す。**教師トレースを student 自身に「同じ内容を君の言葉で言い直して」と 1 回通すだけ。**Dual-Reference Decoding までは実装せず、素朴な言い換えでどこまで再現するかを見る。**効かなければ Dual-Reference が本質だったと分かり、効けば安い手が 1 つ増える。
3. **【R2 の系統則に効く問い】書き換えの効果は容量比によって変わるか。**容量比が小さい (student が教師に近い) ときは元から分布外でないので効かないはず。**「効果が容量比とともに増える」ことを示せれば、それ自体が R2 の系統則の一部になる。**
