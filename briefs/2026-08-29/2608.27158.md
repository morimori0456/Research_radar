# PDPO: Diffusion Policies for Short-Horizon Planning in Robot Crowd Navigation

**topic:** planner_ai (内容による分類 / candidates.json の tag は `fm_distill_finetune` — **欠陥 #4 の実例**) / **project:** P1
**スコア:** P1 **4.0** / P2 2.0 / P3 3.0

## 何を解決する論文か

密で動的な人混みの中をロボットが進む問題では、既存の強化学習手法は**各時刻に 1 つの反応的な行動を出す**構造になっており、「右から抜ける」「左から抜ける」「待つ」といった**複数の妥当な回避戦略を同時に表現できない。**PDPO は **diffusion policy (拡散モデルで行動を生成する方策。ノイズから徐々に行動系列を作り出すため、複数の異なる行動モードを 1 つのモデルで表現できる)** を使って**短い区間の行動チャンクをまとめて生成する。**衝突回避のデモで事前学習し、PPO で online に微調整する offline-to-online の構成。

**そして本論文にはもう 1 つ、本質的に重要な副産物がある — 著者は既存の crowd navigation ベンチマークに評価上の抜け穴を見つけた。**明示的な境界条件が無いため、**学習したエージェントが有効領域の外へ出て混雑を迂回してしまう。**成功率は上がるが、それは課題を解いたのではなく課題から逃げている。著者は境界逸脱を衝突扱いにする設定を追加し、**その厳しい設定でこそ action chunk が効くことを ablation で示した。**

## 手法の核心

- **行動を 1 ステップではなく 5 ステップのチャンクで生成し、receding horizon (逐次後退地平; 数ステップ先まで計画して最初の数手だけ実行し、また計画し直す制御方式) で適用する。**「多峰性を表現するには、行動を系列として出す必要がある」という主張。
- **denoising 過程 (拡散モデルがノイズを段階的に除去して出力を作る手続き) を、内部の意思決定過程とみなして PPO で最適化する。**拡散方策を RL で微調整するときの定式化として素直。
- **offline (デモから模倣) → online (PPO で環境と相互作用しながら改善) の 2 段。**デモは安全な初期方策を与え、online は実分布での最適化を担う。
- **【最重要】ベンチマークの抜け穴の発見と、その修正。**境界逸脱を衝突と数える設定を導入。**「既存手法の高い成功率のうち、いくらが抜け穴由来だったか」を分離した。**

## P1 / P2 / P3 への適用可能性

**R1 (衝突率だけでなく過保守も保証付きで測る) にとって、この論文の価値は手法ではなく、評価の抜け穴を見つけた事実そのものにある。**

R1 の出発点にある問題意識は「衝突率だけでは planner の質は測れない」だった。**本論文はその隣に、もっと痛い事実を置いている — 衝突率という指標は、そもそも正しく測れていないことがある。**エージェントは指標の穴を見つけて逃げる。**これは R1 の主張を一段強くする材料である**: 「過保守も測れ」だけでなく、「その測定が抜け穴で汚れていないことを保証せよ」。**conformal prediction (予測の外れ率を、分布に仮定を置かずに保証付きで抑える統計手法) で保証を付けるとき、保証の対象になる指標が抜け穴で汚れていれば、保証は無意味になる。**

**AD で同型の抜け穴が何かは、すぐ思い当たる。**閉ループシミュレーションで衝突率を測るとき — **経路から逸脱して交通の薄い側へ出る、極端に減速して評価区間内に危険地点へ到達しない、シナリオ終了時刻まで停止し続ける。**どれも衝突率は改善し、どれも運転として失敗している。**08-28 から繰越の「走行ログに solvability を後付け計算」という作業に、この観点を 1 つ足すだけで、R1 の主張の射程が広がる。**

**action chunk の側も P1 に無関係ではない。**08-28 の StreamPI・FlashVLA と本論文は、**「1 ステップ出力か、チャンク出力か」という同じ設計判断を扱っている。**本論文の ablation は「厳しい設定でこそチャンクが効く」と言っており、**評価を厳しくすると設計判断の優劣が入れ替わるという実例になっている。**

### 試すべき実験アイデア

1. **【最優先・R1 に直結、半日】繰越中の solvability 後付け計算に「抜け穴監査」を 1 列足す。** 各評価エピソードについて、**(a) 経路逸脱量、(b) 平均速度、(c) 評価区間内で危険地点に到達したか** の 3 つを記録するだけ。**「衝突ゼロだが危険地点に一度も近づいていないエピソード」が何 % あるかが、その場で出る。**この数字が大きければ、**それだけで R1 の図が 1 枚成立する** — 「現行の衝突率は、この割合ぶん水増しされている」。追加実装はほぼゼロ。
2. **抜け穴を塞いだ設定と塞がない設定で、手持ちの planner の順位が入れ替わるかを見る。**入れ替われば、**「評価設定が結論を決めていた」という最も強い形の主張になる。**入れ替わらなければ、現行の評価は健全だという安心材料。**どちらに転んでも図になる。**
3. **【中期】過保守の定義に、この観点から下限を入れる。** 「衝突ゼロ」を満たすだけでなく「危険地点に規定回数以上遭遇している」ことを評価の前提条件にする。**過保守の測定は、遭遇があって初めて意味を持つ。**
