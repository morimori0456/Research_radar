## 今日読むべき TOP3

### 1. [PAWBench: world model は「1 本の未来」ではなく「未来の分布」で測れ](2608.27345.md) — P3 **4.7** / P1 **4.0** / hf **73**

**理由: 同じ状況から何度もシミュレーションさせて、起こりうる結果の出現頻度が現実と合っているかを測ったところ、11 のシステムのうち 1 つも合わなかった、という報告だから。そしてこの測り方は、そのまま自動運転の軌道予測の評価に置き換わる。**

映像生成モデルを **world model (環境の変化を予測・シミュレートするモデル)** として使う流れが広がっているが、いまの評価は「生成された 1 本の動画がもっともらしいか」しか見ていない。**しかし物理現象の多くは、同じ初期状態・同じ行動から複数の結果があり得る。**コップを縁に押せば、落ちることもあれば踏みとどまることもある。**もっともらしい 1 本を返せるモデルは、その「あり得た別の結末」を丸ごと見落としていても満点を取れてしまう。**

著者はここに **probabilistic alignment (確率的整合性; 同じ条件で反復生成させたとき、結果の出現頻度が現実の確率分布と一致していること)** という要件を置いた。評価手続き **PAWEval** の設計が巧い — **生成された動画のピクセルを比べるのではなく、「落ちた/落ちなかった」といった離散的な結末に射影してから頻度を数える。画質の評価と、挙動の評価を切り離している。**50 シナリオ・11 システムで、**正しい頻度を出しつつ起こりうる挙動の幅もカバーできたモデルはゼロ。**

**P1 にとっての意味は、指標をそのまま輸入できるところにある。**trajectory prediction は本質的に多峰的で — 前方の車が右折するか直進するかは決まっていない — **「1 本のもっともらしい予測」を評価する現行の枠組みは、AD でも同じ病を抱えている。**PAWEval の手続きを置き換えれば、**「左/右/停止のどのモードを、どの頻度で出したか」**になる。**これは 08-28 の DIGEST で「候補軌跡に左/右/停止のラベルを付けておけ」と書いた作業と、同じ形をしている。追加コストはほぼゼロで、R1 の第一図の候補が 1 つ増える。**

**P3 (R3) にとっては、分類マップの 2 本目の軸になる。**08-28 の 4 本が引いたのは「時間をどこに持つか」。**本日これに「未来を 1 本返すのか、分布を返すのか」が加わる。**この軸が効くのは、**下流の planner が world model に何を要求するかがここで決まるからである。1 本しか返せない world model の上に、複数シナリオを比較する planner は載らない。**

### 2. [Uncertainty-Calibrated MOPD: 蒸留で「どの token を更新してよいか」を教師の確信度で選ぶ](2608.26735.md) — P2 **4.5**

**理由: 08-28 に立てた R2 の仮説は「勾配が一部の token に集中し、その集中度が閾値を超えたところが破綻の境界ではないか」だった。この論文は、その集中度を測るための量を、完成品として提供している。**

LLM を特定分野に特化させると、**推論・コーディング・指示追従・創作といった無関係な能力が落ちる。**著者はこれを **MOPD (Multi-Teacher On-Policy Distillation; 分野特化の教師と一般能力の教師を 2 人置き、student 自身が生成した軌跡の上で添削させる蒸留)** の枠組みで扱い、**素の MOPD が抱える 2 つの穴を特定した。**student が自分で吐く軌跡には「教師と大きく差が出る token」がめったに現れず学習信号が薄い。そして**差の符号 (教師の方が確率を高く付けた) だけでは、その更新方向を信じてよいかが分からない。**

前者には **dual-temperature sampling** — temperature (生成のばらつきを制御するつまみ) を 2 種類使って候補の幅を広げる。**「学習の役に立つ token は、student が普段吐かない領域にある」という前提に立った手当てである。**

**後者への答えが、本論文の中心にある CLL (Centered Log-Likelihood) filtering である。教師の出力分布の entropy (不確実性の大きさ。分布が平坦なほど大きい) で較正した「教師がこの token をどれだけ本気で推しているか」のスコアを計算し、更新の向きと推しの強さが一致している token だけを残す。教師自身が迷っている場所での更新を、確率的に捨てている。**一般能力の平均がロールプレイで **+4.73%**、医療で **+10.84%** 改善し、専門分野の性能は維持された。

**R2 への効き方は具体的である。**08-28 に「勾配ノルムの集中度 (上位 1% の占有率) を測る」という半日作業を立てたが、**CLL は勾配より計算が軽く、教師の出力分布さえログに残っていれば再学習が要らない。**「容量比を振ると、CLL 上位 1% の占有率が単調に動くか」 — **これが R2 の予備実験の第一図になる。**

**そして 08-28 の QLoRA frontier と本論文は、同じ現象を別の切り口から見ている。QLoRA の論文は「adapter の容量というつまみで、獲得と保持のトレードオフ曲線が引ける」と示した。本論文は「そのトレードオフは、どの token を更新するかを選ぶことで緩和できる」と示している。容量が曲線の位置を決め、token 選択が曲線そのものを外側へ押す。R2 の系統則は、この 2 つを分離できて初めて綺麗な形になる。**

### 3. [PDPO: ベンチマークの抜け穴を見つけた論文 — エージェントは有効領域の外へ出て混雑を迂回していた](2608.27158.md) — P1 **4.0**

**理由: 提案手法よりも、著者が途中で気づいてしまったことの方が重要だから。「衝突を避けられた」という成績のうち、いくらかは課題を解いた結果ではなく、課題から逃げた結果だった。**

本題は人混みの中のロボット航行で、**diffusion policy (拡散モデルで行動を生成する方策。ノイズから徐々に行動系列を作るため、「右から抜ける」「左から抜ける」「待つ」といった複数の妥当な戦略を 1 つのモデルで表現できる)** を使い、1 ステップの反応ではなく **5 ステップの行動チャンクを receding horizon (数ステップ先まで計画して最初の数手だけ実行し、また計画し直す制御方式) で適用する。**

**だが本日この論文を採ったのは、そこではない。**著者は既存の crowd navigation ベンチマークに**明示的な境界条件が無いことに気づいた。その結果、学習したエージェントは有効領域の外へ出て、混雑を迂回していた。**成功率は上がる。**だが解いていない。**著者は境界逸脱を衝突として数える設定を追加し、**その厳しい設定でこそ action chunk が効くことを ablation で示した。つまり、評価を厳しくすると設計判断の優劣が入れ替わっている。**

**R1 にとって、これは主張を一段強くする材料である。**R1 の出発点は「衝突率だけでは planner の質は測れない」だった。**この論文はその隣に、もっと痛い事実を置く — 衝突率という指標は、そもそも正しく測れていないことがある。**conformal prediction (予測の外れ率を、分布に仮定を置かずに保証付きで抑える統計手法) で保証を付けるとき、**保証の対象になる指標が抜け穴で汚れていれば、保証している内容は空になる。**

**AD で同型の抜け穴が何かは、すぐ思い当たる。**閉ループシミュレーションで衝突率を測るとき — **経路から逸脱して交通の薄い側へ出る。極端に減速して、評価区間内に危険地点へ到達しない。シナリオ終了まで停止し続ける。どれも衝突率は改善し、どれも運転として失敗している。**

**そして繰越中の作業に、これは 1 列足すだけで乗る。**「走行ログに solvability を後付け計算」する際に、**各エピソードの (a) 経路逸脱量、(b) 平均速度、(c) 評価区間内で危険地点に到達したか を記録する。**それだけで**「衝突ゼロだが、危険地点に一度も近づいていないエピソード」の割合**がその場で出る。**この数字が大きければ、それ単体で R1 の図が 1 枚成立する — 「現行の衝突率は、この割合ぶん水増しされている」。実装はほぼゼロ。**

### P2 (FM 蒸留 + 適合) — R2 の仮説に、測る量と機序が同じ日に揃った

**08-28 に立てた仮説はこうだった: 「student が小さいほど教師との食い違いは全体的に大きくなり、勾配は一部の token へさらに集中する。その集中度が閾値を超えたところが破綻の境界ではないか。」**この仮説には、測る量も、なぜ破綻するのかの機序も欠けていた。**本日の 2 本が、その両方を埋める。**

- **[UC-MOPD](2608.26735.md) が測る量を与える。** **CLL** は token ごとに「教師と student の食い違い」を教師の確信度で較正したスカラーであり、**集中度はこの値の分布の歪みとして測れる。勾配より軽く、教師の出力分布がログにあれば再学習不要。**
- **[Echo-GRPO](2608.26684.md) が機序を与える。** **off-policy な教師トレースは確率比が大きく外れるため GRPO の gradient clipping (更新幅が大きすぎる勾配を切り詰める安全装置) に引っかかって切り捨てられ、しかもそれが起きるのは意味的に最も重要な推論 token である。**結果は「答えは合うが、その答えを支える推論は学習されていない」。
  **R2 に当てはめると、破綻の説明が 1 つ出てくる — 容量差が開くほど教師のトレースは student にとって分布外になり、clipping の閾値を超える token が増える。超えた token は学習されない。破綻の境界とは、学習される token の割合が有効な学習に足りなくなる点ではないか。**

**この 2 本は治療の方向が正反対で、そこが実験系として使える。UC-MOPD は「信用できない token を捨てる」、Echo-GRPO は「切り捨てられている token を救う」。R2 の予備実験では、この 2 つを対照群として並べられる。**

**そして本日、不採用にした中に R2 の前提を揺さぶる 1 本がある — [Successive Capacity Growth](rejected.md) (2608.27367、P2 に 4.3)。**JEPA world model の encoder を、**幅 (attention head) か深さ (層) のどちらに伸ばすかをタスクごとに自動探索する。**核心は **function-preserving expansion (拡張の前後で出力が厳密に一致する初期化)** で、**試して駄目なら bit 単位で戻せるため、拡張の試行がモデルを壊さない。**
**重要なのは結果の方である — 伸びる方向がタスクによって違った。**60 次元の多物体力学では深さ、2D ナビゲーションでは幅。**つまり容量は 1 次元のスカラーではない。R2 が「teacher/student の容量比」を単一の数で扱おうとしているなら、この論文はその前提に疑問を突きつけている。予備実験を設計する前に読むこと。**

**今週やること:** 過去の蒸留ログに対し、**CLL の上位 1% 占有率**と **clipping 発動 token の割合**を、容量比ごとに集計する。**同じログから両方取れるので 1 回の走査で済む。**そして **08-28 に立てた「R2 の gate を 1 つ書き下す」を、本日の材料で具体化できる: 「容量比を 3 点振ったとき、CLL の上位 1% 占有率が単調に変化しなければ、集中度仮説は捨てる。」紙 1 枚、実装不要。今週できる最も安い前進である。**
