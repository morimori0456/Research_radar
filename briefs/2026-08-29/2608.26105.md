# VBVR-Pro: A Scalable and Verifiable Suite for Native Visual Reasoning

**topic:** sns_wildcard (分野外・注目度枠) / **hf_upvotes:** 205 (本日の全候補で最高)
**スコア (参考):** P1 3.0 / P2 2.0 / P3 3.0 — **採用理由は relevance ではなく、評価設計の学びである**

## 何を解決する論文か

**native visual reasoning (画像や動画を「理解する対象」でも「出力する成果物」でもなく、思考そのものの媒体として使うこと)** という考え方がある。人間が図を描きながら考えるのと同じで、言語を経由せず視覚状態を書き換えながら問題を解く。**しかしこの方向は、学習させられる課題が足りない・出力の正しさを判定できない・生成の方式を揃えて比べられない、という 3 つで詰まっていた。**VBVR-Pro はその 3 つを同時に埋める閉ループのテストベッドである。

## 手法の核心

- **課題を手で作るのをやめ、300 個を手続き的に生成する。**難易度と種類をパラメータとして制御できるので、**「どの軸を難しくすると何が壊れるか」を統制実験として実施できる。**VBVR-Pro で学習したモデルは、RISE-Video・MME-CoF-Pro・BabyVision など**外部 7 ベンチマークへ転移する** — 手続き生成課題が「そのベンチだけで通用する技」を教えているわけではないことの証拠。
- **【本日の最大の学び】verifiable reward (検証可能な報酬; 出力の正しさを、モデルの判断ではなく決定的な規則で判定できる報酬) を課題ごとに用意する。**著者は主要な **MLLM (Multimodal Large Language Model; 画像と言語を同時に扱う大規模モデル)** を審査員として使う **VLM-as-a-judge (モデルに採点させる方式)** を系統的に調べ、**繰り返し現れる故障モードを特定した上で、規則ベースの採点器がそれを回避することを示している。**人間の判断との細かい一致度も、規則ベースの方が高い。
- **その採点器が、大規模なマルチタスク強化学習の報酬信号として実際に機能する。**評価用の指標を、そのまま学習信号として使い切っている。**「測れるものしか最適化できない」を素直に実装した形。**
- **生成の媒体 (どの substrate で思考するか) を揃えて比較する統制実験の枠組みも提供している。**

## なぜこの枠で採ったか / 持ち帰るもの

**分野は P1/P2/P3 のどれにも直接は当たらない。採ったのは「評価をどう設計するか」という 1 点で、本日の他の 2 本と正面から噛み合うからである。**

本日の [PAWBench](2608.27345.md) は「1 本ではなく分布を測れ」、[PDPO](2608.27158.md) は「その測定には抜け穴がある」と言った。**VBVR-Pro が足すのは 3 つ目 — 「誰が測るのか」。**モデルに採点させるのは楽だが、**採点器の故障モードが評価結果に混入する。**規則ベースの決定的な採点器は、書くのは面倒だが混入が無い。

**これは R1 に直接効く命題である。**R1 は planner の評価指標を提案する研究であり、**提案する指標が「決定的な規則で計算できる」か「判断を要する」かで、主張の強さがまるで違う。**conformal prediction で保証を付けるなら、**保証の対象は決定的に計算できる量でなければならない** — 判断が混ざる量に分布仮定なしの保証を付けても、保証しているのは採点器の癖である。**R1 の指標設計において、これは制約条件として先に置くべき条件である。**

**そして手続き的な課題生成は、R1 の実験設計にも移せる。**走行シナリオを手で選ぶのではなく、**危険度や交通密度をパラメータとして手続き的に生成すれば、「どの軸で planner が壊れるか」を統制実験として言える。**シナリオを手で選ぶ限り、選び方への批判は消えない。

### 試すべき実験アイデア

1. **【R1・紙 1 枚】R1 で提案する候補指標を並べ、「決定的な規則だけで計算できるか」で 2 分する。**判断が混ざるものは、**保証の対象から外すか、決定的な近似に置き換えるかを先に決める。**30 分で終わり、後の設計が全部楽になる。
2. **既存の走行シナリオ集に対し、密度・遮蔽・相対速度の 3 軸でラベルを振れるか調べる。**手続き生成まで行かなくても、**既存シナリオを軸で層別できれば、統制実験に近いことは言える。**
3. VLM-as-a-judge を planner の定性評価に使っている箇所があれば、**本論文の故障モード一覧と突き合わせる。**該当すれば、その評価結果は主張の根拠から外す。
