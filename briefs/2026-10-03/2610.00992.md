# CLRE: Closed-Loop Refinement and Execution for Learned Driving Planners

- arXiv: `2610.00992` / https://arxiv.org/abs/2610.00992
- 配属: planner_ai (P1) ・ candidates.json 内
- スコア: **P1 4.5** ・ hf_upvotes 0

## 何を解決する論文か

学習型の運転 planner は、多くの場合 open-loop (記録された走行ログの軌跡との距離で採点する方式) で学習・評価される。しかし closed-loop (planner の出力で実際に車を動かし、その結果の状態で次の判断をさせる方式) では、ログとの誤差が小さい軌跡でも、車が止まって動かなくなる・他車と衝突する・急ブレーキになる、といった失敗が起きる。CLRE は、学習済みの planner を凍結したまま、新しい学習モデルも足さずに、その出力を後段で補正して closed-loop の失敗を減らす。

## 手法の核心

- **2 層の receding-horizon 制御:** receding-horizon (毎ステップ数秒先まで計画し、最初の一部だけ実行して計画し直す方式。MPC と同じ考え方)。上の層は planner の出力軌跡を「参照」として扱い、有限時間の最適制御問題を解く。cost は「経路に沿った進み具合」と「予測された他車との干渉」のトレードオフ。
- **複数の初期値から解いて候補集合を作る:** 最適化を 1 回だけ解くのではなく、初期値を変えて何度か解き、候補軌跡の集合を作る。局所解にはまっても、どれかが良い解に届くようにしている。
- **OBB による実現可能性の判定:** OBB (Oriented Bounding Box; 車の向きに合わせて回転させた長方形) を使い、予測された他車の OBB との最小距離を horizon 全体で調べる。閾値を下回る候補は捨てる。
- **下の層 (実行):** 残った候補のうち cost 最小のものを、planner に付属の tracking controller (軌跡に追従させる低レベル制御器) で実行する。候補が全部捨てられたら、車線中心線に沿う予備の軌跡に切り替える。さらに、前方の物体までの距離に応じた速度上限と、上限付きの比例ブレーキ則を足している。
- **結果:** Bench2Drive (CARLA simulator 上の closed-loop 運転ベンチマーク) の 126 ルートで、上流の planner に VAD (ベクトル表現の E2E 運転モデル) を使うと、driving score 43.41 → 56.42、route completion (経路を最後まで走れた割合) 57.27 → 72.23、衝突回数 70 → 53。

## P1 への適用可能性

- **「planner 本体」と「実行時の安全層」を分けて評価する根拠になる。**上流の planner を変えずに driving score が +13 点動く。ということは、Bench2Drive のスコアには「後処理の良し悪し」がかなり混ざっている。P1 で planner 同士を比べるときは、同じ後処理を通した結果と通さない結果の両方を出さないと、比較が後処理に左右される。
- **09-29 の ECO (`2609.31383`; 終点を固定する後処理で closed-loop が改善) と同じ型の 2 本目。**「学習型の出力 + 最適化ベースの補正」が 2 本続いたので、P1 のベースライン構成に「後処理あり / なし」の 2 本立てを入れる価値が高まった。
- **失敗の分類にも使える。**論文が挙げる 3 つの失敗 (止まって動かない / 他車と衝突 / 急ブレーキ) は、そのまま closed-loop 評価で数える失敗のカテゴリになる。10-02 の TrafficSignBench が「ルール違反」と「守ったが着かなかった」を分けたのと同じく、1 つのスコアにまとめずにカテゴリ別に出す設計に合う。
- **限界:** 上流は VAD の 1 種類だけ。より強い planner (closed-loop で学習したもの) では伸びしろが小さい可能性がある。衝突は 70 → 53 で、減ってはいるが残っている。後処理の計算時間は abstract からは分からない。

## 試すべき実験アイデア

1. **(2D toy) 後処理の寄与の切り分け:** 2D の車線追従 + 前方に減速車がいる場面で、わざと誤差を入れた「学習型 planner 役」(ログ軌跡 + ノイズ) を作る。(a) そのまま実行、(b) OBB の距離判定だけ足す、(c) 複数初期値の最適化 + 判定、の 3 つで、停止・衝突・急ブレーキの回数を別々に数える。どの失敗がどの部品で減るかを見る。
2. **(同じ toy) 「planner の差」が後処理で消えるか:** 精度の違う planner 役を 2 つ用意し、後処理なしだと差があるのに、後処理ありだと差が縮むかを測る。縮むなら、P1 の評価では planner 単体のスコアを別に報告する必要がある。
3. **(CARLA/Bench2Drive が使えるなら)** 公開されている任意の planner に CLRE 型の後処理を足し、driving score の差分を「後処理の寄与」として記録する。
