# Supervise What Decides Success: Criterion-Aligned Auxiliary Losses for Latent World-Model Planning

## 何を解決する論文か

latent world model (観測を圧縮した latent 空間の中で未来を予測するモデル) で planning するときは、候補の行動列を latent 空間での距離 (予測した終点の latent と目標の latent の距離) で採点する。ところが、タスクの成否は物理量 (例: ロボットの手先の位置が目標から何 cm 以内か) で判定される。論文はこれを success-criterion quantities (成否を決める物理量) と呼ぶ。調べた 4 つの latent world model ではすべて、手先の位置が latent に、成否の判定に必要な精度より粗くしか入っていなかった。それでは成功する候補と失敗する候補を区別できない。論文は、成否を決める物理量を学習の目標にする補助 loss を提案する。

## 手法の核心

- **線形 head による補助 loss:** 学習中だけ、encoder と予測器の出力に線形 head を付け、成否を決める物理量を回帰させる。その回帰誤差を学習の loss に足す。既存の latent world model は、これらの量を「入力」としてしか使っていなかった。
- **推論時は何も変わらない:** head は学習後に捨てる。モデル・計算 cost・入力は推論時には変わらない。
- **診断が先にある:** 「latent から成否の量を何 cm の精度で読み出せるか」を測り、それが成否の判定の閾値より粗いことを確かめてから対策している。この診断は手法とは独立に使える。
- **結果:** この loss だけで、PushT と cube のタスクで成功率がそれぞれ +3.5% と +3.4% (絶対値)。どちらも統計的に有意。

## P3 への適用可能性

- **運転の world model に一番そのまま移せる、安価な変更。**運転の成否を決める物理量は、他車との最小距離・TTC (Time-to-Collision; 今の速度のままだと何秒後に衝突するか)・車線からのずれ、など定義がはっきりしている。これらを補助 loss の目標にするのは、線形 head を 1 つ足すだけ。
- **先に「診断」だけでも価値がある。**手持ちの world model の latent から TTC や最小距離を線形 probe で読み出し、その誤差が判断に必要な精度 (例: TTC 2 秒の閾値を判定できるか) より大きいかを測る。これは学習をやり直さなくても実行できる。
- **10-02 の Planning Limits (`2609.39235`) と組み合わせて読む。**あちらは「予測が正確でも、採点の仕方 (想像の長さと目標の距離) がずれると planning は失敗する」。こちらは「latent に成否の情報が無いと、採点そのものができない」。どちらも「latent 空間の距離で採点する」planning の弱点を別の角度から示している。

## P1 への波及

- planner の採点関数 (scorer) を学習する場合にも同じ問題がある。scorer の内部表現から、衝突の判定に必要な量 (最小距離など) が十分な精度で読み出せるかを、P1 の評価の診断項目に足せる。

## 試すべき実験アイデア

1. **(2D toy、学習不要の診断から) 読み出し精度 vs 判定閾値:** 2D の到達タスクで小さな latent world model (MLP の encoder + 予測器) を学習し、latent から位置を線形 probe で読み出す誤差を測る。成功判定の半径を 0.5 / 0.2 / 0.05 と小さくしていったとき、読み出し誤差が判定半径を超えるあたりで planning の成功率が落ちるかを見る。
2. **(同じ toy) 補助 loss の効果:** 同じ world model に、位置を回帰する線形 head の補助 loss を足して学習し直し、判定半径ごとの成功率の改善を測る。論文の +3.5% が、判定が厳しいほど大きくなるかを確認する。
3. **(運転への橋渡し)** 2D の追従場面で、成否の量を「前の車との距離」と「TTC」にし、どちらを補助目標にした方が衝突の判定に効くかを比べる。
