# TierCEM: Cross-entropy optimization with prioritized constraints

- arXiv: `2610.01319` / https://arxiv.org/abs/2610.01319
- 配属: **planner_ai (P1) に再分類** (取得時は next_arch。keyword `world model` で一致) ・ candidates.json 内
- スコア: **P1 3.5** (P3 3.0) ・ hf_upvotes 0

## 何を解決する論文か

制約同士がぶつかるとき (例: 「衝突しない」と「目的地へ進む」と「車線をはみ出さない」が同時に満たせない場面)、最適化はどれを守ってどれを緩めるかを決めなければならない。普通は各制約に penalty の重みを付けて足し合わせるが、重みの付け方によっては、重み付きの合計スコアが良くなる代わりに、本来優先すべき制約を破る解が選ばれてしまう。TierCEM は、重みを使わずに「制約の優先順位」をそのまま最適化に入れる。

## 手法の核心

- **ベースは CEM:** CEM (Cross-Entropy Method; 行動列をランダムに多数サンプルし、良い上位 (elite) に合わせて分布を更新することを繰り返す最適化。world model を使った planning で標準的に使われる)。
- **elite の選び方だけを変える:** サンプルした候補を、優先度の高い制約から順にふるいにかける。最優先の制約を満たす候補だけ残し、その中から次の制約を満たすものだけ残し……と進む。
- **全滅したときの扱い:** ある制約で候補が 0 件になったら、1 つ前の (空でない) 集合に戻り、その制約の違反量が最小のものを elite にする。こうすると、上位の制約は必ず守ったまま、下位の制約だけが緩められる。重みの調整は不要。
- **評価:** 2D のナビゲーションと、接触の多い物体押し (pushing) のタスクで、真の状態を使う場合と学習した world model を使う場合の両方を試した。制約の順序を逆にすると、競合したときに破られる制約が入れ替わる (= 順序が意図どおりに効いている)。「タスクの進捗」を上位に置くと、進捗を妨げる下位の制約を緩めて前に進める。

## P1 への適用可能性

- **rulebook 型の planner 評価・設計に直結する構造。**自動運転では「衝突回避 > 交通ルール > 快適性 > 進捗」のような優先順位付きのルール集合 (rulebook; 優先順位で並べたルールの階層で軌跡を比較する考え方) がよく使われる。TierCEM はそれを sampling 型の planner に入れる、ごく小さな変更になっている。
- **重み付き cost の planner と比べる実験がそのまま作れる。**「重みを変えると何が破られるか」と「順序を変えると何が破られるか」を並べれば、重み付き cost の脆さを P1 の評価で示せる。
- **評価指標としても使える。**ふるいの手順は、そのまま「候補軌跡を辞書式に比べる評価関数」になる。10-02 の TrafficSignBench の「違反の有無 → 到達の有無」という 2 段の数え方と同じ構造。
- **限界:** 実験は 2D のナビと pushing だけで、運転は無い。サンプル数が少ないと、上位の制約で候補がすぐ全滅し、下位の制約がほとんど効かなくなる恐れがある (論文の主張は abstract までの確認)。優先順位を厳密に守るので、「下位の制約を大きく破って上位をわずかに得する」解も選ばれる。これが運転で望ましいかは別途検討が必要。

## 試すべき実験アイデア

1. **(2D toy、学習不要) 重み vs 順序:** 2D の車線 + 障害物 + 目的地の場面で、CEM planner を (a) 重み付き penalty、(b) TierCEM の順序付き、で作る。penalty の重みを 10 段階に振ったとき、衝突・車線逸脱・到達の破られ方がどう変わるかを、(b) の順序を変えたときの変化と並べる。重みでは破られる制約が不連続に入れ替わるのに対し、順序では予測どおりに入れ替わるか。
2. **(同じ toy) サンプル数の感度:** CEM のサンプル数を 16 / 64 / 256 に振り、上位の制約で候補が全滅する頻度と、下位の制約の違反量を測る。運転の制約数 (5〜10 個) で使えるサンプル数の下限を見積もる。
