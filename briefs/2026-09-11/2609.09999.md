# SalamandraTA — 「モデルが既に正解している例」を捨てるだけで、term accuracy が 78.7% → 89.9%

**topic:** fm_distill_finetune (P2) / **project:** P2
**hf_upvotes:** 0 / **公開:** 2026-09-09T10:25:05Z
**スコア:** **P2 4.5** / P1 1.0 / P3 1.0 — **本日いちばん安く試せる**

## 何を解決する論文か

terminology-aware translation (用語集に従った翻訳) は、**正しく訳すだけでなく、glossary (用語集) が指定した通りの訳語を使うことを要求する。**標準的な recipe は、用語集を注釈した対訳ペアで fine-tuning することである。

**著者はこの標準 recipe の中に、無駄が隠れていると指摘する: 大半の例では、用語集が指定する訳語は、モデルが放っておいても出す訳語と一致している。**そういう例は **「用語集に従う」ことを何も教えていない。**訓練データの体積を食っているだけである。

**だから、モデル自身の訳が用語集と食い違う例だけを残す。**

## 手法の核心

- **選別基準はきわめて単純: fine-tuning 対象のモデルに自分で訳させ、その訳が glossary の指定と矛盾する例だけを残す。**一致した例は捨てる。**難しい例だけが教師になる (Hard Examples Are Better Teachers)。**
- **効果の測り方が良い: データ量を固定した controlled study。**量を減らして良くなったのではなく、**同じ量なら選別したほうが良い**ことを示している。**term accuracy 78.7% → 89.9% (+11.2 ポイント)。選別以外は何も変えていない。**
- データは **two-way synthetic pipeline** (open model を使い双方向に合成する生成手順) で構築され、公開モデル **SalamandraTA-7b-instruct v3.0** の instruction-tuning mixture に組み込まれている。
- **WMT26 Terminology Shared Task の公式評価で、term success 94.2% / chrF++ 74.6** (chrF++ は文字 n-gram ベースの翻訳品質スコア)。22 件の提出のうち**両方の指標で上回ったのは 2 件だけ。**
- **前年ベンチマークでは、著者ら自身の GRPO ベースのシステムを上回った。**GRPO (Group Relative Policy Optimization; PPO を簡略化した強化学習手法で、LLM の後学習に使われる) を使わず、**普通の supervised fine-tuning だけで、である。**

## 追っているプロジェクトへの適用可能性

### (1) P2 に対する含意 —— 「データを増やす」より前に「効かない例を捨てる」

P2 の関心は蒸留と適合を**実務で回せるか**にある。**この論文が提示しているのは、追加コストがほぼゼロの前処理 1 段である。**

> **fine-tuning 前のモデルに推論させ、既に正解している例を訓練セットから落とす。**

**必要なのは推論 1 パスと比較 1 回だけ。**新しい loss も、追加のモデルも、RL も要らない。**そして +11 ポイントは、loss をいじって出る幅ではない。**

**この一般形は「学習信号のない例を除く」であり、翻訳と用語集に固有ではない。**分類なら「既に正しいクラスを出している例」、回帰なら「既に誤差が閾値以下の例」、蒸留なら **「student が既に teacher と一致している例」** に対応する。

### (2) 本日の [OnPoKD](2609.10321.md) と正確に対になっている

**OnPoKD は「サンプルごとに教師信号の作り方を変える」。SalamandraTA は「サンプルを捨てるか残すかだけを決める」。**両者は同じ問題 —— **サンプルによって教える価値が違う** —— に対する、連続版と二値版の答えである。

**実務上の順序は明らかで、まず二値版を試すべきである。**controller の学習は要らず、実装は数十行で、効かなければ即座に分かる。

### 試すべき実験

1. **P2 の既存の fine-tuning データに対し、ベースモデルの推論を 1 回流して「既に正解の例」を数える。****この件数を数えるだけで、この手法の上限が分かる** —— 8 割が既に正解なら伸びしろは大きく、2 割ならほとんど無い。**この 1 ステップは、学習を 1 回も回さずに済む。**
2. **データ量を固定して比較する。**選別後のデータ量 N に合わせ、**無選別からランダムに N 件**を抜いた対照群を必ず作ること。**これをやらないと「量を減らしたら良くなった」という別の現象と区別できない。**本論文の説得力はこの対照設計から来ている。
3. **蒸留への転用版: student が既に teacher と一致しているサンプルを落とす。**残るのは capacity gap (teacher と student の能力差) が実際に現れている領域だけになる。**P2 の capacity gap 対策として、これは筋が良い。**

## 注意点

- **shared task の system description paper であり、機構の説明より結果の報告に重点がある。**なぜ効くかの分析は薄い。
- **「モデル自身が間違える例だけを残す」は、noisy label があると壊れる。**ラベルが間違っている例も「モデルの出力と矛盾する例」として残ってしまう。**用語集という信頼できる正解が存在する設定だから成立している。**自分のデータに正解の信頼性がない場合は、そのまま持ってこないこと。
