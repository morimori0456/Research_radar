# OnPoKD — 蒸留の「教師信号の作り方」自体を、サンプルごとに学習される決定にする

**topic:** fm_distill_finetune (P2) / **project:** P2
**hf_upvotes:** 0 / **公開:** 2026-09-09T15:26:28Z
**スコア:** **P2 5.0** / P1 1.0 / P3 2.0

## 何を解決する論文か

vision-language model (VLM; 画像とテキストを同じ空間で扱うモデル。CLIP 系が典型) を、あるタスクに適合させた teacher から小さい student へ蒸留する —— これは実務でよく回す手順である。**ところが既存手法は、teacher の予測から作った蒸留ターゲットを、全サンプルに一律に適用する。**

**この一律さが、class shift や domain shift (学習時と適用先でクラス分布やドメインが変わること) の下で壊れる。**teacher 自身が自信を持てないサンプルでも、teacher の予測が同じ重みで student に押し付けられるからである。

**OnPoKD の主張: 蒸留ターゲットの構成は、固定の recipe ではなく、学習中に動的に下す決定として扱うべきである。**

## 手法の核心

- **on-policy distillation を VLM 適合に持ち込んだ最初の枠組み**と著者は主張する。**on-policy とは、固定のデータ分布ではなく、いま学習中の student が実際に生成・遭遇する分布の上で教師信号を作ること。**off-policy (teacher が事前に作った固定ターゲット) との対比。
- **軽量な controller (制御器) を別に学習し、サンプルごとに蒸留ターゲットを組み立てさせる。**controller が見る手がかりは 3 つ: **teacher の reliability (その予測がどれだけ信頼できるか)、teacher と student の disagreement (予測の食い違い)、zero-shot prior (fine-tuning 前の元の VLM が何と言うか)。**
- **controller の行動は bounded policy action** (出力範囲が制限された行動) で、**① teacher の教師信号、② zero-shot prior による誘導、③ hard label (正解ラベルそのもの) への固定 —— この 3 者の配合比を動的に決める。**サンプルの信頼度と学習ステージに応じて配合が変わる。
- **controller の更新は validation feedback で行う。**ここが効き所で、**訓練分布へのフィット (train loss) ではなく transferability (未知ドメインへの転移性能) を最適化するように、ターゲット構成が押される。**
- **controller は訓練時のみ使う。**推論時のアーキテクチャも計算コストも元のまま。**既存の蒸留パイプラインに差し込める。**
- 評価は **base-to-novel generalization** (学習で見たクラスから未見クラスへ) と **cross-dataset transfer** (別データセットへ)。強い蒸留ベースラインに対し一貫して改善。

## 追っているプロジェクトへの適用可能性

### (1) P2 の核心論点そのもの —— 「低品質データでの蒸留」は現場の標準状況である

P2 は foundation model の蒸留と他機種・他ドメインへの適合を扱う。**現場のデータは、この論文が想定する「low-quality multimodal data」そのものである** —— ラベルが揺れ、ドメインがずれ、teacher が自信を持てないサンプルが混じる。

**既存の蒸留で「teacher の予測を全部信じる」設計にしているなら、この論文の指摘は直接効く。**

### (2) controller を入れずに、まず 3 者配合を固定比で試す

**controller の学習は実装コストが高い。だが本論文の価値の相当部分は、controller の前段にある観察のほうにある** ——

> **蒸留ターゲットは、teacher 予測・zero-shot prior・hard label の 3 者の配合である。**

**この 3 者を明示的に分けるだけで、既存パイプラインに 1 つ noticeable な自由度が増える。**とくに **zero-shot prior を第 3 の教師として残す**という発想は、実装 5 行でできる。**fine-tuning した teacher がドメインシフトで壊れているとき、fine-tuning 前のモデルのほうが正しいことがある** —— これは実務で誰もが経験しているが、loss には書かれていない。

### 試すべき実験

1. **固定比のグリッド。** target = α·teacher + β·zero-shot + γ·hard, α+β+γ=1 で、**(1,0,0) [= 通常の蒸留]、(0.7,0,0.3)、(0.5,0.3,0.2) の 3 点だけ**を回す。**controller を学習しなくても、zero-shot prior を混ぜる効果があるかないかはここで分かる。**無ければ以降は追わなくてよい。
2. **disagreement でサンプルを層別する。**teacher と student の予測が食い違うサンプル群と一致する群に分け、**各群で最適な配合比が違うかを見る。**違えば「配合をサンプルごとに変える」という本論文の前提が自分のデータでも成り立つ、という確認になる。
3. **validation feedback で選ぶ。**controller の学習まで行かなくても、**上のグリッドを train loss ではなく held-out ドメインの精度で選ぶ**だけで、本論文の狙いの半分は取れる。

**本日の wildcard [NeoHorse-1](2609.08183.md) も "routing-guided on-policy distillation" を使っており、独立に同じ方向を向いている。**片方は VLM の適合、片方は LLM エージェントの post-training で、**分野が違うのに「教師信号を固定 recipe から動的決定に変える」という同じ形をしている。**2 本同時に来たのは偶然としては強い。

## 注意点

- **validation feedback で controller を更新する = validation set に対する過適合の経路が開く。**論文は transferability の改善で示しているが、**自分で回すときは controller 更新用と最終報告用の held-out を分けること。**
- ベンチマークは base-to-novel と cross-dataset で、**いずれも学術データセット間の転移である。**実機・実運用のドメインギャップとは質が違う可能性がある。
