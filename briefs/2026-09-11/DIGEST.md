```
1. いま手元にある fine-tuning / 蒸留データを 1 つ選ぶ
2. fine-tuning 前のモデルで、その全件 (多ければ 500 件でよい) を推論する
3. 「モデルの出力が既に正解と一致している件数 / 全件」を出す

判定:
  8 割が既に正解  → 選別で大きく伸びる。本命として追う
  5 割前後        → 試す価値あり
  2 割以下        → この手法は効かない。以降追わない
```

**論文の実測は、この選別だけで term accuracy 78.7% → 89.9% (データ量は固定)。**新しい loss も RL も追加モデルも要らない。

## 今日読むべき TOP3

### 1. [DRiF — 危険度を「絶対値」ではなく「どちらが危ないかの順序」で学ばせる](2609.10377.md) (P1 4.5 / P3 5.0)

**この論文は R1 の指標設計が抱えている一番大きな弱点に、そのまま使える型を渡してくる。**

いま構想している solvability (その状況で自車に残っている逃げ道の本数) は**絶対量として定義されている。**絶対量で定義すると、「1 本と 2 本の差は等間隔か」「そもそも数え方は妥当か」という反論を全部自分で背負う。**DRiF が自動運転の危険度に対してやったのは、その反論を回避する操作である —— 手作りの危険度スコアの絶対値は信用せず、「A と B のどちらが危ないか」という順序だけを教師にする。**係数も閾値も、順序を取る操作でほとんど落ちる。

**planner を並べたいのであって、危険度に物理単位を与えたいわけではない。だとすれば順序で足りる。**これは弱い主張に見えて、**査読で最も攻撃されにくい形をしている。**Bench2Drive (CARLA 上の closed-loop 評価環境。自車の出力が次の状況を実際に変える設定) で driving score と衝突系メトリクスが一貫して改善しており、code も公開予定。

> **貼れる形にしておく。solvability の定義文を、下の 1 行に置き換えるところから始められる:**
> **「solvability(A) > solvability(B) ⟺ A で取れる衝突回避軌道の集合が、B のそれを真に含む」**
> **この 1 文で閾値も係数も消える。そして順序が付かないペア (どちらも他方を含まない) が必ず出てくる —— そこが本当の研究課題であり、figure 1 の題材である。**

### 2. [OnPoKD — 蒸留の「教師信号の作り方」自体を、サンプルごとの決定にする](2609.10321.md) (P2 5.0)

**既存の蒸留は、teacher の予測から作ったターゲットを全サンプルに一律に適用している。**ドメインがずれると、teacher が自信を持てないサンプルでも同じ重みで student に押し付けられる。**OnPoKD は、ターゲットの作り方を「固定の recipe」から「学習中に下す決定」に変えた。**

**ただし、この論文から今日持ち帰るべきは controller の学習ではなく、その手前にある分解のほうである:**

> **蒸留ターゲットは、① teacher の予測、② zero-shot prior (fine-tuning 前の元のモデルの出力)、③ hard label (正解そのもの) の 3 者の配合である。**

**この 3 つを明示的に分けるだけで、既存パイプラインに自由度が 1 つ増える。**とくに **② を第 3 の教師として残す**発想は実装 5 行で試せる。**fine-tuning した teacher がドメインシフトで壊れているとき、fine-tuning 前のほうが正しいことがある**という現場の経験は、たいてい loss に書かれていない。**controller を作る前に、固定比を 3 点だけ回せば効くか効かないかは分かる。**

### 3. [SalamandraTA — 「既に正解している例」を捨てるだけで +11 ポイント](2609.09999.md) (P2 4.5)

**本日いちばん安い。**用語集に従う翻訳で、**モデル自身の訳が用語集と食い違う例だけを残す**という選別を入れたら、**データ量を固定したまま term accuracy が 78.7% → 89.9%。**選別以外は何も変えていない。前年ベンチマークでは、著者ら自身の GRPO (Group Relative Policy Optimization; PPO を簡略化した強化学習手法で LLM の後学習に使う) を使ったシステムも、**普通の supervised fine-tuning だけで上回った。**

**一般形は「学習信号のない例を除く」で、翻訳に固有ではない。**蒸留なら「student が既に teacher と一致している例を落とす」に対応し、**残るのは capacity gap (teacher と student の能力差) が実際に現れている領域だけになる。**

**実験設計で 1 点だけ守ること: 選別後のデータ量 N に合わせて、無選別からランダムに N 件抜いた対照群を必ず作る。**これが無いと「量を減らしたら良くなった」という別の現象と区別できない。**本論文の説得力は、この対照設計から来ている。**→ **手順はこのページ冒頭の「貼るもの ②」に、コピーできる形で置いた。**

### P3 (次世代アーキテクチャ) —— 「学習させる部分を減らす」設計が 2 本

[Programmable World Model](2609.10540.md) の判断は明快で、**world state の更新を生成モデルから引き剥がし、決定的なプログラムに任せる。**生成モデルは状態を絵にする renderer に降格する。**CombatStateBench で Count Accuracy 94% / State Accuracy 98%。**

**運転に引き直すと効き所が見える:** 車両運動学・交通規則・車線の接続は**決定的に書ける。**書けないのは**他車の意図とその多峰性**だけである。**「全部を 1 本の生成モデルに predict させる」設計は、書けるものまで学習で当てさせている。**

**そして [DRiF](2609.10377.md) も、方向としては同じである** —— 手作りの safety prior を捨てるのではなく、**その順序情報だけを学習に渡す。****「学習させる部分を減らし、書ける構造は書く」が、本日の P3 側の共通形である。**

**R1 との接続が 1 本引ける:** 09-10 の [PlannerForge](../2026-09-10/2609.08965.md) が示した **「生成された safety-critical シナリオの過半が物理的に妥当でない」**は、まさに**状態遷移を生成モデルに任せた帰結**である。**Programmable World Model の答えを合わせると、R1 の立場が 1 文で書ける:**

> **シナリオ生成の妥当性は、生成後に検査して担保するのではなく、状態遷移を決定的にすることで構成的に保証すべきである。**

**なお本日、規則どおりのタイブレークで [MotionBlind](rejected.md) (Video-LLM は速度・方向を読めないという反証ベンチマーク、スコア 4.0) が hf_upvotes 0 対 59 で落ちた。****反証論文は構造的に upvote が付きにくいので、この偏りは毎回同じ向きに出る。**次に `topics.yaml` を触るとき、**「同点時は negative result を優先する」の 1 行**も併せて入れること。
