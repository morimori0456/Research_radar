# MomADv2: Reliable Temporal Memory for End-to-End Autonomous Driving

- arXiv: https://arxiv.org/abs/2608.23405
- topic: **next_arch** (P3) / hf_upvotes **0**
- 公開日: 2026-08-24 (Mon)
- relevance: P3 **5.0** / P1 **4.5** / P2 **0.5**
- 著者: Ziying Song, Shengkai Zhang, Lin Liu, Peiliang Wu, Lei Yang

## 何を解決する論文か

**end-to-end autonomous driving (センサ入力から走行軌跡までを 1 つのネットワークで出す方式) で long-horizon planning (数秒先まで一貫した計画を立てること) を成立させるには、過去の計画を記憶として引き継ぐ必要がある。**しかしこの temporal memory (時間方向の記憶) には既知の失敗モードがある — **driving command (「直進」「右折」といった上位の指示) が切り替わった瞬間、それ以前の記憶は現在の意図と矛盾するのに、モデルはそれを引き継いでしまう。**記憶が助けになるどころか判断を誤らせる。

MomADv2 は、**「使える履歴だけを選び、command と矛盾する記憶を抑える」**ことを明示的な機構として実装した end-to-end planner である。closed-loop の NAVSIM / Bench2Drive、open-loop の nuScenes で評価し、**6 秒先までの planning において前身 MomAD 比で平均衝突率を 15.6% 削減**したと報告している。

## 手法の核心

- **Selective State-Space Planning Memory Query Module が中核。**過去の planning query (過去時刻の計画を表す内部ベクトル) を貯めておき、**temporal continuity (時間的な連続性) と command consistency (現在の指示との整合性) の 2 基準で濾す。**通ったものだけが現在の判断に参加する。「記憶を持つか否か」ではなく「**記憶をどう捨てるか**」を設計対象にした点が新しい。

- **selective state-space mechanism で意図の時間発展を表す。** **SSM (State Space Model; 系列を隠れ状態の逐次更新で表す構造。attention と違い系列長に対して線形計算量)** の、**selective 版 (Mamba 系。入力に応じて「今の入力をどれだけ状態に取り込むか」を動的に変える)** を使う。**この選択性が「command が変わったら過去を流す」という要求と機能的に一致している**のが設計上の要点で、SSM を単に効率のために使っているのではない。

- **Flow-Matching Trajectory Residual Refiner で軌跡を後段補正する。** **flow matching (ノイズから目標分布への連続的な変換の速度場を学習する生成手法。diffusion の近縁だが決定的な ODE で速い)** を使い、**粗い計画出力から expert trajectory (人間の運転軌跡) への residual correction field (残差の補正場)** を学習する。

- **anchor-based planning の安定性を壊さない設計。** anchor-based (あらかじめ用意した軌跡候補の集合から選ぶ / それを基準に微修正する方式) は安定だが粒度が粗い。**residual refiner は anchor を置き換えず上に足すため、安定性を保ったまま局所的な逸脱と error accumulation (誤差が時間方向に積み上がる現象) を抑える。**

- **評価設計が真っ当。**closed-loop 2 種 + open-loop 1 種で、**主要な主張を「衝突率」という安全側の指標で述べている。**軌跡誤差ではなく衝突率で語っている点は、planner 評価としては good practice。

## 読むときの但し書き

- **15.6% は前身 MomAD 比の相対改善であり、絶対衝突率がいくつかは abstract にない。**ベースが高ければ改善幅の意味は変わる。
- **2 つの貢献 (memory module と residual refiner) の寄与配分が不明。**ablation を本文で必ず確認すべき箇所。refiner だけで大半を説明できる可能性は十分ある。
- **「command が変わる」シーンの評価セット内比率が書かれていない。**この機構が効くのは command 切替の前後だけなので、**その比率が低ければ平均指標での改善は別要因かもしれない。**
- **6 秒という horizon の選び方に根拠が示されていない。**horizon を伸ばしたときに改善が持続するか劣化するかは、long-horizon を名乗る以上いちばん知りたいところ。

## P1/P2/P3 への適用可能性

### P3 (次世代アーキテクチャ) — 本日の最重要。E2E 構造の設計判断がそのまま載っている

topics.yaml の P3 が最高優先に置く「最新の end-to-end 自動運転アーキテクチャ」に真正面から当たる。**持ち帰りは 3 点。**

1. **memory は「持つ」より「捨てる」を設計する。**history を全部食わせて attention に選ばせるのではなく、**明示的な妥当性基準 (継続性・指示整合性) でゲートする。**これは可解釈性の面でも効く — なぜその記憶を使ったかが後から言える。
2. **SSM を効率の道具ではなく「選択の道具」として使う。**selective SSM の入力依存ゲートは、**上位指示が変わったら状態をリセットする**という要求に構造的に合致している。SSM 採用の動機として、計算量以外の理由が具体例として示された点に価値がある。
3. **粗い離散選択 (anchor) + 連続残差補正 (flow matching) の二段構え。**これは driving に限らず **VLA (Vision-Language-Action; 画像と言語から行動を直接出力するモデル) の action decoder にもそのまま移せる形をしている。**離散 anchor の安定性と連続出力の精度を両取りする定石として登録しておく価値がある。

### P1 (Planner AI + 評価) — 評価側の材料としても強い

**「command 切替の前後」という、評価を切り分けるべき軸を明示してくれた点が P1 への貢献である。**平均衝突率という単一の数字は、この種の状況依存の失敗を薄めてしまう。**評価セットを command 切替の有無で層別し、層ごとに指標を出す**という設計は、今日から自分の評価に足せる。

## 試すべき実験アイデア

1. **command 切替シーンで層別評価する (半日、モデル学習不要)。**
   手持ちの評価ログを **command 切替の前後 N 秒**とそれ以外に分割し、既存 planner の衝突率・逸脱量を層別に出す。**MomADv2 が解いた問題が、自分の系でも実在するかを先に確かめる。**実在しなければこの論文の機構は不要で、それが分かるだけで得。**学習を 1 回も回さずに済むのが最大の利点。**

2. **memory gating の ablation を自前で組む (2〜3 日)。**
   既存の temporal memory を持つ planner に対し、(a) gating なし、(b) 時間的連続性のみで濾す、(c) 連続性 + command 整合性、の 3 系列を比較する。**論文の 2 貢献のうち memory 側だけを切り出して検証する**のが狙いで、refiner の実装コストを払わずに主張の核を試せる。

3. **anchor + flow-matching residual を VLA の action decoder に移植する (1 週間、P3 の R3 に直結)。**
   driving を離れ、**離散 anchor 選択 + 連続残差**の二段構えが manipulation 系の action 出力でも効くかを見る。**この論文の中で最も分野を越えて持ち運べる部品はここである。**

**優先は 1 → 2 → 3。**1 は半日で終わり、2 と 3 をやる価値があるかどうかを決める。
