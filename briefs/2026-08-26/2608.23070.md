# From Generation to Simulation: How Far Are World Models from Being True Simulators?

- arXiv: https://arxiv.org/abs/2608.23070
- topic: **next_arch** (P3) / hf_upvotes **2**
- 公開日: 2026-08-24 (Mon)
- relevance: P3 **4.5** / P1 **4.0** / P2 **0.5**
- 著者: Tong Wang, Huan Deng, Mucheng Yang, Yang He, Xiaohui Kuang
- Project page: https://github.com/AtongWang/world-model-simulators

## 何を解決する論文か

diffusion model と大規模 video generation の進展を受けて、**generative world model (映像を生成しながら世界の振る舞いを模す学習モデル) が従来の simulator — physics engine、game engine、RL 環境 — を置き換える**という期待が広がっている。**しかし「あとどれだけ足りないのか」を体系的に測った仕事がなかった。**

本論文は **traditional simulator が備える 8 つの capability を外部の物差し (external yardstick) として固定し、2018〜2026 年 6 月の代表的な 200 本を、その物差しの上に配置する。**結果として、world model は一部の能力では既に置き換えに達している一方、**物理法則の保証・構造化された状態の読み出し・長時間の再現可能な発展**では明確に届いていないことを示す。**サーベイだが、主張は「地図を引いた」ことではなく「どの能力が体系的に欠けているか」を数で特定したことにある。**

## 手法の核心

- **評価軸を world model 側の内部指標ではなく simulator 側から取る。** 8 capability は **asset construction (シーンや物体を組み立てられるか)、physics engine (物理法則に従うか)、interaction (働きかけに応答するか)、controllability (指示どおりに動かせるか)、stability (長時間破綻しないか)、state feedback (内部状態を問い合わせられるか)、diversity (多様な状況を作れるか)、evaluation metrics (評価手段が備わっているか)**。**「生成品質が高い」という自己申告的な指標を意図的に外している**のが設計の肝。

- **技術系統を 3 つに整理して横断比較する。** **latent dynamics (観測を潜在空間に落として、その中で時間発展を学習する系統。Dreamer 系)**、**video generation (次フレームの画素を直接生成する系統)**、**JEPA (Joint Embedding Predictive Architecture; 画素を再構成せず、埋め込み空間での予測だけを学習する系統)** の 3 route。

- **200 本を能力 × 系統のマトリクスに配置する。**個別手法の優劣ではなく **route ごとにどの能力が構造的に欠けるか**を見る作りになっている。

- **最も鋭い数字は state feedback。** **implementation 論文 163 本のうち、実行時に entity の状態や物理パラメータを問い合わせられる interface を持つものは 6 本だけ。**つまり世界モデルの大半は、**中で何が起きているかを外から読めない**。従来 simulator なら当然ある機能が、系統を問わず抜け落ちている。

- **提示される 6 つの研究方向:** formalized physics (物理の形式的保証)、unified action interface (統一された行動入力)、first-class state feedback (状態読み出しを一級市民に)、long-horizon stability、downstream-utility evaluation (下流タスクでの有用性による評価)、cross-route hybridization (系統の混成)。

## 読むときの但し書き

- **サーベイであり、新手法も新実測もない。**8 capability の割り付けは著者の判断であり、境界事例の分類は再現性が担保されていない可能性がある。
- **「6/163」は強い数字だが、定義依存である。**何をもって runtime interface とみなすかで数は動く。**それでも桁が変わるほどではない**というのが主張の趣旨だと読むべき。
- **2026 年 6 月までのカバレッジ**なので、直近 2 ヶ月分は入っていない。今日採用した GeoWAM や MomADv2 は当然含まれない。

## P1/P2/P3 への適用可能性

### P1 (Planner AI + 評価) — 「world model を closed-loop sim に使えるか」への直答

**この論文の最大の実務的価値は、P1 にとって否定側の証拠として使えることである。**closed-loop simulation を生成モデルで置き換えたいという発想は自然だが、**planner の評価に本当に必要なのは映像の見栄えではなく、(a) 物理的に妥当な帰結、(b) 衝突・逸脱といった状態を数値で読み出せること、(c) 同じ入力で同じ結果が出る再現性の 3 つ**である。本論文は **(a)(b)(c) がまさに world model の弱点だと名指ししている。**

**特に (b) の state feedback は致命的で、6/163 という数字がそのまま「衝突率を計算できる生成 simulator はほぼ存在しない」を意味する。**衝突判定を映像から目視ないし検出器で推定するしかないなら、それは評価環境として使えない。**「世界モデルで評価環境を作る」という選択肢を、今の段階で退ける根拠として引用できる。**

裏を返せば **P1 側の設計指針も出る — 生成 simulator を採るなら、まず state feedback interface を自分で足すことが前提条件になる。**映像品質の改善は後回しでよい。

### P3 (次世代アーキテクチャ) — world model 設計のチェックリストとして常備する

**8 capability はそのまま自分の world model 設計のレビュー項目として使える。**特に本日同時に採用した GeoWAM と読み合わせると示唆が明快になる — **GeoWAM が pixel から geometry へ state space を移したのは、まさに本論文が指摘する state feedback / physics の弱さに構造で答えた例**とみなせる。geometry は画素と違って**そのまま問い合わせ可能な状態**である。**2 本を並べると「予測対象を下流が読める表現にせよ」という同じ結論に収束する。**

また 3 route の整理 (latent dynamics / video generation / JEPA) は、**P3 の R3 (VLA × world model の分類マップ) の骨格としてそのまま流用できる。**分類軸をゼロから作る手間が省ける。

### P2 (FM 蒸留 + 適合) — 該当なし

## 試すべき実験アイデア

1. **自分の用途に対して 8 capability の要求水準を書き下す (2 時間、実装ゼロ)。**
   8 軸それぞれについて「P1 の closed-loop 評価に必須 / あると良い / 不要」を 3 段階で埋める。**埋めた結果、必須が state feedback と stability と physics に集中するはずで、そこが世界モデルの最弱点である以上、結論は自動的に出る。**この 2 時間で「世界モデルを評価環境にする」という選択肢の是非が決着する。**実験着手が滞っている現状において、90 分ブロックを必要としない数少ない前進である。**

2. **既存の driving world model 1 本に state feedback を後付けできるか試す (2〜3 日)。**
   公開実装を 1 つ選び、**生成された未来フレームから ego と他車の状態を読み出す probe (小さな回帰ヘッド) を潜在表現に付ける。**衝突判定に足る精度が出るかを見る。出れば「6/163 の欠落は原理的でなく実装の怠慢」という仮説が立ち、出なければ 1 の結論が補強される。**どちらに転んでも情報が残る形になっている。**

3. **3 route の分類マップを 20 本規模で自作する (1 日、R3 の着手)。**
   200 本は多すぎるので、**自分の関心 (driving + manipulation) に絞って 20 本を 3 route × 8 capability に配置する。**本論文の project page が既に土台を公開しているため、**ゼロから作るのではなく差分を埋める作業になる。**R3 は着手ゼロが続いているが、この形なら 1 日で最初の版が立つ。

**優先は 1 → 3 → 2。**1 だけは今日中に終わる。
