# GeoWAM: Visual Geometry World Action Models for Autonomous Driving

- arXiv: https://arxiv.org/abs/2608.23486
- topic: **planner_ai** (P1) / hf_upvotes **0**
- 公開日: 2026-08-24 (Mon)
- relevance: P1 **4.5** / P3 **4.5** / P2 **1.0**
- 著者: Yiren Lu, Xin Ye, Jiaming Liu, Jin Yao, Yi-chung Chen

## 何を解決する論文か

**WAM (World Action Model; 「次に世界がどうなるか」の予測と「自車が次に何をするか」の行動出力を 1 つのモデルで同時に学習する枠組み)** の主流実装は、**video generation backbone (動画生成モデル。次フレームの画像を作る) で未来の観測を予測し、そこに action head (行動出力の枝) を足す**形をとる。つまり世界の状態を **pixel 空間**で表現している。

本論文の主張は、**pixel は driving の状態表現として間接的すぎる**というものである。画像は geometry (空間構造) と motion (動き) を、appearance・texture・illumination (見た目・質感・照明) と混ぜて持っているため、モデルは 2 次元の観測から 3 次元の変換を毎回推論し直す羽目になる。**そこで GeoWAM は、未来の画像ではなく未来の scene geometry (point cloud で表した空間構造) を予測する事前学習目標に置き換える。**open-loop / closed-loop の双方の評価で、image ベースの WAM より明確に強い driving policy が得られたと報告している。

## 手法の核心

- **state space を pixel から geometry へ移す。**「driving の action は 3 次元空間の中で実行されるのだから、状態も 3 次元空間で持つべき」という一貫した立場をとる。point cloud は rigid transformation (剛体変換; 物体が形を変えずに動く) と non-rigid transformation (非剛体変換; 形そのものが変わる動き) の双方を明示的に表現できる、というのが選定理由。

- **pretraining objective は「future geometry prediction」。**未来フレームの画像を作るのではなく、未来の scene geometry を予測させる。この 1 点が論文の中核であり、得られる表現は空間構造と時間発展の両方を同時に符号化する、と主張している。

- **action head は geometry-conditioned。**学習済みの geometric dynamics を条件として受け取り、未来の ego trajectory (自車の走行軌跡) を出力する。表現学習と行動出力が同じ空間で繋がる設計。

- **評価は open-loop と closed-loop の両方。**open-loop (記録済みログに対する予測精度の評価) だけでなく closed-loop (自車の出力が次の観測を変える条件下での評価) でも比較している点は、planner 評価としては最低限の作法を満たしている。

- **結論の形は「アーキテクチャの勝ち」ではなく「pretraining objective の勝ち」。**同じ枠組みの中で予測対象を pixel → geometry に差し替えたときの差分を主張しており、**目的関数の選択が表現の質を決める**という読み方をすべき論文である。

## 読むときの但し書き

- **point cloud をどこから得ているかが abstract から読めない。**LiDAR 実測なのか、画像からの depth 推定 (monocular depth / stereo) なのかで、話の実務的な意味は全く変わる。「visual geometry」という語からは画像由来の geometry を指している可能性が高いが、確認が必要。
- **「substantially stronger」の中身が数値で書かれていない。**どのベンチマークの、どの指標で、どれだけかは本文待ち。
- **geometry 予測は appearance を捨てる。**信号機の色、ブレーキランプ、路面標示など **appearance にしか存在しない情報**は原理的に落ちる。この論文がそこをどう扱っているか (捨てているのか、別経路で入れているのか) は、実用性の分かれ目になる。

## P1/P2/P3 への適用可能性

### P1 (Planner AI + 評価) — 本命。ただし「評価の解釈」の方に効く

**直接効くのは planner の学習そのものより、planner を比較するときの前提の方である。**本論文が示したのは「**同じアーキテクチャ・同じデータでも、pretraining objective を変えるだけで closed-loop 性能が大きく動く**」という事実で、これは planner のベンチマーク比較において **backbone の事前学習条件を揃えないと比較が成立しない**ことを意味する。異なる論文の planner を open-loop 指標だけで並べる比較は、この差分を素通りしてしまう。

もう一点、**open-loop と closed-loop の両方で改善したと報告している**のは注目に値する。この 2 つは乖離することが知られており (open-loop の軌跡誤差が小さくても closed-loop で破綻する例は多い)、**両方が同方向に動いた要因が何だったかは、評価指標の設計を考えるうえで直接の材料になる。**

### P3 (次世代アーキテクチャ) — world model の設計判断として最重要級

topics.yaml の P3 は world model と end-to-end driving を最高優先に置いており、本論文はその交点にある。**持ち帰るべき一般命題は「world model の予測対象は、下流タスクの action が実行される空間に合わせろ」**である。driving なら 3 次元 geometry、manipulation なら物体の pose や接触状態、という具合に読み替えられる。**video generation を world model の既定解とみなす風潮に対する、具体的な反例として使える。**

### P2 (FM 蒸留 + 適合) — 弱い

事前学習目標の話であり、蒸留や少データ適合とは直接繋がらない。強いて言えば「geometry 予測で得た表現は、image 表現より下流適合が効率的か」は問いとして立つが、本論文は主張していない。

## 試すべき実験アイデア

1. **予測対象だけを差し替える ablation を最小構成で再現する (1〜2 日)。**
   手持ちの軌跡予測モデルの backbone を、(a) 未来画像予測、(b) 未来 depth / point cloud 予測、の 2 通りで事前学習し、**下流の trajectory head は完全に同一にして**比較する。見るのは絶対性能ではなく **(a) と (b) の差の符号と大きさ**だけ。論文の主張が自分のデータで再現するかを問う、最も安いテスト。

2. **appearance 依存シーンだけを切り出して負けを探す (半日、上記の後)。**
   信号機・ブレーキランプ・路面標示が判断を支配するシーンを評価セットから抽出し、geometry ベースがそこで image ベースに**負けているか**を見る。**論文が報告していない失敗モードを先に自分で見つけるのが目的**で、勝ちの再現より情報量が大きい。

3. **open-loop / closed-loop の乖離を指標として測る (1 日、P1 の評価設計に直結)。**
   同一モデル群に対し open-loop の軌跡誤差と closed-loop の衝突率を両方測り、**両者の順位相関**を取る。GeoWAM の「両方で勝った」という報告が、**pretraining objective を変えると乖離そのものが縮む**ことを意味するなら、それは planner 評価にとって本論文の最大の収穫になる。

**優先は 1 → 3 → 2。**1 が成立しなければ 3 も 2 も土台を失う。
