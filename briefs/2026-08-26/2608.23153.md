# Conformal Risk Minimization for Semi-Supervised Domain Adaptation via Optimal Transport

- arXiv: https://arxiv.org/abs/2608.23153
- topic: **fm_distill_finetune** (P2) / hf_upvotes **0**
- 公開日: 2026-08-24 (Mon)
- relevance: P2 **4.0** / P1 **2.5** / P3 **0.5**

## 何を解決する論文か

ある集団のデータで学習したモデルを別の集団に配備すると **distribution shift (分布のずれ)** が起き、精度と信頼性の両方が落ちる。**SSDA (Semi-Supervised Domain Adaptation; ラベル豊富な source domain と、ラベルがごく僅かしかない target domain を併用して適合させる設定)** はこの状況の標準的な定式化だが、**既存の SSDA 手法は点予測の精度だけを最適化しており、不確実性の定量化を持たない。**

**CP (Conformal Prediction; 予測を 1 点ではなく「集合」で出し、真の答えがその集合に入る確率を、データ分布に仮定を置かずに保証する統計手法)** を後付けすれば保証は得られる。**しかし後付けの CP は、予測集合が実用に耐えないほど大きくなる。**理由は、SSDA の事前学習が **nonconformity score (「この予測はどれだけ外れっぽいか」を表すスコア。集合の大きさを決める) の幾何**を全く考慮していないため。

**CRM (Conformal Risk Minimization; CP の目的を学習中の目的関数に組み込み、集合が小さくなるようモデル自体を最適化する)** はこれを教師あり設定で解決済みだが、**学習中に nonconformity の閾値を計算するために大量のラベルを要する** — SSDA でまさに欠けているものである。本論文は **OT (Optimal Transport; 2 つの分布の間で「移す総コスト」が最小になる対応付けを求める枠組み) で疑似ラベルを作り、その信号で CRM を少ラベル環境でも回す**ことでこの循環を断つ。

## 手法の核心

- **問題の構造は循環である。**「集合を小さくするには CRM が要る → CRM にはラベルが要る → ラベルがないから SSDA をしている」。**この循環をどこで切るかが本論文の設計判断で、切り口が OT による疑似ラベル生成。**

- **OT で source のラベル付きデータと target の未ラベルデータを対応付け、target 側に疑似ラベルを与える。**単純な信頼度閾値による疑似ラベルと違い、**分布全体の対応として一括で決める**ため、target 側のラベル分布が極端に歪みにくい。

- **CRM を SSDA の目的関数に end-to-end で統合する。**後付けではなく、**domain invariance (ドメインによらない表現を学ぶこと) と conformal efficiency (予測集合の小ささ) を同時に最適化する。**この 2 つが同時に最適化できる、というのが主張の核。

- **得られる予測集合は 3 条件を満たす: compact (小さい)、coverage-valid (被覆保証が有効)、そして domain-specific constraint を反映できる。**論文の例は skin lesion classification (皮膚病変の分類) で、**互いに矛盾する診断が同じ集合に同居しないよう制約を課せる。**「集合で出す」形式が、単なる不確実性表示ではなく**ドメイン知識を注入する場所**にもなっている点は面白い。

## 読むときの但し書き

- **OT 疑似ラベルの品質がそのまま CRM の質を決める。**shift が大きいと OT の対応付け自体が崩れるはずで、**shift の大きさに対する頑健性が本手法の実用範囲を決める。**abstract には条件が書かれていない。
- **評価は healthcare 中心。**画像分類での話であり、回帰や系列予測にそのまま移るかは別問題。
- **CP の被覆保証は exchangeability (データの順序を入れ替えても分布が変わらない性質) を前提とする。**domain shift 下でこの前提がどう扱われているか (target の校正データで取り直しているか等) は、保証の意味を左右する最重要点で、本文で必ず確認すべき。
- **計算コストへの言及がない。**OT は素朴に解くと重い。Sinkhorn 近似等を使っているはずだが規模が不明。

## P1/P2/P3 への適用可能性

### P2 (FM 蒸留 + 適合) — 「少データ適合」の軸に正面から当たる

topics.yaml の P2 は fine-tuning を「**少データでの適合、ドメインギャップの克服**」の観点で評価せよと明記している。**本論文はその設定そのもの**であり、加えて**適合の成否を測る新しい物差しを持ち込む。**

**持ち帰りの核心は、適合の評価軸に「予測集合の大きさ」を足せることである。**通常、ドメイン適合の成否は target 側の精度で測る。**しかし精度は「当たっているか」しか言わず、「どれだけ自信を持てているか」を言わない。**同じ精度でも、予測集合が小さいモデルと大きいモデルでは実務価値が全く違う。**conformal efficiency (集合の平均サイズ) は、この差を分布仮定なしに数値化する。**しかも**追加のラベルなしに計算できる**ので、少データ設定と相性がよい。

**second-order の持ち帰りとして、OT 疑似ラベルは蒸留にも形が移る。**teacher が target ドメインの未ラベルデータに疑似ラベルを振る、というのは蒸留の常套だが、**通常は信頼度でフィルタするだけで、分布としての整合は見ていない。**OT で source-target 間の対応として疑似ラベルを決める発想は、**蒸留における pseudo-label の質を上げる独立の道具**になり得る。

### P1 (Planner AI + 評価) — 間接的だが筋は通る

**planner の評価に conformal な保証を持ち込む、という方向は成立する。**軌跡予測を 1 本の線ではなく**保証付きの領域**として出せれば、planner 側の安全余裕の設計に直接使える。ただし本論文は分類タスクであり、**軌跡のような連続・高次元・時系列の出力に CP を適用するのは別の技術的困難がある** (集合ではなく tube を作る話になる)。**着想として繋がるが、この論文から持ってこられる実装はない。**

### P3 — 該当なし

## 試すべき実験アイデア

1. **既存の適合実験に conformal efficiency を後付けで測る (半日、学習ゼロ)。**
   過去に走らせた domain adaptation の結果があるなら、**そのまま post-hoc CP をかけて予測集合の平均サイズを出す。**論文の主張は「後付けだと集合が大きくなる」なので、**その「大きい」がどれくらいかを自分の系で見ておく。**これが CRM を導入する価値のベースラインになる。**学習を一度も回さずに済み、しかも今後の適合実験すべてに使える指標が 1 本増える。**

2. **CRM の統合を、疑似ラベルなしの縮小版で試す (2 日)。**
   OT の実装は後回しにして、**まず「少数の target ラベルだけで CRM を回す」を試し、どこで壊れるかを見る。**論文の主張は「それだと足りない」なので、**壊れることを確認するのが目的。**壊れ方 (集合が大きいままか、被覆が崩れるか) が分かってから OT を足すと、OT が何を直したのかが説明できる。**貢献の切り分けを自分で再現する形。**

3. **OT 疑似ラベルを蒸留パイプラインに単体で移植する (2〜3 日、本論文の主張の外)。**
   CP を一旦切り離し、**teacher の疑似ラベルを信頼度フィルタから OT ベースに置き換えるとどうなるか**だけを見る。**P2 の蒸留運用に直接効くのはむしろこちらの可能性がある。**評価は student の target 精度と、疑似ラベルのクラス分布の歪み。

**優先は 1 → 3 → 2。**1 は半日、3 は蒸留運用への効き目が大きい。2 は理解のための実験なので後でよい。
