# Projector Is All You Train

- arXiv: https://arxiv.org/abs/2608.19726
- topic: fm_distill_finetune (P2) / relevance **4.5** / hf_upvotes 0

## 何を解決する論文か

MLLM (Multimodal Large Language Model; 画像や 3D 点群などのモダリティ専用 encoder を、projector と呼ばれる小さな変換層で言語モデルに繋いだモデル) を新しいモダリティに対応させるとき、慣習として **backbone (言語モデル本体) と projector の両方を学習する。**

本論文の問いは単純である: **その backbone の学習は本当に必要なのか。** 3D MLLM で検証した答えは「不要」であり、projector だけを学習すれば、同じ encoder / backbone を使った共同学習版にも既存のベースラインにも匹敵する性能が出る。

## 手法の核心

- **projector-only training**: modality encoder も言語モデル backbone も凍結し、その間の projector だけを学習する。手法というより、学習対象の切り分けに関する主張である。
- **共同学習は既存能力を壊す**: backbone を一緒に学習すると、言語モデルが元々持っていた能力に drift (ずれ) が生じる。projector-only は backbone の重みを一切動かさないので、**この drift が定義上ゼロになる。** 「頑張って忘却を抑える」のではなく「忘却しうる経路を消す」構成。
- **学習スループットが約 2 倍**: 勾配を backbone に流さないぶん、同じ時間で倍のサンプルを回せる。
- **主張の一般性を 2 方向で支える**: 複数の言語モデル backbone で再現し、かつ 3D classification / captioning に加えて言語・視覚・空間推論の標準ベンチマークでも測る。後者は「新モダリティが付いた代わりに元の能力が落ちていないか」を測るための評価になっている。

## P1/P2/P3 への適用可能性

**P2 の適合コストを、下限側に押し下げる論文。** 08-21 に整理した「適合の層」で言えば、これは**表現層の適合を、境界面 1 枚だけに閉じ込める**という主張である。fine-tuning でも PEFT/LoRA (Low-Rank Adaptation; 重み更新を低ランク行列に制限して学習する省メモリな適合手法) でもなく、そもそも backbone に触らない。

**実務的な含意が明確に 2 つある。** (1) backbone を凍結しているので、複数モダリティ・複数ドメイン向けの projector を作っても backbone は 1 つで共有でき、デプロイ時の重み管理が単純になる。(2) 新モダリティを足すたびに旧能力の回帰テストをやり直す必要が減る。

**ただし限界も明確に見ておくべきである。** projector-only が成立するのは、backbone が既に持っている表現空間の中に、新モダリティの情報を写せる場所がある場合に限る。3D 点群は言語モデルが既に持つ空間概念に写しやすい側だと考えられる。**新モダリティが backbone の表現空間に対して本当に「新しい」場合 (例: 制御信号や力覚の時系列)、この結論は素直には移らない。** ここは P2 で試すときの最初の検証点になる。

**08-21 との接続**: [GS-VLA](../2026-08-21/2608.19066.md) は観測層で適合し、パラメータ更新ゼロで忘却を回避した。本論文は表現層で同じことを、更新範囲を projector に限定することで実現する。**「安い層から順に埋める」という戦略に、2 日連続で証拠が積まれた形になる。**

### 試すべき実験アイデア

1. **projector-only / LoRA / full fine-tuning の 3 者を、「新タスク性能」「旧能力の保持率」「学習時間」の 3 軸で 1 枚の表に並べる。** 論文は projector-only 対 joint の比較だが、実務の選択肢には LoRA が必ず入る。3 者比較は P2 の意思決定表としてそのまま使える。
2. **モダリティの「backbone からの遠さ」を振って、projector-only が壊れる境界を探す。** 3D 点群 → 深度 → LiDAR → 力覚/制御信号、と遠ざけていく。境界が見えれば、これは R2 (蒸留の capacity gap 系統則) と同じ型の系統則になる —— **capacity gap ではなく「表現空間の距離」を軸にした版。R2 の姉妹実験として設計できる。**
3. **projector の容量を振る。** backbone を凍結した状態で projector だけを太らせたとき、どこで飽和するか。飽和点が「backbone の表現空間に写せる情報量の上限」の代理指標になる。
