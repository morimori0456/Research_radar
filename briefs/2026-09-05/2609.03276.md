## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語を入力に行動を出す汎用方策) が実機に載り始めた結果、**評価そのものが破綻し始めている。**実機評価は人手がかかり、シーンのリセットが必要で、**同じ方策を測り直すと順位が変わり**、しかも得られるのは二値の成功率だけで**「どう下手なのか」が分からない。**

R2S-Eval は 2 つを組み合わせる: **実世界の評価環境に合わせて較正したシミュレータで rollout 動画を作り (real-to-sim calibration)、その動画を VLM に**対で**見せて優劣を判定させ、集約して方策の順位を出す。**さらに「この評価パイプラインが妥当な結論を出しているか」を検証する protocol まで付けている。

## 手法の核心

- **real-to-sim calibration:** 実機の評価設定に合わせてシミュレータを較正し、**繰り返しのハードウェア試行の代わりに rollout 動画を大量生成する。**実機試行の回数そのものを減らすのが狙い。
- **VLM pairwise preference:** 単独の動画に絶対点を付けるのではなく、**2 本を比べてどちらが良いかを答えさせる。**絶対評価より判断が安定するという、reward model 一般で知られる性質をそのまま使っている。
- **pairwise の集約で方策順位を作る。**二値の成功/失敗ではなく、**「実行の質」の差が順位に反映される。**
- **結論の妥当性を測る protocol を同梱:** 「この評価は、従来の実機評価が抱える不安定性を実際に緩和しているか」を検証する手続き。**評価手法の論文が、自分の評価手法を評価する枠組みまで出している点が本論文の性格を決めている。**
- **結果: シミュレーションと実世界の双方で、安定した方策結論・人間の選好との一致・実機作業量の削減・二値成功率では見えない質の差の検出、を報告。**

## P1 / P2 / P3 への適用可能性

**R1 と主張が同型で、しかも領域が違う。****これは 09-04 の PDT / WM-LOCO に続く「同じ形が独立に別領域で出ている」の 3 例目であり、R1 の introduction を最も安く強くする材料である。**

R1 の主張:「衝突率という集約スコアは、状態の余裕を隠す」。
本論文の主張:「成功率という二値指標は、実行の質を隠す。しかも測り直すと順位が変わる。」

**運転・歩行・操作という 3 つの無関係な領域で、同じ形の不満が同時に出ている。**R1 の introduction は **「これは自動運転固有の不満ではない」**と 1 段落で書けるようになった。**査読者が「その分野だけの話では」と言う経路を先に塞げる。**

**さらに実務的に効く点が 1 つある。****「同じ方策を測り直すと順位が変わる」を、本論文は評価手法の欠陥として扱っている。**R1 が 10 月に「solvability は planner の順位を入れ替える」と主張するとき、**まず問われるのは「その入れ替えは再現するのか、seed の揺らぎか」である。**09-04 の PDT が示した two-half / two-seed のゲートと、本論文の安定性 protocol は**同じ穴を別角度から塞ぐ道具**である。**R1 は最初から「順位の安定性」を測って出すべきで、後から言われて足すのでは遅い。**

> **一方、本論文の手法そのものを R1 に取り込むのは薦めない。**VLM に優劣を判定させる方向は、**R1 が目指す「計算できる・読める量」と逆向き**である (VLM の判断は事後的で、なぜそう判定したかが読めない)。**R1 の位置取りは 09-04 に確定した 3 語 —— 「事前に・陽に・読める形で」 —— のままでよい。****本論文は related work で「事後・暗黙・学習された判定」の代表として引く。対立軸として使える。**

P3 は 3.0。real-to-sim 較正した simulator を評価器として使う構図は、R3 の「world model を何のために持つか」の 1 用途 (評価基盤としての world model) だが、今月は軸のメモに留める。

### 試すべき実験アイデア

1. **【30 分・09-06 gate の後すぐ・R1 の書き物】introduction の 1 段落を書く:「集約指標が振る舞いの差を隠す」という同型の指摘が、運転 (PDT)・歩行 (WM-LOCO)・操作 (R2S-Eval) で 2026-09 の 1 週間に独立に出ている。**引用は 3 本揃った。**図がなくても捨てにならない作業である。**
2. **【10 月・実験設計に先回りして入れる】solvability による planner 順位の入れ替えを、データ 2 分割 × seed 2 つで再現するゲートに通す。**PDT の 6 条件と本論文の安定性 protocol の共通部分だけを取ればよい。**「入れ替わった」の主張は、このゲートを通ってから書く。**
3. **【メモ】pairwise 判定の集約という形式は、R1 でも使える。**「場面 A と場面 B、どちらが危ないか」を solvability で順位付けし、**人間の判断とどれだけ一致するか**を測れば、指標の妥当性を人手評価と突き合わせられる。**10 月に人手評価を少量入れる余地として記録しておく。**
