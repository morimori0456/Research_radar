# StyleDrive — 想像した未来が長いほど壊れる、を 3 点で押さえる

**topic:** next_arch (**届いたラベル。内容は planner_ai 本流**) / **project:** P1 / **hf_upvotes:** 0
**スコア:** P1 **4.5** / P2 2.5 / P3 4.0
**著者:** Yuxuan Han, Kunyuan Wu, Liyunong Yang, Zilu Wang, Cansen Jiang ほか / 2026-09-03 公開

## 何を解決する論文か

world model を使った強化学習では、実環境を走らせる代わりに**モデルの中で未来を想像して (imagined rollout) 学習効率を上げる。**しかしこの想像は、**長く回すほど誤差が積み上がって現実から離れる。**

本論文は、driving world model の欠点を 3 つに分解した: **① 長期 rollout の時間的不整合、② 自車と周囲の相互作用のモデル化不足、③ 運転スタイル (慎重/機敏など) の多様性に対応できない。**そして 3 つに 1 つずつ対策を当て、閉ループ benchmark で大きな差を出した。

## 手法の核心

- **temporal consistency regularization:** 過去の latent state (潜在状態; 観測を圧縮した内部表現) を **gated cross-attention** (どの過去情報をどれだけ通すかを学習ゲートで制御する attention) 経由で現在に統合し、長期 rollout の誤差蓄積を抑える。
- **explicit state disentanglement:** 場面の状態を **ego-relevant (自車の判断に効く) と ego-irrelevant (効かない)** に明示的に分離する。**「全部を上手に予測する」のではなく「効くものだけを分けて持つ」**という設計。
- **GRPO (Group Relative Policy Optimization; 1 ステップごとの報酬でなく、まとめて生成した複数軌跡の相対順位で学習する PPO の簡略版。LLM の RL 学習で普及した手法) を運転方策に適用。**軌跡単位の相対 advantage を使うので報酬の分散が小さく、**再学習なしで複数の運転スタイルを出し分けられる。**
- **結果: Bench2Drive (CARLA 上の閉ループ運転 benchmark) で driving score 88.44 (従来の world model 系ベストから +17.08)、success rate 66.82 (+16.58)。**さらに実機の AGV (automated guided vehicle; 工場等で使う自動搬送車) に載せて sim-to-real 転移も確認。

## P1 / P2 / P3 への適用可能性

**R1 にとっての価値は、性能値ではなく「長期 rollout は壊れる」という前提が、また 1 本、独立に補強されたことにある。**

**+17 点という改善幅は、そのまま裏返すと「従来の world model 系はそれだけ壊れていた」という意味である。**R1 の主張の骨は「集約スコアは壊れ方を隠す」だが、**本論文は「壊れ方の原因は 3 つに分解できて、それぞれ別の対策が要る」という形で、隠れていた中身を開けて見せている。**R1 の related work で **「集約スコアの改善余地が二桁ある領域では、指標の弁別力そのものが疑われるべきだ」**と書くための、最も新しい数値根拠になる。

**GRPO による multi-style は、R1 にとって「同点ペアの作り方」の新しい供給源である。**R1 の 10 月の実験は「集約スコアが同じで solvability が違う 2 場面」を集める必要がある。**同じ方策から慎重スタイルと機敏スタイルを再学習なしで出せるなら、driving score が近く挙動が明確に違うペアを、意図的に大量生成できる。**これは実データを漁って偶然の同点を探すより、はるかに速い。

> **R1 の主張に対する反証リスクも同時に読む。**本論文の ② state disentanglement は「ego-relevant な状態だけ分離すれば判断は良くなる」という立場である。**もし disentanglement だけで安全性の差が説明できるなら、solvability という別量は要らない、と言われうる。**先回りの答えは **「分離は方策を良くする操作、solvability は方策を測る操作であり、良くした後にも順位付けは必要」**である。**1 段落で書ける。今週書いておく。**

P3 は 4.0 だが、R3 は今月着手しない方針のため**軸のメモに留める:** 分類マップの軸③(終点か過程か・自己訂正するか) に対し、**「過程を長く保つために過去 latent をゲート付きで混ぜる」という具体的な実装値**を追加。

### 試すべき実験アイデア

1. **【09-06 gate の後・半日】Bench2Drive の公開ログで、driving score が近い 2 方策のペアを取り、各時刻の solvability を重ねる。**本論文が示した通り方策間の差は大きいので、**まず「差が大きいペア」で solvability が確かに割れることを確認してから、同点ペアに進む。**順序を逆にすると、指標が壊れているのか場面が難しいのか切り分けられない。
2. **【1 時間・R1 の書き物】「長期 rollout の誤差蓄積」と「solvability の時間的低下」は同じ現象か、別か。**前者はモデルの予測誤差、後者は状態の余裕。**別物であることを 1 段落で切り分けておく。**混同されると R1 の新規性が消える。
3. **【メモ・R2 と共通】GRPO の「軌跡単位の相対 advantage」は、R2 の候補軸② (clipping で切り捨てられる推論 token) と同じ族の話である。**蒸留と運転で同じ手法が別目的に使われている。**R2 の対照群設計を書くとき、この論文を「同じ道具・別目的」の例として引ける。**
