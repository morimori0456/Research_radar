## 何を解決する論文か

VLA (Vision-Language-Action; 画像と言語から robot の action を出す foundation model) は、課題や robot ごとに fine-tuning が要る。このとき「data と学習 update をどれだけ使うか」「どの checkpoint を採用するか」「simulation の data で実 data を減らせるか」に実務的な答えがない。この論文は、SO-101 arm にチェスの駒 (king) を、マス目の名前 (e4, a5 など) だけを指定して動かさせる課題で、π0.5 (Physical Intelligence の VLA) を fine-tune して、これらを実験的に調べた。

## 手法の核心 (実験から得られた知見)

- 課題: 精密な manipulation と、盤面の空間理解の両方が要る。
- データ: teleoperation (人が遠隔操作した) demonstration と、人間のばらつきを真似した randomized scripted expert の simulation demonstration。
- simulation では、成功率が **data 量にも update 数にも scale する**。
- **learning rate を最後に短く下げる cool-down だけで成功率が最大 31 点上がり、checkpoint の比較には cool-down が必須**。
- **validation loss と action error は checkpoint 選択の指標として信頼できない**。
- 実機では最大 256 demonstration で fine-tune し、10 policy を各 25 trial で評価。暫定結果として、simulation demonstration での pretraining は、特に実 data が少ないときに大きく効く。
- negative result: 自分の rollout を使う filtered behavior cloning、RECAP 型の advantage conditioning、自動 coach による修正、residual RL (既存 policy への補正項だけを RL で学ぶ) のどれも、単純な behavior cloning を測定できる程度には上回らなかった。

## 適用可能性 (P2、P3 にも)

- P2 の「少データでの他機種適合」を扱う実務寄りの報告で、loss の新案ではなく **評価と checkpoint 選択の落とし穴**が価値の中心。
- 運転への接続: 自分の fine-tuning でも validation loss で checkpoint を選んでいるなら、成功率ベースの選択と食い違わないかを確認する理由になる。sim で pretrain してから実 data で適合する流れは、運転 data の少ない domain への適合にも使える。
- 注意: 1 課題・1 robot の case study。実機結果は "partial" と著者自身が書いている。運転や大規模 domain への一般化は言えない。

## 試すべき実験アイデア

1. 手元の fine-tuning の最終部分に LR cool-down を足した場合と足さない場合で、同じ checkpoint の下流成功率を比べる (最小の実験)。
2. 複数 checkpoint について validation loss の順位と下流 metric の順位の相関を測り、loss が選択指標として使えるか確かめる。
3. sim 由来 data で pretrain してから、実 data を 1/4, 1/2, 全量と変えて適合する。実 data の削減余地を見積もる。
