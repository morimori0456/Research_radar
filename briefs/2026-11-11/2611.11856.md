# DeltaForge: A Post-hoc Mixture-of-Experts VLA for Multi-Domain Autonomous Driving (2611.11856)

- トピック: next_arch / プロジェクト: P3 (P2 の適合にも直結) / スコア 4.5
- URL: https://arxiv.org/abs/2611.11856

## 何を解決する論文か

運転 VLA (Vision-Language-Action; 画像と言語から運転出力を得る model) は、運営者ごとに共通の base model を私有 data で fine-tune し、domain 別の expert を作る形で育つ。これを 1 つに統合するのは高コストで、重み merge (重みを足し合わせる) は domain が増えると精度が落ち、dense な mixture-of-experts (MoE; 入力ごとに専門 sub-network を選ぶ構造) の routing は重すぎる。DeltaForge は、独立に fine-tune された N 個の domain model を、**重みと小さな proxy data だけから**単一の multi-domain model に統合する。

## 手法の核心

- 同じ base から fine-tune された model は、重みの変化量 (delta) が構造を共有する、という観察を使う。
- 全 domain の delta をまとめて SVD (Singular Value Decomposition; 行列を主要な方向に分解する) し、各 delta を **全 domain 共通の部分**と **domain 固有のごく小さな部分**に分ける。
- router は小さな domain 固有部分だけを扱えばよいので安い。
- clip 単位の blind router (どの domain かの label を要らない) を 2 つ、proxy data の soft label で訓練する。1 つは VLM の reasoning expert 用、もう 1 つは flow-matching の dynamics expert (action 生成側) 用。
- 結果: 都市・off-road・高速、乗用車・トラック・ATV (All-Terrain Vehicle; 全地形対応車) の 6 domain で、各 domain の専用 model に近い精度を、merge・routing・centralized (data を集めて学習)・federated (data を共有せず学習) の全 baseline より高く、ほぼ単一 model の parameter・計算コストで出す。
- 新しい domain の追加は、その delta を共通の基底へ射影するだけで、end-to-end の再学習は要らない。学習していない domain の組合せにも汎化する、と報告。

## 適用可能性 (P3 / P2)

- P2 の「他機種・他ドメインへの適合」を、**適合した model をあとから 1 つにまとめる**問題として扱う。車種・地域ごとの fine-tune を重ねる運用に直結する。
- P3: 運転 VLA の構造 (VLM 側と flow-matching action 側を別々に routing) の具体例。
- 注意: 各 domain の絶対精度、routing の遅延、proxy data の必要量は abstract では不明。「共通の基底に載る」前提は、同じ base と近い fine-tune 設定のときに成り立つはずで、設定が違うと崩れる可能性がある。

## 試すべき実験アイデア

1. 手元で同じ base から fine-tune した model が 2 つ以上あれば、delta を並べて SVD し、上位の特異値にエネルギーがどれだけ集まるか (共通構造がどれだけあるか) だけを先に測る。ここが小さければ手法は効かない見込み。
2. 単純な重み平均 (merge) と、共通+固有に分けた場合で、各 domain の精度の低下を比べる。
3. 新 domain を 1 つ足す手順 (射影のみ) で、既存 domain の性能がどれだけ保たれるかを確かめる。VLA-MOPD (2611.12286; data 空間で統合) と同じ expert 群で比較できると良い。
