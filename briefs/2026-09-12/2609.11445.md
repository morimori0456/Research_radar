# FARM — 凍結した world model の内部状態には、既に「これから失敗する」が書かれている

**topic:** next_arch (P3) / **project:** P3 (+ P1)
**hf_upvotes:** 0 / **公開:** 2026-09-10T12:14:37Z
**スコア:** **P3 4.5** / P1 3.5 / P2 2.5

## 何を解決する論文か

ロボットを実際に動かすには、動作中に失敗を検知する online failure monitoring (実行中にリアルタイムで「このままでは失敗する」を判定する仕組み) が要る。既存の監視器は、失敗の代わりになる信号 (例: 行動の不確かさ) からリスクを推定するか、監視専用のモデルを別に学習させている。

FARM は問いを 1 つに絞る: **事前学習済みのロボット用 world model (次に何が起きるかを予測するモデル) を凍結したまま、その内部の予測状態から失敗の情報を直接読み出せるか。**答えは Yes で、**約 3.4 万パラメータの読み出し層を学習するだけで**、専用の監視器 15 種と同等以上の失敗検知ができた。

## 手法の核心

- **backbone は VLA-JEPA の予測状態を使い、凍結したまま一切更新しない。**JEPA (Joint-Embedding Predictive Architecture; 画素ではなく潜在表現の空間で「未来の表現」を予測する自己教師あり学習の枠組み) で学習された world model を VLA に組み込んだもの。
- **学習するのは 33,985 パラメータの supervised readout (凍結した特徴の上に載せる小さな分類器) だけ。**出力はステップごとの失敗スコアと、causal trajectory risk (その時点までの情報だけを使って計算する、軌跡全体のリスク)。
- **性能: 7 つのタスクで 5-fold の out-of-fold 評価 (学習に使っていない分割で評価する交差検証) を行い、pooled AUROC 85.68 / AUPRC 88.59。**AUROC は失敗と成功を順位付けで分けられるかの指標、AUPRC は失敗が少ないときに厳しくなる指標。10 タスクのベンチマークでは、見たことのあるタスクで 15 の比較手法中最良。
- **移植性: 4 種類の実機ロボット群 (PIPER X, SO-101, Franka) で、backbone を更新しない条件のまま検証。**読み出し層をそのまま使う場合と、読み出し層だけを再学習する場合の両方を試している。
- **コスト: backbone の状態が既に計算されていれば、追加の遅延は CUDA で平均 0.23 ms。**途中までの履歴からでも失敗を判別できる。

## 追っているプロジェクトへの適用可能性

### P3 — world model の価値を「生成の質」以外で測る

world model はたいてい「未来をどれだけ上手に予測・生成できるか」で評価される。**FARM が示しているのは別の価値で、予測の副産物である内部状態が、それ自体として再利用できる特徴になっている、ということである。**P3 で world model を採用するかを判断する際、「生成がきれいか」だけでなく**「その表現から、下流で欲しい量が線形に近い形で読み出せるか」**を評価軸に加えられる。

### P1 — 失敗の予兆を、planner の評価信号として使う

planner の closed-loop 評価は、衝突や逸脱が**起きたか**を数える。**FARM の形を使えば、それが起きる何ステップ前から予兆が見えていたかを測れる。**「失敗の予兆が早く現れるのに回避しなかった planner」と「予兆そのものが遅い状況」を区別できれば、評価の解像度が上がる。

R1 の solvability (その状況で自車に残っている逃げ道の本数) と組み合わせると、**「逃げ道が減っていく過程を、モデルの内部状態は捉えていたか」**という問いが立つ。

### 試すべき実験

1. **手元の E2E 運転モデル (または world model) の中間特徴に対して、「N 秒後に衝突するか」を当てる linear probe (凍結した特徴の上に線形分類器を 1 層だけ学習して、情報が含まれているかを調べる手法) を学習する。**N は 1, 2, 3 秒の 3 通り。ラベルは TTC (Time-to-Collision; 今の速度のままだと何秒後に衝突するか) が閾値を下回るかで作れる。
2. **比較対象として、同じ probe を「入力画像の事前学習済み encoder の特徴」にも当てる。**world model の予測状態のほうが良ければ、**未来を予測するように学習したこと自体に価値がある**と言える。差が無ければ、ただの表現力の問題である。
3. **AUROC だけでなく、「失敗の何ステップ前に閾値を超えたか」の分布を必ず出す。**監視器として使えるかは、早く分かるかどうかで決まる。

## 注意点

- **AUROC 85.7 は、実運用で誤警報を許容できる水準か微妙である。**監視器は誤警報が多いと無視されるようになる。**運用を考えるなら、AUROC ではなく「誤警報率を固定したときの検出率」で判断すること。**
- 評価はロボット操作のタスクで、失敗の定義が比較的はっきりしている (物を落とす、掴み損ねる)。**運転の「失敗」はより連続的で、ヒヤリハットのような境界事例が多い。**
- 読み出し層の学習には失敗例のラベルが必要。**失敗例が極端に少ないドメインでは、この学習自体が成り立たない可能性がある。**
