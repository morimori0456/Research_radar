# Per-token gating for on-policy distillation — FKL と RKL の混ぜ方を、4 係数の 1 つの式にまとめる

**スコア:** **P2 4.5** / P3 1.5 / P1 1.0

## 何を解決する論文か

on-policy distillation (OPD; student が自分で生成した系列の上で、teacher が token ごとに教師信号を与える蒸留。teacher の生成文を真似させる通常の蒸留と違い、student が実際に陥る状態で教えられる) では、**forward KL と reverse KL をトークンごとに重み付けして混ぜる per-token gating** が標準的な技法になりつつある。

- forward KL (FKL): teacher の分布を広く覆うよう student を引き伸ばす (mode-covering)。
- reverse KL (RKL): teacher が確率を高く置く一点に student を集中させる (mode-seeking)。

既存手法の EOPD と ToDi は、それぞれ**ゲートの信号を 1 種類、方向を 1 つに固定**しており、両者は直接比較されたことがない。この論文は両者を特殊ケースとして含む 4 係数の式を提案し、**同じ土俵で比べられるようにした。**

## 手法の核心

- **ゲートの式: λ_t = σ(a·h_t + b·u(x) + c + d·gap_t)。**λ_t はトークン t で FKL と RKL を混ぜる比率、σ は sigmoid。abstract から読める範囲では、**h_t はそのトークンでの entropy (分布の不確かさ)、u(x) は入力単位の不確かさ、gap_t は teacher と student の食い違い、c は定数の bias** である (各項の正確な定義は本文で確認すること)。
- **EOPD と ToDi は、この式の 1 次元の制限 (係数を 1 つだけ残した形) として再現される。**これで、既存 2 手法が同じ族の別の点であることが分かり、直接比べられる。
- **新しい自由度は 2 つ: 複数の信号を同時に使うこと (multi-channel) と、明示的な bias 項 c。**
- **実験: TweetEval (感情分類・ヘイト判定) で Qwen3-32B → Qwen3-4B。**4 係数の族は、強さを揃えた単一信号のゲート (entropy だけ / gap だけ) より 36 セル中 33 セルで高精度。**「ゲートを動的にしたこと」の効果を分離するため、実効的な KL の大きさを揃えた固定比率の baseline と比べても 26 セル中 19 セルで上回る。**
- **統計の扱いが誠実。**セル同士はデータ・モデルを共有しているので、この数え上げを独立な検定として扱わず「探索的な方向の証拠」と明記している。主要 9 比較を 3 seed で追試すると方向は一致するが、効果は単 seed の見積もりより小さく、n=3 では有意でない。

## 追っているプロジェクトへの適用可能性

### P2 — 蒸留 loss の設計空間を「1 本の式」として持てる

**この論文の実務上の価値は、精度の数字ではなくパラメータ化そのものにある。**蒸留を回していると「FKL と RKL のどちらを使うか」「どこで切り替えるか」を毎回場当たり的に決めることになるが、**この式を置けば、それが 4 つの係数の探索に落ちる。**既存の EOPD / ToDi をわざわざ別実装する必要もなく、係数を固定するだけで再現できる。

**09-11 の [OnPoKD](../2026-09-11/2609.10321.md) とつなげると整理がつく:**

- **OnPoKD はターゲットの中身** (teacher の予測・fine-tuning 前のモデルの出力・正解ラベルの配合) をサンプルごとに変える。
- **この論文は、同じターゲットへの距離の測り方** (FKL か RKL か) をトークンごとに変える。

2 つは直交していて、組み合わせられる。**どちらも「一律の recipe をやめて、単位ごとに決める」という同じ方向の別の軸である。**

**ただし、効果の大きさは期待しすぎないこと。**著者自身が、3 seed の追試では有意でないと書いている。**「どれを選んでもほぼ同じ」可能性も残っている**と読むのが正しい。

### 試すべき実験

1. **(最初の 1 本) 固定比率の混合 (λ を定数 c だけにする) を、FKL のみ・RKL のみと並べて回す。**動的なゲートを実装する前に、**混ぜること自体に効果があるか**を確かめる。これが効かなければ、残りの 3 係数を探索する意味は薄い。
2. 次に **entropy 項 (a) だけ** を加える。h_t は student の logits からすぐ計算でき、実装は数行で済む。
3. **teacher と student の大きさの差を 2 通り (例: 8 倍と 2 倍) 作って、ゲートの効果が capacity gap (teacher と student の能力差) の大きさで変わるかを見る。**gap_t 項が効くなら、gap が大きいほど効果が大きくなるはずである。
4. どの実験でも **seed は 3 以上**。この論文自身が、1 seed の効果の見積もりは過大になると示している。

## 注意点

- **評価タスクが短い分類 (TweetEval) だけ。**生成が長いタスクや、分類以外の出力 (検出・行動) では、トークンごとのゲートがそもそも意味を持つか分からない。
- 係数 4 つを探索すること自体にコストがかかる。**探索コストを払ってまで得られる改善幅は、本文の効果量で判断すること。**
