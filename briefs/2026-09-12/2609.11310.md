# Soft prompting for few-shot VLM adaptation — 重みを触らず、トークン 1〜3 個で LoRA に並び、しかも何も忘れない

**topic:** fm_distill_finetune (P2) / **project:** P2
**hf_upvotes:** 0 / **公開:** 2026-09-10T09:38:11Z
**スコア:** **P2 4.5** / P3 2.5 / P1 1.0

## 何を解決する論文か

VLM (vision-language model; 画像とテキストを同時に扱う基盤モデル) を、**学習時にほとんど見ていないドメイン (航空写真・工業画像・医療画像) の物体検出に、注釈付き画像 10 枚だけで適合させる**問題を扱う。既存の選択肢は discrete prompt optimization (プロンプトの文面を探索して最適化する方法) と LoRA fine-tuning の 2 つだった。

この論文は 3 つ目の選択肢である **soft prompting** を見直す。結論は明快で、**置く位置と初期化を正しく選べば、学習可能なトークン 1〜3 個 (平均 7,168 パラメータ) で最良の LoRA 設定と同じ精度に届き、しかも元の能力をまったく落とさない。**

## 手法の核心

- **soft prompting (入力列に「学習可能な連続ベクトル」を数個差し込み、backbone は凍結したまま、そのベクトルだけを学習する方法)。**LoRA (Low-Rank Adaptation; 重み行列に低ランクの差分を足して学習する PEFT の代表手法。PEFT = parameter-efficient fine-tuning、全重みではなく一部だけを学習する適合法の総称) と違い、モデルの重みは 1 つも変わらない。
- **設計判断 1 — 置き場所: visual token と text token の境目 (cross-modal boundary) に置く。**他の位置より良い (10.0 vs 8.4 mAP。mAP = mean Average Precision、物体検出の標準指標)。
- **設計判断 2 — 初期化: 「空白 (empty space) トークン」の埋め込みから始める。**意味のある単語やランダムな値から始めるより良い。
- **精度: Roboflow20-VL (多ドメインの少数ショット検出ベンチマーク) の 10-shot で 14.2 mAP、最良の LoRA と同等。**学習パラメータは 2 万分の 1 以下。
- **忘却がない。**同じ精度を出す LoRA は、元のタスク (NaturalBench VQA; 画像についての質問応答) の精度を相対 35% 落とし、最大ランクでは 56% 落とす。**soft prompting は元の性能を一切変えない。**代償は最適化の難しさで、seed によるばらつきが LoRA より大きい。
- **学習したトークンは「重み」ではなく「プロンプト」として振る舞う。**再学習なしで新しい版のモデルに移しても効き (Qwen3.5-9B で +0.8 mAP)、読める文章に言語化すると既存のプロンプト探索法 (DetPO, GEPA) と同等以上になる。

## 追っているプロジェクトへの適用可能性

### P2 — 「他機種・他ドメインへの適合」の既定の選択肢を見直す根拠になる

P2 の relevance criteria にある 4 項目 (少データ適合・ドメインギャップ・効率的適合・基盤モデルの転用) に、1 本で全部当たっている。とくに効くのは次の 2 点である。

**(1) 忘却のコストを数字で見せたこと。**LoRA は「軽い fine-tuning」として既定の選択肢になりがちだが、**同じ精度で元の能力を 35〜56% 失う**という数字は重い。複数ドメインに 1 つの基盤モデルを配って使う構成なら、ドメインごとに LoRA を当てるたびに共通の能力を少しずつ壊していることになる。soft prompt なら、ドメインごとに数トークンを差し替えるだけで基盤モデル自体は共通のまま使える。

**(2) モデルを入れ替えても適合結果が残ること。**P2 で言う「他機種への適合」には、**基盤モデル側が版上げされたときに適合をやり直す手間**も含まれる。LoRA の差分は元の重みに紐付いているので、モデルを変えれば学習し直しになる。**soft prompt は新しい版のモデルでも再学習なしで効いた** (+0.8 mAP は小さいが、符号が正であることに意味がある)。

### P3 との接続

VLA (vision-language-action model; 画像と言語指示から行動を直接出力するモデル) も VLM を backbone にしている。**「新しい環境に少数デモで適合させつつ、事前学習で得た汎化を壊さない」は VLA の post-training (事前学習後の追加学習) で最も揉める点**であり、同じ設計判断 (境目に置く・空白で初期化) がそのまま試せる。

### 試すべき実験

1. **手元の適合タスク 1 つで、LoRA と soft prompt (1〜3 トークン、境目に配置、空白トークンで初期化) を並べ、「適合先の精度」と「元のタスクの精度低下」の 2 軸で散布図を描く。**比較すべきは適合先の精度ではなく、**同じ適合精度のときの忘却量**である。
2. **seed を最低 3 つ回す。**soft prompt は seed によるばらつきが大きいと著者自身が書いている。1 seed の比較では勝ち負けが逆転しうる。
3. **(安い追試) 学習した soft prompt を最近傍の単語に言語化し、ハードプロンプトとして別のモデルに入れて効くかを見る。**効くなら、適合結果を「重み」ではなく「文章」として残せることになり、モデル更新の際の引き継ぎが大幅に軽くなる。

## 注意点

- **絶対的な精度は低い (10-shot で 14.2 mAP)。**「LoRA と同等」は「どちらもまだ実用に届いていない水準での同等」である。本番の精度が必要な場面で LoRA を置き換える根拠にはならない。
- 評価は物体検出のみ。**回帰・セグメンテーション・行動出力のような密な出力に対して、数トークンの容量で足りるかは未検証。**
- 忘却なしは構造上当然 (重みを変えていない) であり、発見というより性質である。**新しい知見は「その性質を持ったまま LoRA に並べられる」という部分**に限られる。
