### 1. [Driving on Memory — カメラを外して記憶だけで走らせたら、NAVSIM のスコアが落ちなかった](2608.31029.md) — P1 **5.0**

**理由: R1 の 3 本柱のうち「抜け穴監査」だけが、9 週間ずっと「やるべきなのは分かるが、どうやるのかが決まっていない」状態だった。この論文はその手順を、運転ベンチマークそのものの上で、完成形で示している。**

Bosch Research の実験は乱暴なほど単純である。**end-to-end 自動運転モデル** (センサ入力から中間表現を挟まず直接軌跡を出すモデル) **からカメラ入力を丸ごと取り上げ、代わりに「同じ場所を過去に走ったときの記憶」を与える。**記憶は道路の形や、その場所での走り方の癖は持っているが、**いま前に何がいるかは一切持っていない。**

**NAVSIM では、それでスコアがほとんど落ちなかった。**評価対象のシーンを見ていないモデルが、主要な end-to-end 手法に並ぶか、上回った。

**この設計が R1 にとって重要なのは、一般化した形が短い一文になるからである** —— **測りたいと主張している能力「だけ」を取り上げた対照条件を作り、同じ指標で走らせる。同等の点が取れるなら、その指標はその能力を測っていない。**

**そして裏返すと、量が 1 つ出てくる。**`score(フル観測) − score(記憶のみ)` は、**そのベンチマークが実際に測っている「動的シーンへの反応」の幅**である。**著者はこれに名前を付けていないが、実質的な出力はこの差分であり、NAVSIM では小さく Bench2Drive と RealEngine では大きい。**つまり **「ベンチマークが壊れている」ではなく「ベンチマークごとに反応の余地が違い、それを測れる」**という話になっている。

**R1 の主張の形が、これで一段強くなる。**これまで R1 は「衝突率の隣に置く量を定義する」という**提案**の形をしていた。この型を借りれば、**「既存指標が測れていないことを実測で示し、その穴を埋める量として提案する」**という**証拠付きの形**になる。**RoboPAD @ NeurIPS 2026 (09-10 AoE・4〜9 ページ・open-problem / benchmark / perspective 歓迎) は、まさにこの形の投稿を募集している。**

> 必要なのは走行ログと車両の運動モデルだけで、**08-31 以降ずっと未着手のまま繰り越されている半日の作業と、道具が完全に同一である。**

### 2. [The Intervention Gap in Latent World Models — 報酬の当てはまりは、介入を正しく動かすかを何も保証しない](2608.29998.md) — P1 **4.5** / P3 **4.5**

**理由: R1 が書こうとしている論文の構造が、そのまま別分野で先に成立している。図 1 の設計を考える時間がゼロになる。**

著者は **intervention fidelity (介入忠実度)** を、world model の独立に測れる性質として立てる。定義は **「モデル自身が環境に触れずに想像した数ステップ先の遷移が、環境側で同じ介入を行ったときと同じようにタスク変数を動かすか」。**

**そして最も刺さる 1 行がこれ —— この誤差が大きくなるほど実際の性能 (episode return) は下がるのに、reward 予測誤差は小さいまま、ほぼ平坦である。**指標が飽和して差を作らない間に、性能が落ちている。**Driving on Memory の「記憶だけでスコアが落ちない」と、証拠の型が同じである。分野は連続制御と自動運転で無関係なのに、同じ形で同じことが起きている。**

**構造の対応が一対一で取れる。**

| この論文 | R1 |
|---|---|
| episode return / reward 予測誤差 (既存の集約指標) | 衝突率 |
| intervention fidelity (隣に置く新しい量) | **solvability** (いまこの状態から、まだ助かる候補が何本残っているか) |
| 「reward の当てはまりは介入忠実度を明かさない」 | **「衝突率は逃げ道の残数を明かさない」** |
| **capture-gated** (資格のある事例だけ数える) | **抜け穴監査 (分母の健全性)** |

**この capture ゲートの位置付けが、R1 にとっての一番の収穫である。**著者は**まず「モデルがそもそもその問い合わせを内部に表現しているか」を判定し、表現している事例だけを次の測定に進める。**表現していないものを混ぜて平均すれば、「表現していない」と「表現しているが間違っている」が混ざって何も分からなくなるからである。

**R1 では「分母の健全性」は、抜け穴を潰す守りの作業として書かれていた。この論文はそれを、測定手続きの前段として組み込んでいる。「まず数える資格のある事例を選び、その上で新しい量を測る」という 2 段構成が、R1 の図 1 の骨格にそのまま使える。**

> **反直観な副産物が 1 つ:** タスク信号を一切使わない自己教師あり world model のほうが、タスクに合わせて学習させたモデルより介入の作用素をよく保存していた。**「下流タスクに寄せたほうが良い」という標準的な直観と逆である。**R3 の設計判断に効くが、**R3 は今月着手しない方針なので軸への記録に留める。**

### 3. [Does On-Policy Distillation Really Distill? — 教師の信号はノイズだらけで、生徒はそれを気にしていなかった](2608.31046.md) — P2 **5.0** / hf **88**

**理由: 「蒸留の支配変数は loss ではなく監督の当て方」という W35 以来の観察の 4 例目であり、しかも一歩踏み越えている。そして R2 が 9 週間探していた「教師の寄与を分離する測定」が、この論文の中に完成した形で入っている。**

**OPD (On-Policy Distillation; 生徒が自分で生成した系列を教師に採点させ、token ごとの密な教師信号として使う蒸留法)** は、**RLVR (Reinforcement Learning with Verifiable Rewards; 正解が機械的に検証できるタスクで、最終的な正誤だけを報酬にする強化学習)** の疎な報酬に対する解決策として広まった。

**著者は前提を疑う。**教師が採点しているのは生徒が書いた文章であり、**それは教師にとって自分では書かない文章である。**測ってみたら教師の信号には相当なノイズがあり、**教師を大きくするほどノイズの割合が増えた。**

**そして生徒はそのノイズにほとんど反応しなかった。**ノイズを残しても除いても到達性能は同じ。**普通なら「頑健で良かった」と読むところを、著者は逆に読む —— 生徒の改善が教師の信号内容に依存していないなら、改善は別のところから来ている。**

**分解した結果がこれ: 学習は低 log-probability の token に集中しており、教師が与える advantage を単一の固定された負の値に置き換えても、性能が変わらない。**つまり **OPD は主に「確率の低い token を抑制する」ことで効いていて、その動作に教師は要らない。**教師なしの手法 (OPSA) を作ったら、Qwen3-1.7B で AIME24 の Avg@32 が +35.41 ポイント伸びた。

**R2 にとって、これは 4 例目であり、かつ最も強い形である。**[UC-MOPD](../2026-08-29/2608.26735.md) / [Echo-GRPO](../2026-08-29/2608.26684.md) / [DART-SD](../2026-09-01/2608.18524.md) の 3 本は「教師の信号を、どこに当てるかが効く」だった。**本論文は「その信号が教師由来である必要はない」と言っている。**

**そして capacity gap (教師と生徒の能力差が大きすぎて蒸留が効かなくなる現象) の読み方が変わる。**RESEARCH_PIPELINE.md には**「容量比 1.0 でも蒸留が効く反例 5 本で、容量差が原因という当初の前提は棄却」**と記録されている。**本論文はその先を示唆する —— 蒸留の利得の大部分が知識転移ではなく確率分布の整形であるなら、「capacity gap」として測られてきた量は、そもそも知識転移の量を測っていなかった可能性がある。**

**検証が異様に安い。既存の蒸留パイプラインに条件を 1 つ足すだけ —— 教師由来の advantage を定数に置き換える。保たれれば教師は寄与していない。落ちれば、落ちた分が教師の寄与の上界である。**

> **引用前の注意:** 検証は **Qwen3-1.7B という小さいモデル、数学推論という狭い領域**のみ。**相対 263% は元の水準が低いことの裏返しでもある。**生徒サイズを振った曲線が原論文にあるかの確認が先。

### P3 — 次世代アーキテクチャ (R3: VLA × world model 統合)

**R3 の分類マップの第 1 軸「時間をどこに持つか」に、決定的な形が入った。**[Video World Models](2608.30692.md) は、これまで粗く二分されていたこの軸を 3 段に切る:

1. **token の中に持つ** (履歴を読み直す) —— **pixel を予測目標にしている限り、隠れ状態はそこに載らない。**
2. **追記のみのアーキテクチャ状態に持つ** (Transformer の KV cache) —— 書き換えられないので毎回導出し直しになり、**外挿しない。**
3. **その場で書き換えられる状態に持つ** (遷移固有値に負を許した linear attention / TTT の fast weight) —— **外挿する。**

**そして W35 の収束点「画素は world model の言語として粗すぎる」に、初めて機構レベルの理由が付いた。**W35 の根拠はすべて**結果** (画素で学ぶと下流性能が伸びない) だったが、**本論文の主張はもっと強い —— 粗いのではなく、勾配が一度も届いていない。**見えていないものは pixel loss に現れないので、学習信号としてゼロである。**解像度や denoise 回数で埋まらないのは当然で、実際に埋まっていない。**

**[Intervention Gap](2608.29998.md) が、この結論の射程を確定させる。**あちらは**潜在空間**の world model で同じ穴が空くことを示した。**つまり問題は表現の媒体 (画素か潜在か) ではなく、監督が届いていない範囲そのものである。****2 本合わせると、R3 の設計原則が 1 行になる: world model に何を保持させたいなら、それに勾配が届く経路を明示的に作らなければならない。**

**R3 は今月着手しない方針を維持する。**軸の更新だけ記録し、手は動かさない。**なお [2608.30144 (Rethinking Language's Role in Efficient VLA for AVs)](rejected.md) は survey で、推論時に言語をどこで使うかによる 4 段分類 (Language Residue) を提供している。分類マップを作る段階になったら、列としてそのまま入る。**
