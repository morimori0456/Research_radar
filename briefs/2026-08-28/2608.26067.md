# StreamPI: Streaming Multimodal Temporal Modeling for Vision-Language-Action Models

- arXiv: https://arxiv.org/abs/2608.26067
- topic: **next_arch** (P3) / hf_upvotes **16** (本日の本流トピック最高)
- 公開日: 2026-08-26 (Wed)
- relevance: P1 **2.5** / P2 **1.5** / P3 **4.5**

## 何を解決する論文か

**現在の主要な VLA (Vision-Language-Action; 画像と言語指示から行動を直接出力するモデル) — π0.5 を含む — は single-frame paradigm、つまり「今この 1 枚の画像」だけを見て行動を決めている。**過去の観測を保持しないので、**一度見て隠れたものを覚えていられないし、複数フレームからしか得られない精密な空間把握もできない。**

StreamPI はここに **パラメータを 1 つも増やさずに時間軸を足す。**やり方は 2 つで、**(1) attention の掛け方だけで時間構造を作る、(2) 学習時のフレーム間隔をランダム化して、同期的な学習と非同期的な実機配備のずれを吸収する。**そして **LLM backbone の length extrapolation (学習時より長い系列にも外挿できる性質) を使うことで、single-frame で事前学習した重みをそのまま引き継げる。**LIBERO (ロボット操作の標準シミュレーションベンチマーク) と実機で π0.5 を上回る。

## 手法の核心

- **instruction-anchored temporal modeling — (視覚観測, 言語指示) のペアを時間の最小単位とする。**フレームだけを並べるのではなく、**毎ステップ言語指示をもう一度置く。**そして**ペアの内側は bidirectional attention (前後どちらも見る、双方向の注意) で視覚と言語を融合させ、ペアをまたぐ方向は causal attention (過去だけを見る、因果的な注意) にして自己回帰的な streaming 推論を保つ。**

- **これによって言語指示が「消えない錨」になる。**単純に過去フレームを継ぎ足すと、**系列が伸びるほど最初に置いた指示が薄まる。**指示を各時刻に埋め込み直すことで、**作業のどの時点でも指示が同じ強さで効く。**この論文で最も移植価値の高い設計判断はここだと思う。

- **random-interval streaming training — 学習時に使うフレームの間隔を固定せずランダムに振る。**まず**適切な間隔を空ける (例: 3 フレームおき) だけで、行動の実行が速く滑らかになる。**そのうえで**間隔をランダム化すると、フレームが来るタイミングの揺れに強くなる。**

- **なぜ間隔の話が重要か — 学習と配備で時間の流れ方が違うからである。**学習はオフラインで、フレームは等間隔に並んでいる。**実機は非同期で、推論時間や通信で間隔が揺れる。**この論文は**そのずれを、データ拡張の一種として学習時に注入して潰している。**構造ではなくデータの与え方で解いている点が実務的。

- **single-frame の事前学習重みをそのまま継承できる。**新しいパラメータが無く、系列長の外挿に頼っているので、**既存の π0.5 系の資産を捨てずに時間軸を足せる。**推論時も **single-frame と multi-frame を切り替えられる。**

## 読むときの但し書き

- **「パラメータを増やさない」は「コストが増えない」ではない。**過去フレームを持つ以上、**系列長が伸びて attention の計算量と KV cache のメモリが増える。**streaming 推論なので前の計算は再利用できるはずだが、**実機のレイテンシがどうなったかの数字を本文で必ず確認する。**リアルタイム制御では、ここが採否を決める。
- **length extrapolation への依存が弱点になりうる。**LLM backbone が学習時より長い系列で性能を保つ、という性質に乗っている。**backbone を変えたときに同じように効く保証はない。**
- **π0.5 との比較が主軸である。**他の multi-frame VLA (明示的に時間モデリングを持つ既存手法) との比較がどれだけあるかで、「無料で時間軸が手に入る」という主張の強さが変わる。
- **abstract に "andom-interval" という誤植がある。**random-interval のこと。内容には影響しないが、**この段階の原稿である**という目安にはなる。

## P1/P2/P3 への適用可能性

### P3 (次世代アーキテクチャ) — 本日の hf 最高票。R3 の分類マップの「記憶」軸を埋める

**R3 (VLA × world model 統合アーキテクチャ) の次のアクションは「既存統合手法の分類マップ作成」である。StreamPI はそのマップの、まだ空白だった列に入る。**

**world model を持つ理由の一つは「過去を要約して未来を予測するため」だが、StreamPI は未来を予測せずに過去だけを持つ。**しかも**別モジュールを立てず、attention の掛け方だけで持つ。**つまり**「記憶をどこに置くか」という軸で見ると、最も軽い端にある。**

**本日採用の [LM-X](2608.25757.md) と対にすると構造が見える。**

| | 過去の保持 | 未来の予測 | 追加パラメータ |
|---|---|---|---|
| StreamPI | context 内 (attention) | しない | なし |
| LM-X | (単一フレーム) | スカラー要約量 (進捗・事象・分散) | ヘッドのみ |
| world model 併設型 | 潜在状態 | 観測を生成 | 大 |

**この 3 行が R3 のマップの背骨になる。**そして **08-27 の WorldSync の診断 (world model は専門家がやらない行動に追従できない) を踏まえると、いちばん下の行のコストが最も高く、信頼性が最も低い。**上 2 行が同程度の性能を出すなら、**「world model を立てる必然性は何か」という問いが R3 の中心になる。**これは R3 の主張として十分に鋭い。

**もう 1 つ、wildcard で採った [VoiceMem](2608.26005.md) がこの表の 4 行目に入る** — 記憶を**外部の検索可能なストアに置き、レイテンシ予算の中で引く**方式。**StreamPI が context に持つのに対し、VoiceMem は外に持って 134ms で引く。**長い作業では context に全部持つのは破綻するので、**この 2 つは長時間タスクで正面から競合する設計選択である。**

### P1 (Planner AI + 評価) — 直接ではないが、「学習と配備の時間のずれ」は AD で最も痛い場所

**random-interval streaming training が扱っている問題は、自動運転でそのまま起きる。**オフラインのログは等間隔で、実車の推論は間隔が揺れる。**そして AD の場合、揺れは性能低下ではなく安全性の問題になる。**

**評価の観点では、これは「時間の揺れに対する頑健性」という測るべき軸を 1 つ提示している。**手持ちの planner / predictor に対し、**入力フレームの間隔を意図的に揺らして性能がどう落ちるかを測る**のは、既存の評価に足せる安価な軸である。**落ち方が急なら、それは配備前に知っておくべき脆弱性である。**

### P2 (FM 蒸留 + 適合) — 該当薄

「事前学習済み重みを捨てずに新しい能力を足す」という点は P2 の関心と重なるが、**手段が構造 (attention mask) であって適合手法ではない。**無理に繋げない。

## 試すべき実験アイデア

1. **手持ちのモデルで「入力間隔を揺らす」評価を足す (2 時間、学習ゼロ)。**
   **既存の推論パイプラインで、フレームを等間隔でなく揺らして流すだけ。**新規実装はサンプリング部分の数十行。**得られるのは、自分のモデルが同期的な学習前提にどれだけ依存しているかという数字である。**
   **これは 08-27 に挙げた「等速直進の基準線を足す」と同じ性質の作業** — 実装が小さく、結果がどちらでも意味がある。**落ちなければ安心材料、落ちれば配備前に見つけるべきだった脆弱性。**

2. **言語指示を各時刻に置き直すかどうかの A/B (半日、小規模学習 2 本)。**
   StreamPI の設計の中で **instruction-anchoring は最も切り出しやすい要素である。**指示を系列の先頭に 1 回だけ置く版と、各時刻のペアに置き直す版を比べる。**長い作業ほど差が出るはずで、差が出る系列長そのものが知見になる。**

3. **R3 の分類マップに「記憶をどこに置くか」の列を作り、本日の 3 本を配置する (2 時間、実装ゼロ)。**
   上の表をそのまま出発点にして、**手持ちの調査済み手法を 4 行のどれかに割り当てていく。**割り当てられない手法が出てきたら、それが**新しい行 = R3 の空白**である。**R3 の次のアクションが「分類マップ作成」である以上、これは着手そのものである。**
