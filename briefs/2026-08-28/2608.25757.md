## 何を解決する論文か

**VLA (Vision-Language-Action; 画像と言語指示から行動を直接出力するモデル) は、長い作業を「次の数百ミリ秒の行動を当てる」という短い単位の予測だけで学習している。**その結果、**1 つの行動出力が、作業がどこまで進んだか・次に何が起きるべきか・今の自信はどれくらいか、を全部暗黙に背負わされる。**しかもそれらは実行中に外から見えない。**動いている間、モデルが今どう思っているかを読む手段がない。**

LM-X はこれを、**行動と並べて 3 つの量を明示的に教師付きで予測させる**ことで解く。task / event / motor という 3 つの時間スケールに対応させ、**予測した 3 量をそのまま行動生成の条件として使い戻す。**つまり説明が後付けの可視化ではなく、制御の内側にある。**RoboTwin2.0 の難易度ランダム化 50 タスクで 74.1% (GR00T N1.7 は 55.4%)、実機 7 タスクで 68.6% (同 50.7%)。**

## 手法の核心

- **RTG (return-to-go; 強化学習で「この時点からエピソード終端まで得られる報酬の残り合計」を指す量。ここでは作業の残り工程量として使う) を毎ステップ出力させる。**外から見える進捗を連続量で吐かせる、ということ。実験では **RTG が意味的な進捗を追い、作業が後戻りしたときにはちゃんと逆行する**と報告されている。

- **ETG (event-to-go; 次の意味的な遷移点までの距離) を出力させる。**「掴む」「持ち上げる」「置く」の境界がいつ来るかを予測させる中間スケールの信号。RTG が作業全体の進捗、ETG がその中の次の区切り。

- **heteroscedastic action flow で局所的な信頼度を出す。**heteroscedastic (不均一分散; 入力によって予測のばらつきの大きさ自体が変わること) な行動生成にし、**分散を伝播させて「今この瞬間の行動がどれくらい当てにならないか」を数値で出す。**報告では **迷っている場面と、制御が振動している場面で分散が上がる。**

- **3 つの信号が行動生成を条件付ける。**出力して終わりではなく、入力に戻す。だから性能が上がる方向に働く — ablation では **全部入りが行動のみの backbone に対して +16.0 ポイント、最良の単一ヘッド版に対しても +10.8 ポイント。**

- **本番の大規模学習の前に、小さな統制実験で設計を検証している (後述、ここが本論文最大の実務的価値)。**本番は 64 枚の NVIDIA B200 で 20 日、実機軌跡 20,000 時間超 — うち **1,000 時間超が「失敗した方策のロールアウト」**である。成功データだけでなく、失敗した走行を明示的に混ぜている。

## 読むときの但し書き

- **3 つの信号はすべて教師付きである。**RTG も ETG も、**学習時にラベルが要る。**RTG は軌跡の全長が分かれば計算できるが、**ETG の「意味的な遷移点」は誰かが定義しなければならない。**このラベル付けのコストと自動化の程度が、他ドメインへ移せるかの分かれ目になる。abstract には書かれていないので本文で必ず確認する。
- **「biological sensorimotor control に着想を得た」が、著者自身が解剖学的な対応は主張しないと明記している。**比喩であって根拠ではない。**評価すべきは 3 スケールに分けたことの効果だけで、生物学的もっともらしさではない。**
- **分散が「迷い」で上がるのは定性的な観察である。**校正 (predicted variance が実際の誤り率と一致しているか) の検証があるかは本文次第。**校正されていない不確実性は、監視には使えても保証には使えない。**
- **比較対象が GR00T N1.7 の 1 本に見える。**同規模データで学習した他の VLA との比較がどれだけあるかで、主張の強さが変わる。

## P1/P2/P3 への適用可能性

### P3 (次世代アーキテクチャ) — 本日の P3 の主役。R3 の分類マップに新しい軸を 1 本立てる

**R3 (VLA × world model 統合アーキテクチャ) の分類マップを作るとき、LM-X は「world model を持たないまま、world model が担うはずの役割の一部を、予測ヘッドとして方策の内側に置いた」設計例として位置づけられる。**

world model を別に立てる方式は、未来の観測を生成してから評価する。LM-X は生成しない。**代わりに「未来について知っておくべき要約量」だけを直接予測する** — あとどれだけ残っているか (RTG)、次の区切りはいつか (ETG)、今の出力は当てになるか (分散)。**画素を作らずに済むので、推論時のコストが増えない。**

**これは 08-27 に見た WorldSync の診断と正面から噛み合う。**あちらの結論は「world model は専門家がやらない行動には追従できない」だった。**行動追従性が保証できない予測器で未来を生成するくらいなら、未来の要約量だけを予測する方が安全ではないか、という選択肢を LM-X が具体的に示している。**R3 のマップの軸としては **「未来をどの粒度で表現するか」** — 画素 / 幾何 / 潜在状態 / **スカラー要約量 (LM-X)** / 予測しない、という並びになる。**この軸の右端 (スカラー要約) は、コストが最も低く、追従性の問題も最も小さい。**

**もう 1 つ、本日採用の [StreamPI](2608.26067.md) と組で読むと構造が見える。**StreamPI は「過去をどう持つか」、LM-X は「未来をどう持つか」。**どちらもパラメータをほとんど増やさずに、単一フレーム VLA に時間軸を足している。**この 2 本は同じ問題の前半と後半である。

### P1 (Planner AI + 評価) — 「実行中に読める信頼度」という評価対象

**08-27 の DIGEST で、P1 の 3 本が同じ方向に収束したと書いた — planner の質は「起きたこと」でなく「起きなかったこと」で測れ。LM-X はそこに 4 本目として、別の角度から入る。**

**方策自身に「今どれくらい当てにならないか」を吐かせ、それが実際の失敗と一致するかを測る、という評価軸である。**これは反実仮想ではなく校正 (calibration) の問題だが、**目的は同じ — 単一の成否ではなく、その走行がどれだけ際どかったかを連続量で捉える。**

**R1 (HIL 評価 × conformal 安全指標) との関係が具体的である。**conformal prediction (予測の外れ率を、データ分布に仮定を置かずに保証付きで抑える統計手法) を planner の安全指標に使うとき、**入力として「モデル自身が出す不確実性」があるかないかで、設計がまるで変わる。**LM-X は **heteroscedastic な分散を方策が自前で出す** 例を提供している。**R1 に「モデルの自己申告の不確実性を、conformal で保証付きの区間に変換する」という具体的な筋道が 1 本増えた。**

ただし**校正の検証が本文にあるかを先に確認すること。**自己申告の分散が校正されていないなら、conformal で包み直す価値がむしろ上がる (それこそが conformal の役目) — **どちらに転んでも R1 の材料になる、という点でこの確認作業は損をしない。**

### P2 (FM 蒸留 + 適合) — 該当薄。ただし「失敗ロールアウトを学習に混ぜる」は蒸留にも効く

学習データ 20,000 時間超のうち **1,000 時間超が失敗した方策のロールアウト**という構成は、**08-27 の PROOF-Gen (teacher の失敗軌跡の 93% を回収した) と同じ発想の別実装である。**失敗を捨てずに使う、という点で共通している。R2 の予備実験を組むとき、**「teacher の失敗を捨てるか使うか」は独立に振れる条件として持っておく価値がある。**

## 試すべき実験アイデア

1. **手持ちのモデルに RTG ヘッドだけを足す (半日、新規学習は小規模 1 本)。**
   3 つの信号のうち **RTG が圧倒的に安い** — 教師ラベルは軌跡の長さから機械的に計算できるので、人手の定義が要らない。**既存の方策に線形ヘッドを 1 つ足して、進捗の残量を回帰させるだけ。**得られるのは 2 つ: (a) 補助損失として本体の性能が動くか、(b) **推論時に進捗が読めるようになる。**ablation の +16.0 ポイントのうち、どれだけが最も安いヘッドで取れるかが分かる。

2. **「pretraining gate」の作法をそのまま輸入する (所要ゼロ、意思決定のみ)。**
   **本論文が 64 GPU × 20 日を投じる前に、5 タスクの統制実験で設計の各要素が効くことを確認している** — これは論文の技術的貢献ではないが、**本日いちばん実務価値の高い記述である。**
   memory に「実験着手 8 週連続ゼロ、原因は 90 分ブロックの確保」と記録されている状況で効くのは、**「本番の前に、設計判断を分ける最小の実験を 1 つ決める」という手続きそのものである。**R2 (蒸留の capacity gap の系統則) についても、**「これが出なければ本実験に進まない」という gate を 1 つ書き下す**だけで、着手の敷居が下がる。**新規実装ゼロ、必要なのは紙 1 枚。**

3. **既存の走行ログに対して、事後的に RTG と分散の相関を測る (2 時間、学習ゼロ)。**
   モデルを変えずにできる版。**成功した走行と失敗した走行を分けて、失敗直前の区間でモデルの出力分布のエントロピーが上がっているかを見る。**上がっていれば「自己申告の不確実性は使える」、上がっていなければ「別の信号が要る」。**どちらでも R1 の設計判断が 1 つ確定する。**
