# A Token-Level Analysis of Sampled-Token Reverse-KL On-Policy Distillation

- arXiv: https://arxiv.org/abs/2608.25643
- topic: **fm_distill_finetune** (P2) / hf_upvotes **0**
- 公開日: 2026-08-26 (Wed)
- relevance: P1 **0.5** / P2 **4.5** / P3 **1.0**

## 何を解決する論文か

**OPD (On-Policy Distillation; 蒸留の一形式で、student に自分で文章を生成させ、その生成した軌跡の各 token に対して凍結した teacher が「自分ならどれくらいの確率でその token を出したか」を答え、それを教師信号にする方式) は今の蒸留の主流の一つである。**だが**この loss が、生成された数千 token のうちどこに更新を集中させているのかは、これまできちんと分解されていなかった。**

この論文は **reverse KL (逆向きの Kullback-Leibler divergence。student を基準に teacher との差を測る向きで、mode-seeking — teacher の分布のうち一つの峰に寄せる性質を持つ) の per-token 推定量に対し、student の logit についての勾配を解析的に分解する。**結果として **「勾配の大きさは 2 つの因子の積になる」**ことを示し、**実測でその積が極端に偏っていること**を示す。**主たる貢献は手法ではなく、この特徴づけの方である。**著者自身がそう明記している。

## 手法の核心

- **K2 estimator (reverse KL を、サンプルした token 1 つから低分散に推定する推定量。Schulman の KL 推定量系列の一つとして知られる) の勾配を、student の logit について解析する。**サンプルした token だけを使う実装が実際に何をしているかを、式のレベルで開く。

- **勾配の L1 ノルムが 2 因子に分解される。**
  **(a) teacher と student の対数確率の差の絶対値** — teacher がどれだけ違う意見を持っているか。
  **(b) student 側の softmax 由来の因子で、サンプルされた token が student にとって低確率であるほど大きくなる** — student が自分でも意外に思った token ほど大きい。
  **つまり「teacher が強く反対している」かつ「student 自身が自信のない」token に、更新が集中する構造になっている。**これは設計してそうなったのではなく、**素朴に実装すると自動的にそうなる。**

- **実測で、この偏りが極端である。**数学の蒸留実験で、**per-token の勾配ノルムは著しく不均一。低確率 token が総和の不釣り合いに大きな割合を占め、しかもそれらは teacher との差が大きい token とも重なっている。**2 つの因子が独立ではなく、同じ token で同時に大きくなっている。

- **SuRe (Surprise-aware Reweighting) — 既にある偏りをさらに強める重み付け。**detached (重み自体には勾配を流さない、stop-gradient した値として扱う) で bounded (上限を設けて発散を防ぐ) な重み規則。**新しい方向を作るのではなく、loss が既に持っている配分を増幅するだけ**という位置づけ。

- **効果は控えめかつ正直に報告されている。**Qwen3 系の 2 つの student 規模で、**数学の指標がいくつか改善し、選んだ OOD (out-of-distribution; 蒸留対象外の) ベンチマークでは明らかな劣化が見られない。**「大幅改善」とは書いていない。

## 読むときの但し書き

- **著者が「主たる貢献は解析であり、SuRe はその一実装にすぎない」と明言している。**この態度は信頼できるが、**同時に SuRe の実用的な旨味はそれほど大きくない可能性が高い**という読み方もできる。**持ち帰るべきは重み規則ではなく、勾配がどこに行っているかという事実の方。**
- **検証が数学ドメイン中心である。**数学の推論では「決定的な 1 手」が存在しやすく、低確率 token に情報が集中しやすい。**要約や対話のように正解が広い分布を持つタスクで同じ偏りが出るかは分からない。**
- **「low-probability token を重視する」は諸刃である。**student が低確率を割り当てる token には、**本当に重要な転換点**と**単なるノイズ・タイポ・teacher の気まぐれ**の両方が含まれる。**bounded にしているのはそのためだろうが、比率が悪いドメインでは害になりうる。**
- **改善幅と分散が示されていない。**08-27 の AQLoRA が指摘した「数 % の差を主張するには基準となるノイズ床が要る」がここにも当てはまる。**seed 間のばらつきに対して改善が大きいかを本文で確認する。**

## P1/P2/P3 への適用可能性

### P2 (FM 蒸留 + 適合) — 本日の P2 の 2 本柱の一方。topics.yaml の「新しい loss」に直撃し、R2 の中心を突く

**この論文が P2 に与える最大のものは、蒸留の失敗を診断する言語である。**

これまで蒸留がうまくいかないとき、原因を **「student の容量不足」「teacher が悪い」「データが足りない」** といった粒度でしか語れなかった。**この論文は「勾配が実際にどの token に流れたか」という粒度を与える。**そして**その分布は測れる。**loss の値ではなく、**loss がどこに効いたかの分布を見る**という診断が成立する。

**R2 (蒸留の capacity gap の系統則) にとって、これは仮説の解像度を一段上げる。**

**capacity gap — teacher と student の容量比が開くと蒸留が破綻する現象 — を、この分解を通して読み直すと、具体的な予測が立つ。**
student が小さいほど、teacher との対数確率の差 (因子 a) は全体的に大きくなる。**同時に、student が自信を持てない token の割合 (因子 b が大きい token) も増える。**
**つまり容量比が開くにつれ、勾配ノルムの分布は「一部の token への極端な集中」へ移行するはずである。**そして**その集中度が閾値を超えたところが、破綻の境界なのではないか。**

**これが R2 にとって重要なのは、測定可能な中間量を与えるからである。**「破綻したかどうか」という結果指標だけを見て曲線を引くのは難しいが、**勾配ノルムの集中度 (例えば上位 1% の token が総和の何割を占めるか) は、破綻する前から連続的に動く量である。**
**前兆が測れるなら、破綻点まで実験を回さなくても曲線の形が見えてくる。**これは**実験コストを直接下げる。**memory に「実験着手 8 週連続ゼロ、ボトルネックは 90 分ブロックの確保」と記録されている状況では、**必要な計算量が減ることは、着手可能性そのものに効く。**

**さらに、本日採用の [QLoRA frontier](2608.25677.md) と組み合わせると、R2 の予備実験が 1 つの形にまとまる。**
あちらは **「容量を振ると 2 つの望ましい性質のトレードオフ曲線が出る」ことを、安い設定で確認済みだと示した。**
こちらは **「その曲線の背後で何が起きているかを測る中間量」を与える。**
**曲線を引く手続きと、曲線を説明する量が、同じ日に揃った。**

### P3 / P1 — 該当薄

VLA の蒸留にも原理的には移せるが、**token 単位の離散的な分布を前提にした解析なので、連続値の行動出力にそのまま持ち込めない。**flow matching や diffusion ベースの行動ヘッドに対する類似の分解は、本論文の射程外である。**ただしそこは空白であり、埋める価値はある**という点だけ記録しておく。

## 試すべき実験アイデア

1. **過去の蒸留ログから、勾配ノルムの集中度を後付けで測る (半日、新規学習ゼロ)。**
   **学習をやり直す必要はない。**保存済みの teacher / student の対数確率があれば、**上の 2 因子は推論だけで再構成できる。**
   出す数字は 1 つ — **「勾配ノルムの上位 1% の token が、総和の何割を占めるか」。**
   **この 1 つの数字を、過去に回した蒸留の設定ごとに並べる。**うまくいった設定と、うまくいかなかった設定で違いがあるか。**違いがあれば、それが R2 の中間量の候補である。違いがなければ、この仮説はここで捨てられる。**どちらでも半日で判定が済む。
   **08-27 に挙げた「過去の蒸留ログで teacher の生成の何割をフィルタで落としたか数える (2 時間)」と同じログを触るので、同じ枠で両方できる。**

2. **teacher/student の容量比を 2 点振って、集中度が動くかを見る (1 日、小規模学習 2 本)。**
   上の測定で違いが見えたら次はこれ。**同じ teacher に対して student を 2 サイズ用意し、集中度を比較する。**予測は「小さい student ほど集中度が高い」。**2 点で方向が確認できれば、そこから点を増やして曲線にする価値が確定する。**
   **2 点で方向が出ないなら、点を増やしても出ない。**これは**本実験に進むかどうかの gate として機能する** — 本日の [LM-X](2608.25757.md) が 64 GPU × 20 日の前に置いていたのと同じ役割の、小さな関門である。

3. **SuRe を実装するのは、上の 2 つが済んでからでよい。**
   重み規則自体は数十行だが、**著者自身が控えめに位置づけているものを先に実装しても、得られる情報が少ない。**順序としては診断が先。
