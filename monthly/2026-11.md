## 3. 来月の基礎テーマと非技術書

### 基礎テーマ【提案】: **古典的手法 (運動モデルの rollout と reachability) — 3ヶ月目の繰り越し。ただし順序を逆にする**
reachability = 「ある時間内に車が到達しうる状態の全体」。**テーマを変えない理由**: R1 の toy がこのテーマそのもので、OKR の O1 と同じ作業だから。**変えるのは順序**: 9月・10月は「読む→作る」で 2回とも作る段に届かなかった。11月は **先に作り、後で読む。**

| 期限 | 作るもの (= `experiments/` への commit) | 読むもの (commit の後) |
|---|---|---|
| **11-08 (日)** | bicycle model (x'=v cosθ, y'=v sinθ, θ'=v tanδ/L) + 操舵×加速の格子 + 3秒 rollout + 障害物 1個 (円)。衝突しない本数 (= solvability) を数える ~40行。**汚くてよい** | なし |
| 11-15 | 場面を 20個に増やし、場面別成功率ヒストグラム (CodeMidas 型) + solvability を 1枚の図 (= 図 1) に | Werling+ 2010 (Frenét frame: 道路の沿い方向/横方向で軌道を張る古典) |
| 11-22 | 「格子 rollout は到達可能集合の**内側**近似で、solvability=0 は"本当に回避不能"を意味しない」を 3行で書く | Althoff & Dolan 2014 §1–3 (T-RO) |
| 11-29 | swap 検査 (障害物配置を別場面と入れ替えて solvability を再計算し、値が壊れるか見る) | — |

**判定は 11-08 と 11-15 の `git log --oneline -- experiments/ | wc -l` のみ。** 実施枠は LIFE_PLAN の不可侵枠 (土曜 90分: 11-07・11-14)。**11-15 に 0 件なら、テーマの問題でなく手順の問題と確定する。** その場合の分岐は §7-1 (エージェントが下書きを作る境界変更の承認) に回す。
