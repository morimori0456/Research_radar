### 課題: 自動運転トラックの「保有者」が Aurora から顧客に移るが、安全証拠は Aurora が整備した車両で積まれたものしかない

- **誰が困っているか / 深刻度**: DaaS に移る顧客 (FedEx・Werner・Schneider など、[CNBC](https://www.cnbc.com/2026/09/22/aurora-autonomous-semi-ride.html)) と、その保険会社。規模は、年末に約200台、第2世代 hardware で約1,500台まで作れる (事実)。**2027年末には、その大半を Aurora 以外が整備・運用することになる** (事実: 会社の計画)。
- **なぜ未解決か**: **これまでの safety case (安全性を論証した文書一式) は「Aurora が sensor を清掃・校正し、Aurora の運用で走らせる」ことを前提に積まれてきた** (推測。TaaS の構造上そうなるはず)。所有者が変わると、整備の頻度・タイヤ・積載・運行時間帯の分布が変わる。**しかし「この車両はまだ評価された条件の範囲内にいるか」をオンラインで判定する指標は、公開情報では見当たらない。** 責任の分け方 (Aurora と顧客) も記事は触れていない (事実: 開示なし)。
- **既存プレイヤーとその限界**: **Aurora** は自社の safety case framework を公開しているが、第三者が保有する車両への適用範囲は不明 (推測)。**FMCSA** (米国の商用車運行を所管する当局) の整備規則は人間の運転手を前提にしている。**保険** は料率の根拠となるデータを持っていない。W35 カード3 (比較対象がない運行条件) では「条件」が問題だったが、**今回は「運用する人」が変わる**。
- **対象者の技術との接続**: **P1 (評価) に直結する。**「整備状態・運用の分布が変わったときに planner の性能が落ちたか」を走行ログから検出するのは distribution shift の検出問題で、R1 の solvability のように**毎ステップ値が出る指標を monitor として転用**できる (推測)。衝突率では DaaS の1顧客分 (数十台) では何年経っても判定できない (W37 カード2 の単調性の議論がそのまま効く)。
- **最初の一歩 (1週末)**: Aurora の公開 safety case framework を読み、**各主張を「Aurora が運用を握っていることを前提にしている / していない」の2列に振り分ける表**を作る。前提にしている行が DaaS で穴になる箇所の一覧になる。所要は半日。

### 課題: robotaxi が新しい国・都市でサービスを始めるまでの lead time が1〜2年あり、その大半は「その土地のデータを集める」時間である

- **なぜ未解決か**: **汎化の主張 (foundation model・world model) は論文の中では成功率で語られるが、事業の側では「新しい都市で有料化できるまでの月数」でしか効果が見えない。** この2つを結ぶ測定がない。W33 カード3 (「1箇所で証明した性能を次に持ち越せない」) の**時間軸版**で、今回は Singapore の monsoon のように**気象そのものが新しい分布**として公式に名指しされた。
- **既存プレイヤーとその限界**: Waymo・WeRide・Pony.ai・Zoox は各社でデータを集めている。**lead time が年々縮んでいるかどうかを外から検証した人はいない** (推測: 公開の集計は見当たらない)。規制側 (Spain DGT など) は許可台数を段階的に出すだけで、何をもって次の段階に進めるかの基準は公開されていない。

### 課題: 果実収穫 robot は「成功率 60–70%」で評価されているが、農家の採算を決めるのは失敗の中身 (取り残しか、傷つけたか) である

- **誰が困っているか / 深刻度**: 米国の青果農家。H-2A の認定は年約43.5万件で過去最高 (事実)。調査では**「人が集まらないこと」よりも「人件費の上昇」が上位の懸念**で、投資したい技術の1位は収穫の自動化である (事実: 上記2ソース)。つまり買う理由はすでにある。
- **なぜ未解決か**: **成功率は「失敗1回のコスト」を平均で潰してしまう。** 取り残し (後で人が摘めば済む) と、傷つけた (商品価値がゼロになり、樹も傷む) とでは、1回あたりの損失が桁で違う (推測。果実の単価と等級の差から)。**robot 側の論文や売り込みは成功率を報告し、農家の損益計算は失敗の種類ごとの損失で決まる。** この変換がないので、農家は「人件費との比較」ができない (推測)。
- **既存プレイヤーとその限界**: 収穫 robot のスタートアップ (W28 カード2 で観測した「自律農機は死ぬ」の系譜)、humanoid を農業に持ち込む UBTECH・Unitree など (事実: 報道あり)。**どちらも失敗の種類別の内訳を出していない** (推測)。研究側も成功率と cycle time までで止まっている。
- **対象者の技術との接続**: **評価設計の話で、P1 の「衝突率 vs 正常運転の採点」と同じ構造をしている**: 二値の成否ではなく、**失敗の重み付き cost** で方策を並べ直すと順位が変わるか。VLA の manipulation 評価に「失敗の種類別の損失」という軸を足すのは、W37 カード3 と同じく**報告する軸を1本足すだけ**で済む。
- **最初の一歩 (1週末)**: **表計算1枚。** AEWR (H-2A の最低賃金。州ごとに毎年告示される) と、りんご1箱あたりの単価を公開統計から取り、「成功率 x%・傷つけ率 y% のとき、人と同じ収穫コストになる (x, y) の境界線」を描く。**成功率が同じ 65% でも、傷つけ率によって採算が合ったり合わなかったりすることを示せれば、この課題は成立する。** 所要は2〜3時間。
