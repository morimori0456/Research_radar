### 課題: 連邦の ADS competency 基準は、今後3年かけて「測られる側」の大手によって書かれる。その間、中小の事業者は自分が合格するかを事前に確かめる手段がない

- **誰が困っているか / 深刻度**: 対象は L3 以上の中小事業者 (May Mobility: 3拠点、上場で $300M 超を調達する見込み)、トラック、そして Tesla Cybercab・Zoox のようにハンドルのない車 (現行の FMVSS と合わない、事実)。$1.4B の上場企業にとって、「3年後の基準に合格するか分からない」ことはそのまま開示すべきリスクになる (推測)。
- **なぜ未解決か**: **予算 $5M は、metric を作るには小さく、データを集めるには大手の走行ログに頼るしかない規模である** (推測)。consortium の参加者は ADS の開発者・製造者・運行者で (事実)、**基準は実質的に大手のデータ分布の上で決まる** (推測)。完成時期は公表されていない (事実)。
- **既存プレイヤーとその限界**: SAE・UL 4600 は safety case の書き方を定めるが、合否を判定する仕組みではない (W28 カード1)。Waymo は自社の論文で指標を出しているが、自己評価である。**W28 カード1 で「当局が試験法を公募している」と書いたことが、3年・$5M・FMVSS 行きという形で制度になった。**
- **対象者の技術との接続**: **P1 (planner 評価) の出口がここで具体的になる。** 実際に問われているのは「behavioral competency ごとの metric + repeatable な評価法」で、これは closed-loop planner 評価の研究課題そのものである。公開データ上で計算できる competency metric を論文にしておけば、consortium に外から入れる数少ない入口になる (推測)。
- **最初の一歩 (1週末)**: NHTSA の 2020 年 ANPRM "Framework for ADS Safety" ([Federal Register](https://www.federalregister.gov/documents/2020/12/03/2020-25930/framework-for-automated-driving-system-safety)) に並ぶ competency 候補 (ANPRM: 規則案の前段で意見を募る告示) を書き出す。それぞれについて **nuPlan / Waymo Open の公開ログで計算できるか (○ / △ / ×) を1枚の表にする。** ○の行が「外から出せる metric」の一覧になる。所要は半日。

### 課題: 学習ベースの運転ソフトが fork されて配布されると、「recall で直した」ことが利用者の車に届いたかを誰も確認できない

- **誰が困っているか / 深刻度**: Comma の利用者と、周りの道路利用者。事故は5件、死者3人 (事実)。失敗の型は「同じ車線の停止車両・低速車両」で、ADAS の失敗としては昔からある型である (事実: 調査の文言)。Comma の出荷台数は公開されていない (事実)。対応車種は数百あるので、影響を受ける人は数万人規模とみられる (推測)。
- **なぜ未解決か**: **recall は「製造者が OTA (Over-The-Air: 無線でのソフト更新) を配れば完了」という前提で設計されている。** open-source では、fork (Sunnypilot など) が本家の修正をいつ取り込むかを誰も管理していない (事実: 記事)。さらに openpilot の運転は E2E (End-to-End: カメラ入力から操作まで1つのモデルで出す) の学習モデルが担っている。**「修正」は重みの差し替えなので、ルールの diff のように目で見て確かめることができない** (推測)。W29 カード (学習方策の recall は「直した」ことを誰も確認できない) の**配布経路版**にあたる。
- **既存プレイヤーとその限界**: NHTSA が権限を持つ相手は「製造者」なので、fork の開発者は想定外である (事実: 記事)。Comma 本家は自社のリリースは管理できるが、fork には手を出せない。**修正がどの fork まで届いたかを測る仕組みはない。**
- **対象者の技術との接続**: **P1 (評価) と P2 (蒸留)。** 「同じシナリオ集合で、重みの版ごとに停止車両への反応を比べる」のは、regression test (以前できたことが壊れていないかの確認) を学習モデルに適用した形である。蒸留した student が teacher の安全挙動を保っているかを見る評価と、同じ道具で済む (推測)。
- **最初の一歩 (1週末)**: GitHub API で openpilot の主要 fork を列挙し、**各 fork が固定しているモデル重みのファイル (hash) と、本家の最新との遅れ (日数) を表にする。** 「本家が直しても N% の fork には M 日届かない」という数字が出れば、課題として成立する。所要は半日〜1日。英語の短い記事にもそのまま使える。

### 課題: robot 用の学習データが「時間単位」で売買され始めたが、1時間のデータが下流の性能をどれだけ上げるかを測る方法がない

- **誰が困っているか / 深刻度**: データを買う側 (humanoid・manipulation の企業) と、データを提供する側 (Index の利用者 約7万人/週)。Tesla は Optimus の稼働の一部を data 生成に回していると認めた (事実)。**生産設備の稼働時間を data に振り向けているのに、その対価がいくらかを誰も値付けできていない** (推測)。robotics への投資は 2026年に $23B に達し、前年全体に迫っている ([briefs.co](https://www.briefs.co/news/robotics-startups-raised-23-billion-in-2026-closing-in-on-all-of-2025/))。このうち相当額が data の収集に流れているとみられる (推測)。
- **なぜ未解決か**: data の価値は下流のタスク・モデル・既に持っている data に依存し、**「追加の1時間」の限界効用は学習をやり直さないと分からない** (推測)。data valuation (Data Shapley など) の研究はあるが、大規模 VLA では計算が重すぎる。そのため市場は「時間」と「多様性の自己申告」で値段を付けている (推測)。
- **既存プレイヤーとその限界**: Figure Index は自社で使うために集めている。9月に開いた data marketplace は egocentric 動画・teleop 記録 (遠隔操作で集めた実演データ) を売っているが、**買い手が品質を検証する手段は公開情報の範囲では見当たらない** (推測)。
- **対象者の技術との接続**: **P2 (蒸留) に直結する。** 蒸留の研究課題である「どの data で student を学習させると capacity gap が縮むか」は、data valuation とほぼ同じ問いである。teacher の出力を proxy (代わりの指標) に使えば、「学習し直さずに data 1時間の価値を見積もる」方法として研究課題になる (推測)。
- **最初の一歩 (1週末)**: LeRobot の公開データセットを1つ選ぶ (例: PushT)。**episode を 25/50/100% に random に間引いて小さな BC (behavior cloning: 実演を教師あり学習で真似る) 方策を学習させ、成功率と data 量の曲線を描く。** 次に、同じ本数を teacher の loss が高い順に選んで比べる。曲線に差が出れば、「時間」は価値の単位として不適切だと言える。2D toy の規模なら Jetson でも回る (推測)。
