## 課題カード (3枚)

### 課題: ハンドル無しの車が有料で人を運び始めたが、その「運転能力」を審査する関門は制度のどこにも無いことが、今週実車で証明された

- **誰が困っているか / 深刻度**: 直接の当事者は NHTSA と Austin の乗客45台分。だが本質的な当事者は**この経路を後から通る全社**である。AQ26002 が見るのは「車体が FMVSS に適合するか」だけで、**ADS (Automated Driving System) が安全に運転できるかは、連邦のどの手続きにも審査ポイントが無い** (事実: NHTSA 自身が audit query の範囲を compliance と明示)。Waymo が週50万回・14都市 (事実) まで来た規模に対し、審査は依然として**事後の recall と、事故報告の集計**しかない。
- **なぜまだ解決されていないか**: **FMVSS が「車体の物理」の基準であって「方策の振る舞い」の基準ではないから。** ミラー・ハンドル・エアバッグは静的に測れるが、運転能力は分布上の性質で、合否線を引くには「正常な運転を repeatable に採点する手法」が要る。それは W36 で観測したとおり **ASCEND が3年 $5M でこれから作る** ものである。**空席の時間差が最低3年ある**、というのが今週の新しい情報の実質だ (推測: その間に走る車の台数は、Waymo の目標値だけで年5,000万回オーダー)。
- **既存プレイヤーとその限界**: **NHTSA** — 手法を持たないので、持っている道具 (書類の compliance) で介入するしかない。**州** (Texas TxDMV) — 「公衆を危険にさらす」と判断すれば停止できる権限はあるが、判断の根拠となる指標を持たない (W36 記載)。**各社の内部 simulation** — 数は出せるが第三者が再実行できない。**空席は変わらず「測られる側でない主体が、公開ログで再実行できる運転能力の採点法」。** 今週の増分は、その空席が**思考実験ではなく、実際に有料運行が通り抜けた穴として可視化された**こと。
- **対象者の技術との接続**: **P1 / R1 の中心そのもの。** R1 の **solvability** (その瞬間に残っている逃げ道の本数) は、衝突が一度も起きていない走行に順序を付ける量であり、かつ走行ログから決定的に計算できる = **repeatable**。今週の事象は R1 の導入文を書き換える材料になる: 「基準が無い」という一般論から、**「2026-09-03 に、運転能力を一度も第三者審査されないまま有料運行が始まった」という日付入りの1文**へ。査読者に対する動機付けの強度が変わる (これは位置づけの話で、技術内容は変わらない)。
- **最初の一歩 (1週末)**: **[2609.04921](../briefs/2026-09-09/2609.04921.md) の結果を、R1 の図1の代わりに引用できるか30分で判定する。** 同論文は nuPlan closed-loop で「**標準ベンチで強い planner ほど、生成した難シナリオ下での劣化が大きい**」を独立 black-box planner で実測している。これは R1 が図1で言おうとしていること (ベンチの優劣 ≠ 安全性の優劣) と**同じ主張の、他人による実測**である。判定は YES/NO で出る: 引けるなら図1は「自分で測る図」から「他人の測定を再解釈する図」に降格でき、**必要な作業量が実験から作図に落ちる**。

### 課題: 規制の経路を選ぶ自由が「安全証拠を積むほど台数を制限される」逆インセンティブになっている

- **誰が困っているか / 深刻度**: ルールに従った側が損をしている。**Zoox は exemption を取り、年2,500台の上限を受け入れた。Tesla は self-certification を選び、上限は無い** (事実: 上記2ソース)。今は45台なので実害は小さいが、**制度がスケール局面で効く順序が逆になっている** — 証拠を出した者に上限が付き、出さなかった者に付かない。これは W35 で書いた「許可台数を決めるのが経済規制当局で、安全実績との接続関数が無い」の**連邦版**であり、同じ欠落が2階層で独立に現れた。
- **なぜまだ解決されていないか**: **「安全証拠 → 許可台数」という変換関数が誰にも書けないから。** exemption の 2,500台/年 は交渉で決まった数字であって、実績から導かれた数字ではない (推測。ただし公開文書に導出の記載は無い)。関数が無いので、規制当局には「上限をかける」か「かけない」の二値しか道具がなく、事業側から見ると**上限のかからない経路を選ぶことが常に支配戦略**になる。
- **既存プレイヤーとその限界**: **保険** — 台数と実績を価格で結ぶ唯一の既存メカニズムだが、robotaxi の料率根拠は非公開で、業界の共通言語にならない。**業界団体** (Auto Innovators) — W36 で意見提出期限を延ばした側であり、上限を導入する方向の合意は作りにくい (推測)。**ASCEND** — 採点法は作るが、**採点結果を台数に変換する部分は範囲外**。ここは誰も座っていない。
- **対象者の技術との接続**: 直接の研究テーマにはならないが、**R1 の指標に「単調性」という要件を1つ足す。** 台数に変換したい量は、走行が増えるほど推定が締まり、**証拠量に対して単調に動く**必要がある (衝突率は稀事象なので、この性質が悪い — 100万マイル走っても信頼区間が閉じない)。solvability のような**全走行で毎ステップ値が出る量**は、この点で構造的に有利である。**「なぜ衝突率ではだめか」の理由が、統計的検出力に加えて制度的な使い勝手からも1本増えた** (推測込み)。
- **最初の一歩 (1週末)**: **紙1枚。** 「1,000万マイル走ったとき、衝突率と solvability 分位点それぞれの信頼区間がどこまで締まるか」を、公開されている disengagement/crash rate の桁だけを仮定して手計算する。必要なのは二項分布と、solvability 側は毎ステップ観測できるという仮定だけ。**この図はカード1の図1の副図にもなり、投稿しなくても R1 の主張の背骨になる。** 所要2時間。

### 課題: 建設の労働不足が「慢性」から「締切つき」に変わったのに、robot が新しい現場で使えるようになるまでの時間を誰も測っていない

- **誰が困っているか / 深刻度**: 建設 GC とデータセンター事業者。**2026年に349,000人、2027年に456,000人の追加労働者が必要。未充足なら $124B の産出損失、2028年までに熟練工200万人超の不足** (Deloitte 試算)。従来この不足は慢性的なコスト問題だったが、需要の筆頭が **AI データセンター建設**に移ったことで**締切のある不足**になった (事実: 上記 IBTimes の主題)。締切がある不足では、買い手の要件が「人より安い」から「**人より早く立ち上がる**」に変わる。
- **なぜまだ解決されていないか**: **robotics 側が最適化してきた量が違うから。** ブロック積み・鉄筋結束・墨出しの robot は既に現場に入っている (事実) が、売り込みも論文も **「導入後の生産性」** を報告し、**「導入までの時間」** は誰も報告しない。建設現場は日ごとにレイアウトが変わり、同じサイトでも昨日の設定が今日通用しない。つまり必要なのは1回のセットアップ時間ではなく、**毎朝の再立ち上げ時間**である。この量が測られていないので、GC は締切に間に合うかを見積もれず、**間に合わないリスクを取るくらいなら人を高く買う** (推測だが、上の不足が数字として残り続けていることと整合する)。
- **既存プレイヤーとその限界**: 建設 robotics 各社 (W34 で観測した「他社の既存機に後付けする」路線を含む) は**サイト単位の実績**で語る。**humanoid 系**は「人と同じ作業」を掲げるが、W36 カード3 で書いたとおり「同じ作業」の中身が定義されていない。**ベンチマーク側** (RoboArena 等の実機評価) はタスク成功率までで、**成功に至るまでに要したデモ数・調整時間を報告する設計になっていない**。空席は「新環境での **time-to-first-useful-task**」という単一指標。
- **対象者の技術との接続**: **P3 (VLA) の評価設計に直結し、W33 カード3 (「1箇所で証明した性能を次へ持ち越せない」) の時間軸版になる。** VLA の売りは zero-shot / few-shot の汎化だが、その主張は現在**成功率でしか検証されていない**。同じモデルを「新環境で最初の有用な1回に到達するまでのデモ数・秒数」で測ると、汎化の主張が事業側の要件語 (立ち上げ時間) に直訳される。**測定対象は変わらず、報告する軸を1本足すだけ**で、これは対象者が既に持っている評価の道具で足りる。
- **最初の一歩 (1週末)**: **公開されている VLA / manipulation の論文5本を選び、「新環境での初回成功に要したデモ数または調整時間」が本文中に書いてあるかを ○/× で表にする。** ほぼ全部が × になるはずで (推測)、**その空欄の表そのものが成果物**である。英語で1ページにすれば発信物 (Phase 1 の3目標のひとつ) を兼ね、かつ「報告項目を1つ足そう」という主張は査読論文より短い形式で出せる。所要は半日。
