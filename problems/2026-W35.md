## 課題カード (3枚)

### 課題: 学習方策の recall は「直したこと」を誰も確認できない — OTA を配った時点で「完了」になっている

- **誰が困っているか / 深刻度**: 規制当局 (NHTSA ODI)、運行事業者、そして事故に遭う側。2026年だけで AV の ADS recall は Waymo 3,800台 (冠水路, 5/12)・Waymo 3,871台 (高速の工事区間, 6/18, campaign 26E035)・Zoox 105台 (26E044)・school bus 関連 (2025/12) と積み上がる。決定的な事実として、**Waymo は school bus 案件で「11/17 にソフト更新で是正完了」と学区に伝えたが、学区は 12/1 に同種の違反映像を提出した**。是正が効いていない状態で「完了」と報告できてしまう。[The Robot Report](https://www.therobotreport.com/waaymo-recalls-robotaxi-software-after-school-bus-safety-failures/) / [KXAN](https://www.kxan.com/investigations/waymo-recalls-software-for-self-driving-cars-following-school-bus-violations/) / [NHTSA 26E035](https://static.nhtsa.gov/odi/rcl/2026/RCAK-26E035-6843.pdf)
- **なぜまだ解決されていないか**: **制度の設計が部品交換を前提にしているから。** NHTSA が追うのは **completion rate (該当車両のうち是正措置が適用された割合)** で、機械部品ならこれで十分だった — 部品が載れば欠陥は消える。学習方策では「重みが載った」と「その振る舞いが消えた」が別物なのに、制度側に後者を測る欄がない。技術側の理由は **統計的検出力**: 対象事象がレアなほど、消えたことの確認に必要な曝露量が跳ね上がる (Austin では1学年で19件 = 遭遇あたり数%オーダー)。加えて **regression (直した副作用で別の振る舞いが壊れること) を測る枠組み**も公開されていない。
- **既存プレイヤーとその限界**: NHTSA ODI = completion rate 止まり。各社の内部 simulation/replay = 非公開で第三者が同じ試験を再実行できない。Austin 学区のバス車載カメラ = 実は**最も機能した検証装置**だが、対象が1都市の1事象型に限られ、たまたま定点観測が存在しただけ (推測: 他の是正事案には対応する観測者がいない)。
- **対象者の技術との接続**: **P1 (planner 評価) の中心にほぼ一致する。** ただし問いの形が普段と違い、「方策 A は良いか」ではなく「**方策 A → A' の差分が、狙った事象を消し、他を壊していないか**」— つまり targeted behavior regression testing。scenario-conditioned な評価集合と、**確認に必要な曝露量の見積り**が要る。蒸留 (P2) では同じ道具が「蒸留後 student が teacher の稀な安全挙動を落としていないか」の検出にそのまま移る。
- **最初の一歩 (1週末)**: **検出力の計算を1枚の図にする。** 「レアイベントの発生率 p、是正で p→p/10 を有意水準 5%・検出力 80% で示すのに必要な遭遇回数 N」を p の関数でプロットし、Austin の実数 (1学年19件) と Waymo の公表走行規模を当てはめて **「是正の確認に何ヶ月かかるか」**を出す。数ヶ月〜数年になれば、「OTA 配布 = 是正完了」という制度は原理的に成立しないと数字で言えて、次の問い (曝露を待たずに確認する方法 = 標的シナリオ試験の設計) が立つ。

### 課題: 許可される「台数」を決めているのが経済規制当局で、安全実績との接続関数が存在しない

- **誰が困っているか / 深刻度**: 州の規制当局、保険、自治体、そして先行企業 (実績のない後発と同じ土俵に置かれる)。今週 Nevada で一度に 7,000〜8,000台の上限が出た。注目点は **決めたのが Nevada *Transportation* Authority — 料金・事業免許を扱う経済規制当局**であって安全規制当局ではないこと。**Tesla が 5,000台**で、公開されている driverless 実績は Waymo と比較可能な水準にない (推測: 少なくとも第三者が比較できる公開データがない)。全米の robotaxi は週70万回超 (米45万・中国25万, McKinsey) の規模に達している。
- **なぜまだ解決されていないか**: **「台数」という軸を扱う制度部品が存在しないから。** 現行の道具は全て二値 (exemption を出す/出さない、許可する/しない) で、**蓄積した証拠量 → 許される fleet 規模**を写す関数がない。連邦側も同じ方向で、8/31 締切の interim guidance は exemption の可否手続きの整備であって台数の刻み方ではない。DOT 長官は「50州50ルールでは企業がスケールできない」と統一標準を志向するが (推測: 統一の圧力は下限を上げるより上限を緩める方向に働きやすい)、その統一標準にも段階的認可の形は今のところ見えない。
- **既存プレイヤーとその限界**: CA DMV/CPUC = 段階制を持つが州内限定・手続き重視で、証拠量と台数の対応が明文化されていない。NHTSA exemption = 上限台数の概念はあるが年間の販売台数枠であって運行実績連動ではない。保険 = 本来この関数を持つべき主体 (料率 = リスク×曝露) だが、AV の料率算定根拠は非公開。
- **対象者の技術との接続**: これは **safety case の「量」への拡張**。W33/W34 で追ってきた「証拠の転移」の次の形で、問いは「都市 A の証拠は都市 B でいくら割り引かれるか」から「**証拠 X 単位は、台数 Y をどこまで正当化するか**」に変わる。planner 評価の指標を、可否判定ではなく **exposure budget (許容される曝露量)** の推定に使い直す発想。
- **最初の一歩 (1週末)**: **散布図1枚で「関数が無い」ことを実証する。** 公開データ (CA DMV の autonomous mileage/disengagement CSV、CPUC の四半期報告、各州の許可発表) から、企業×州ごとに **横軸 = 許可時点での累積 driverless マイル、縦軸 = 許可された台数上限**をプロットする。相関が見えなければ「台数は実績と無関係に決まっている」が図で言える。相関が見えたら、その傾き = 現在市場が暗黙に使っている交換レートで、こちらの方が発見として大きい。
- (関連: W28 カード3「第三者検証の不在」、W33 カード3「証拠の転移」。本カードの増分は**可否の軸ではなく数量の軸**であること。)

### 課題: 自動運転トラックの収益源は「人間の運転データが存在しない運行条件」— 比較対象が空の場所で安全を主張している

- **誰が困っているか / 深刻度**: 荷主・保険・FMCSA、そして「人間より安全」を証明したい各社自身。米国の物流は **倉庫職 約50万件の欠員**、**ドライバー不足は2026年末に全世界240万人超**という需要圧の中にある。Aurora は Fort Worth–Phoenix 約1,000マイル路線を開設したが、これは **単独ドライバーの federal Hours of Service (HOS — 連邦の連続運転・休憩規制) を超える距離**であることが商品価値そのものである (2026-02 開設、以後10路線・累計25万 driverless マイル)。Kodiak/Atlas は **積載135トン超の triple-trailer** 運行を開始 (2026年前半)、公道進出は2027年前半予定。[truckinginfo](https://www.truckinginfo.com/news/aurora-adds-1000-mile-driverless-run-from-fort-worth-to-phoenix) / [Kodiak](https://kodiak.ai/news/atlas-driverless-permian-expansion)
- **なぜまだ解決されていないか**: **論理の穴が儲けと同じ場所にあるから。** 業界標準の安全主張は「人間ドライバーの事故率と比較して〜」だが、その人間の統計は **HOS 内で運転された人間のマイル**からしか作れない。**HOS を超える連続運行・triple-trailer という、まさに黒字化を担う条件には人間の基準線が原理的に存在しない。** さらに、連続20時間級の運行で問題になるのは方策の巧拙より **degradation (センサ較正ずれ・熱・汚れが時間とともに蓄積する劣化)** だが、公開の crash rate は連続運行時間で層別されていない (推測: FMCSA の大型車事故統計に driverless の連続稼働時間軸は無い)。誰も測っていない軸に価値が寄っている。
- **既存プレイヤーとその限界**: Aurora の safety case = 「Aurora Driver 起因の衝突ゼロ / 25万マイル」— **母数がレアイベントの検出に足りない**うえ、比較先が明示されていない。FMCSA の統計 = 層別なし。Teamsters は CA DMV を提訴中だが、争点は経済影響評価であって運行条件別の安全証拠ではない。保険 = 事実上ケースバイケース (推測)。
- **対象者の技術との接続**: 評価の入口が「指標の作り方」ではなく **comparison class の選び方 (何と比べるのが妥当か)** になる点が新しく、planner 評価の設計判断そのもの。加えて **長時間運行下の性能劣化を測る**問いは、蒸留 (P2) の「軽量 student が長時間・入力劣化下で先に壊れないか」と同じ実験装置で扱える。VLA/E2E (P3) では入力分布のドリフトに対する頑健性の話に直結する。
- **最初の一歩 (1週末)**: **「基準線が無い区間」を数える。** 各社が公表している路線 (Aurora 10路線、Kodiak の Permian 15ルート) の距離を地図から拾い、FMCSA の HOS 規則 (11時間運転 / 14時間勤務) に照らして **「単独ドライバーで1シフト完結できない路線の割合」**を出す。次に FMCSA の大型車事故統計を見て、**連続運転時間で層別された事故率が公開されているか**を確認する — 無ければ「収益路線の安全比較には使える基準線が無い」が事実として確定し、それ自体が発表できる観測になる。

- **反復テーマ (W28→W35 で7週不動): 「学習方策の性能を、誰がどう客観的に測るか」。** 今週の増分は、この問いが**3つの別々の関節に同時に現れた**こと。W34 までは「基準が無い」という1点の指摘だったが、今週は (a) **是正の確認** (recall の効果)、(b) **認可の量** (台数)、(c) **比較対象の選択** (HOS 超え路線) と、制度の異なる箇所で同じ欠落が独立に露出した。**同じ穴が3箇所に空いているなら、それは個別の制度不備ではなく、評価という部品が存在しないことの帰結である** (推測だが、この解釈は今週初めて成立した)。
- **今週入った新しい軸: 「時間」が変数になった。** 過去のカードは全て静的な評価 (この方策は安全か) だったが、今週は **差分の評価 (直したか)** と **持続の評価 (20時間走った後も同じか)** が入った。どちらも1回の試験では答えられず、**評価を「試験」ではなく「監視」として設計する**必要がある。これは事業形態としても意味が違い、売り物が一度の認証ではなく継続契約になる (推測)。
