# VLA / World Model / E2E Driving — Living Survey
最終更新: 2026-08-30

## 一言でいうと
言語・視覚・行動を1つのモデルで扱う **VLA (Vision-Language-Action)** と、世界の遷移を予測する **world model** を
end-to-end 自動運転にどう接続するかを追う分野。論点は「どう繋ぐか」→「世界状態をどう保持するか」→「未来を*描く*必要があるのか」→
「何で測るのか」(W33) → **使い方の順序尺度**(W34)と降り、**2026-W35 で問いが「どう作るか」から「そもそも使えるのか」へ移った。**
**5本が独立に収束した命題が1つ: world model の予測対象は、下流が読める表現・行動が実行される空間に合わせろ**
(画素は幾何・動き・見た目を混ぜて持っているので、状態表現としては間接的すぎる)。
**そして使用可否を分ける軸が最後に入った —— 自己訂正が起きない world model は、長い rollout を要求する planner の下では原理的に使えない。**
**中心の問いも書けるようになった: 記憶の置き場所・未来の返し方・行動の座標系のどれを見ても選択肢が並列に存在する以上、
「world model を*別に立てる*必然性は何か」。** これは R3 の主張として成立しうる形をしている。

## 系譜マップ
- **★ 「使えるか否か」を分ける軸 —— 自己訂正の有無(2026-W35 新設。他の軸と違い良し悪しではない)**
  - **VGI-Bench (19583、hf 170)** — 映像生成モデルの視覚的推論を測るベンチ (27 タスク・810 事例、**最強の Seedance 2.0 でも 51.0%**)。
    **最も重い発見は denoising 過程の内部観察から出た: 後段ステップは初期に立てた仮説を精緻化しているだけで、推論の誤りを訂正していない。**
    **★ world model を planner の内側に置くとき、我々は暗黙に「多少ずれてもモデルが妥当な方向に引き戻してくれる」と期待している。
    その期待が成り立たない** —— 途中で経路がおかしくなっても、モデルは**おかしいまま、最後までもっともらしく**進む。
    **判定は半日で付く: rollout の途中に意図的に誤った状態を注入し、以降が訂正するか誤りを前提に進むかを見るだけ。
    訂正が起きないなら「world model を別立てにする論拠」か「短い horizon に限る制約」のどちらかが確定する。**
  - **設計要件としてもう1点: 「最終フレームがもっともらしいか」ではなく「そこに至る過程が妥当か」を採点対象に入れたこと。**
    終点だけを見る評価では**途中を飛ばして正解の絵に着地したモデルが満点を取れてしまう。**
    **推論の媒体として生成を使う以上、過程こそが推論そのものである。**難易度の較正 (全モデルが 0% か 100% を取るタスクは差を語らない) も明示的な設計要件
- **★ 未来を「1本」返すか「分布」で返すか(2026-W35 新設。軸2)**
  - **PAWBench (27345、hf 73)** — **同じ初期状態・同じ行動から複数の結果があり得る**(コップを縁に押せば落ちることも踏みとどまることもある)。
    いまの評価は「生成された1本の動画がもっともらしいか」しか見ないので、**あり得た別の結末を丸ごと見落としたモデルが満点を取れる。**
    著者は **probabilistic alignment (同じ条件で反復生成させたとき、結果の出現頻度が現実の確率分布と一致していること)** を要件として置いた。
    **評価手続き PAWEval の巧さ: 画素を比べるのではなく「落ちた/落ちなかった」という離散的な結末に射影してから頻度を数える ——
    画質の評価と挙動の評価を切り離している。** 50 シナリオ・11 システムで、**正しい頻度を出しつつ挙動の幅もカバーできたモデルはゼロ。**
  - **★ この軸が効く理由: 下流の planner が world model に何を要求するかがここで決まる。1本しか返せない world model の上に、
    複数シナリオを比較する planner は載らない。** そして **W35 時点で「未来を分布として返す world model の上に載る planner」の事例が
    4軸のどこにも無い —— これが R3 の空白の第一候補である**
- **★ 画素は world model の言語として粗すぎる —— 5本が独立に収束(2026-W35 で確定)**
  - **Gen2Sim (23070)** — **実装を伴う 163 本のうち、実行中に状態を外から問い合わせられるのは6本だけ。**最も一般的な根拠
  - **GeoWAM (23486)** — **未来の画像でなく未来の幾何を予測する事前学習**に変えたら open-loop でも closed-loop でも強くなった。
    **幾何は画素と違って、そのまま問い合わせ可能な状態である** —— Gen2Sim の指摘に構造で答えた具体的な反例
  - **WorldSync / WorldEcho (24885)** — **評価の物差しも画素でなく SE(3) 幾何へ移せ。★ 診断がさらに重い:
    world model は専門家の行動なら概ね実行するが、専門家がやらない妥当な行動では指令を無視するか映像が破綻する。**
    **world model を方策の学習・評価基盤として使う価値は、まさに専門家がやらない行動を試せるところにあった。
    つまりこの構想は、いちばん要る場所でいちばん弱い**
  - **MomADv2 (23405)** — 記憶は「持つ」ではなく **「どれを捨てるか」**を設計する。**上位指示が「右折」から「直進」に切り替わった瞬間、
    それ以前の記憶は現在の意図と矛盾する。**時間的連続性と指示整合性の2基準で過去の計画を濾す。
    **汎用の教訓が2つ: ① SSM (State Space Model) を速度のためでなく「選択のため」に使う** ——
    入力に応じて過去の取り込み量を変える性質が「指示が変わったら過去を流す」に構造的に一致する (**SSM を採る動機として計算量以外の具体例**)。
    **② 粗い候補から選ぶ + 連続的な残差で微修正するという二段構えの action 出力は、driving を離れて VLA にそのまま移せる**
  - **CLAP (27406)** — 人間動画と複数機種を混ぜて1つの world model に。**共通化の足場は手先姿勢 = 物理量。**
    → **軸「行動をどの座標系で表現するか」が3値で埋まる: 機種専用 / 潜在で共通化 / 物理量で共通化**
  - **★ 対極の解答も同じ週に出た: RoG-DAgger (24525)** — 学習した world model の代わりに、
    **車両の運動モデルという「間違えようがない、ただし粗い」予測器**で未来を評価する。**忠実度は低いが、行動追従性は定義上完璧である。**
    **WorldSync と並べると軸が1本立つ: 「行動追従性を、専門家分布の外でどう担保しているか」。この軸で既存手法を並べると大半が空欄になる**
- **★ 時間をどこに持つか(2026-W35 で表が埋まった。軸1)**

  | 手法 | 過去の保持 | 未来の予測 | 系列が伸びたときのコスト |
  |---|---|---|---|
  | **StreamPI (26067)** | context の中 (attention、暗黙) | しない | **系列長とともに増える** |
  | **LM-X (25757)** | 持たない | スカラー要約量 (進捗・事象・分散) | 一定 |
  | **VoiceMem (26005)**(分野外) | 外部ストア | しない | 明示的な検索 (134ms) でほぼ一定 |
  | world model 併設型 | 潜在状態 | 観測そのものを生成 | 大きく、一定 |

  - **★ 右端の列が設計選択を決めている。**StreamPI 型は作業が短いうちは最も素直で安いが、数分〜数十分に伸びると context が破綻する。
    VoiceMem 型は初期コストが高いが伸びない。**つまり「VLA にどう記憶を持たせるか」に単一の正解は無く、想定タスクの時間長で答えが変わる**
    —— **マップの軸として「対象タスクの時間スケール」を明示的に持つべきである** (wildcard 枠の分野外1本を並べて初めて見えた軸)
  - **★ そして表のいちばん下の行 —— 観測そのものを生成する方式 —— が、コストが最も高く、行動追従性が最も怪しい (WorldSync)。
    上3行が同程度の性能を出すのなら、R3 の中心的な問いはこうなる: world model を別に立てる必然性は何か。
    マップを作る作業が、そのまま主張の準備になる**
  - **StreamPI の設計判断2つは移植価値が高い**: ① **(視覚観測, 言語指示) のペアを時間の最小単位にする** ——
    フレームを継ぎ足すのではなく**毎時刻に言語指示を置き直す** (単純に系列を伸ばすと最初の指示が薄まる。
    **指示を各時刻に錨として置けば、作業のどの時点でも同じ強さで効く**)。ペア内は双方向 attention、ペア間は因果的 attention で streaming 推論を保つ。
    **新規パラメータはゼロで、既存の事前学習済み重みをそのまま引き継げる。**
    ② **学習時のフレーム間隔をランダムに振る** —— 学習と実機で「時間の流れ方」が違うという問題への、データ側からの回答
  - **LM-X (25757)** — 行動を出すモデルに **RTG (return-to-go; 作業の残り工程量)・ETG (event-to-go; 次の意味的な区切りまでの距離)・
    heteroscedastic な分散 (入力ごとにばらつきの大きさ自体が変わる)** を明示的に吐かせ、行動生成に戻す。
    **1つの行動出力が進捗も意図も自信も暗黙に背負う状態をやめる** = **実行中に外から読める。**
    50 タスクで **74.1% (GR00T N1.7 は 55.4%)**、実機7タスクで **68.6% (同 50.7%)**、ablation で行動のみ構成に **+16.0 ポイント。**
    **★ 手法より手続きが白眉: 64 GPU × 20日の本番学習の前に、5タスクの統制実験で設計の各要素が効くことを確認している**
- **★ R3 分類マップ —— 4軸が確定(2026-W34。08-19 から2回直したが、最後の直しは「足りない」ではなく「順序があった」という発見)**
  - **軸1: world model をいつ・どう使うか —— 順序を持つ1次元。後ろほど学習の誤りが決定に直接効く**

    | 段 | 使い方 | 実例 | 誤ったとき |
    |---|---|---|---|
    | 1 | **学習時**(表現学習・データ生成) | 既存手法の大半 | 学習の失敗として現れる |
    | 2 | **評価時**(方策の採点) | Hydra-0(落選、r=0.96) | 方策選択を誤る |
    | 3 | **推論時 — 許容集合の後の順位付け** | **Calibrated Predictive Safety (17496)** | **許容集合の外には出られない。保証は壊れない** |
    | 4 | **推論時 — 選択そのもの** | **DA-WAM (19085)** / **τ₀-VLA (16885)** | 誤った候補が選ばれる(所在は特定できる) |
    | 5 | **推論時 — 探索の規則を生成** | **RP1 (18669)** | **world model の誤りか探索器の誤りか事後に切り分けられない** |

    **段3だけが、学習モデルの誤りに対して構造的に頑健である。** そして **RP1 にはもう1つ悪い性質がある** ——
    **探索器は world model の想像だけで学習されるので、world model の誤差が大きい領域を積極的に突きに行く動機を構造的に持つ**
    (model exploitation の分析が論文に無い = 本文の最優先確認箇所)
  - **軸2: 内部表現は何か** — BEV / occupancy / 点群 / **意味を持った 3D** / **部分的に記号化された潜在** /
    **直交成分に分解された潜在**。**GaussianDWM++ (16234)** が「言語で指せる」性質を表現レベルで持つ唯一の実例、
    **Orthogonal JEPA (20065)** が最新の追加(下記)、**Neurosymbolic World Models (17959、落選)** が記号側の実例
  - **軸3: 受理基準 —— その world model を、何をもって信頼するのか(2026-W34 で中身が入った)**
    - **意思決定の側から: Decision-Metric Alignment (18746)** — **受理基準は再構成誤差でも probe 精度でもなく、
      「潜在コストが候補を実タスクの順に並べるか」。** **潜在から中身が読み取れることと、その表現で並べ替えてよいことは別の能力である。**
      指標は2つ: ① ランダム行動列での順位相関、② **探索が絞り込む各段階での同じ一致度**(こちらが本質 ——
      **全体で合っていても拮抗した候補の間で崩れるなら、探索は最後の一歩で誤る**)。
      **決め手は改善側から: 行動を条件に含める目的関数を足すと成功率は上がるのに probe スコアは変わらない**
    - **生成物の側から: SemComp-Bench (17426)** — **結果の達成と意味的な接地を別々に採点し、判定を検証可能な二値質問の集合に分解する。**
      **driving への直訳は容易** —— 達成 = ego が意図した状態に到達したか、接地 = 他車の同一性・道路構造・物理が保存されているか。
      **留保: VLM 審判と人間の判断の一致率が無く、審判の妥当性検証が無ければ審判のバイアスを測っているだけかもしれない**
    - **サンプリングの側から(2026-W34、planner-evaluation と共有): (1-r)^N (17956)** — **「その world model を N 回転がして
      問題が出なかった」が保証する量には閉じた式で天井がある。** マップは使い方を分類していたが受理基準を分類していなかった
  - **軸4(副軸): 予測器を凍結するか、共進化させるか** — **17496 は encoder を凍結**し、
    **19085 は momentum target(本体の重みを緩やかに追う複製)で planner 最適化中も予測の教師信号を切らさない。**
    **同じ週に両極が揃ったので軸として立てる根拠がある**
  - **★ 軸5(2026-W34 新設): 統合の場所は「重みの内側」か「実行時の外殻」か** —
    **Zetta (16590)** と **EnvHarness (19880)** が同じ週に独立に後者へ振れた。**R3 は暗黙に「1つのネットワークに統合する」を
    前提していたが、凍結した基盤 + 進化する足場という形が並列の選択肢として存在する**(harness-and-scaffolding サーベイに詳述)
  - **★ 軸を自分で発明せずに引く手がある: What Matters for Latent Actions (19613)** —
    **LAM (Latent Action Model; 動作ラベルのない動画から、連続2フレームの差を説明する「潜在的な行動」を教師なしで取り出し、
    本物の行動の代用として方策学習に使うモデル)** の設計選択を **41 通り・3次元**で横断比較
    (潜在行動の表現形式 / 学習目的と正則化 / 下流の方策への繋ぎ方)。**41 通りで検証済みの軸を引くほうが、自前で発明するより速く強い。**
    **R3 を「調査中」から動かす、最も実行コストの低い一手。** 主要結論も使える ——
    **VLM backbone を潜在行動で fine-tuning したものが、下流の方策学習の初期値として最も強い。**
    **なお本論文は4つ目の検証として「潜在行動の質を測る4つの proxy 指標が下流性能を予測できるか」を評価しており、
    18746 と完全に同型の問い。分野も手法も無関係な2本が同じ穴を独立に指摘した**
- **★ 支配的成分による容量独占(2026-W34 新設)— 自動運転 world model の構造的な病**
  - **Orthogonal JEPA (20065)** — **自車の並進運動と背景の流れが分散の大半を占め、他車の意図・遠方の小物体・信号といった
    「小さいが判断を左右する成分」に容量が回らない。** 予測経路を**直交する複数成分に割る**ことで支配的成分に潰されないようにする。
  - **★ 18746 と組むと、測る手段と直す手段が揃う**: **factorize した各成分に対して decision-metric alignment を個別に測る。**
    **「表現全体では判断に使えないが、この factor だけは使える」が観測できれば、planner に渡す latent の部分集合を選ぶ根拠になる**
- **★ 適合は重みの内側だけで行うものではない(2026-W34)— 90% → 10% が突きつけたもの**
  - **GS-VLA (19066)** — **VLA は標準ベンチで9割成功するが、カメラの取り付け位置をわずかにずらすと最悪ケースで1割まで落ちる。**
    解き方は「方策の問題」を「画像の問題」に作り替えること: カメラの動きが作業空間に対して十分小さければ、
    **視点の正規化は「新たに見えるようになった領域を埋める」というシーンにも方策にも依存しない課題に縮約される。**
    **400万パラメータの 3D Gaussian Splatting ベース正規化器を、凍結した方策の手前に挿すだけ。**
    方策アーキテクチャを変えても、未見タスクでも、摂動の大きさを変えても効く(この3軸で「特定の方策に合わせ込んだのではない」を支える)。
  - **★ R3 の動機付けが1本増えた**: **崩れ方がここまで急峻なら、VLA の内部表現は 3D 的に接地していない。**
    **すると world model を統合する動機は「未来が読めるから」だけでなく「3D 的な接地を持ち込めるから」という第2の柱を持つ**
  - **留保**: 「plug-and-play」を名乗る条件が abstract から読めない。**3D Gaussian 表現の構築にシーンごとの前処理が要るなら配備コストはゼロではない**
- **★ 統合を「表現の中で」行う側 vs 「推論時の手続きで」行う側(2026-W34 で両極が揃った)**
  - **表現の中で: GaussianDWM++ (16234)** — 点群 / occupancy / BEV は**テキストと 3D 構造を細かい粒度で対応づけられない**
    (「右前方の白いバンだけ消して」の指す先が表現上で決まらない)。**3D Gaussian に視覚言語モデル (Qwen/SigLIP) の特徴を蒸留して埋め込み**、
    事前に決めたクラス集合に縛られず**任意の語で 3D を指せる意味場**を作る。理解・言語推論・天候や車両の編集・生成が一枚に載る。
    **見落としやすい点: Gaussian tokenizer がやっているのは蒸留である**(teacher は 2D 画像特徴、student は 3D プリミティブ上の特徴場 ——
    **形がまったく違う。「別表現への転用」という形の蒸留であり、容量比では測れない例がまた1つ増えた**)
  - **推論時の手続きで: τ₀-VLA (16885)** — 階層 VLA の**上位の判断が毎回1回の forward pass で出ている**ことを欠陥として指摘。
    **「ここで開けるか、先に退けるか」という後戻りできない選択にも「そのまま続ける」にも同じ計算しか割かれていない。**
    上位判断を **compute-scalable な推論問題**に書き直し、必要なときだけ代替案を探索し、**その探索の審判に world model を使う。**
    **P1 にも刺さる: 同じ方策が計算量に応じて性能を変えるなら、性能は1点ではなく曲線として測らねばならない**
    (**留保: 探索の具体形 —— 幅・深さ・打ち切り条件、いつ探索を起動するかの判定 —— が abstract に無く、ここが実用性を決める**)
- **★ world state を context に持つか、外部に持つか(2026-W33 末 → W34 も有効)**
  - **Alaya-EVOKE (13546)** — 素朴な実装は「見てきたもの全部」をネットワークの入力に抱え続けるので、session が伸びるほど遅く重くなる。
    **シーンの幾何をネットワークの外の倉庫に置き、カメラの向きで索引を張って、今の視界に要る分だけ取り出す** ——

    - **token/feature で混ぜる側は失敗すると名指しされた: BrainWAM (12854)** — 運転の planning は

      共有 attention 空間を占拠し、予測ダイナミクス側の寄与が抑え込まれる**(attention-allocation mismatch)。**足したのに片方しか働いていない。**

      **重み共有の効果がいちばん面白い部分: 追加学習なしにプロンプトを書き換えるだけで動作の粒度・タスクの長さ・未知シーンでの振る舞いが変わる**

  - **RynnBrain 1.1 (17977)** — 2B→122B の open な MoE family。「1バックボーン + embodiment-specific masking で異機体を跨ぐ」recipe。標準ベースライン/蒸留 teacher 化の公算(hf=136)
- 行動ラベルなしで監督を作る
  - latent action: **WALA (11397)** — action-free 動画から実行可能な latent action を学習。予測ターゲットは raw pixel でなく **DINOv3 特徴 + depth の delta**
  - flow を action 表現に: **FlowWAM (13017)** — optical flow は RGB と同形式なので同一動画生成器で dual-stream 化、policy mode / world-model mode を1モデルで。flow は生動画から自動抽出=action-free 事前学習
  - デモを一切使わない: **TerraZero (13028)** — 実ログは**地図形状のみ**、あとは手続き生成 + self-play RL。左側通行まで創発
  - 生成 pretraining の転移: **GenCeption (09024)** — text-to-video 生成 backbone を feed-forward な知覚モデルに転用し専用 SOTA に 1/7〜1/500 のデータで並ぶ。「world model 的 pretraining は知覚・3D にどれだけ転移するか」の定量的根拠
- world model の表現を行動に近づける
  - **RynnWorld-4D (06559)** — RGB+depth+flow の 4D 予測、denoising を回さず 1-forward で行動
  - 共通教訓: 明示的幾何(点群骨格 / depth+flow / pointmap)の係留が長時間 rollout の安定性と行動接続を改善
- 推論ステップを畳む(diffusion → 一発生成)— planner-evaluation サーベイの DRIFT/VSFM と同一潮流
  - **DriftWorld (15065)** — 学習時に action-conditioned drift を獲得し推論は単一 forward。diffusion 比 **17倍高速・30+fps** で推論時 action search が実用域に
- 長期文脈: **どこでコストを払うか**の両端
  - 推論時に畳む: **RoboTTT (15275)** — TTT の fast weights に履歴を圧縮し 8K timestep、レイテンシ不変。**context 長 = 新しい scaling 軸**(閉ループ性能が単調改善)
  - 学習時に畳む: **LongStraw (14952)** — GRPO の共有 prompt を autograd 外に出し応答ブランチを1本ずつ replay。2M+ token の RL を固定 GPU で実行可能に(※著者自ら「実行可能性であって学習の正しさではない」と留保。精度主張には引用不可)
  - latent memory: **LaMem-VLA (07608)** — short/long dual memory
- world model を「評価器」にする(planner-evaluation サーベイと相互参照)
  - **Point as Skeleton (06516)** — 生成型 closed-loop 評価、nuPlan IF 公開
  - **WM Admissibility (07196)** — L0–L4 認定 ladder。視覚品質上位 ≠ 行動追従性上位の「逆転」を実証
  - **KineBench (19876)** — 評価から **抽出器誤差を追い出す**。生成映像から行動を逆推定する IDM をやめ、汎用視覚 FM で手先 6D pose を直接抽出 → 物理シミュで再実行して closed-loop 検証。IDM が OOD で壊れる **attribution ambiguity** を回避(planner-evaluation サーベイと相互参照)
- 学習パラダイム
  - **Post-Training in E2E AD (08072)** — 模倣後の post-training を教師信号の形式で4分類した初の統一サーベイ。「事前学習(模倣)+post-training」の2段構え設計の根拠
- 実時間化の基準点
  - **Vidu S1 (03118)** — 民生 GPU 540p/42FPS の対話型生成。few-step 蒸留+専用サービングを対で設計

## Open Questions
- **★ 手持ちの world model 候補は、rollout 途中に誤った状態を注入されたとき訂正するか**(19583)—
  **訂正が起きないなら、その world model を閉ループ planner に入れる構成は成立しない。「別立てにする論拠」か
  「短い horizon に限る制約」か、どちらに転んでも R3 の設計判断が1つ確定する。半日**(W35 の第2候補実験)
- **★ 「未来を分布として返す world model の上に載る planner」の事例は、本当に存在しないのか**(27345)—
  **4軸のどこにも見当たらない。空白であることを確認できれば、それ自体が R3 の空白 = 研究機会の証明になる。
  列を1本 (「1本 / 分布」) だけ埋めるのが最短**
- **★ 上3行 (context / スカラー要約 / 外部ストア) が同程度の性能を出すなら、world model を別に立てる必然性は何か**
  (26067 × 25757 × 26005 × 24885)— **R3 の中心的な問い。マップを作る作業がそのまま主張の準備になる**
- **同一初期状態から 20 回 rollout して結末の分散を測ると、手持ちの world model はどうか**(27345)—
  **分散がほぼゼロならそれは決定的予測器であり、別立てにする論拠が1つ消える。逆に分散が出れば必然性の証拠。半日**
- **AD に embodiment gap はあるか**(27406)— 走行ログを2車種以上に分け、**曲率・加速度の系列だけを共通表現として
  片方で学習・他方で評価する。落ちなければ「AD に embodiment gap は無い」と言えて、それはそれで R3 の主張を1つ絞れる**
