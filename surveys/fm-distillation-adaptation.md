# Foundation Model Distillation & Adaptation — Living Survey
最終更新: 2026-08-23

## 一言でいうと
大きな基盤モデルの能力を**小さく・低メモリ・ローカル実行可能**な形に移し、他ドメイン・他機種へ適合させる方法を追う分野。
論点は「どう縮めるか」→「何で教えるか」→「一様適用の解体」→ **前提の崩壊**(W33: 効いているのは容量差ではなく情報差)と降り、
**2026-W34 で2つの構造が同時に決まった。**
**(1) 蒸留を測る横軸が決まった** —— **step length (teacher が一度にどれだけ長い区間を直すか)** は SFT と on-policy distillation を
両端とする**連続軸**で、**最適点は両端ではなく中間にある。** 反証は仮説を壊すだけだが、これは実験計画が作れる。
**(2) 適合を行える層が4つに揃った** —— **観測 / 表現 / データ / 手続き。**
**戦略が一行で書ける: gap を一枚岩で埋めようとせず、分解して層ごとに最も安い手段で埋める。
そして力学の根本的な違いはどの層でも埋まらない —— この最後の一行を書けることが重要である。**
実験の作法にも1つ重い教訓が入った: **capacity gap を測っているつもりで budget gap を測ってしまう事故が実在する。**

## 系譜マップ
- **★ R2 の横軸が決まった: step length(2026-W34 の芯)**
  - **SOPD (16333)** — 蒸留では無自覚に2択をしている: **正解の軌跡をそのまま真似させる (SFT)** か、
    **student が自分で出した答えを teacher に直させる (on-policy distillation, OPD)** か。
    前者は student がどこを歩いているかを無視し、**後者は1トークンずつ小突くだけなので「その道は諦めて別の道を行け」が言えない。**
    **本論文の主張は、この2つが対立する手法ではなく1本のつまみの両端だということ。つまみの名前は step length ——
    teacher が一度にどれだけ長い区間を直すか。最大に振れば SFT、最小に振れば OPD。そして両方に勝つのは中間である**
    (ALFWorld で vanilla OPD より平均成功率 **+13.4 ポイント**)。
  - **なぜこれが R2 を動かすか**: **容量比は3日連続で主役から降ろされた**(08-17 時間方向の情報差 / 08-18 入力方向の情報差 /
    08-19 監督の粒度)。**だが 08-17・08-18 は「容量比では説明できない」という反証であり、反証は実験計画を作れない。
    本論文だけが連続的に振れるつまみを渡してくる。** 既存パイプラインの監督単位を変えるだけで試せ、追加の teacher もデータも要らない
  - **破綻境界の測り方: BRIDGE (16010)** — R2 の定義には「破綻境界」という語が入っているのに、**測り方が何も決まっていなかった。**
    BRIDGE は pruning の文脈で **「前向きに削って崩落点を探すな。先に極端に壊してから、何を戻せば復活するかを見ろ」**という手続きを与える。
    **問題の形は蒸留と同型**(1つの軸に沿って性能が崩落し、崩落点は事前に分からない)。
    **逆向きのほうが崩落の原因を直接観測できるぶん系統則を引くには筋が良い可能性がある。**
    > **境界の注意**: pruning は既存の重みを削るので元の解の近傍に留まるが、**蒸留は student を一から学習させるため探索空間そのものが違う。
    > 借りるのは「境界の探し方」という手続きであって、「崩落の原因」まで同一と決めてかからないこと**
  - **R2 の実験計画(優先順)**: ① **step length を数点振った性能曲線**(単峰なら最適点の位置がスケール則の対象)→
    ② **「容量比 × step length」の2次元格子で交互作用**(**最適 step length が容量比とともに動けば、容量比と情報差を1本の式で結ぶ理想的な系統則。
    動かなければ2つは独立で R2 は step length 側に寄せる。どちらでも骨格が決まる**)→ ③ **破綻境界を forward と reverse の2通りで測る**
    (**食い違えばそれ自体が重要な negative result** = 破綻点が経路に依存する = 単純なスケーリング則が引けない)→
    ④ **どの層の容量が破綻を決めているか**(特定の層に集中するなら R2 は「総容量比」ではなく「臨界層の容量」で書け、主張が一段鋭くなる)
- **★ 着手前に必ず入れる3つの手続き(2026-W34 で確定。飛ばした場合に何が起きるかの実例が揃った)**
  1. **ノイズ床を先に測る** — **Thinking in a Low-Resource Language (17744)**: frontier MoE 3種を低資源言語で fine-tuning したところ
     accuracy がほとんど動かず、**それより深刻なことに、random seed を変えるだけでスコアが 7.7 ポイント動いた** ——
     **著者らが測ったあらゆるデータ・recipe の効果より大きい。効果を測る以前に、測定装置が効果より大きく揺れていた。**
     **seed だけを変えた3〜5本でノイズ床を測る。効果量がノイズ床を下回るなら、その実験は結論を出していない**
  2. **学習予算を揃える** — **What Does Attention Transfer Transfer? (18399)**: 「teacher の attention map を写す蒸留は
     分布内精度をほぼ回復するのに分布がずれると劣る」という既知の報告を**解体**し、**転写自体はほぼ完璧で恒久的**だと確認した上で、
     **残る差の相当部分が「学習 schedule が停止規則で途中で打ち切られていたこと」に由来する**と示した(最後まで回すと 3 seed 中 2 seed で
     事前宣言した閾値を下回る)。**★ R2 が最も起こしやすい事故がこれである —— 学習予算を揃えずに比較すると、
     予算の差を容量の差と読み違える。capacity gap を測っているつもりで budget gap を測ってしまう。**
     **したがって R2 の主実験は最初から2次元格子にすべき: student の幅(容量)× 学習 epoch(予算)。
     破綻境界が縦線なら破綻は容量の関数、斜めなら容量と予算は交換可能。** 後者なら R2 の主張は
     **「capacity gap の系統則」ではなく「capacity と budget の交換率」**になる ——
     **これは弱くなるのではない。「student をここまで小さくするなら学習をこれだけ延ばせ」という運用の指針が出る、実務的に有用な形である**
  3. **入力分布のずれを先に潰す** — **GS-VLA (19066)** が示したのは、**性能の8割が消えた原因が容量でも学習量でもなく
     入力分布のずれだった**という事例。**R2 が観測する「破綻」の一部が入力分布のずれで説明できてしまう危険がある**
  - **閾値は実験前に決めて decisions/ に書く**(18399 の「3 seed 中 2 seed で結論が変わった」は 17744 の宿題そのものの実例)
- **★ 適合を行える層は4つある(2026-W34 で完成)— gap を一枚岩で埋めない**

  | 層 | 何を触るか | 代表 | 性質 |
  |---|---|---|---|
  | **観測** | 入力を学習時の基準に引き戻す | **GS-VLA (19066)** | **パラメータ更新ゼロ = 忘却なし** |
  | **表現** | 境界面だけ学習 | **Projector Is All You Train (19726)** | **忘却が定義上ゼロ、学習は約2倍速** |
  | **データ** | 学習分布をモデル自身に補わせる | **SDGC (19490)** | 人間の追加アノテーションゼロ |
  | **手続き** | 探索規則を適合 | **RP1 (18669)** | world model は共有したまま |

  - **GS-VLA (19066)** — **カメラの取り付け位置をわずかにずらすと、VLA の成功率は 90% から最悪 10% に落ちる。**
    カメラの動きが作業空間に対して十分小さければ**視点の正規化はシーンにも方策にも依存しない課題に縮約される**ので、
    **400万パラメータの 3D Gaussian Splatting ベース正規化器を凍結方策の手前に挿すだけで済む。**
    **これまで適合は重み (fine-tuning, PEFT) か表現(蒸留)で行うものだった。本論文はそれを観測空間で行う**
  - **SDGC (19490)** — π0.5 のような最先端 VLA は新しいロボットに載せるとハードウェア構成のわずかな違いで大きく落ちる。
    素直な対処(新機体の expert デモでの fine-tuning)は、**そのタスクは上手くなる代わりに元の指示追従能力と行動 prior を失う。**
    解き方は **zero-shot の VLA 自身に追加の学習データを作らせること** —— 新機体上で pretrained VLA をそのまま動かし、
    **その online interaction rollout を fine-tuning データに混ぜる。** **元モデルの振る舞いを元モデルから蒸留し直しており、
    catastrophic forgetting 対策の replay buffer を人間ではなくモデル自身に用意させる構成。**
    **★ 前提条件を正直に書く: zero-shot 方策が新機体でまともに動かないと、自己 rollout は有害なデータになる。
    ALOHA のような近い機体同士では成り立つが、力学が大きく違う機体では成り立たない。この閾値がどこにあるかが我々の確かめるべき点**
  - **★ W34 課題カード2(建設機械の retrofit / 油圧特性の違うメーカー横断の掘削機に1つの方策を載せる)への処方箋が書ける:
    センサ配置の差は観測層、モダリティの追加は表現層、機体固有の癖はデータ層。力学の根本的な違いはどの層でも埋まらない。**
    **retrofit 先で expert デモを大量に集めるのは高く、zero-shot 方策を動かして自己 rollout を貯めるほうがはるかに安い**(19490 が最も現実的な処方)
  - **★ そもそも重みの更新は要るのか(2026-W34 末に立った疑い)** — **Zetta (16590)** は同じクラスの問題に
    **重みを一切触らず、critic と復帰動作だけを差し替える**形で答える。**保証という観点ではこちらのほうが検証は容易である ——
    コードは読めるが重みは読めない。** **比較軸は性能ではなく「回復した性能あたりの検証コスト」に取るのが良い**
- **★ 複数の適応先があるときの資源配分(2026-W34 新設)— P2 に欠けていた層**
  - **TSFT (17180)** — **「1つの pretrained な方策を、限られた予算の下で複数の領域へどう配分して適応させるか」を、
    伸びの予測 + 整数計画として解く。** **P2 が集めてきたのは適応の手法ばかりで、複数の適応先があるときの配分は扱われていなかった。
    実務では適応先は常に複数ある(車種、センサ構成、地域、天候)。**
  - **★ R2 の出口がここにある**: **R2 の系統則が引ければ、それは TSFT 型の予測モデルの中身を与える** ——
    「capacity gap の系統則が引けたら何に使えるのか」への答えとして書ける。
    **W34 カード2 の「事前に計算できる機体間距離と性能低下幅の相関」は、TSFT の言葉では伸び予測モデルの特徴量を作る作業にあたる**
  - **> KPI への警告(MANIGUARD 17386 由来)**: **安全ラベル付きデモで fine-tuning すると安全成功率は大きく改善するが、
    デモを増やしても閉じない差が残る(着手ロールアウトの 21-42% が依然として違反)。**
    **「少データでの適合」は裏返せば「データ量と性能の関係」を前提にしているが、飽和が先に来るなら KPI は
    「必要データ量」ではなく「飽和後の残余違反率」に置くべきかもしれない**
- **★ 容量比 1.0 でも蒸留は成立する —— 支配変数は情報の差(2026-W34 で決定打)**
  - **S²VOPD (14144)** — 蒸留では普通、teacher が student より多くを知っていることが出発点になるが、実務ではどちらも無いことのほうが多い。
    **本論文はその差を反対側から作る。teacher を強くするのではなく、student の入力を壊す。**
    teacher には元の画像を、student には**強く加工して情報を落とした同じ画像**を見せ、student 自身の出力に teacher が評価を与える。
    **teacher と student は同じモデルでよい。それでも student だけが情報を欠いているので、
    「特権情報を持つ teacher」と同じ学習信号が追加コストゼロで発生する。**
  - **主張の説得力は対照実験の符号にある**: **試した4系統すべての加工で性能が上がり、teacher と student に同じ入力を与える
    対称な自己蒸留では逆に性能が落ちた。** つまり効いているのは加工による正則化ではなく、**非対称性そのもの**である。
    **ただし加工が強すぎてもいけない —— 答えの根拠そのものを消してしまうと壊れる。
    消してよいのは「あってもなくても答えが変わらない情報」だけ**(運転の知覚に移すなら photometric な加工は安全側、遮蔽系は危険側という予測が立つ)
  - **留保**: abstract が途中で切れており定量結果・対象タスク・比較対象が未確認。**本文入手後に最初に見るべきは
    「本物の強い teacher を使った通常の on-policy distillation」が比較対象に含まれているか** ——
    無ければ本手法は「teacher が無いときの代替」であって「teacher の代替」ではない
- **蒸留は「別表現への転用」の形も取る(2026-W34)**: **GaussianDWM++ (16234)** の Gaussian tokenizer は
  **teacher が 2D 画像特徴、student が 3D プリミティブ上の特徴場**で、**形がまったく違う。**
  P2 の criteria にある「基盤モデルを別ドメインに転用する recipe」に**「別表現への転用」という形で当てはまり、
  R2 の文脈では容量比では測れない蒸留の例がまた1つ増えたということでもある**
- **★ 「student で足りるか、teacher を呼ぶか」を設計問題として書き直す(2026-W34)**
  - **LLMRouter (06867)** — query ごとに使う LLM を選び分ける **routing** を5つの部品に分解し直し、
    学習データを自動生成する仕組みと、品質・コストの2軸で測るベンチマークを出した。**分野は完全に外。**
  - **なぜ効くか**: **蒸留を実務で回すと必ず「student の答えで十分な入力」と「teacher に投げ直すべき入力」を切り分けることになる。**
    我々はこれを信頼度の閾値というヒューリスティックでやっているが、routing の文献はまったく同じ問題を学習問題として定式化してきた。
    **しかも蒸留では教師データが自動で作れる**(teacher と student の両方が手元にあるので、両者の出力差を測ればラベルになる)。
  - **借りるのは問題の立て方と評価の作り方だけ。読むのは定式化の節で 30 分**
- **★ 容量差ではなく「情報差」ではないのか(2026-W33 の芯)— R2 の設計を書き換えた構図**
  - **同日に4本、比 1.0**: **FIRE-VLA (13395、採用)** は**そのラウンド開始時点の自分を凍結したコピー**を teacher にし、
    唯一の違いは **teacher だけが実際に起きた未来の軌道を見られること**。**HPSD / SSPO / TraVEL**(いずれも落選)も同型 ——
    高品質な初期フレーム / 証拠スニペット / ego 軌道を、**学習時だけ teacher 側に与える**。
    **4本とも teacher/student の容量比は 1.0 である。効いているのは容量ではなく、teacher だけが何かを見ていることだ。**
  - **さらに極端な隅: AI4AI at Test-Time (12307)** — 強いモデルが弱いモデル用の **harness(推論時にモデルの外側に置く足場のコード。
    処理の振り分け、決定論的な計算、出力形式の強制)** をコードとして書き、**パラメータは一切更新されない**まま 0.49 → 0.91。
    著者自身が利得の源を **決定論的コードへの外出し・routing・回答形式の強制**と明示し、**「より長く考えさせたから」ではないと否定**。
    **留保が重い**: harness は**ベンチマークごとに正解データ 5% を見て作り込まれている**ので、
    「能力が移った」のか「採点との噛み合わせを直しただけ」かは abstract の範囲では分解されていない
  - **R2 への帰結(3軸に組み替える)**: **容量軸 × 情報軸**の2次元に、**「パラメータ更新の有無」**を3本目として足す。
    予備実験は **比 {1.0, 2, 8} × 特権情報 {なし, 未来の一部, 未来の全部} の 3×3**(比 1.0 × 特権なし = 素の自己蒸留が対照)、
    そこに **AI4AI の「更新ゼロ」を水平線**として格子の外側に引く。
    **どんな蒸留手法もこの水平線に勝たなければならない。このベースラインは学習コストがゼロで、誰も回していない。**
  - **既存研究がこの2つを混ぜて論じている以上、分離すること自体が主張になる**(R2 の新規性の中心)
  - **FIRE-VLA の弱点も型として持ち帰る**: 主要数値が **nuScenes の open-loop L2** に乗っている ——
    **自車の過去状態だけからかなり当たってしまい、閉ループ安全性と相関しないことが広く知られている指標**。
    改善の中身も著者が正直で、**「稀な重篤な軌道」が刈られただけで通常軌道は一様に良くなっていない**(能力向上ではなく**裾の除去**)。
    **売り方としては地味だが、安全評価の観点ではむしろこちらのほうが価値がある**
- **★ 適合ではなく「選択」が壊れている(2026-W33)— UDA の出口**
  - **8万モデルの統制実験 (12035)** — 9データセット × 11ドメイン間シナリオ × 10 UDA アルゴリズム ×
    **13 label-free validator(目標ラベル無しでモデルの良し悪しを推定する手法)**の総当たり。結論は3つで順番が効く:
    (1) **良いモデルはたいてい存在している**(適合能力の不足は主問題ではない)、
    (2) **それを選び出せない** —— validator と真の最良の差は**大きく、かつ構造的**(運悪くではなく**系統的に外す**)。
    **13個のうち一貫して信頼できるものは1つも無かった**、(3) **ensembling と少量の目標ラベルは縮めるが埋めきらない**(解決を主張していないのが誠実)。
  - **我々の痛みどころは 30分の棚卸しで判定できる**: 「どの checkpoint を出荷するか」の根拠が
    **「source の validation loss が最小」なら、本論文が否定した validator の1つを使っている**。実験不要
  - **R1 との交差**: 「良いモデルは存在するが選べない」は **「安全な planner は存在するが、どれが安全か検証できない」**に写る。
    **ラベル無しのモデル選択に保証を付ける**のは conformal の自然な適用先で、**「既存13個はどれも保証を持たない」は R1 の新規性の議論をそのまま補強する**
- **★ 蒸留の壊れ方 —— 5つの独立した顔(2026-W33 で地図が埋まった)**

  | # | 失敗の形 | 機序 | 出典 |
  |---|---|---|---|
  | 1 | **伝わらない** | 特徴を合わせているのに inductive bias が渡らない。**pooling と flatten が空間格子を壊す** | iBKD (10723) |
  | 2 | **伝わりすぎて上書きする** | teacher 特徴に寄せると **student 元来の視覚・言語対応が壊れる**。特徴でなく **patch 間の類似度という「関係」だけ**を渡す | MVRD (10864) |
  | 3 | **発散 / 欠損** | **excess**(student が出すが teacher がほぼゼロ → 補正が発散し更新を壊す)と **deficit**(teacher が出したいが student がサンプルせず信号に現れない) | TIDE (09836) |
  | 4 | **そもそも teacher が要るのか** | 外部監督ゼロの自己蒸留が、正解ラベルありの手法と GRPO の**両方を上回る** | U-OPSD (06296) |
  | 5 | **teacher が捨てたものが伝わらない** | 蒸留は引力だけで、**teacher が学習途中で捨てた方向**を使っていない。early checkpoint を**時間的な負例**として押し離す | ASD (11789) |

  - **TIDE (09836) の degenerate agreement は特に危険**: on-policy distillation で **student が同じフレーズをループすると、
    teacher も「いま出ている繰り返しの続き」として同じ語に高確率を振るので一致度がほぼ満点になる** ——
    **応答は壊れているのに指標は完璧に見える。** 診断は**応答長と一致率を同じ図に重ねるだけ**で今日中にできる。
    処方は **excess を上限のある関数で殺し、deficit は teacher の上位 K 語を直接 loss に入れて**サンプリングを待たない ——
    **「on-policy は student が踏まない道を学べない」という原理的な穴を、サンプリングを介さない項で回避している**
  - **U-OPSD (06296) が R2 に与えるもの: スイープの端の基準線**。teacher を用意する前に、
    **student を自分自身で蒸留したときの改善幅**を測る。**R2 のすべての結果はこの線からの上積みとして報告すべきで、
    これが無いと R2 は「大きい teacher は良い」という当たり前の話に見えてしまう。**
    やっていることは素直 —— 多数決で疑似正解を作り(票が割れた問題は捨てる)、**その疑似正解で条件付けた分布**から
    **多数決を外れた生成にだけ**自己蒸留する = **「答えを見た自分」が「答えを見ていない自分」を教えている**。
    弱点も明確で、**thinking モードではほぼ効果が消える(既に強いモデルには効かない)**、多数決が定義できる離散出力に閉じている
  - **★ 報告の作法が2日連続で同じ形を要求している(R2 の図の設計に直結)**: iBKD は **「データが減るほど優位が広がる」という傾き**で、
    ASD は **13組の teacher-student ペアを横断して「どのペアで最も効いたか」**で報告している。
    **R2 が出したい主張は「どこで壊れるかを予測できる」であって勝ち負けではない。実験設計をこの形に合わせるだけで主張の強さが変わる。**
  - **測る量にも注意**: ASD で **cross-architecture ペアに最も効いたのは clean 精度ではなく頑健性 (mCE)**。
    **bias が不一致なペアでは、壊れるのは平均精度ではなく頑健性かもしれない** —— **clean 精度だけで測ると破綻境界を見逃す。破損ベンチを1つ常設すること**
- **逐次適合が壊れる原因は「手法の種類」ではなく「勾配の大きさ」(2026-W33)**
  - **SFT Conflicts, RL Coexists (03573)** — 機種 A に合わせ次に B に合わせると A が落ちる現象を勾配干渉として説明。
    **通常の教師あり微調整では干渉が勾配の「大きさ」に比例して効く (norm-limited) のに対し、RL では「ばらつき」で抑えられる (variance-limited)**
    ため更新方向がほぼ直交して共存できる。**ただし「だから RL にしよう」と読むと転用を誤る** ——
    効いているのは RL という手法ではなく、**RL の中に副作用として入っていた正規化処理**である、というのが著者の特定した機序。
    **そこから自然に出る問い「通常の微調整の側で同じ正規化をかけたらどうなるか」を論文は答えていない。
    既存パイプラインに数行足すだけで検証でき、効けば RL 化の投資を丸ごと回避できる**
  - **処方より先に診断**: **ドメイン A と B の勾配 cosine similarity を層ごとに記録するだけ**。
    負の層が無ければ我々に干渉は無く、この論文の話は丸ごと不要と判定できる
- 何を模倣させるか(手法)
  - output 蒸留(教師出力を模倣)… ベースライン
  - **feature-level 蒸留** … 一般に output より優位
    - **Cross4D-JEPA (00514)** — dense correspondence で 13x 圧縮・同等。利得の主因は「粒度」
    - **Geometric FM Distillation (01851)** — feature 優位 / エンコーダ温存 / SVD warm start
  - タスク空間の中間表現経由: **TGRIP (04812)** — semantic BEV map 経由で異アーキ teacher→student、capacity gap に強い
  - **関係構造を運ぶ**: **MobileSAM2 / HyperKD (12297)** — hypergraph で時間対応(フレーム間)と多粒度マスクの知識を構造ごと転写。点ごとの一致より student の容量要求が緩い。蒸留 loss を student アーキ探索 (NAS) の目的関数にも使う
  - **丸ごと蒸留せず「アンカー」として使う(部分蒸留)**: **LAWM-3D (05706)** — 基盤モデルの出力を模倣するのでなく、
    自前 encoder の**中間特徴を既存 3D foundation model の特徴に固定する制約を1本足すだけ**。視点間の幾何対応を
    「学習で当てさせる」のでなく**外部の基盤モデルから明示的に与える**。フル蒸留よりはるかに軽く、既存の学習ループに
    alignment loss を追加するだけの最小変更で載る。**着手コストが低い割にリターンが読みやすい**レバー
  - 模倣でなく「重みを生成する」: **PAW (02512)** — compiler が adapter を直接 emit、0.6B≈32B・メモリ 1/50
- teacher の要否を問い直す(今週の主戦線)
  - **最終状態でなく「学習の差分」を運ぶ**: **Direct-OPD (05394)** — 小モデルで RL を回し、(pre-RL, post-RL) の log 比を dense な implicit reward として強い student に適用。ターゲット上で高価な RL を回さずに weak→strong
  - **固定 teacher を要さない self-distillation**: **SEED (14777)** — 生徒自身が自分の軌跡から hindsight skill を抽出し、skill 有無の確率差を token 単位の dense 蒸留信号に変換、outcome RL と同時最適化(off-policy 分布ずれを回避)
  - **student 自身を摂動の条件に**: **SAKD (11557)** — teacher の静的特徴でなく進化中の student 特徴を条件に、パラメータフリーの cyclic shift で多様なビューを生成。追加パラメータ・多段学習なしで multi-teacher 級
  - **生成軌跡上で teacher を当てる (on-policy)**: **ABOPD (18835)** — 固定データでなく **student 自身の生成軌跡上で teacher が監督**し exposure bias を潰す。反復/自己回帰生成(diffusion policy・world model・AR planner)全般に横展開。ABot-World-0 の LongForcing はこの long-horizon 版
- **軌道の「どこを学ぶか」に重みを配る(2026-W32)— 選別(捨てる/使う)から重み付け(区間ごとに配る)へ**
  - **正解から逆算して中間目標を作る**: **ABSeeker (05102)** — 学習時に ground-truth を持っている立場を使い
    **「この答えに至るには途中で何を掴んでいる必要があったか」を答え側から復元**(answer-backtracked clue recovery)、
    clue の回収度で各ステップを採点。**失敗軌道の中の正しかった判断にも点が入る** = 成功軌道だけ残す rejection
    sampling が捨てている情報を回収する。SFT (loss 重み) と GRPO (報酬) の両方に同じ信号を差し込む。
    Qwen3.5-4B・**8.5k 例**で BrowseComp 37.3%。**前向きの reward shaping は恣意的になるが、逆算なら中間目標が
    ゴールから機械的に決まる**のが設計上の利点。弱点は clue の復元自体を LLM に任せており必要条件性が未検証
  - **teacher との食い違いを「損失」でなく「重要度」として読む**: **AgentOPSD (05987)** — 正解を使わず、
    **privileged teacher と student の log-prob 差**を turn 単位に集約し、**log-odds 空間の Bayesian 再帰更新**で
    「ここが勝敗の分かれ目だった確率」を持つ。**絶対値でなく信念の変化量**で pivotal turn を判定。
    critic も追加 rollout も不要で既存の policy optimization にそのまま乗る。ALFWorld 89.1%
  - **2本の対比が設計空間そのもの**: ABSeeker は**外部の正解から逆算**(根拠が固いが正解が要る)、
    AgentOPSD は**内部のモデル比較から推定**(正解不要だが teacher の質に全面依存)。
    **我々は事後的に最適軌道を計算できる場合が多い = ABSeeker 側から試すのが筋**
  - 系譜上の位置: **SEED (14777)**(自分の軌跡から hindsight skill → 確率差を dense 信号に)・
    **Direct-OPD (05394)**(RL 前後の log 比を dense reward に)の延長線上。3本とも
    **「疎な結果報酬を、確率差から作った密な信号に化かす」**という同一の型
- 何で教えるか(データ)— 「一様適用」を捨て選別/検証する(2026-W30 の主戦線)
  - **検証を通ったものだけが次の種になる**: **RST (05466)** — (課題, 環境, 模範解答, 採点器) の4点を整合させたまま
    **検証済みタスクを種に再帰的に難化**させ、生成軌跡を rejection sampling → SFT → agentic PPO。
    15 ラウンドで **$0.05/件・37,484 タスク**、強モデルの pass@4 が 90% → 2.5%。**「作ってから検証」ではなく
    「検証を通ったものだけを次の入力にする」**という順序が肝(planner-evaluation サーベイと相互参照)
  - **サンプル単位で選別する**: **KD Hurt / CHAD (19956)** — Bangla 要約で標準 KD は +0.0003 しか上げず訓練の **約51% が student を悪化**。各サンプルの KD 勾配が validation を下げる方向と揃うか(**gradient alignment**)で有害を弾く gate + **capacity-proportional constraint (CPDP)** で 60M が 50倍の Qwen2.5-3B 超え。コード公開
  - **経験をどう重みに焼くか**: **Experience Distillation (21051)** — 集めた経験を素朴な **SFT で焼くと ICL 利得の 3.8% しか回収できない**。**context distillation**(文脈で得た ICL 振る舞いを重みへ内在化)なら環境対話ゼロで 64.8%+ を保持、RL 同等を **9.6倍少ない環境サンプル**で
  - **検証済み合成データで焼く**: **SLAI T-Rex (20145)** — **solver-verified synthetic data**(最適化ソルバで解の正しさを自動検証した合成文書)を SFT に混ぜ人手ラベル無しで正解保証。10K の特化 SFT で GPT-5.4-Mini を +3.98pt。「生成は難しいが検証は容易」なドメイン(実行可能性・衝突判定)に転用可
  - **負の知見(監督の汚染)**: **LAWM-3D (05706)** — multi-view 動画を足しても 3D 理解は出ない。原因は
    **未来フレームの見た目が漏れるショートカット学習(appearance leakage)**。処方は **non-injective な RGB-D 同時再構成**で
    覗き見を封じること。**データを増やす前に何が supervision を汚しているかを疑え**という順序の教訓
    (vla-world-model サーベイと相互参照)
  - **負の知見**: **Answer-Conditioned CoT (14552)** — 失敗サンプルを gold answer で救済すると答えから逆向きに正当化した chain になり、**correctness filter で検出できない形で**データが劣化(最難問で最大 ~27pt)。症状は early final-answer statement、処方は **answer-blind 生成**
  - 分布の広さ: **ZipDepth (08771)** — 頑健性は teacher でなく multi-domain データで決まる。1/50 サイズで zero-shot 保持
  - 少データの選定: **Few-Medoids (05891)** — クラス centroid 近傍の典型例選定が random に一貫勝ち

## Open Questions
- **★ R2 の予備実験を、着手前に3つの手続きで固める**(17744 / 18399 / 19066)—
  ① **seed だけを変えた3〜5本でノイズ床を測る** → ② **閾値を実験前に決めて decisions/ に書く** →
  ③ **student の入力分布が teacher の学習分布からずれていないことを確認** → ④ 本実験。**①②③ を飛ばして ④ に入らないこと**
- **★ R2 の主実験は「容量 × 予算」の2次元格子にする**(18399)— **破綻境界が縦線なら破綻は容量の関数、斜めなら交換可能。**
  斜めなら R2 の主張は「capacity gap の系統則」ではなく **「capacity と budget の交換率」**になる。**弱くなるのではなく、実務的に有用な形になる**
- **★ 最適 step length は容量比とともに動くか**(16333 × R2)— **動けば容量比と情報差を1本の式で結ぶ理想的な系統則、
  動かなければ2つは独立。どちらでも骨格が決まる**
- **★ 破綻境界は forward と reverse で同じ答えになるか**(16010)— **食い違えばそれ自体が重要な negative result**
  (破綻点が経路に依存する = 単純なスケーリング則が引けない)
- **★ step length の軸に沿って、消える失敗の種類は変わるか**(16333 × 17744)—
  17744 の切り分けは「**SFT は振る舞いを作るが自分の欠陥は直せない、RL は欠陥を直すが振る舞いは作らない**」。
  **既に走らせるログを失敗の種類別に数え直すだけでよい。変わるなら SOPD の軸は「性能の軸」ではなく「どの失敗を直す軸か」だったことになり、
  R2 の主張は単なるスケーリング則より一段深いものになる**
- **★ 同一モデル・(a) 同じ入力 /(b) student 側だけ加工 の2条件は再現するか**(14144)—
  **(a) が悪化し (b) が改善すれば主張は再現。1〜2日。ここが再現しなければ以降は不要**
- **★ 適合に重みの更新は本当に要るのか**(19490 × 16590)— **同じ embodiment gap に対して、自己生成データでの fine-tuning と、
  重みを触らず critic と復帰動作だけ差し替える構成を比べる。比較軸は性能ではなく「回復した性能あたりの検証コスト」**
- **★ projector-only が壊れる境界はどこか**(19726)— **モダリティを backbone から遠ざけていく
  (3D 点群 → 深度 → LiDAR → 力覚/制御信号)。R2 が capacity gap を軸にした系統則なら、こちらは「表現空間の距離」を軸にした系統則になり、
  同じ実験フレームで回せる**
- **★ 自己 rollout と expert データの最適な混合比は**(19490)— 論文が示すのは有効性、実務で要るのは比率の指針。
  **「旧タスク保持率 vs 新タスク到達性能」の曲線。そして zero-shot 方策が新機体でまともに動かないと自己 rollout は有害なデータになる ——
  その閾値がどこにあるか**
- **embodiment gap を「観測 gap」と「力学 gap」に分解できるか**(19066 × W34 カード2)—
  Open X-Embodiment で機体ペアごとに分解する。**センサ配置の差は観測層で吸収でき、力学の差は吸収できない**が仮説
- **S²VOPD の比較対象に「本物の強い teacher を使った通常の OPD」は含まれているか**(14144)—
  **無ければ本手法は「teacher が無いときの代替」であって「teacher の代替」ではない**
- **拾い残し**: **IAR (2608.20281、quota 落ち)** は「適合させると汎用性が落ちる」に **model merging** で答え汎用性能を **+12.1pt 回復**。
  **19490 と同じ問題・別解で、本来は2本並べたい。fm_distill の候補が薄い日に最優先で拾う。**
  **RoleSub (2608.18410、quota 落ち)** は VLA の実行時 KV を 9〜11% まで削る —— **蒸留が容量を削るのに対しこれは帯域を削る(圧縮の軸を2本に分ける材料)**
- **★ 蒸留の効果は容量差から来ているのか、情報差から来ているのか**(13395 / 12307 + 落選3本)—
  **比 {1.0, 2, 8} × 特権情報 {なし, 未来の一部, 未来の全部} の 3×3** を小規模で回す。
  **比 1.0 × 特権なし(素の自己蒸留)を対照、AI4AI の「更新ゼロ」を水平線として格子の外側に引く。**
  **容量比をどこまで開いてもこの水平線に勝てない領域があるなら、それが R2 でいちばん強い図になる**
- **★ この 3×3 について「何が出たら進め、何が出たら捨てるか」を、実験を回す前に `decisions/` に書けるか**
  (Spark-to-Paper 由来)。**書けるかどうか自体が、実験が設計できているかの検査になる**
- **★ 「どの checkpoint を出荷するか」の根拠は何か**(12035)— **30分の棚卸しで判定でき、実験は要らない。**
  source の validation loss が最小、なら 8万モデルの実験で否定された validator を使っていることになる
- **degenerate agreement は我々の蒸留 run で起きているか**(09836)— **応答長と一致率を同じ図に重ねるだけ**。
  続けて **excess 率と deficit 率を別々に数え、容量比を振ってどちらが先に立ち上がるかをプロットする(R2 の中心 figure 候補)**
- **自己蒸留だけでどこまで行くか**(06296)— **R2 のすべての結果はこの基準線からの上積みとして報告する。
  これが無いと R2 は「大きい teacher は良い」という当たり前の話に見えてしまう**
- **我々の蒸留は pooling / flatten で空間格子を壊していないか**(10723)— **コードを読むだけで実験すら要らない**。
  さらに **bias 不一致と容量比を直交させて振る**と、R2 の図が1次元から面になる
- **蒸留の副作用を測っているか**(10864)— run の前後で「狙った能力」と「壊れうる能力」を**必ず両方**測る習慣にする。
  最も面白い仮説: **VLA 化(action post-training)で全層劣化した深度推定能力を、関係蒸留でコストを増やさず戻せるか**
- **clean 精度だけで測っていないか**(11789)— **cross-architecture ペアで壊れるのは平均精度ではなく頑健性**かもしれない。**破損ベンチを1つ常設する**
- **逐次適合の干渉は実在するか**(03573)— ドメイン間の**勾配 cosine similarity を層ごとに記録するだけ**。
  負の層が無ければ以降不要。あれば **「通常の微調整に per-sample の勾配正規化を足すだけ」**(論文が答えていない問い)を先に試す
- **合成のみで学習したモデルの、合成 held-out と実 held-out の落差は1つの数字でいくつか**(09100)—
  小さければ我々に synthetic-to-real の問題は無く、議論が終わる。**この論文の価値は数字ではなく、数字が移植できないことを示した点にある**
  (**base model の優劣は実データ比率によって順位が入れ替わる = 1変数ずつ振って最良を積み上げる進め方は必ず間違える**)
- **構造化出力の pseudo-label を「信頼できる区間だけ切り出して使う」は軌道に移るか**(12600)—
  最初の2秒は信頼でき先は怪しい、という形。**さらに信頼度をヒューリスティックから conformal に置き換えれば
  「採用区間では誤差が閾値以下である確率が 1−α 以上」となり、R1 と P2 が同じ実験で交わる**(**R4 として登録を推奨**)
