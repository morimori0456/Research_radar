# Planner Evaluation & Safe Motion Planning — Living Survey
最終更新: 2026-08-23

## 一言でいうと
自動運転プランナを「衝突率」一本で測る時代を終わらせ、**過保守・介入頻度・安全被覆を保証付きで**測る評価と、
その保証を計画制約に埋め込む手法を追う分野。論点は 採点 → 診断 → 評価器の認定 → 評価の入力側 → 最終スコアの分解 →
**定義そのものの破綻** (W33) と降りてきて、**2026-W34 でついに底に着いた**: **では、何を保証できるのか。**
答えは2つの天井として確定した —— **仕様ベースの検査は書き漏らした危険を原理的に見つけられず、
サンプリングは測度ゼロの不連続モードに届かない。どちらの手段でも届かない領域が存在する。**
そのぶん**主張は言えるようになった**: 学習にどこまで任せるかは**順序を持つ1次元の軸** (順位付け → 選択 → 探索規則) であり、
**保証は「学習モデルを審判にしない」ことから来る** —— 正確には **「学習モデルは審判を*書いて*よいが、審判を*務めて*はならない」。**

## 系譜マップ
- **★ 保証の天井 —— どちらの手段でも届かない領域がある(2026-W34 の芯)**
  - **サンプリング側の天井: Sampling-Verification Danger Law (17956)** — 確率 r の稀な臨界事象を N 本の独立試行が
    **全て取り逃す確率はちょうど (1-r)^N**。**r = 10⁻³ に対し N = 1,000 でも見逃し確率は約 37%。**
    さらに深いのはその先で、**滑らかに食い違うモデル同士は必ず「体積を持った」食い違い領域を作るのでランダムに試せばいずれ当たるが、
    不連続なモード切替はこの体積を一切持たない** —— **稀だから見つからないのではなく、測度が無いから原理的に見つからない。**
    運転での該当箇所: **黄→赤の判断境界 / 譲る・譲らないの切替 / 緊急ブレーキの発動閾値。**
    **R1 にとって都合の悪い事実でもある** —— conformal が与えるのは交換可能性の下での平均的被覆であって、測度ゼロの臨界集合は捕まえない
  - **仕様側の天井: MANIGUARD (17386)** — 安全をタスク成功から切り離して仕様として書き実行時に検査すると、
    **成功したロールアウトのうち 6〜21% が仕様に違反していた** —— **成功率だけを見ていると、成功例の2割近くを誤って良いものとして数えている。**
    判定は **LTL_f (有限長の実行系列に「常に〜」「〜するまで」を書ける論理)** のオートマトン監視器が物理量に接地した述語の上で行い、
    論文は **"rather than learned classifiers or LLM judges"** と明示。**ただし書いた仕様の違反しか見つけられない。**
  - **★ 2つの天井は互いを埋めない。** 仕様は書き漏らしに届かず、サンプリングは測度ゼロに届かない。
    **「両方使えば埋まる」は証明されていない。** **指標の論文としては、届かない領域の存在を明示するほうが誠実であり、強い**(R1 の設計判断)
- **★ 学習にどこまで任せるか —— 順序を持つ1次元の軸(2026-W34 で確定。R1 の Table 1 になる)**

  | 学習の担当範囲 | 実例 | 失敗したとき何が起きるか |
  |---|---|---|
  | 許容集合を作った後の**順位付けだけ** | **Calibrated Predictive Safety (17496)** | **許容集合の外には出られない。保証は壊れない** |
  | **選択そのもの** | **DA-WAM (19085)** | 誤った候補が選ばれる。ただし誤りの所在は特定できる |
  | **探索の規則ごと** | **RP1 (18669)** | world model の誤りか探索器の誤りか、**事後に切り分けられない** |

  - **後ろへ行くほど性能は上がり、後ろへ行くほど「何が保証されているか」を言えなくなる。**
  - **[17496] が R1 の否定形を肯定形に変えた**: 候補を K 本出す → world model が実行前に潜在空間で転がし危険度と進捗を予測 →
    **そこから先の判定は学習を一切含まない決定論的 shield が行い、全部落ちたら段階的な退避手順に落ちる。**
    論文の一文がそのまま R1 の主張になる —— **「学習された順位付けは、許容された候補を並べ替えるだけである。保証は shield と退避手順から来る」。**
    **空けている穴もそのまま R1 の置き場所**: risk head の較正は**経験的**であって有限サンプルの被覆保証ではない。
    **conformal を入れれば閾値が「誤り率 α 以下を保証する値」として決まり、α を振れば W34 カード1 の operating curve が掃ける**
  - **[19085 DA-WAM] は味方ではなく、R1 が正面に置くべき対立仮説の最強版。** 候補軌道1本につき別々の未来を予測し、
    採点器は現在の観測ではなく**その候補を実行した後の予測状態**を見て点を付ける。**許容集合を作らず、学習された採点器が選択そのものを行い、
    NAVSIM v1/v2 で最高性能。** **「性能を最大化するなら学習に任せるのが正しい」が現在の事実であり、R1 はそれを認めた上で
    「我々が問うのは別のことだ」と書く。** 批判の足場も1つある —— **NAVSIM では他車が ego の選択に反応しないので、
    過剰に慎重な停止のコストが原理的に計上されない**(W34 カード1 の後者は、このベンチでは測れていない)
- **★ 「学習モデルは審判を*書いて*よいが、審判を*務めて*はならない」(2026-W34 で規範が確定)**
  - **変遷**: 「審判に学習モデルを使わない」(08-18) → 「使うなら判断を検証可能な粒度に分解し、何を保証しないか明記せよ」(08-21、
    **SemComp-Bench** が VLM 審判を二値質問の集合に分解した実例) → **役割分離という別解 (08-23 Zetta 16590)。**
  - **Zetta ζ (16590)** — embodied agent の**外殻 (harness)** の設計。判断を1周期に押し込むのをやめ、
    **行動周期で効く監督 / エピソード単位の改善提案 / 検証を通ったものだけを採用する関門**の3つの時間スケールに分ける。
    **base policy の重みには一切触らない。** 最重要の設計判断は **critic が学習された判定器ではなく「コード」であること** ——
    速く、人が読め、なぜ発火したかを説明できる。**agentic model は critic を書く側に回り、判定する側には立たない。**
    **否定形でも条件付きでもなく役割分担の言明になったので、査読で通しやすい。**
  - **独立な傍証が今週2本**: **MANIGUARD (17386)** の "rather than learned classifiers or LLM judges"、
    W33 の **CaliBench** の「FID を避けて閉じた式の参照分布を使う」。**分野も手段も違う3本が独立に同じ結論に至っている**
  - **★ W34 カード1/3 への実装が付いた**: **① 過保守側にも critic を置けば「発火回数」という観測量が入る** ——
    カードが詰まっていた「不要停止には分母がない」に対し、**真の分母は諦めて、同一 critic を全 planner に当てて相対比較に落とす。**
    **② takeover lead time は critic の発火時刻と実際の失敗時刻の差**で機械的に出る(人手分類の作業が critic 1本で自動化される)
- **★ 中間表現の指標は下流の判断を保証しない —— 3分野で独立に(2026-W34 で一般性が確定)**
  - **Decision-Metric Alignment (18746)** — **潜在表現から中身が読み取れること (probe 精度) と、
    その表現で候補を実タスクの順に並べ替えられることは、別の能力である。** 指標は2つ: ① ランダム行動列での
    「潜在コストの順位 vs 実コストの順位」の Spearman 順位相関、② **探索が候補を絞り込む各段階での同じ一致度**(こちらが本質) ——
    **全体で順位が合っていても、絞り込んだ後の拮抗した候補の間で崩れるなら、探索は最後の一歩で誤る。**
    **決定打は改善側から: 行動を条件に含める目的関数を足すと成功率は上がるのに probe スコアは変わらない。**
    **R1 は同じ問いを planner の評価指標について立てる —— 「ベンチマークのスコアが高い planner は、閉ループで本当に良い planner なのか」。
    測り方はそのまま移植でき、発明ではなく移植として書けるので通しやすい**
  - **同型の指摘が独立に3本**: 本論文 (world model のコスト関数) / **survey 20111** (planner の benchmark) /
    **What Matters for Latent Actions 19613** (潜在行動の proxy metric)。**分野が違って構造が同じなら、それは分野の話ではなく測り方の話である。**
    **ただし引き上げすぎると論文が散る** —— **R1 の本文は自動運転に閉じ、他2分野は「同型の指摘が独立に存在する」という1段落の傍証に留める**
- **★ 評価の階梯が俯瞰の側から言語化された(2026-W34)— R1 の立ち位置が確定**
  - **Planning-Oriented E2E AD survey (20111)** — 現代の end-to-end driving を分ける本質は「中間表現を持つか否か」ではなく、
    **その中間表現が学習され・教師づけられ・評価されているか**である。**評価の階梯**を明示的に描く:
    **open-loop の軌道一致度 → closed-loop simulation → non-reactive real-log evaluation → long-tail testing → human-preference-aware metrics。**
    **DA-WAM が最高性能を出した NAVSIM は3番目に位置する。** 結論は厳しい ——
    **ADE/FDE のような displacement 系 open-loop 指標だけでは、安全で人間に沿った運転の証拠としてほぼ何も言えない。**
  - **★ R1 は「誰も言っていないこと」ではなく「survey が未解決と認定した穴」を埋める位置にある** ——
    open challenge に **runtime safety assurance / reproducible benchmarking / world-model validation** が並び、
    **R1 の問いはこの3つの交点にそのまま乗る。導入で引くのにこれ以上強い形はない**
  - **評価プロトコルを提案する論文の書き方: ControlledShifts (17882)** — 測り方を **2つの関数 (characterization / splitting) として明示**させ、
    **集約スコアは混ぜずに直交分解する** (prediction quality と prediction stability)。**R1 を写経する型。**
    **留保: unified robustness score の合成式が abstract から読めず、2軸を1つにまとめる段で混合の問題が再発しうる**
  - **測る対象を作る側にも手が要る: EnvHarness (19880)** — 静的な環境を**内部ロジックに触れずに外側から包む**ので、
    **元の verifier (正解判定器) が必ず保持される。** **シナリオ生成が実務で信用されない最大の理由が
    「生成したシナリオの正解を誰も保証できない」ことである以上、この設計原理は真っ直ぐ刺さる**(R1 の future work)
  - **指標が正しく測れていることの示し方: Thinking in a Low-Resource Language (17744)** —
    各指標に**棄却条件を先に書き、対照条件を置き、自分の計測器が失敗した件数を公開する**
- **2軸分解の独立な一致が4例に(R1 の導入部で引ける)**: R1 の「衝突率(成立性)と過保守さ(目的達成)」/
  W33→08-19 VibeWorlding の「physical feasibility と intent fulfillment」/ 08-20 ControlledShifts の「prediction quality と prediction stability」/
  08-21 SemComp-Bench の「結果の達成と意味的接地」。**対象も手法も無関係な分野で同じ構造の分解が独立に現れている ——
  「単一スコアは2つの異なる失敗様式を混ぜる」は運転分野の内輪の話ではなく、評価という営みの一般的な設計判断として書ける。主張の一般性は査読で効く**
- **局面分解型の評価という仕分け軸(2026-W34)**: **Beyond Final Scores (13417)** — 最終スコアだけでは
  進歩がどこで生まれどこで失われたか分からない。run の振る舞いを **問題の立て方 / 実装と実行 / 結果を受けた次の手の修正**の3局面に分解し、
  **ログから機械的に判定できる規則ベースの指標**で測る。結論は **「最終成績が同じ2つの run でも、詰まっている局面は違う」。**
  **運転にも自然に写る**(状況をどう認識し挙動を選んだか / 選んだ挙動を軌道としてどう出したか / 環境の反応を次の周期にどう反映したか)。
  **運転側に局面分解型の指標がほとんど無いならそこが R1 の新規性の置き場所、既にあるなら R1 は保証のつけ方に新規性を寄せる**
- **定義のほうが壊れている(2026-W33 の芯)— 「能力が足りない」で説明できない失敗の3層**
  - **層1: 測る側 —— 代理指標は下流を説明しない**
    - **VIScore (11174)** — world model の latent 表現の綺麗さ(等方性・probing・軌跡の直線性)は **planning 成功を説明しない**。
      **同じ目標分布を狙う2つの正則化が planning で割れる**以上、「目標分布に近い」という指標は成否について何も言っていない。
      処方は測る場所を **encoder → predictor → planner の3段**に広げること(**predictor が正しい未来に届くか / 出し分けの多様さ /
      planner が到達不能な未来を到達可能と信じ込んだ量**)。未見のモデル・データでも順位相関 0.75 超、
      **校正誤差が定数当てはめを下回った唯一の指標**(「順位は当たるが値は無意味」の逃げ道を塞いだ)
    - **判定器そのものを測る: OSReward (28609)** — 長い行動列の成否を人手で捌けないので VLM judge に任せている状況は我々と同型。
      **SOTA judge でも誤り方が一方向に偏る —— 失敗を成功と言う側へ系統的に倒れる。** ランダムな誤差は数で消えるが
      **向きを持った偏りは何件集めても消えない**。手続きだけを移植すればそのまま1本の仕事になる
      (自前 GT → 判定器の混同行列 → 間違えた事例だけの Hard セット)。**false success rate を conformal で α 以下に囲う**筋が
      R1 の空欄だった「で、何を保証するのか」を埋める
  - **層2: 生成・選択する側 —— もっともらしい出力は正しい出力ではない**
    - **反実仮想の欠落: 11601** — driving world model に **action だけ差し替えて生成しても、それは「あのとき実際に起きていた
      条件のもとでの未来」ではない**(**abduction 段の欠落**)。正解付きの検証環境を構築して代表2手法が外れることを実証。
      処方は**学習ゼロ・モデル凍結**。**log-replay 評価(「このログで我々の planner ならどうしていたか」)が体系的に甘くなる** —— R1 の基盤に直撃
    - **多峰性の圧殺: Clustered Randomized Smoothing (12037)** — 頑健化のための平均は **どのモードでもない1本**を出す。
      クラスタごとに平滑化して混合分布にし、**「モードの和集合」に対する保証**を導出。軌道予測で Wasserstein -27%、quadrotor 衝突率 -81%。
      **過保守さの第一候補「モード取り逃し率」(真の分布にあったモードのうち planner が候補に残さなかった割合)はここから来る**
  - **層3: 使う側の定義 —— 目的関数・プロトコル・粒度**
    - **The Objective Is the Bottleneck (12959)** — 予測器は余っている(75 ステップ先でも静止仮定の 0.189 倍)のに
      **planner は 25 ステップ先しか想像していない**。壊れているのは **潜在二乗距離というコスト**で、真の距離との相関は
      **r=0.426、約80 unit で飽和し 120 を超えると減少に転じる(ゴールから離れるとコストが下がる領域が実在する)**。
      **予測精度と長horizon 成功は逆順に並ぶ —— 予測損失で checkpoint を選ぶと最も下手なものを選ぶ。**
      **フレーム間隔だけを教師にした temporal distance head** は空間距離の予測としては劣る(r=0.819 対 0.9897)のに planning は上手い:
      **壁越えコストを 24% 高く見積もる(二乗潜在距離は 4% 低く)= 学習されたのは proximity ではなく reachability**。
      再学習ゼロで到達率 **26.0% → 98.0%**、予算 1/3 でも 92.0%
    - **処方の側: AirForesight (12835)** — 中間表現から復号した軌道が**専門家の行動方向と一致するよう縛る
      cross-space planning consistency loss** 1本。**12959 が診断、本論文が処方**という対で読む(UAV 由来、移植できるのは loss の形だけ)
    - **プロトコル: OpenART (00677)** — **目標を固定し、環境状態だけを正規の操作で進化させて失敗を探す**。
      重要な数字は攻撃成功率ではなく **「指示文だけを変える手法に対する優位が、単純な環境の約2%から最複雑環境では17%超へ広がる」**。
      **運転に写せば、固定シナリオ集は混雑場面ほど失敗率を過小報告している**(分野外からの独立証拠なので査読で強い)
    - **粒度: Environment Scaling (03571)** — 環境は増やすより選べ。**見た目(ドメイン・画面)で多様性を測ると、
      同じ能力しか要求しない環境が並んでいても「多様」と誤判定する**。評価スイートを本数ではなく
      **「要求される判断のカバー率」**で語り直す(**FactorDrive (09591) の PCF が、その語彙をゼロから作らずに済む候補**)
- **学習済みモデルの外側に決定論的な検証層を貼る(2026-W33 で定着を確認)— ネットワークは提案し、別の層が審査する**
  - **DPC の位相的 feasibility 保証 (10332)** — 学習ポリシーに**確率的でない決定論的な安全保証**を、実行時の安全フィルタ無しで与える。
    根拠は **DPC が白箱であること**で、著者自身が **RL や黒箱の近似 MPC では構造的に不可能**と明言。
    **これは R1 の存在理由をそのまま補強する** —— 我々が評価したい E2E の学習型 planner は黒箱側にあり、**そこには確率的保証しか置けない**
  - **実車統合 (12198)** — NN は挙動を**提案**し、最適化ベースの監督層が走行可能性と安全制約を**強制**。
    open-loop → closed-loop 統合 → 実車走行まで一本で報告(数値は無く、価値は統合の詳細)。落選した **11451**(neuro-symbolic safety guard)が
    シミュレーションの数値で**まったく同じ構造**を独立に主張しており、**同日2本 = 設計パターンとして定着したと見てよい**
  - **保証の3型(R1 の見取り図。ここが今週揃った)**

    | 型 | 保証の種類 | 要求すること | 使えるか(E2E 学習型 planner) |
    |---|---|---|---|
    | **conformal 型** | 確率的 (1-α) | 何も要求しない(黒箱でよい) | **使える**(R1 の主線) |
    | **DPC 型 (10332)** | 決定論的・厳密 | **planner が白箱の model-based であること** | 使えない(だから R1 が要る) |
    | **clustered smoothing 型 (12037)** | **モードの和集合に対する下界** | 黒箱でよい | **使える。多峰性を保ったまま保証を書く言語** |

  - **★ 空き地の存在証明(R1 の中心主張。今週4本が独立に空けた)**: **UnsDrive (09098) / DPC (10332) / 実車統合 (12198) /

## Open Questions
- **★ 既存の閉ループベンチマークの検出力を、走らせる前に計算する**(17956)— nuPlan / CARLA / Bench2Drive / NAVSIM の
  シナリオ数 N に事象率 r を仮定して **(1-r)^N**。**「このベンチは r ≥ x の事象しか検出できない」の一文が各ベンチに付くなら、
  それ自体が R1 の貢献になりうる。** ControlledShifts の枠組みと組めば「どの軸を、どの解像度まで検出できるか」の2次元表。
  **前提条件ゼロ・所要1時間**(W34 推薦実験)
- **★ Plan-Real Spearman を DA-WAM の scorer に当てたとき、上位候補の間で順位は保たれているか**(18746 × 19085)—
  **最も価値のある結果は「NAVSIM のスコアは最高だが、上位候補の間では順位が壊れている」。出れば R1 の主張は思弁ではなく測定になる。**
  **順序を間違えないこと: 順位が保たれていないなら、conformal を被せる土台がそもそも無い。conformal 化はこの測定の後**
- **★ 運転の安全仕様は LTL_f で何本書けて、何が書けないか**(17386)— **目的は書けることではなく、書けないものを見つけること。**
  書けない仕様が出たら、そこが「仕様ベースでは捕まえられない安全性」= 統計的保証を要する領域として特定できる。**紙とログのみ・半日**
- **★ 「停止してよい条件」を仕様として書き、それを満たさない停止を数えられるか**(17386 × W34 カード1)—
  **分母が観測不能だった過保守さの測定を、仕様で分母を定義することで回避できるか。**
  できれば規制文書2件が名指しした量に対応する指標が初めて定義できる。できないなら、なぜ書けないのかが R1 の問題設定そのものになる
- **既存ログを、成功と安全で独立に集計し直したら何%になるか**(17386)— **MANIGUARD の 6-21% に相当する数字が
  運転でいくつかは、我々が最初に知るべき量。新しい実験は要らない**
- **RP1 の学習された探索器は、順位が崩れている領域に手設計探索より高頻度で入り込むか**(18669 × 18746)—
  **探索器は world model の想像だけで学習されるので、world model の誤差が大きい領域を突きに行く動機を構造的に持つ。**
  **今週の2本を繋ぐだけで書け、誰もやっていない。R1 にとって最短の新規性**
- **同一 planner を open-loop displacement / non-reactive real-log / reactive closed-loop の3protocol で測ると順位は入れ替わるか**
  (20111)— **survey は入れ替わると主張している。自前の数字で示せれば R1 の一次証拠になる**
- **既存ベンチマークは推論計算量を固定して報告しているか**(16885)— **計算量に応じて性能が変わる方策が現れた以上、
  「計算時間固定で性能を1点報告する」評価は対象を取り違えている可能性がある。数本確認するだけ・1時間。**
  固定しているなら「計算量を横軸に取った安全性能曲線」が R1 の新規性候補
- **交通規則の遵守を評価対象に含めているベンチマークはあるか**(落選 Plug-and-Play Traffic Element Awareness 18035)—
  **信号・標識を差し込むと5つの異なるパラダイム全部で一貫して改善する = 既存ベンチはほぼ評価していない。**
  R1 が「既存ベンチが測っていないもの」を列挙するときの有力な一項目
- **「変わらなかった」を「頑健だった」と読んでいないか**(落選 Inference-Time Attention Steering 17095)—
  同論文は差が出なかった理由を突き止めて **"verified exposure, not robustness"** と書いた。**作法として R1 に効く**
- **★ 安全層の「過保守さ」を測る量を確定させる**(09098 / 10332 / 12198 / 11451 が4本とも測っていない = R1 の空き地)。
  第一候補は **モード取り逃し率**(真の分布にあったモードのうち planner が候補に残さなかった割合。12037 由来で、
  平均速度低下や介入頻度より**因果的に上流**)。副次に却下率・不要な減速回数・到達時間の悪化・介入頻度。
  **3日連続で同じ次アクションが要求されており、これが R1 の最初の実装物**
- **★ 予測損失で checkpoint を選ぶと、下流の planning はどう並ぶか**(12959 / 11174 / 落選 10145 が**独立に同じ図を要求**)。
  手持ち checkpoint を「予測損失 × closed-loop 成功率」の2軸で並べ直すだけ。**逆相関が出ればモデル選択の運用を即変更、
  出なければ他分野の話として棚に戻せる。どちらに転んでも1日で決着**(W33 推薦実験)
- **temporal distance head を運転に移すと、何を学ぶか**(12959)— 走行ログのフレーム間隔を教師にすると、
  拾うのは「到達しやすさ」ではなく **「人間の運転者がそうしなかった」という選好** ではないか。
  だとすれば**専門家の過保守さをコストとして焼き付ける**ことになり、R1 が測りたい量と正面から衝突する
- **現行の closed-loop 判定器(ルールベース / VLM)の誤りは、どちらの向きに偏っているか**(28609)—
  全体精度ではなく **false success rate を単独で報告**する。同じ向きなら知見の転用が正当化される。
  さらに **false success rate ≤ α を conformal で保証したとき、人手レビューを省ける走行は全体の何%か**(保証レベル vs 自動化率の曲線)
- **log-replay 評価の主張のうち、どれが反実仮想を前提にしているか**(11601)— 洗い出すだけで実験不要。
  前提にしているものは主張を弱めるか abduction 段を足す必要がある
- **固定シナリオ集は、混雑場面ほど失敗率を過小報告しているか**(00677)— 目標固定・環境進化のプロトコルを
  closed-loop 運転シムで最小構成で回し、**環境の複雑さに対する優位の広がり**を再現できるかを見る
- **評価スイートは飽和しているか**(03571)— シナリオを N 本サンプリングして planner 間の順位が安定する N を描く。
  **既に安定しているなら収集の追加投資を止める根拠が1枚の図で出る**

- **ADE/FDE は多峰性の劣化を検出できない**(12037)— 分布距離(Wasserstein か簡易なモード数推定)を1本足す。潰れていなければ以降不要
