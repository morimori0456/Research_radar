# Fast Generative Inference — 推論ステップを削る生成 — Living Survey
最終更新: 2026-08-30

> 新設 (2026-W29)。プランナー (P1) と world model (P3) の双方で「反復 denoising を捨てる」
> 論文が独立に3本以上溜まり、既存2サーベイのどちらにも収まらなくなったため分離した。

## 一言でいうと
軌道生成も world model も diffusion / flow matching で書けるようになった一方、車載では
**NFE (Number of Function Evaluations; サンプリング時のネットワーク評価回数) がそのままレイテンシ予算**になる。
削り方は6系統 — 学習し直さずに削る (schedule) / 学習して削る (one-step drift) / 生成を1回にする /
**生成を完走しない**(深さ方向の early exit + 出力段の除去) / **そもそも本番に載せない**(学習時だけ生成し推論では枝ごと捨てる) /
そして **2026-W34 で加わった「入力そのものを伸ばさない」**(世界の状態を context の外に置き、必要な分だけ索引で引く)。
削る対象は反復回数でも深さでもなく**経路そのもの**でありうるし、**context 長そのもの**でもありうる。
**捨てても壊れないことは、根性ではなく構造(参照関係の禁止・索引の設計)で保証できる**というのが本サーベイの通奏低音。
削ると失うのは多様性・多峰性であり、**どこまで削ってよいかは下流タスクが決める**のが共通の教訓。

## 系譜マップ
- **★ 入力そのものを伸ばさない(2026-W34 新設)— 削る対象を「計算量」から「context 長」へ**
  - **Alaya-EVOKE (13546)** — 長い session を保てる world model を作るとき、**素朴な実装は「見てきたもの全部」を
    ネットワークの入力に抱え続けるので、session が伸びるほど遅く・重くなる**(監督コストが線形にスケールする)。
    **本論文はシーンの幾何をネットワークの外の倉庫に置き、カメラの向きで索引を張って、今の視界に要る分だけ取り出す。
    これで session がいくら伸びても入力の長さは一定に保たれる。**
  - **少ステップ化の側も揃っている**: **3ステップの student で、CFG (条件への忠実性を上げるため推論を2回走らせる定番技法。
    コストが2倍になる) を使わずに、単一 H200 で 1.5 秒ぶんの映像を 2.11 秒。**
  - **★ 手法選択の根拠が2例そろった**: **Alaya-EVOKE と DreamX-Phi (13489) が、異なるドメイン・異なる teacher 設計で、
    独立に DMD(出力分布ごと teacher に合わせる蒸留。1サンプルずつの模倣ではない)を選んでいる。**
    **点ごとの模倣より分布合わせのほうが容量差に強い可能性があり、R2 の手法選択の根拠として引ける**
  - **すぐ試せる副産物**: **self-forced rollout**(student 自身の出力を入力に戻して訓練する。毎ステップ正解を与える teacher forcing の逆)は、
    **teacher を一切変えずに訓練ループだけ書き換えれば入る。** 訓練時は正解を見て推論時は自分の出力を食う、というズレは軌道予測でも同じ形で起きている
  - **他系統との違い**: SimWAM は**生成経路を本番に載せない**、Adaptive-WAM は**生成を途中で止める**、
    本論文は**入力を伸ばさない** —— **3つは直交しており、同時に適用できる**
  - **★ 分野外から同じ答えが出た: VoiceMem (26005、2026-W35)** — 記憶を **context ではなく外部ストア**に置き、
    **既存の待ち時間から逆算した 134ms の予算の内側で明示的に検索して引く。**
    **★ 重要なのは予算の決め方である: 「何ミリ秒までなら許されるか」を、性能ではなく系に既にある遅延から導いている。**
    **運転側に同じことをするなら —— 遅延を人工的に足したときに solvability (逃げ道の残り本数) がいつから落ち始めるかを見る。
    落ち始める点が、その系の実質的なレイテンシ予算であり、以後モジュールを増やすたびに参照される定数になる**
    (planner-evaluation サーベイの solvability 計算に相乗りできる)
  - **★ 対極の代償も同じ週に測られた: StreamPI (26067、2026-W35)** — 記憶を context の中に持つ方式は
    **パラメータ増ゼロ・既存の事前学習済み重みをそのまま引き継げる**という圧倒的な安さがある代わりに、
    **コストが系列長とともに増える。** **つまり「削り方」の選択は、想定するタスクの時間長で決まる ——
    短い作業では context 型が最も素直で安く、数分〜数十分に伸びると外部ストア型に逆転する**
- **★ 削るのではなく、そもそも本番に載せない(2026-W33 新設)— 学習時だけ生成し、推論では枝ごと捨てる**
  - **SimWAM (07468, P3)** — 映像生成の枝と軌道予測の枝を**一緒に学習させ、学習が終わったら映像側を丸ごと捨てる**。
    NAVSIM **91.5 PDMS**・低レイテンシ・nuScenes へ zero-shot、**コード/重み公開**。
    **本系統の肝は「捨てても壊れない」の保証方法** —— 単に補助タスクを足しただけなら軌道側は未来映像に頼るように育つが、
    **isolated attention mask で参照関係そのものを禁止し、依存すること自体を不可能にしている**。
    Adaptive-WAM (06008) が**生成を途中で止める**のに対し、こちらは**生成経路を本番に一切載せない** ——
    削減率で言えば最も極端な端で、しかも**「学習時にはあるが本番には無い情報」全般の道具**になる(未来映像である必然性はない)。
    落選した **World Tokens** が独立に同じ設計に到達している
  - **非同期化で「削らずに隠す」: BrainWAM (12854, P3/P1)** — 重い映像側の生成処理と軽い行動側の処理を
    **非同期に回す**ことで、**予測文脈を保ったまま推論遅延を短縮**する。削減ではなくスケジューリングの軸で、
    **アーキテクチャ全体を移植せずここだけ移植する**手が成立しうる
- **★ 遷移を「学習する」のをやめて「積分する」(2026-W33 新設)— 効率は構造から出た副産物**
  - **LDR (09926, P3)** — 未来 latent を丸ごと予測させるのをやめ、**運動学の積み上げ(位置は速度の積分、速度は加速度の積分)を
    決め打ちで書き、ネットワークには3次以上の残差だけを出させる**。結果として **パラメータ 1/26・実行 143倍速**、
    かつ **分布内/分布外の誤差ギャップが baseline の 1/20**。**速さは目的ではなく、学習させる量を減らしたことの帰結**である点が
    本サーベイの他系統と異なる(他は「学習済みの重いモデルをどう安く回すか」)。**検証は白箱の合成物理ベンチのみ**
- **★ 出力を伸ばさずに計算だけ深くする(2026-W33 新設)— token 数がレイテンシになる系での削り方**
  - **BDH-CQ (09888, hf 207)** — 思考を言語化せず **latent の反復計算**で解き、**150M で ARC-AGI の cost-accuracy Pareto を突破**
    (1タスク $0.0007)。**CoT は「考える量」を token 数で払う設計で、リアルタイム制約下では token 生成コストが直接レイテンシになる。**
    反復回数で計算量を可変にできる点は、**シーン難易度に応じた計算配分**(Adaptive-WAM の深さ配分と同じ思想)を
    生成ではなく推論の側で実装する道
- **学習し直さずに削る**(既存の学習済みモデルに追加コストゼロ)
  - **VSFM (11442)** — flow matching の「一定速度」という暗黙の設計選択を任意の速度プロファイル v(t) に一般化。
    学習済みモデルでも **ODE を非一様な時刻グリッド (τ-schedule) で積分するだけ**で適用可。
    利得の理由は Euler 積分の local truncation error が誘導グリッド上で小さくなるため(理論が明快)。
    プロファイルは motion planning の速度計画(braking 等)から借用しているのが面白い
- **学習して削る**(推論を単一 forward に畳む)
  - **DRIFT (14507, P1)** — 軌道 latent 空間で one-step drift。48 proposal を1回のバッチ推論で生成、
    proposal+集約が 10.82ms。alpha (ノイズ強度) で多様性/保守性を振る
  - **DriftWorld (15065, P3)** — action-conditioned drift を学習時に獲得し、推論は現在観測+候補 action から
    単一 forward で未来フレーム生成。diffusion 比 **平均17倍高速・30+fps**
  - **RynnWorld-4D (06559)** — denoising を回さず 1-forward で行動を出す(4D 予測系からの流入)
  - **ABot-World-0 / ODE distillation (19191)** — 多step の拡散/フロー生成を **少step に蒸留**しつつ、**LongForcing** で長 self-rollout の distribution shift を抑える。few-step 化と long-horizon drift 対策を同時に解く(vla-world-model と相互参照)
- **そもそも生成を完走しない(2026-W32 新設)— 時間方向でなく深さ方向に削り、出力段を捨てる**
  - **Adaptive-WAM (06008, P3→P1)** — video diffusion planner を制御実験で解剖したところ、
    **denoising timestep(時間方向)には性能がほぼ鈍感**で、効くのは **DiT の深さ**、しかも最終層は不要で
    **中間層 hidden state から既に良い軌道がデコードできる**。そこで複数ブロックに trajectory diffusion head を付け、
    軽量 **trajectory-quality scorer** が閾値を超えたら即打ち切り(超えなければキャッシュから続行)。
    deploy 時は **CFG の反復 denoising ループも VAE decode も実行しない** — どちらも未来動画の合成にしか要らないため。
    NAVSIM **90.8 PDMS**(固定 exit + 64 proposal で 92.6)/ **平均 170ms**(full-depth 320ms 比 47% 減)、
    target domain の fine-tuning なしで nuScenes 転移。**「world model を生成器でなく特徴抽出器として使う」**割り切り
  - 他系統との違い: VSFM / DRIFT / DriftWorld はいずれも **生成を最後まで走らせた上で**回数を削る。
    こちらは**下流タスクに必要な情報が生成の途中にある**という前提に立ち、完成品を作らない。
    **シーン難易度に応じて深さを動的配分**する点も他にない軸(vla-world-model サーベイと相互参照)
- **削った先に何が開くか**(速さが機能を生む)
  - 推論時 **action search** が実用域に入る (15065): 1制御周期あたり評価できる候補軌道の本数が桁で増える
  - **オフライン代理評価器**になる (15065): rollout スコアが ground truth と最大 **0.99 相関**
  - **実時間の対話的生成** (03118 Vidu S1): 民生 GPU 540p/42FPS。few-step 蒸留と専用サービングを対で設計
- **削ると失うものを管理する**
  - **多峰性の消失**: 候補集合を平均するとモード間の谷に落ちる (**CE-MPPI 06499** の averaging-induced failure)
  - **多様性 vs 追従性**: **Flow-ERD (06957)** — entropy 正則化 reverse-KL で teacher 追従と多様性を両立させる
    realism–diversity パレート。few-step 化の代償を明示的に測る枠組み
  - **集約の設計**: **DRIFT (14507)** — 多仮説を1本に畳む集約を **proposal 品質ラベルなし**で学習
- 直交する軸: **制約の厳守**。**MDOC (12423)** は CBF 射影を生成ステップに挿入し、
  ステップ数を削っても hard constraint (衝突回避・走行可能領域) を破らない道を示す。
  **BiCompoDiff (21341)** は競合制約を **微分可能 energy** 化して逆過程に勾配注入し、制約ごとに破れ量を分解できる
  (annealed MCMC の精緻化ステップは追加コストと制約充足のトレードオフ = ステップ数と品質の同じ軸)

## Open Questions
- **★ 「入力を伸ばさない」を運転に移せるか**(13546)— **外部倉庫が持つのはシーンの幾何であり、
  動き回る交通参加者をどう扱うかは abstract から読めない。** 運転で決定的なのは
  **「交差点を一周して戻ってきたとき、さっき見た駐車車両が同じ場所にあるか」** —— **本文で最初に確認すべき点はここ**
- **★ self-forced rollout を、手持ちの軌道予測 student に足すと long-horizon の崩れは減るか**(13546)—
  **teacher は現状のまま、訓練ループを「自分の出力を入力に戻す」形に変えるだけ。1〜2日で分かる。**
  効けば R2 に「teacher を変えずに student の horizon 耐性だけ上げた」という統制された結果が1つ手に入る
- **DMD(分布合わせ)は点ごとの模倣より容量差に強いか**(13546 × 13489 が独立に DMD を選んだ)—
  **2例が独立に同じ選択をしているのは信号だが、統制比較は誰もやっていない**
- **「学習時だけ生成し推論で捨てる」を、映像以外の特権情報に転用できるか**(07468)—
  **他車の未来軌道の正解 / 後知恵で計算した最適軌道**を学習時だけ与え、isolated attention mask で依存を構造的に禁止する。
  **最初に確認すべきは「映像側を一切使わずに軌道側だけ学習した場合との差」**(小さければ主張は成立しない)
- **公開重みで、我々の推論環境でのレイテンシは実用域に入るか**(07468)— 論文の数字ではなく自環境の値で投資判断する
- **非同期スケジューリングだけを切り出して移植できるか**(12854)— アーキテクチャ全体より先にここだけ試す手
- **「遷移を積分として書く」は、我々の trajectory prediction で速度と外挿の両方に効くか**(09926)—
  出力パラメータ化だけを「速度・加速度の積分 + 残差」に変え、**評価は分布内誤差ではなく分布内/外のギャップ**で見る
- **反復回数で計算量を可変にする設計は、planner のレイテンシ予算配分に使えるか**(09888)—
  Adaptive-WAM の「深さの動的配分」と同じ思想を、生成側ではなく推論側で実装することになる
- **削る軸は「反復回数」と「深さ」のどちらが効率的か** — 06008 は timestep に鈍感で深さに敏感だと報告したが、
  これは planning が粗い情報しか使っていないからか、**NAVSIM が粗い判断しか要求していない**からか。
  合流・遮蔽・カットインのサブセットで感度が復活しないかを見れば切り分けられる
- **早期 exit の安全性を保証付きで言えるか** — trajectory-quality score を非適合度スコアとして calibration し
  「早期 exit した軌道の失敗率 ≤ α」を conformal で主張できるか(06008)。ただし **exit 位置が入力依存で変わる時点で
  交換可能性 (exchangeability) が壊れていないか**が論点。ここが解ければ R1 との接続点になる
- **scorer と exit head が同じ hidden state を共有する自己都合バイアス**はないか — 浅い exit の軌道を
  scorer が高く評価してしまう構造的な危険。早期 exit が誤った時の失敗分布を見る必要がある(06008)
- **NFE を横軸にした品質カーブは手法ごとにどう違う形をするか** — 「低 NFE で崩れる点」が
  手法選定の実質的な判断材料になるはずだが、統一プロトコルでの比較がまだない(W29 出力キューの中心仮説)
- 推論時 τ-schedule 変更 (11442) は、画像生成でなく**軌道生成**でも同じ利得を出すか。
  出るなら既存の flow-matching 軌道生成器に追加コストゼロで載る
- one-step drift で失う多峰性は、運転の意思決定(追い越すか待つか)でどこまで許容できるか。
  許容できないなら「速い生成 × 多仮説保持」を両立する構成は何か(DRIFT の proposal 集合はその一案)
- 高速 world model の rollout スコア (0.99 相関, 15065) は運転ドメインでも代理評価になるか —
  なるなら評価コストの桁が変わる(planner-evaluation サーベイの admissibility 認定と組で使う)
- **DRIFT (proposal 生成) × DriftWorld (高速 rollout 評価) を直列に繋げるか** — 1制御周期内で
  「安く多数出して、安く評価して、1本選ぶ」が閉じるかは実測しないと分からない
